# 라운드 391 — 원장을 세는 생성기 여섯을 통계 행 한 곳 위로 · 업종 성적의 비용 (2026-09-30)

라운드 390 이 `docs/PLAN_R390_CONTAMINATION_GUARDS.md` 의 *"아직 남은 것"* 으로 적어 둔 일이다 — 운영 보정표(랩)와
화면 캡션은 `ledger_view.stat_rows` 를 지나게 됐는데, **화면·연구에 적중률과 표본 수를 내는 생성기**는 여전히 원장
전체(진입가 축척이 어긋난 행 · 시장 접미사만 다른 복사본 포함)를 세고 있었다. 계획은 넷을 적었는데 원장을 읽는 곳을
**유도해서** 세니 여섯이었다.

원장 행수'를 잠근다) — 정보량만 통계 행으로 센다.

## 업종 성적의 비용 — 한 화면에 비용이 둘이었다

`gen_sector_perf.py` 가 `COST = 0.36` 을 박아 두고 있었다. 판정은 2026-09-22 부터 0.41(R350)로 빼는데, 이 표만 옛
비용으로 빼서 중앙 판정 바로 옆 *'이번 판단을 만든 근거들'* 의 업황 줄에 **비용 이름 없이** *"EV +0.15"* 로 나갔다.
이 표는 매일 다시 만드는 **화면용** 산출물이라 R255 가 남긴 연구 재현용 상수가 아니다. 운영 비용 한 곳
(`verdict_core.COST_PCT`)을 읽고, 업종 행마다 `cost_pct` 로 싣고, 화면이 *"EV +0.13 · 왕복 비용 0.41% 차감"* 으로
같이 적는다. 칸이 없는 옛 산출물(클라우드 복원이 하루 늦게 준다)이면 비용을 **안 붙인다** — 모르는 수를 붙이지 않는다.
화면 줄을 읽는 `sector_cycle.ledger_perf` 는 행을 그대로 넘기므로 고치지 않았다(§1 파일).

취약구간 지도·놓침 연구의 0.36 은 **안 바꿨다** — 화면에 안 나가는 연구 순서용이고 그 수들은 각 라운드의 재현 기반이다.

## 운영 계층 표는 다시 만들지 않았다 — 사람이 정할 일

`gen_hier_tables.py` 는 고쳤지만 `data/hier_prob_tables.json` 은 **그대로**다(2026-08-09 · 315칸). 그 표는 판정 중에
읽히는 확률의 재료라 다시 만들면 화면 확률이 움직인다 — 모델 변경이고 11-16 전방 재평가 동결 중이다. 고친 것은 **다음에
누가 다시 만들 때** 같은 규칙을 타게 하는 것뿐이다. 다만 재 보니 사실 하나가 드러났다:

- 운영 표는 **개발 구간 54,961행**(L5 n 합) 시절에 만들어졌고, 오늘 원장의 같은 모집단은 **223,276행**이다(4배).
- 오늘 다시 만들면 칸이 315 → 1,187 이 되고, 업종 층(L2)은 패치만 보던 옛 코드로 79,784행 · 새 코드로 186,262행이다.

**운영 확률표가 원장의 4분의 1로 서 있다**는 것은 버그가 아니라 R59 가 채택한 그날의 표이고, 다시 만들지는 결정
사항이다(모델 버전 · 사유 · 11-16 전후). 회귀 §382 가 *"계층 표 생성기는 자동 실행에 없다"* 를 잠근다 — 자동 실행이
조용히 모델을 바꾸지 않게.

## 회귀가 잠그는 것 (§382 · 13건)

- 축척 감사가 모든 종목을 네 갈래 중 하나에 넣는다(합 = 원장 종목 수 · 조용히 건너뛰지 않는다) · 작은 종목의 어긋난 행이
  행 목록에 들어 있다 · 오염 점검이 두 판정자의 행 불일치를 수로 적고 열쇠는 싣지 않는다.

- 워크플로가 부르는 스크립트 중 원장을 읽는 것(**유도** · 14개)은 `stat_rows` 를 지나거나 통계가 아닌 **사유**가 적혀 있다
  (감사기 셋 · 행 기록기 둘 · 줄 세기 둘 · 파일 복사 하나) · 예외 목록에 낡은 이름이 없다 · 심기 양방향(주석의 파일 이름은
  안 센다 — AST 로 문자열 상수와 호출 이름만 본다).
- 통계를 내는 여섯이 실제로 `stat_rows` 를 부른다 · 계층 표 생성기는 자동 실행에 없다.
- 표본 감사의 에피소드가 코드 6자리로 묶인다(심기) · raw 는 원장 전체 · 정보량은 통계 행.
- 업종 성적이 비용을 숫자로 박지 않는다(AST) · 화면이 EV 옆에 비용을 적는다 · 칸이 없으면 안 붙인다.
- 산출물이 뺀 수를 실으면 음이 아닌 정수이고 표본 감사는 *raw − 통계 행 = 축척 + 복사본* 이다(옛 판은 칸이 없다 —
  클라우드는 오늘 밤 옛 코드로 돌고 있어 내일 되받는 판에는 칸이 없을 수 있다).

## 오늘 밤 클라우드가 라운드 390 을 증명했고, 두 판정자가 갈린 곳을 드러냈다

2026-09-29 예약 실행(R390 코드 · 성공 · 전 단계 통과)이 라운드 390 의 장치들을 처음 돌렸다:

- **채점 자리 도장이 그날 먹었다** — 케이스 축적 로그: *"진입가 축척 도장(채점 봉으로 그 자리에서) — 어긋남 2,598 ·
  같음 252,932 · 댈 수 없음 0"*. 같은 줄 아래 *"축척 감사의 행 목록을 못 읽었습니다 — 채점 자리의 도장으로만
  거릅니다"* 는 **예상한 그대로**다(복원된 옛 판에는 행 목록이 없다 · R389 의 '하루 늦음'). 도장이 그 하루를 메웠다.
- **새 꼬리 검사(오염 점검 `--verify`)가 통과했다** — 본 행 393,887 · 못 잰 곳 0 · 0 이어야 하는 수 전부 0.
- 완료 열쇠가 코드 6자리로 바뀐 뒤 계획 줄이 *"완료 253,030건"*(= 255,529 − 복사본 2,499)이다 — 복사본이 다시 안 생겼다.
- 증분: 원장 255,529 → 255,930(+401) · 전방 기록부 960 → 1,020 · 시점 재무·잔여 호가 +60 · 뉴스 +8.

그런데 두 수가 안 맞았다 — **도장은 2,598행, 같은 실행의 축척 감사는 2,342행.** 같은 항등식(`ledger_view.entry_scale_off`)을
쓰는 두 판정자가 256행 갈렸다(§4). 되받아 행으로 대 보니 **도장에만 256 · 감사에만 0** 이고, 그 256행은 **22종목**에
몰려 있었다 — 전부 원장 행이 **20개 미만**인 종목이다. 축척 감사가 `MIN_ROWS = 20` 미만 종목을 **조용히 건너뛰고**
있었다(몇 개를 건너뛰었는지도 안 적었다 · R194). 1,549종목 중 **139종목 · 1,623행**이 한 번도 안 재졌다.

그 22종목의 실제 일봉을 받아 재니 배율이 **0.94~0.99** 로 종목마다 일정한 계단이다(두 단이 있는 종목도 있다) — 첫 봉이
2023-12 ~ 2024-12 인 종목들이고, 라운드 389 가 본 *'자료원이 과거 봉을 고쳐 쓴다'* 와 같은 모양이다. 목표·손절이 진입가에서
2~3% 라 이 정도 어긋남으로도 결과가 흔들린다(1봉째에 판정된 비율이 종목에 따라 13/15 · 11/14). **도장이 맞았고 감사가 못
봤다.**

고침: 감사가 20행 미만 종목도 잰다. **행 목록**(`offender_keys` · 통계에서 뺄 행)에는 넣고 — 항등식은 행 하나로도 사실이다 —
**종목 단위 목록**(`offenders` · R364 의 정의 · §362 상한 19)은 그대로 두고 작은 종목은 `small_*` 로 따로 적는다(22종목 ·
256행). 모든 종목이 네 갈래(잰 것 · 못 읽음 · 20행 미만 잰 것 · 20행 미만 못 읽음) 중 하나에 들고 그 합이 원장 종목 수와 같다
(1,410 + 0 + 139 + 0 = 1,549). 오염 점검은 두 판정자를 행으로 대 본 수를 알림에 싣는다(`scale_judges` · 열쇠는 안 싣는다 ·
§9) — 고친 뒤 **도장에만 0 · 감사에만 0**. 실패가 아니라 알림인 이유: 도장은 채점하는 봉으로, 감사는 같은 날 뒤에 다시 받은
봉으로 재므로 그 사이 자료원이 과거 봉을 고쳐 쓰면 정당하게 갈릴 수 있다.

되받은 원장(255,930행)으로 다섯 산출물을 다시 만들었다 — 통계 행 250,833(축척 2,598 · 복사본 2,499 제외) · 고유 종목 1,513 ·
에피소드 44,949 · 전체 ICC 0.1337. 동봉본도 255,930행 전량으로 갈았다(R360·R372 의 묶음).

## 서 있는 결론

바뀌지 않는다. 매수권 적중·EV 는 소수점 둘째 자리에서 움직였고(기준선 59.9 → 60.1% · EV −0.143 → −0.119 · 비용 0.36),
**비용 차감 우위 없음**은 그대로다. 크게 바뀐 것은 **표본을 얼마나 믿을 수 있나**(ICC 2.5배 · 유효표본 42%)이고, 그 방향은
*"표본이 실제보다 독립적으로 보였다"* 다 — 라운드 217 의 규칙(케이스 수를 표본 크기로 읽으면 실제보다 좁다)이 한 겹 더
강해졌다.

## 이 라운드의 규율

- **계획의 목록을 그대로 믿지 않았다.** *"넷"* 이라 적혀 있었는데 원장을 읽는 곳을 유도하니 통계를 내는 것이 여섯이었다 —
  놓침 연구는 R363 이 오염을 찾은 바로 그 출력이었는데 목록에 없었다(R114·R242 의 *손 목록은 낡는다*).
- **효과를 원인별로 갈랐다.** ICC 가 2.5배 움직인 것을 *"통계 행으로 옮기니"* 로 적지 않고 축척·복사본을 따로 빼 봤다 —
  전부 축척 쪽이다.
- **고친 것과 다시 만든 것을 가른다.** 계층 표 생성기는 고쳤고 운영 표는 안 만들었다 — 만드는 것은 모델 변경이다.
