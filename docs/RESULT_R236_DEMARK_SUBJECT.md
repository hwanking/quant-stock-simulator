# 결과 R236 — 상태값에 주어가 없었다 · 46점의 출처 · '지지'가 두 번 (2026-09-08)

사용자 지적 셋. 하나는 **계산이 맞고 주어가 빠진 것**이었고, 하나는 **산식이 화면에 없던
것**이었고, 하나는 문자열 조합 실수였다. 값·판정·산식은 하나도 바꾸지 않았다.

## 1. Perfected — 계산은 맞다, 주어가 빠졌다

사용자: *"Buy Setup 0/9, Sell Setup 1/9 인데 Perfected 가 '충족'이다. 카운트가 9가 아닌데
충족이 나오면 렌더링이 꼬인 것 아닌가."*

엔진을 보면 그렇지 않다:

```python
is_perfected_buy = buy_perfected_map.get(latest_buy_setup_idx, False) if latest_buy_setup_idx else False
'perfected_status': "충족" if (is_perfected_buy or is_perfected_sell) else "미충족",
```

`perfected_status` 는 **진행 중인 카운트가 아니라 가장 최근에 완성된 9 셋업**을 두고 하는
말이다. 카운트가 0/9 여도 지난 셋업이 완성됐을 수 있다 — 둘은 다른 시점의 사실이다. 화면이
그 둘을 **주어 없이 나란히** 놓아 모순으로 읽혔다.

그래서 사용자가 제안한 *"9 미만이면 무조건 '미해당'으로 덮어써라"* 는 **택하지 않았다.**
그건 실제로 있었던 사실(지난 셋업이 완성됐다)을 지우는 일이다. 대신 주어를 적는다 —
`Perfected: 충족 (매수 셋업 기준)` + *"가장 최근에 완성된 9 셋업을 두고 하는 말이라 위의
진행 중인 카운트와 다를 수 있습니다."*

**그리고 '미충족'이 두 가지를 한 낱말로 말하고 있었다** — 완성된 셋업이 아직 없었거나
(`latest_*_idx` 가 없음), 있었지만 조건을 못 채웠거나. 물타기 '불가' 한 낱말이 셋을
뭉뚱그렸던 자리와 같은 모양이다. 화면이 **둘을 가르지 않는다고 적는다**(§3 — 모르는 것을
아는 척하지 않는다). 가르려면 엔진이 그 사실을 따로 내보내야 하고, 그건 새 라운드다.

## 2. 46점의 출처 — 산식은 한 곳에서 문장으로 낸다

탭 머리는 `중립 46점`, 아래는 `Bullish 6 · Bearish 11` 뿐이라 46 의 출처가 없었다. 엔진에는
있었다:

```python
s = float(np.clip(50 + (bull - bear) * 0.9, 0, 100))
```

50 + (6 − 11) × 0.9 = **45.5 → 46점**. 사용자가 본 수가 그대로 나온다(§253 이 이 계산을
실제로 돌려 재현한다).

산식 문장은 **엔진이** 낸다(`reasons` 에 한 줄 추가). 화면은 그 문장을 읽기만 한다 — 화면이
산식을 다시 적으면 계수가 바뀔 때 문장만 낡는다(§4). 계수를 바꾸면 §253 이 걸리게 두 줄을
같이 잠갔다.

화면 실측(2026-09-08 · 팬오션): `종합 40점 = 50 + (Bullish 6 − Bearish 17) × 0.9 (0~100 제한)`.

## 3. 'TDST 지지 지지 유지'

`tdst_support_str` 의 값 자체가 `"지지 유지"` 인데 접두어로 `"TDST 지지 "` 를 붙였다. 값은
그대로 두고 접두어만 뺐다 → `TDST: 지지 유지 · 저항 미돌파`.

## 4. 바꾸지 않은 것

- DeMARK 점수 산식·계수(0.9)·문턱·`perfected` 판정 로직 — 한 글자도.
- `tdst_support_str` 가 내는 값('지지 유지'/'이탈'/'N/A') — 그대로.
- 엔진 파일에서 바뀐 것은 **표시 문자열 두 줄과 주석**뿐이다(계산부 불변 · `git diff` 로 확인).
