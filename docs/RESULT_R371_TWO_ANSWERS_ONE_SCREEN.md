# 라운드 371 — 표는 '매도', 상세는 '보유 유지' · 한 화면의 두 답은 어디서 갈렸나

2026-09-27 · 킷 함수 둘(이력 문장 읽기 · 짧은 줄) · 화면 세 자리 · 검사 1절(12건)
· 규칙·판정·문턱·산식 **불변** · 버전 없음(바뀐 파일이 어느 축의 담당도 아니다 · `ui_kit`·`web_app`)

## 1. 사용자가 본 것

관심종목 표의 보유 행: **매도 — 손절선 아래** (현재가 6,090). 같은 종목을 열자 머리 문장은
**"지금은 사지 마세요 — 조건이 갖춰지면 후보"**, 보유 계획 칸은 *2026-09-27 기준 · 1차 매도가 6,262 ·
버틸 수 없는 가격 5,845 · 오늘 값과 같습니다*. 사용자: *"팔라고 하고 밑에서는 후보라고 하는데 뭐가
어떻게 된거야?"*

## 2. 먼저 셌다 — 갈린 자리는 셋이고, 계산은 하나도 안 틀렸다

**① 순서.** 관심종목 표는 페이지에서 중앙 판정보다 **앞**에 그려진다(표 → 중앙 판정 → 관심종목
채우기). 표는 저장된 계획(09-04 에 잰 손절선 6,115원)으로 판정해 현재가 6,090 ≤ 6,115 → '매도'.
그 실행 뒤쪽의 채우기 자리가 규칙(**닿으면 다시 잼** · 라운드 224)대로 계획을 오늘 값으로 다시 쟀다
— 새 손절선 5,845 · 새 1차 6,262 — 그리고 상세 카드는 그 새 계획으로 '보유 유지'를 그렸다.
**같은 실행 안에서 표는 옛 계획, 상세는 새 계획**이다. 다음 실행부터는 둘 다 '보유 유지'.

실측(`_probe/r371_row.py`): 행의 이력 줄은 *"2026-09-27 버틸 수 없는 가격 6,115원(2026-09-04 기준)
아래 (현재가 6,090 · −0.4%) → 정리 검토 · 기준 다시 잼"* · 지금 계획 손절 5,844.77 · 1차 6,261.66 ·
잰 날 2026-09-27 · `watch_action(row, 6090)` → **'보유 유지'**.

**② 잘린 말.** 라운드 340 이 바로 이 모양(*"오후엔 매도, 저녁엔 보유 유지"*)을 보고 이력 줄을 표에
넣었는데, 표가 그 줄을 **34자로 잘라** *"2026-09-27 버틸 수 없는 가격 6,115원(2026-…"* 까지만
보였다 — **"→ 정리 검토 · 기준 다시 잼"** 은 툴팁에만 있었다. 표의 '매도'와 상세의 '보유 유지'를 잇는
말이 화면에서는 없는 것과 같았다(라운드 301·312·314 의 *말없이 자르는 자리*).

**③ 다른 물음.** 머리 문장 *"조건이 갖춰지면 후보"* 는 **새로 사려는 사람**의 판정(중앙 판정의
`next_headline`)이고, 보유자 판정(버틸 수 없는 가격 · 1차 매도가 · 물타기 6조건)은 다른 함수의 다른
물음이다. 둘 다 맞는데 **같은 화면에 두 이름표가 붙을 때 그 이유가 같은 줄에 없었다**(라운드 214 ·
R243 의 *두 이름*).

얼마나 흔한가(`_probe/r371_count.py` · 보유 14행 · 이름 안 찍음): 계획을 다시 잰 행 **3** · 그중
**손절선을 넘겨** 다시 잰 행 **2**(사용자가 짚은 행 · 오늘 / 다른 한 행 · 09-14) · 지금 kind 는
**14행 전부 '보유 유지'**. 즉 손절선을 넘긴 두 행 다 '매도'가 **한 번도 화면에 머물지 못했다** — 규칙이
닿는 순간 다시 재기 때문이다(§4 사람의 결정).

## 3. 고친 것 (규칙은 안 바꿨다)

- **`ui_kit.hold_log_parse` · `hold_log_short`** — 이력 문장(`portfolio.hold_plan_update` 가 남긴
  세 갈래)을 읽어 표 폭에 맞게 **다시 말한다**: *"오늘 손절선 6,115원 넘겨 기준 다시 잼 → 새 손절선
  5,845원"*. 모르는 문장은 None 이고 종전대로 자른다(§3). 문장을 되파싱하므로 **생성기 출력을 그대로
  심어** 세 갈래가 다 읽히는지 회귀가 본다(§4).
- **`watch_action`** — 지금 계획이 선을 넘겨 다시 잰 것이면(마지막 이력의 날짜 = 잰 날) `hold_reset` 을
  싣고 이유 둘째 줄에 적는다: *"옛 계획(버틸 수 없는 가격 6,115원 · 2026-09-04 기준)으로는 파는
  자리였습니다 — 닿으면 다시 재는 규칙대로 2026-09-27 에 기준을 다시 쟀고, 새 버틸 수 없는 가격은
  5,845원입니다 · 규칙은 바꾸지 않았습니다"*. 이력 날짜가 잰 날과 다르면(그 뒤 다시 잰 계획) 안 적는다.
- **관심종목 표** — 이력 줄이 킷의 짧은 줄을 읽고, 선을 넘겨 다시 잰 행은 경고색.
- **채우기 자리** — 이 실행에서 계획이 **끝나서**(선에 닿음 · 창 경과) 다시 재어졌을 때만 **한 번**
  다시 그린다(세션 키 `_r371_rerun_{코드}_{날짜}` · 스냅샷은 세션 캐시라 재계산 없음). 다시 그린 표는 새
  계획과 이력 줄을 같이 낸다 — 한 화면에 두 답이 남지 않는다.
- **머리 문장 옆 한 줄** — *"이 문장은 새로 사려는 사람에게 하는 말입니다 — 보유 중인 판단은 다른
  물음이라 따로 냅니다: **보유 유지** (관심종목 표와 같은 판정 · 아래 '내 보유 포지션 · 보유자 기준'
  칸에 이유)"*. 판정은 표와 **같은 함수·같은 행**(`watch_action`)에서 읽는다 — 새 판정을 만들지 않는다.
  관심종목에 없이 사이드바에만 적은 보유(계획 없음)는 자리만 가리킨다.

## 4. 사람의 결정 — 손절선을 넘긴 계획을 바로 다시 잴 것인가

라운드 224 의 규칙은 *"닿으면 다시 잰다"* 이고 라운드 340 이 이미 *"팔지 않은 보유자에겐 손절선이
한 단계 내려가는 효과 · 보유자 재측정 여부는 룰북 결정이라 사람이 정한다"* 라고 적어 두었다. 오늘 수가
그것을 다시 말한다 — 손절선을 넘긴 행 **2/2** 에서 '매도'는 다음 실행을 못 넘겼다. 이 라운드는 그
사실을 **보이게** 했을 뿐이다. 갈래는 셋이고 어느 것도 측정이 고를 수 없다(원장은 종목 단위 · 보유
계획 이력은 14행): ⓐ 지금대로(닿으면 다시 잼 · 이력이 말한다) ⓑ 손절선을 넘긴 계획은 '팔았음'을
누를 때까지 그대로 둔다(매도 판정이 머문다 · 안 팔면 계속 붉다) ⓒ 손절선은 내려가지 않게만 한다
(1차 매도가만 따라 오른다). 어느 쪽이든 `hold_plan_update` 한 곳이다.

## 5. 확인

- 회귀 §366(12건): 생성기 세 갈래를 킷이 전부 읽음 · 모르는 문장 None · 짧은 줄 세 모양 · 선을 넘겨
  오늘 다시 잰 행의 kind·`hold_reset`·이유 둘째 줄·짧은 줄 · 이력 날짜가 다르면 안 적음 · 이력 없으면
  빈 글자 · 채우기 자리의 조건부 한 번 다시 그리기(세션 키) · 표가 짧은 줄을 읽음 · 머리 문장 옆 줄이
  같은 함수를 부름.
- 쓰기를 막은 앱 테스트(`_probe/r371_apptest.py` · 창으로 안 했다 · R320): 보유 행 하나를 복사해
  손절선을 현재가 위로 올린 가짜 계획을 **세션에만** 넣고 열었다 — 결과는 `_probe/r371_apptest.txt`
  (아래 커밋 메시지에 옮긴다).
- 사전 점검: 컴파일 3개 실패 0 · 정의 전 사용 0 · §366 12건 통과.
- 전체 회귀 첫 판 **실패 1** — §204 *"견해가 표의 판단을 다시 계산하지 않는다"* 가 `watch_action`
  호출 **수**를 세는 검사라 머리 문장 옆의 한 번에 걸렸다. 그 검사가 이미 R224 의 상세 카드 호출을
  *"한 정의를 두 화면에서 부르는 것은 §4 가 막는 것이 아니다"* 라며 빼고 있었고, 이 호출도 같은
  성질(같은 함수 · 같은 행)이라 같은 자리에서 뺐다 — 새 판정을 안 만드는지는 §366 이 따로 본다.
  검사를 무르게 한 것이 아니라 예외의 사유를 그대로 한 번 더 적용한 것이다. 두 번째 판은 커밋
  메시지에.

## 6. 안 한 것

- 규칙(닿으면 다시 잼)은 안 바꿨다 — §4 는 사람의 결정이다.
- 표를 중앙 판정 뒤로 옮기지 않았다 — 페이지 차례는 사용자가 정한 것이고(라운드 290) 옮기면 표가
  종목 분석을 기다린다. 대신 계획이 끝난 실행에서만 한 번 다시 그린다.
- 머리 문장의 보유 판정은 관심종목 행이 있을 때만 이름표를 적는다 — 사이드바에만 적은 보유는 계획이
  없어 표와 같은 판정이 없다(§3).
