# 정보 구조 (Information Architecture) — 글로벌 메뉴와 이행 경로

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 현재 web_app.py는 사이드바 + 단일 스크롤 페이지에 모든 기능이 세로로 쌓인
> 구조다. 이 문서는 목표 정보 구조(글로벌 메뉴 9개)를 확정하고, 현재 코드의
> 각 섹션이 어느 메뉴로 이동하는지, 어떤 순서로 이행하는지를 정의한다.
> **계산 로직은 옮기기만 하고 변경하지 않는다.**

## 4. 정보 5단계 원칙 (모든 화면 공통 위계)

| 단계 | 내용 | 화면 내 위치 | 예 (종목 분석) |
|---|---|---|---|
| ① 무엇을 해야 | 행동 결론 | 최상단, 가장 크게 | "조건 확인·관망" 배너 |
| ② 왜 | 올린 요인 3·내린 요인 3·차단 게이트 | 결론 바로 아래 | 게이트 체크리스트·근거 카드 |
| ③ 계산·근거 | 산식·가중합·상한 과정 | 탭 안 | 퀀트 점수 탭 |
| ④ 과거 적중 | 유사 사례·리플레이 적중률 (표본 수 병기) | 탭 안 | 백테스트·케이스 스터디 탭 |
| ⑤ 원천 데이터 | 출처·기준일·미수신 항목 | 최하단/감사 탭 | 데이터 감사 탭 |

규칙: 하위 단계가 상위 단계보다 먼저 보이면 안 된다. 어느 화면에서든
①을 보기 위해 스크롤이 필요하면 위계 위반이다.

## 5. 마이그레이션 경로 (단계적 이행)

Streamlit 단일 스크립트에서 한 번에 다중 페이지로 넘어가면 session_state·
캐시(get_shared_snapshot)·사이드바 의존이 동시에 깨진다. 두 단계로 나눈다.

### 1단계 — 단일 페이지 내 섹션 그룹핑 (구조 변경 없음)

- 사이드바 상단에 라디오/세그먼트 "화면 선택"(9개 메뉴 이름)을 추가하고,
  기존 섹션들을 `if selected_menu == ...:` 블록으로 감싸 조건 렌더링한다.
- 계산 함수·캐시 키·session_state 키는 일절 건드리지 않는다. 렌더 호출의
  묶음 순서만 바뀐다.
- 이 단계에서 정보 5단계 위계(결론 상단 격상)와 데이터 스탬프 컴포넌트를 적용.
- 검증: 화면 선택별로 기존과 동일한 수치가 렌더되는지 스냅샷 비교.

### 2단계 — 화면 분리 (st.Page / pages 디렉터리)

- Streamlit 멀티페이지(st.navigation + st.Page)로 메뉴당 1파일 분리.
- 공유 자원은 모듈로 추출: 종목 선택 상태·분석 파라미터(t_ref·rho)·
  스냅샷 캐시를 `ui_shared.py`(신규, UI 계층)로 이동 — quant_indicators.py 등
  계산 모듈은 임포트 대상일 뿐 수정하지 않는다.
- 전역 헤더(검색·테마·데이터 상태 배지)를 각 페이지 공통 렌더 함수로.
- URL 쿼리 파라미터로 종목 딥링크(?ticker=005930) 지원 — 추천 카드→종목 분석
  이동에 필요.
- 검증: 1단계 스냅샷과 화면별 동일 수치 + 페이지 전환 시 재계산이 캐시로
  흡수되는지 확인.

### 단계 공통 금지사항

- final_action_score·게이트·가격 레벨 산식 변경 금지.
- UI에 필요한 필드가 파이프라인에 없으면 임의 값 생성 금지 — 각 화면 명세의
  '필요 데이터 인터페이스'(SCREEN_SPECIFICATIONS.md)에 정의만 남긴다.
- 미수신·산출 불가 상태를 UI가 감추지 않는다 (빈 상태 규칙 준수).
