# 결과 R225 — 보유자 카드는 중앙 판정을 읽고 보유 계획을 같이 적는다 (2026-09-07)

R224 의 화면 실측 뒤에 남은 둘. **값·판정 불변** — 화면이 어디서 읽고 무엇을 말하는지만
바꿨다.

## 1. 무엇이 있었나

- 종목 상세의 "이미 갖고 있다면 · 현재가 기준 대응" 카드가 **four_scores 를 직접**
  읽었다(`target_tech_1st`·`stop_loss_price`). 다른 모든 화면은 `verdict_core.build()` 의
  `hold_trim`·`hold_stop` 을 읽는다(§4). 값은 같은 키에서 오지만 CORE 는 정합이 깨진
  값을 비우므로, 카드만 비워야 할 값을 보여 줄 수 있었다.
- R224 가 관심종목의 보유 계획을 **잰 날에 고정**하자, 같은 종목 상세 화면에 두 수가
  같이 보이게 됐다 — 카드의 오늘 값(현재가에서 다시 잰 값)과 아래 블록의 계획 값.
  어느 것이 관리 기준인지 카드가 말하지 않았다.
- 포트폴리오 탭의 보유자 행동점수(가중 35/15/20/15/10/5 · 등급 68/58/48)는 사전등록·
  실측 없이 정한 옛 값이다(R224 §5). 그 자리에 그 말이 없었다 — 숫자만 보여 주면 그게
  판단이 된다(R223).

## 2. 무엇을 바꿨나

| 어디 | 무엇 |
|---|---|
| 종목 상세 카드 | `_ex_tgt`·`_ex_stop` 과 도달 가능성 줄이 `CORE.get('hold_trim')`·`CORE.get('hold_stop')` 을 읽는다 |
| 종목 상세 카드 | 관심종목에 이 종목의 보유 계획(`paid`·`snap_hold_at`·기준값)이 있으면 한 줄: "보유 계획(잰 날 기준): 1차 매도가 X · 버틸 수 없는 가격 Y — 위 두 값은 오늘 다시 재면 나오는 값이고 관리 기준은 계획 값" (같으면 "오늘 값과 같습니다"). 값은 관심종목 행에서 그대로 — 새 계산 없음 |
| 판정 근거 상세 표 | 3행(기술적 1차 목표가 · 보유자)·5행(손절가 · 보유자)의 값도 four_scores 직접 읽기였다 — §242 의 첫 검사가 잡았다. CORE 로. (판정 기록 `prediction_log` 는 엔진 원값을 남기는 자료 경로라 그대로 둔다 — 화면이 아니다) |
| 포트폴리오 탭 | 보유자 행동점수 구성표 밑에 "가중치와 등급 문턱은 사전등록·실측 없이 정한 옛 값 — 판단은 6조건과 보유 기준값으로" |
