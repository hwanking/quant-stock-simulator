# 라운드 459 — 토큰 만료(EGW00123)를 알아채고 다시 받는다 · '연결 확인'은 잔고를 한 번만

2026-10-09 · 증권사 어댑터 · 판정·점수·문턱·주문 규칙 **불변** · 버전 없음.

## 왜

라운드 457 이 계좌 15초 갱신을 켰다. 그래서 *"15초마다 증권사를 부르는 지금 구조가 토큰을 어떻게 다루나"* 를 읽었다.

- 토큰은 저장소 밖 파일(`~/.gaeum/kis_token_*.json`)에 하루치를 두고 **다시 쓴다** — 15초마다 새로 받지 않는다(한국투자는 발급 횟수를 제한하고 발급마다
  알린다). 이건 맞았다.
- 그런데 **증권사가 먼저 토큰을 무효로 하면**(만료·시계 어긋남) 그 사실을 알아채는 길이 없었다. 파일의 만료 시각이 지나기 전까지 같은 토큰을 계속
  보내, 그동안 15초 갱신·워커의 모든 호출이 거절로 끝났을 것이다(워커는 잔고를 못 읽으면 보호 매도도 판정하지 못한다).
- 공식 샘플(`koreainvestment/open-trading-api` · `legacy/rest/current_price_samle.py`)은 응답 `msg_cd == "EGW00123"` 를 *토큰 만료*로 보고 토큰을
  다시 받은 뒤 같은 조회를 한 번 더 부른다. 그 코드만 근거로 삼았다(다른 코드는 확인하지 못해 적지 않았다 · §3).
- 곁들여 시스템 → 설정의 '연결 확인'이 잔고를 **두 번** 읽고 있었다(확인에서 한 번 · 스냅샷용으로 또 한 번).

## 무엇

- `broker_kis.TOKEN_EXPIRED_CODES = ('EGW00123',)` · `KisBroker._forget_token()`(메모리 + 저장소 밖 파일 · 저장소 안 token_dir 이면 파일은 안 건드린다).
- `_call` — 응답 코드가 만료면 토큰을 잊고: **조회**(잔고 · 매수가능 · 주문 내역)는 새 토큰으로 **한 번만** 다시 부른다(다시도 만료면 `BrokerError` ·
  끝없이 돌지 않는다) · **주문·취소는 다시 보내지 않는다** — `BrokerError('… 주문·취소는 다시 보내지 않았습니다')`. 게이트웨이가 코드를 붙여 거절했으니
  들어간 주문은 없고(모름이 아니라 거절 · `TransportError` 아님), 다시 보내는 판단은 실행부의 상태기계가 한다. 실행부는 바퀴마다 주문 **앞에**
  내역·잔고를 조회하므로 그 조회가 이미 새 토큰을 받아 둔다.
- `health_check` 가 읽은 잔고를 `balance` 로 같이 돌려주고, '연결 확인'은 그것을 장부에 남긴다(두 번 안 읽는다).

## 확인

회귀 §444(5건 · 네트워크 0 · 가짜 전송): 조회 — 낡은 토큰으로 만료 → 잊음 → 새 토큰 발급 → 같은 조회 한 번 더 → 성공(호출 순서 잔고·토큰·잔고) ·
다시도 만료면 한 번만(잔고 두 번 · BrokerError) · 주문 — 만료면 주문 호출 1번뿐 · '다시 보내지 않았습니다' · 거절(모름 아님) · 다음 조회는 새 토큰으로
성공 · `health_check` 가 잔고를 돌려주고 조회 1번 · 코드 목록은 공식 샘플 근거 하나.

  파일 만료 시각에 새로 받는다.
