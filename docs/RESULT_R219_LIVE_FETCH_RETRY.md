# R219 — 실시세 호출 29개 중 26개가 맨몸이었다: 호출부가 아니라 한 곳을 감쌌다 (2026-09-03)

**상태**: 검증 하네스 수정 · **계산 파일 불변**(§1) · 판정·문턱 변화 없음.

## 발단 — 하루에 두 번, 같은 원인으로 회귀가 죽었다

| 시각 | 죽은 자리 | 종목 | 로그 |

## 얼마나 넓은가 — 손으로 세지 않고 AST 로 유도했다

`_q53b`·`_q54`·`_q56` 처럼 **자기 엔진을 새로 만들어 쓰므로** 인스턴스 하나만
감싸도 안 잡힌다.

## 고침 — 클래스 메서드를 한 곳에서

```python
for _cls219, _meth219 in ((qi.QuantIndicatorsEngine, 'run_full_pipeline'),
                          (qi.QuantIndicatorsEngine, 'run_screener_scan'),
                          (be.BitemporalEngine, 'load_bitemporal_data'),
                          (be.BitemporalEngine, 'fetch_index_daily')):
    setattr(_cls219, _meth219, _retry_live(getattr(_cls219, _meth219)))
```

- **성공 경로는 그대로다** — 반환값을 그대로 돌려준다.
- 실패하면 **한 번만** 다시 받는다. 두 번째도 실패하면 그대로 올리고,
  R218 의 중단 요약이 *어디까지 갔는지* 적는다.
- **예산 8** — 네트워크가 통째로 죽은 환경에서 실행 시간만 두 배가 되지
  않게. 예산이 바닥나면 재시도 없이 바로 올린다.
- ⚠️ **계산 파일은 고치지 않는다**(§1). 이 감싸기는 회귀 프로세스 안에서만
  살고 `quant_indicators.py`·`bitemporal_engine.py` 파일은 그대로다. 진짜
  고침(수집 계층의 재시도)은 그 파일을 만져야 하므로 여기서 하지 않는다.

## 첫 판이 틀렸다 — 다시 받아도 소용없는 실패까지 재시도했다

회귀 로그가 잡아 줬다:

```
[재시도] load_bitemporal_data — 999999.KS: 네이버에 종목 페이지가 없습니다(메인으로
  넘어감) — 상장폐지·합병이면 이 코드로는 다시 받을 수 없습니다.
  시세 미수신과는 다른 사유입니다. (남은 재시도 예산 7)
```

**엔진이 "다시 받을 수 없다 · 시세 미수신과는 다른 사유"라고 적어 두는데
내 래퍼가 그걸 무시했다.** 라운드 204 가 정확히 이 구분을 만들어 뒀고
(`page_status == 'item_page_missing'`), R165 가 *"사유를 섞지 않는다"* 를
규칙으로 남긴 자리다 — **엔진은 지켰는데 내가 어겼다.**

실측 피해: 일부러 없는 종목(999999)을 넣는 검사 **둘이 예산 8 중 2를 미리
태웠다.** 진짜 네트워크 흔들림에 쓸 몫이 그만큼 줄어 있었다.

고침은 한 줄이다 — 그 사유면 재시도하지 않고 그대로 올린다. 다만 **문장으로
가르는 것은 무르므로**(§6 — 낱말 판별은 낡는다) §236 이 그 리터럴과
`page_status` 판별이 엔진에 아직 있는지 본다. 문구가 바뀌면 검사가 먼저
걸리고, 조용히 '전부 재시도'로 돌아가지 않는다.

## 검사 — 심어서 양방향으로 (§236)

산문이 아니라 **동작**으로 확인한다:

| 심은 것 | 기대 | 결과 |
|---|---|---|
| ① 한 번 실패 후 성공 | 값을 돌려준다(호출 2회) | 통과 |
| ② 그 재시도 | 예산을 1 쓴다 | 통과 |
| ③ 늘 실패 | 예외를 **그대로 올린다**(삼키지 않는다) | 통과 |
| ④ 예산 0 | **재시도 없이** 바로 올린다(호출 1회) | 통과 |
| ⑤ 성공 경로 | 손대지 않는다 | 통과 |
| ⑥ '다시 받을 수 없는' 실패 | **재시도하지 않는다**(호출 1회) | 통과 |
| ⑦ 그때 예산 | **안 쓴다**(진짜 흔들림에 남긴다) | 통과 |

그리고 **커버리지를 AST 로** 센다 — 이 파일이 부르는 실시세 메서드 집합이
감싼 집합에 포함되는지. 새 호출이 생기면 여기서 걸린다. 감싼 목록도 손으로
적지 않고 **실제로 감싼 것**(`_LIVE_WRAPPED`)을 쓴다(§110 — 손 목록은 낡는다).

## 남는 것

- 이것은 **회귀를 살려 두는 장치**이지 수집을 튼튼하게 만드는 것이 아니다.
  앱 자체는 여전히 시간초과에 그대로 노출된다(오늘 화면이 두 번 멈췄다).
  수집 계층 재시도는 `bitemporal_engine` 을 만져야 하므로 §1 에 따라 별도
  판단이 필요하다.
- 운용 규칙은 그대로다 — **회귀는 앱 서버를 내리고 돌린다**(R218b · CLAUDE.md
  §6). 재시도는 보험이지 면허가 아니다.
