# 라운드 458 — 계좌 스냅샷은 한 규칙 · 저녁 작업이 하루 한 점 · 지휘 띠의 낡은 시각 · 레이더 두 칸

2026-10-09 · 판정·점수·문턱·주문 규칙 **불변** · 버전 없음.

## 왜 (찾은 것 셋)

1. **실행부가 워커 바퀴마다 스냅샷을 무조건 쌓았다** — `run_cycle` 의 `L.account_snapshot(c, broker.env, bal)` 이 조건 없이 돌았다. 워커는
   60초마다 돌므로 실전이 켜지면 장중에만 하루 약 390행(보유 JSON 까지)이 쌓인다. 라운드 457 이 화면 15초 갱신에 저장 간격 규칙을 넣었는데
   **같은 장부에 쓰는 다른 자리**(실행부)는 그 규칙 밖이었다(라운드 246 의 *고침이 판정자 한 명에게만*).
2. **화면을 안 연 날은 자산 곡선에 점이 없었다** — 잔고를 읽는 자리가 화면과 (실전·보호 중인) 워커뿐이라 꺼짐 모드에서는 화면을 열어야만 그날
   점이 생겼다. 그리고 같은 값이면 안 남기는 규칙이라, 값이 그대로인 날은 화면을 열어도 점이 없었다.
3. **지휘 띠의 '동기화' 시각이 15초 갱신을 못 따라갔다** — 띠는 조각 밖이라 화면 전체가 다시 그려질 때만 바뀐다. 같은 화면에서 띠는 09:30,
   계좌 칸은 12:43 을 말했다(라운드 454 덤과 같은 모양).

## 무엇

- `swing_account.should_snapshot` — 규칙에 **새 날 첫 값**을 더했다(같은 값이어도 날짜가 바뀌면 남긴다 · 자산 곡선의 하루 한 점). 나머지는 그대로
  (보유·현금이 바뀌면 바로 · 가격만 바뀌면 600초마다 · 같은 날 같은 값은 안 남김 · 시각을 못 읽으면 남김).
- `swing_executor.run_cycle` — 스냅샷을 그 규칙 뒤로. 이 바퀴의 판단은 방금 읽은 잔고를 쓰므로 덜 남겨도 주문·보호에 닿지 않는다. 못 남기면
  메모만(바퀴는 계속).
- `scripts/run_swing_worker.py --snapshot` → `account_snapshot_once` — 한 바퀴 뒤 잔고를 **한 번** 읽어 같은 규칙으로 남긴다(주문 없음 · 연결 정보가
  없으면 증권사를 안 부른다 · 실패는 사유를 돌려주고 예외를 안 던진다). 저녁 작업(`scripts/nightly_local.py`)의 스윙 단계가 이 인자를 넘긴다.
- `swing_view.bar_items` — 자동 갱신이 켜져 있으면 '한국투자' 아래 글자가 *"자동 갱신 15초 · 시각은 아래 계좌 칸"*(낡은 시각을 적지 않는다).
- 경쟁사 레이더 — QuantConnect 상시 실행(배포 문서: 상주 서버 · 최대 5번 자동 재시작 · 상태 보존 없음 · 가동률 수치 없음)과 TradingView 차트
  (기능 페이지: 차트 21종 · 지표 400+ · 드로잉 110+ · 화면당 16 차트)를 읽어 **미확인 → 보유** · TradingView 모바일 항목 추가 · Composer FAQ 는 404 라
  그대로 미확인. `--diff --write` 가 바뀐 2건을 기계적으로 적었다. 차이(검토)는 여전히 알림·상시 실행 4건.
