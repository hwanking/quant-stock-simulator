# 결과 R275 — 전방 기록부의 빠진 거래일을 화면이 말한다 (2026-09-11 · 상태표 #20)

## 1. 무엇이 있었나

11-16 재평가(R55·R57·R66)가 읽는 원장은 **전방 기록부**(`.portfolio/forward_registry.jsonl` · fr-1 · 매
거래일 상위 60 판정을 박제)인데, 그 원장은 화면 어디에도 없었다. 화면의 "실전 추천 추적 파이프라인"
줄은 다른 원장(improvement DB · 동결 케이스 230건)이다. 빠진 날은 문서에만 있었다 — R253 *"22거래일 중
16일을 잃었다"*(09-10) · R264 §4 *"19일 중 13일 결손"*(08-14 기준). 상태표 #20 은 *"축소 가드가 줄 수만
본다 — 날짜 결손은 못 잡는다고 적어 두고 안 고쳤다 · 화면 표시는 남음"* 이었고, R272 가 앞으로의 결손을
워크플로에서 잡게 했으니 남은 것은 **이미 빠진 날을 화면이 말하는 것**이다.

R253 의 "22 중 16"(09-10 아침)에 09-10 · 09-11 이 더해진 수와 같다 — 같은 셈이다. 09-11 은 손으로
띄운 클라우드 실행(main = R272)이 끝나면 채워질 수 있다(그 실행의 '전방 판정 기록' 단계가 새 코드로
지나갔다). 나머지 17일은 그날의 실시간 입력이라 **다시 만들 수 없다**(R253).

## 3. 고침

| 자리 | 무엇 |
|---|---|
| `forward_registry.date_coverage(path, start, today)` | 행수 · 기록된 날짜 · 전방 구간 거래일 수 · 기록/빠진 날 목록. 시작일·휴장일 판정은 이미 있는 한 곳씩을 부른다 — 새 숫자 없음 |
| `web_app.py` 모델 성적 · 추적 줄 아래 | *"전방 판정 기록부 (재평가일 … 에 읽는 원장 · 매 거래일 상위 60 판정을 박제): 360행 · 기록된 거래일 6/24 (2026-08-09 ~ 2026-09-11) · 빠진 날 08-10, 08-11, … 외 6일. 빠진 날은 그날의 실시간 입력이라 다시 만들 수 없습니다 — 재평가 표본은 기록된 날만큼입니다."* 못 읽으면 "읽지 못했습니다 (…) — 미측정입니다" |

빠진 날은 12개까지 적고 나머지는 "외 N일"로 — 한 줄이 표가 되지 않게.

## 4. 검사 — §289 (5건)

심기 셋(거래일 5 중 기록 2 · 주말만 든 구간은 거래일 0 · 파일 없으면 행 0 이고 거래일은 그대로 세어 전부
빠진 날) · 화면이 한 곳에서 읽고 '다시 만들 수 없다'와 미측정 갈래를 말한다 · 시작일·휴장일 판정을 새로
만들지 않았다.
