# 라운드 485 — 외부 프로그램은 창 없이: 자식 프로세스는 CREATE_NO_WINDOW · 작업 스케줄러는 pythonw

2026-10-11 · `noconsole.py`(한 곳) · 자식을 띄우는 파일 19개 · 작업 스케줄러 두 작업 재등록 · 값·판정·문턱·주문 규칙 불변 · 버전 없음

## 무엇이 있었나

사용자: *"화면에 창이 떴다가 꺼졌다가 하는데 너 때문이야? 안되게 해줘"* · *"모든 외부 프로그램 실행을 창 없이 돌도록 바로 고쳐줘."*

**내 탓이었다.** 그 시각 배경에서 전체 회귀(라운드 484)가 돌고 있었다. 배경 실행은 콘솔이 없고, 콘솔 없는 프로세스가 콘솔
프로그램(git · PowerShell · python 자식 렌더)을 띄우면 Windows 는 **자식마다 새 콘솔 창**을 만든다 — 회귀 한 번이 자식을 수백 번
띄우므로 창이 계속 떴다 꺼졌다. 회귀를 바로 멈췄다.

같은 모양이 둘 더 있었다:

| 자리 | 무엇이 창을 띄우나 |
|---|---|
| 작업 스케줄러 `gaeum-swing-worker` | `python.exe` 로 등록 — 평일 08:50 부터 **장중 내내** 콘솔 창 · 10분마다 반복 실행(라운드 462)도 창 |
| 작업 스케줄러 `gaeum-watch-refresh`(저녁 작업) | `python.exe` 로 등록 — 17:00 부터 수 분 콘솔 창 |
| 미리보기로 띄운 앱 서버 | 스윙 칸이 작업 상태를 PowerShell 로 읽는다(라운드 453 · 15초 자동 갱신이면 15초마다) |

그 앞 회귀(09:49)는 §451 에서 멈췄고 PowerShell 이 종료 코드 `0xC000026B`(창 스테이션 종료 중)를 남겼다 — 원인은 재지 않았다.

## 고침

- **`noconsole.install()`** — `subprocess.Popen` 의 기본 `creationflags` 에 `CREATE_NO_WINDOW` 를 붙인다(Windows 에서만 · 멱등).
  자식은 콘솔을 갖되 창이 없고, 그 자식의 자식은 숨은 콘솔을 물려받는다. 호출이 스스로 콘솔 깃발(새 콘솔·분리·창 없음)을
  줬으면 건드리지 않는다. 출력·종료 코드·환경은 그대로다.
- **자식을 띄우는 파일 19개**가 import 직후 그것을 부른다 — 앱(`web_app`) · 회귀 · 스윙 작업 상태·알림(`swing_ops` ·
  `swing_notify`) · 저녁 작업 · 사전 점검 · 되받기 · 업데이트 이력(커밋 훅) · 계보 감사 등. 대상은 손으로 안 적었다 —
  `subprocess` 를 가져오는 파일 전부이고 회귀 §466 이 AST 로 빠짐을 잡는다(새 파일이 빠뜨리면 실패).
- **작업 스케줄러 두 작업을 `pythonw.exe` 로 다시 등록**했다(시각·반복·규칙 그대로 · 다음 실행 10-12 08:50 · 17:00). 두 스크립트는
  기록을 `.portfolio/*_run.txt` 에 스스로 남겨 표준출력이 없어도 잃는 것이 없다. 저녁 작업의 자식 단계는 출력을 파이프로 받아야
  하므로 `noconsole.console_python()` 이 같은 자리의 `python.exe` 를 고른다(창은 install 이 막는다).

## 확인

- 설치 뒤 띄운 python 자식이 보고한 `GetConsoleWindow()` = **0**(창 없음) · git 정상 · install 두 번째는 False(멱등).
- `pythonw.exe` 로 저녁 작업(계획) · 워커(쓰기 금지) · 리포트(계획) 셋 다 종료 0 · 표준출력·표준오류를 **None** 으로 심어도 셋 다 종료 0.
- 등록 확인: 두 작업의 실행 파일이 `C:\Python314\pythonw.exe`.
- 회귀 §466(4건) — 빠짐 0(훑은 파일 수를 찍는다) · 깃발 표 · 실제 자식 창 0 · 등록 스크립트·저녁 작업.
- 전체 회귀(라운드 484·485 같이 · 창 없이 돌았다): **6,644건 · 실패 1 · 건너뜀 0**. 실패는 §454 ②' — 작업 카드 검사가 저녁 작업 셋째 단계의 시간 상한(7200초)과 옛 차례의 단계 이름을 **글자로** 박아, 라운드 484 가 단계를 하나 끼워 넣자(셋째가 상한 30분 단계로 바뀜) 판정은 맞는데 검사가 붉어졌다(R98b 계열). 심는 기록·상한을 단계 표에서 만들게 고쳤고 앞 절과 이어 돌린 드라이런에서 ②' 통과. 다음 전체 회귀는 라운드 486 이 돈다.

## 하지 않은 것 · 남은 것

- 대조 시험 한 번이 `CREATE_NEW_CONSOLE` 로 자식을 띄워 **창을 한 번 띄웠다** — 그 시험은 회귀에 넣지 않았다(§466 ③ 은 창 없는 쪽만 본다).
- git 이 커밋 훅을 띄우는 것 · 내 셸 명령 자체는 이 저장소 코드 밖이다 — 훅이 부르는 업데이트 이력 스크립트의 자식은 막았다.
- 진짜 증거는 다음 평일이다 — 08:50 워커 · 17:00 저녁 작업이 창 없이 돌고 기록을 남기는지(`swing_worker_run.txt` · `nightly_local_run.txt`).

## 배운 것

- **사용자 화면도 내가 쓰는 자원이다** — 배경에서 도는 일이 화면에 무엇을 띄우는지 본다. 묻기 전에 *"너 때문이야?"* 가 나왔다면 이미 늦었다.
- **자식을 띄우는 길은 한 곳에서 막는다** — 호출부 19곳을 하나씩 고치지 않고 기본값을 바꿨다(라운드 120e).
