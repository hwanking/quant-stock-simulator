## 왜

사용자가 외부 검토 둘을 붙였다. 둘째(P0 목록)는 주문 사고와 직접 닿는 주장들이라 **주장마다 코드를 열어 가렸고, 전부 참이었다.**

우위 없음 문구 삭제(§9 — 접은 것이지 지운 것이 아니다 · 면책 한 줄은 늘 보인다 · 라운드 226) · 1차 목표 1.5R(라운드 160 실측 −0.20%) ·

## 무엇

- `swing_executor.run_cycle` — ① 계획·일봉 재채점을 **먼저**(모드와 무관) → 보호할 보유(`swing_ledger.protect_needed` = 관리 중 + 해제
  확인 중)가 없고 주문 모드가 아니면 심박만 남기고 끝 · 있으면 `protect_gate`(연결 정보만 본다 · 모드 조건 없음)로 증권사를 불러
  **보호만** 하는 바퀴(`protect_only`) → 신규 매수는 관문이 막는다. 워커는 `wants_broker` 로 연결을 만든다(종전엔 주문 모드에서만).
  검토가 제안한 STOPPED/PROTECTION_ONLY/LIVE_APPROVAL/LIVE_AUTO 넷은 **안 만들었다** — OFF 의 뜻을 바로잡으면 같은 것이고, 모드
  이름이 늘면 장부·시험·화면이 같이 움직인다. 보호까지 멈추는 길은 ④ 되돌려 받기 하나다.
- 되돌려 받기 2단계 — `release` 는 그 종목에 열린 매도 주문이 있으면 `RELEASE_REQUESTED` 를 적는다(관리 목록 `managed_open` 에서
  빠져 새 보호 주문은 안 내고 · `_cancels` 가 취소를 바퀴마다 요청) · 내역으로 맞춘 뒤 열린 매도가 없으면 `_finish_releases` 가
  `RELEASED` · 없으면 바로 `RELEASED` · 확인 중 체결되면 SOLD·CLOSED(RELEASED 를 덧붙이지 않는다). 화면은 '확인 중'으로 보인다.
- 진입가 — `verdict_core.build()` 가 `entry_price=entry` 를 싣는다(값 불변 · AST 로 잠근다). `swing_engine.entry_of` 는 그것을
  그대로 읽고(출처 `central`), 옛 리포트(칸 없음)만 구간 가운데로 물러선다(`buy_zone_mid`). 모델 가격과 호가 단위로 맞춘 주문 가격을
  **둘 다** 저장(`entry_model`·`target_model` · 옛 장부엔 열을 더한다 · 멱등) · 표는 다르면 괄호에 둘 다.
- `plan_id` — `[SPEC, 종목, 자료일, 진입, 목표, 손절, 대기, 보유, 비용, 규칙집 버전, 엔진 버전]` 의 해시. 규칙집 버전은 리포트에 적혀
