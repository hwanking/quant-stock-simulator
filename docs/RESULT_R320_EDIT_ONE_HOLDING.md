# 결과 R320 — 보유 종목 **하나만** 매입가·수량을 고친다 · 되돌릴 수 있게 (2026-09-16)

사용자: *"보유중에 수량 및 매입가 바꿀 수 있게 해줘야지."*

> ⚠️ **같은 날 라운드 321 이 이 설계를 바꿨다** — 사용자가 *"리스트에서 · 한번에 여러개"* 를 원해
> 한 종목 칸과 옛 격자를 걷어내고 **목록 편집기 하나**로 합쳤다. 행의 '고치기'는 그 편집기를 켜는
> 길로 남았다. 아래 §4(버튼 대비)·§5(사고)는 그대로 유효하다. → `docs/RESULT_R321_BULK_EDIT_LIST.md`

## 1. 기능은 있었다 — 쓰기 어려웠다

관심종목 절 위 토글 **'매입가·수량 편집 · 빼기'** 를 켜면 입력칸이 나온다. 그런데 켜는 순간
**표 전체(보유+미보유)가 위젯 격자**로 바뀐다 — 라운드 229 가 5,424px(화면 6장)로 잰 그 모양이다.
한 종목 수량을 고치려고 화면 전체를 바꿔야 했다.

라운드 244 가 '빼기'를 같은 이유로 기본 표에 꺼냈다(*"두 번 물었으면 이름 문제가 아니다"*).
같은 길을 쓴다.

## 2. 고침

| 무엇 | 어떻게 |
|---|---|
| 행마다 **'고치기'** | '빼기'와 같은 칸에 한 줄 · 같은 길(`?edit=<코드>`) — **표 높이·칸 수 그대로** |
| 한 종목 편집 칸 | 표 위에 입력칸 둘(매입가 · 수량)과 저장·닫기 — 저장된 값으로 채워져 열린다 |
| **같은 규칙** | 토글 격자와 한 종목 칸이 `_wl_with_position` 하나로 행을 바꾼다(§4) |
| **되돌리기** | 저장 **전 행 전체**를 쥐었다가 코드로 갈아 끼운다 — '빼기'(R244)와 같은 원칙 |
| 안내 | *"매입가를 0 으로 두면 **미보유**로 옮겨집니다 · 보유 판단에만 쓰이고 점수·적정가·추천에는 안 들어갑니다"* |

안내 문구는 **실제 규칙에 맞춰** 적었다 — 보유 여부는 매입가 하나로 갈린다(`_wl_owned`). 수량만
0 이어도 보유는 그대로다. §329 가 그 규칙과 문구를 같이 잠근다(규칙이 바뀌면 문구가 먼저 거짓이 된다).

## 3. 확인 — 사용자 파일을 안 바꾸고

`GAEUM_NO_LOCAL_WRITE=1`(읽기만 · 세션만 바뀐다)로 **앱을 통째로** 돌려 눌렀다:

```
보유 행 하나의 칸이 **저장된 값으로** 열린다                        참
수량 바꿔 저장 → 그 행만 바뀐다 · 칸이 닫힌다                       참
매입가 0 저장 → 미보유로 옮겨진다 · 행은 남는다                     참
되돌리기 → 저장 전 매입가·수량이 돌아온다 · 행 수 그대로            참 (R321 판으로 다시 쟀다)
예외 0개 · 관심종목 파일 수정시각 **안 바뀜**
```

## 4. 곁들여 잡은 것 — **본문의 주요 버튼이 안 보였다**

브라우저로 보니 '저장'이 비활성처럼 흐렸다. 실측:

| 버튼 | 바탕 | 글자 | 대비 |
|---|---|---|---:|
| 사이드바 '최신화' | 파랑 | 어둠 | 5.86:1 |
| 본문 '저장' · 본문 **'5종목 지금 계산해서 채우기'** | **어둠** | 어둠 | **1.22:1** |

라운드 116 이 *"파란 바탕 위라서"* primary 글자를 **어둡게** 뒤집었는데, 본문에서는 전역 규칙
`.stButton > button {{ background: 어두운색 !important }}` 이 바탕까지 어둡게 칠했다. 사이드바는
제 규칙이 파랑을 칠해 멀쩡했고 — **한 곳만 보고 통과로 읽혔다.** 새 기능이 만든 결함이 아니라
원래 있던 결함이고(§5 — 대비는 브라우저에서 실측한다), **전제(파랑 바탕)를 같은 규칙 안에** 적어
고쳤다: 본문 '저장' **1.22 → 5.86:1** · 일반 버튼(12.77 · 17.59) 그대로. 라이트 테마는 뒤에서 모든
버튼을 따로 잡으므로 안 닿는다.

## 5. ⚠️ 사고 — 확인하던 중 보유 두 행이 비었다

브라우저 창으로 확인하던 중 **관심종목 파일이 19:53:29 에 쓰였고, 보유 행이 16 → 14** 가 됐다.

오늘 R316 확인 때 앱을 통째로 그린 덤프(편집 기능을 넣기 **전**)와 대조했다:

```
매입가·수량이 비워진 보유 행   2
새로 담긴 행                   1
그 밖의 보유 값 변화           0
```

- 편집 칸은 **'저장'을 눌러야만** 쓴다 — 자동으로 쓰는 경로가 없고, 쓰기를 막은 앱 테스트에서도
  파일이 안 바뀌었다. 게다가 **채워져 있던 두 칸을 직접 0 으로 지우고** 저장해야 이렇게 된다.
- 같은 시각 그 창에서 **종목 검색·담기**가 있었다 — 사용자가 같은 창을 쓰고 있었다. 처음 연 창에
  **내가 누르지 않은 편집 칸**이 이미 열려 있었던 것도 그래서다.
- 그런데 나는 원인을 찾으려 **그 창을 여러 번 새로고침·이동**했다. 그래서 두 행이 **의도된 정리인지
  가릴 수 없게 됐다.**

그래서 **되돌리지도, 그대로 두지도 않았다.**
- 사고 전 값은 `_probe/r320_before_values.json` 에 따로 둔다(원 단위 글자 · 지금 보유 14행의 매입가가
  전부 정수라 같은 값일 가능성이 높다 · 커밋 안 됨).
- 복구 도구 `_probe/r320_restore_two_rows.py` 를 만들어 두었고 **돌리지 않았다** — 지금 파일을 먼저
  백업하고, 두 행의 매입가·수량만 되적고, 그 사이 다시 적은 행은 덮지 않는다.

**남기는 것**: 사용자 자료를 **쓰는** 기능은 창이 아니라 쓰기를 막은 앱 테스트로 확인하고, 창은
보기만 한다. 그리고 쓰는 기능에는 **처음부터 되돌리기**를 붙인다 — 이번 되돌리기는 이 사고에서
나왔다.
