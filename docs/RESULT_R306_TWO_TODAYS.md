# 결과 R306 — 한 등록부에 '오늘'이 **둘**이었다 (2026-09-16)

R305 를 커밋하려고 돌린 전체 회귀가 **처음** 붉어졌다. 00시대에 돌린 탓이다.

```
[FAIL] 화면이 원장과 같은 말을 한다 — ['usability|loss_control_tradeoff',
                                   ['점검일이 1일 지났는데 안 적음']]
```

## 1. 내 변경 때문인지부터 셌다 — 아니었다

재검토일이 **2026-09-15** 인 이슈를 화면이 *"다음 점검 2026-09-15"* 라고 적었다.
지역 날짜로는 어제이므로 **1일 지남**이어야 한다.

원인은 한 줄이다:

```python
def _today():
    return datetime.now(timezone.utc).date()      # ← UTC
```

그런데 이 등록부에 적히는 날짜(`next_review` · `eta`)는 **사람이 KST 로 정한 날**이고,
**닫는 쪽**(`issue_tracker.resolve_by_key` · 라운드 256)은 이미 **지역 날짜**로 견주고
있었다:

```python
today = datetime.now(timezone.utc).astimezone().date()   # ← 지역
```

**한 등록부에 '오늘'이 둘이었다.** 어긋나는 창은 **KST 00:00~09:00**(UTC 로는 전날)뿐이라
낮에 돌리면 안 보인다 — 자정 직후에 돌려서 처음 드러났다.

라운드 222(*검사에 SQLite `date('now')` 를 썼다가 틀렸다 — UTC 라 한국 아침엔 어제다*)와
라운드 283(*검사가 도는 시각과 재려는 사건의 시각이 다르면 '오늘'은 이름이 아니라
버그다*)이 고친 **그 자리**다. 세 번째다.

## 2. 고침 — 정의를 한 곳에 둔다

`issue_ops._today()` 를 **지역 날짜**로 바꾸고, 닫는 쪽이 **그것을 부른다**(늦은 임포트 —
모듈 수준에서 서로를 부르면 순환이다). 이제 등록부의 '오늘'은 하나다(§4).

회귀 §318 이 **심어서** 잰다: 어제가 점검일이면 `1일 지남`, 오늘이면 아직 아님
(양방향 · R194), 그리고 닫는 쪽이 같은 함수를 부르는지.

## 3. 남는 것 — 이 이슈는 닫아야 하나

그 이슈(`usability|loss_control_tradeoff` · 손절 조이기 노출 결정)는 재검토일이
**지났고 결정도 났다** — 사용자가 09-15 에 *"노출해줘 대가 같이 적고"* 를 골랐고
라운드 293 이 시행했다(플레이북 항목에도 그 결정이 적혀 있다).

**닫지 않았다.** 등록부 행의 상태를 바꾸는 것은 사람의 결정이고(R256 이 같은 이유로
이미 닫힌 행을 안 되돌렸다), 지금 화면은 **"점검 예정일 2026-09-15 · 1일 지남"** 이라고
사실대로 말한다 — 감춰지지 않는다. 닫을지는 등록부를 쥔 사람이 정한다.

## 4. 규칙으로 남기는 것

- **'오늘'의 정의는 한 곳이다.** 같은 등록부를 읽고 쓰는 두 함수가 다른 시간대를 쓰면,
  하루의 일부 시간대에서만 어긋나 **오래 숨는다.**
- **시간대 버그는 그 시간대에 돌려야 보인다.** 이 결함은 KST 09:00 이후에는 절대 안
  나온다 — 이 저장소의 회귀가 거의 낮에 돌았기 때문에 지금까지 통과했다.
- **붉어지면 먼저 "내 변경 때문인가"를 센다**(R289) — 여기서는 아니었고, 그래서 찾을
  자리가 달랐다.
