# 결과 R329 — 가늠 AI 질문 하나에 앱 전체가 다시 돌았다 · 대화만 다시 돈다 (2026-09-17)

사용자(R328): *"챗봇처럼 나와야 하니깐 바로 말처럼 써 주면서 대답을 해 줘."* R328 이 **말투**를 고쳤고, 남은 것은
**시간**이었다 — 추천 질문을 누르거나 입력하면 답이 **40~60초** 뒤에 떴다.

## 무엇이 느렸나

답을 만드는 `gaeum_chat.answer` 는 중앙 판정 값을 조합하는 함수라 밀리초다. 느린 것은 답이 아니라 **다시 그리기**였다 —
Streamlit 은 버튼·입력 하나에 스크립트 **전체**(시세 · 엔진 · 차트 · 관심종목 · 설명 절)를 처음부터 다시 돌린다.

## 고침 — 대화를 조각(`st.fragment`)으로

- 대화 구역(창 머리 · 말풍선 · 추천 질문 · 메일 링크 · 입력칸)을 `@st.fragment` 함수 하나로 감쌌다. 누름·입력은 **이 조각만**
  다시 돌린다. 맥락(`_ctx60`)은 마지막 전체 실행이 만든 것을 인자로 그대로 쓴다 — 값을 새로 만들지 않는다(§4).
- 조각 안의 입력칸은 하단 고정 입력바가 아니라 **놓인 자리**에 그려진다. 그래서 입력칸을 **창 안 맨 아래**로 옮기고 CSS 로
  창 바닥에 붙였다(말풍선이 길어져도 바로 친다). 창은 입력바 높이를 비워 둘 이유가 없어져 오른쪽 아래 18px 로 내렸다.
- 그러면 하단 입력바(`stBottom`)가 없어진다. 그것을 전제한 두 자리를 같이 고쳤다:
  ① 준비 표시(`gn-ask-ready`)를 *입력바가 있을 때만* 켜고 있었다 — 그대로 두면 **창이 영영 안 뜬다.** 스크립트가 붙으면 켠다
  (못 붙으면 클래스가 안 생겨 대화 구역·입력이 페이지 안에 그대로 보인다 — 대화는 여전히 된다).
  ② 바깥 클릭 닫기가 `bar && …` 라 입력바가 없으면 **안 닫혔다.**
- 조각 재실행은 바깥 `try` 를 지나지 않으므로 예외는 조각 안에서 받는다.

## 실측

- 먼저 네트워크 없는 시험 앱으로 조각 안 입력칸이 되는지 봤다(브라우저): 버튼·전송 뒤 **전체 실행 1 그대로** · 조각 실행 1→2→3.
  ⚠️ 앱 테스트(AppTest)는 조각만 다시 돌리지 않고 전체를 돌려 이것을 못 잰다(전체 1→2→3). 그리고 내 브라우저 도구의
  Enter 는 조각 밖 평범한 입력칸에서도 전송이 안 됐다 — **도구의 한계**이고 앱 결함이 아니다(전송 버튼은 된다).
- 앱(1920px 탭 · 전체 렌더가 멈춘 뒤): 추천 질문 → 답 **1.97초** · 입력 질문(말뜻) → 답 **0.45초**(종전 40~60초).
  창은 열린 채 · 맨 아래로 내려감 · 입력칸 바닥 1054 / 창 바닥 1062 · 최소화 620→52px · 머리 누름 복원 620 · 닫기 · 다시 열기에
  대화 4말풍선 그대로.
- ⚠️ 확인 중 한 번 창이 닫혔다 — 내 도구의 클릭 좌표가 화면 흉내(1920px) 아래서 어긋나 **창 밖**을 눌렀고, 그것은 바깥 클릭
  닫기가 제대로 도는 것이다. 이후 입력은 스크립트로 넣었다.
