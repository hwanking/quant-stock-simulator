# 라운드 366 — 프록시는 괜찮았고, 이름이 방법을 안 말하고 있었다

2026-09-27 · 화면 문장 한 마디 · model v2026.09.23.1 → **v2026.09.27.1**(`kind='ui'`)
· 값·문턱·상한·판정·산식 변경 **0**

사용자가 영상 하나와 제안 셋을 붙이며 **자기가 찾은 것**을 같이 적었다:
*"코드를 확인하면서 '월봉 10선' 계산이 실제 월봉이 아니라 일봉 200일 평균을
사용하는 경로를 확인했습니다. 이 부분은 영상 아이디어를 추가하기 전에 먼저 점검할
가치가 있습니다."* **맞는 지적이고, 그 순서도 맞다.**

⚠️ **영상은 확인하지 못했다** — 그 주장(성과·기법)을 근거로 쓰지 않고 **제안만**
쟀다(R342·R354·R356 와 같은 규칙).

---

## 1. 지적은 사실이다 — 코드가 스스로 적어 두었다

```python
# 월봉 10이평선 (일봉 200일 이동평균 프록시) & 월봉 추세 지표 연산
df['ma_200'] = df['adj_close'].rolling(window=200, min_periods=20).mean()
```

매수를 막는 게이트(`m10_disparity < 0` → 추세 역행 매수 제한 · 이격 +25% 상한 67점)가
읽는 것은 **일봉 200일 이동평균**이다. 월말 종가 10개의 평균이 아니다.

라운드 354 가 이 차이를 이미 쟀는데 **지수에서** 쟀다(KOSPI 12.5% · KOSDAQ 13.9%
어긋남). 그 라운드의 물음이 *"지수를 게이트에 걸까"* 였기 때문이다.
**게이트는 개별 종목에 걸리고, 그 자리는 한 번도 안 쟀다** — 사용자가 짚은 자리가
정확히 그것이다.

## 2. 쟀다 — 개별 종목에서는 **2.13%** 만 갈린다

표본은 **원장에 있는 종목 앞에서부터 120개**(고르지 않았다 · 게이트가 실제로 도는
모집단) · **못 읽음 0** · 잰 (종목, 날) **312,151**.
누출을 막으려고 **그 날이 속한 달은 미완성으로 빼고** 완성된 월봉 10개만 썼다.

| | |
|---|---|
| 두 정의의 위/아래 판정이 갈린 (종목,날) | **2.13%** (6,634 / 312,151) |
| 프록시가 "아래" / 진짜 월봉이 "아래" | 50.13% / 49.69% — 기준선이 거의 같다 |
| 프록시만 아래 → 게이트가 **더** 막는다 | 1.28% |
| 진짜만 아래 → 게이트가 **덜** 막는다 | 0.84% |
| 종목별 어긋남 — 중앙 / 최대 | **2.0% / 4.3%** · 10% 넘는 종목 **0 / 120** |

→ **프록시는 이 게이트에서 틀린 값이 아니다.** 정의를 진짜 월봉선으로 갈아도
게이트의 답은 100 중 98 이 같고, 남는 2 도 한쪽으로 쏠리지 않는다(1.28 vs 0.84).

⚠️ **지수가 개별 종목보다 더 갈린다**(12.5~13.9% vs 2.13%). 처음엔 반대일 거라
생각했는데 반대였다 — 지수는 변동성이 작아 주가가 두 선 **근처**에 머물러 위/아래가
자주 뒤집히고, 개별 종목은 대개 두 선 **모두**의 위나 아래에 분명히 있다.
**같은 물음이라도 모집단을 바꾸면 크기가 여섯 배 다르다**(R309 의 그 규율).

## 3. 그래서 고친 것은 계산이 아니라 **이름이 말하지 않은 것**

정의를 안 바꿨다(§2 — 바꿀 근거가 없고, 바꿔도 새 정보가 거의 없다 · R354 도 지수에서
같은 결론). 이름도 갈아 치우지 않았다 — *'월봉 10선'* 은 사용자가 아는 낱말이다.
**넣은 것은 방법 한 마디**이고, 넣은 자리는 **매수를 막는 근거 문장** 하나다:

> 월봉 10선 아래 (−x.x%) — 추세 역행 매수 제한 (리플레이 실측 −8.7%p) → 상한 64점
> **· 이 선은 일봉 200일 이동평균으로 잽니다**

사용자가 *"왜 막혔나"* 를 읽는 그 줄에 **무엇으로 잰 선인지**가 같이 있어야 한다 —
R239 가 모형 이름을 실제 입력에 맞춘 자리, R359 가 축 설명을 좁힌 자리와 같은 계열
(**이름이 계산보다 넓으면 사용자는 없는 근거를 있다고 읽는다**).

⚠️ **다른 호출부는 짧은 이름을 그대로 뒀다**(관심도 배지·리포트·업종 성적 표 등).
그 자리들은 게이트의 **근거**가 아니라 상태 표시이고, 같은 문구를 여러 곳에 되풀이하면
읽을 것이 묻힌다(R226·R301). 그리고 `market_attention.py` 는 이미 주석으로
*"월봉 10선 ≈ 200 거래일 이동평균"* 을 적어 두고 있다.

## 4. 영상의 제안 셋 — 무엇을 가져오고 무엇을 안 가져왔나

| 제안 | 판정 |
|---|---|
| ① **종가 기준** 손절 판정 (장중 휩쏘 무시) | **후보로 남긴다 — 잴 수 있다.** 우리 채점기는 `first_touch(bars, tp, sl)` 로 **장중 hi/lo 터치**를 쓴다 — 원장 254,329행이 전부 그 규칙 위에 서 있다. 종가 기준으로 바꾸는 것은 **룰북 변경**이고 라운드 346 이 잰 것과 같은 종류다(그 기계·경로 자료가 이미 있다). **사전등록 거리** |
| ② 돌파 시 거래량 1.5배 / 1.2배 | **수는 못 쓴다** — 손으로 고른 값이다(§2). 개념(돌파에 거래량 확인)은 잴 수 있고, 문턱은 측정이 정해야 한다 |
| ③ 월봉/일봉 뷰 분리 · 투자정책별 우선순위 | **전제가 없다** — '투자정책' 개념이 코드에 없다. 박스권 목표 전환은 라운드 160 이 이미 *측정 완료 · 채택 보류* 다 |

⚠️ **문구만 고치는 제안은 안 했다.** 화면이 *"종가 기준"* 이라 적는데 채점이 장중
터치로 도는 것은 **화면과 엔진이 다른 말을 하는 것**이고(§4), 그것이 R279·R322 가
고친 자리를 새로 만드는 일이다. **순서는 재는 것이 먼저다** — ①은 R346 처럼
사전등록을 먼저 커밋하고 재는 별도 라운드다.

## 5. 안 한 것 · 못 잰 것

- **정의를 안 바꿨다** · 값·문턱·상한·판정·산식 **불변**. 바뀐 것은 문장 한 마디다.
- 표본은 **120종목**이다 — 전 종목(1,547)이 아니다(비용 · 종목당 일봉 한 번).
  어긋남이 종목별로 0.8~4.3% 에 모여 있어 표본을 늘려도 자리가 크게 바뀌진 않을
  것이나 **그것은 추론이다**(§3).
- **월봉 기울기·유지 개월 수**(`m10_slope` · `m10_maintained_cnt`)는 **안 쟀다** —
  이 라운드가 잰 것은 위/아래 판정 하나다.
- 영상의 성과 주장은 근거로 **안 썼다**(확인 못 했다).
