# 라운드 402 — 게으른 캐시가 '읽었다'를 읽기 전에 찍었다

> 2026-10-01 · 값·문턱·판정 불변 · sector 축 v2026.10.01.1(`bugfix`) · 회귀 §391(6건)

## 무엇을 봤나

라운드 401 을 올린 뒤 서버를 다시 띄우고 **내 탭**에서 첫 화면을 확인했다. 기본으로 뜨는 종목의 요약 표가
**'계층 보정 확률 · 미산출'** 이었고, 그 확률 옆에 붙어야 할 라운드 401 의 기본값 대조 줄도 없었다.
같은 페이지를 한 번 더 그리자 **'약 66%'** 와 그 줄이 나왔다.

한 번은 없고 한 번은 있다 — 값의 문제가 아니라 **때의 문제**다. 차례로 갈랐다:

| 물음 | 잰 것 | 답 |
|---|---|---|
| 확률 함수가 이 점수에서 None 을 내나 | `blended_prob(59, …)` 를 점수별로 | 아니다 — 58~64 띠 0.599 |
| 화면이 넘기는 **실제 인자**로는 | 같은 종목 파이프라인의 four_scores·업종으로 | 아니다 — 0.654 (시장×변동성 층) |
| 앱 안에서는 | 쓰기를 막은 앱 테스트에서 함수를 감싸 인자·반환·예외 기록 | 1회 불림 · 0.6632 · 예외 0 · 화면에 '약 N%' |
| 모듈을 다시 읽나 | `importlib.reload` 목록 | case_layers 는 없다 |
| **그럼 첫 화면만 왜** | 캐시 코드 | 깃발을 **읽기 전에** 올린다 |

```python
def _hier_doc():
    if not _HIER['loaded']:
        _HIER['loaded'] = True          # ← 깃발이 먼저
        ... _HIER['doc'] = json.load(f) # ← 문서는 나중
    return _HIER['doc']
```

Streamlit 은 세션마다 스레드가 따로 돈다. 서버를 막 띄우면 '처음 부른 사람'이 둘일 수 있고, 두 번째 스레드가
그 사이에 오면 **깃발은 섰는데 문서는 아직 None** 이라 None 을 받는다. 부르는 쪽(`web_app`)은
`except Exception: pass` 로 받아 '미산출'을 적었고 **사유는 한 글자도 안 남았다**(§3).

## 재현 — 심어서

`json.load` 를 0.3초 늦추고, 스레드 A 가 읽는 중에 본 스레드가 같은 접근자를 부른다(`_probe/r402_cache_race.py`):

| 캐시 | 읽는 도중 두 번째 호출 | 다 읽은 뒤 |
|---|---|---|
| `case_layers._doc`(케이스 계층 표) | **None** | 문서 |
| `case_layers._hier_doc`(계층 보정 확률 표) | **None** | 문서 |
| `sector_cycle.ledger_perf`(업종 성적) | **None** | 문서 |

셋 다 같은 모양이고 저장소에서 이 모양은 **이 셋뿐**이다(깃발 대입을 AST 로 전수).
첫 화면의 '미산출'이 **이 경쟁 때문이었다는 것**은 재현하지 못했다(읽는 창이 몇 ms 라 서버 기동에서
다시 맞추기 어렵다) — 확인한 것은 ① 이 결함이 셋 모두에 있다 ② 그 증상과 정확히 같은 모양(첫 번만 None ·
다시 그리면 값)이다 ③ 다른 갈래(함수·인자·다시 읽기)는 전부 아니다, 까지다.

## 고침 — 한 곳

`artifact_io.load_once(cache, path)` — 잠금 안에서 한 번만 읽고 **문서를 넣은 뒤에** 깃발을 세운다. 세 자리가
그것을 부른다(R120e — 같은 결함을 셋에서 따로 고치지 않는다). **경로·실패 동작은 그대로다** — 못 읽으면 None 이고
다시 읽지 않는다(종전과 같다 · 고치면 매 호출 파일을 여는 다른 동작이 된다).

## 잠근 것 — §391(6건)

- 심기: 세 캐시 모두 읽는 도중에 부른 두 번째 스레드가 **문서를 받는다**
- 심기 반대쪽: 깃발을 먼저 올리는 옛 모양은 **같은 시험에서 None** 을 받는다(시험이 눈멀지 않았다)
- 같은 파일을 같은 내용으로 읽는다(case_layers 두 표 · 파일을 직접 읽은 것과 같다)
- 못 읽으면 None · 깃발은 선다(종전 동작)
- 판별식 심기(옛 모양은 잡고 깃발 없는 코드는 안 잡는다)
- 구조: `['loaded'] = True` 깃발을 올리는 자리는 **`artifact_io.py` 하나뿐**(훑은 파일 수를 찍는다)

## 버전

`sector_cycle.py` 는 **sector 축**의 담당 파일이라 값이 안 바뀌어도 버전을 먼저 냈다(버전 지연 검사가 커밋 날짜를
읽는다 · 라운드 351 이 바로 그 자리에서 걸렸다). `v2026.09.09.1 → v2026.10.01.1`(`bugfix`). case_layers 와
artifact_io 는 어느 축의 담당 파일도 아니다.

## 곁들여 — 의심했다가 재서 닫은 것

같은 앱 테스트가 이 확률에 넘어가는 국면 코드가 **'PULLBACK'** 임을 보였다. 원장의 국면 칸은 BULL·BEAR·SIDEWAYS
라서, 계층 표의 국면 층이 다른 낱말로 적혀 있으면 그 층이 조용히 건너뛰어질 수 있다고 의심했다. 쟀다
(`_probe/r402_regime_vocab.py`): 표의 국면 층(L4 · L4b · L2) 낱말은 **ABOVE_BOTH · PULLBACK · REBOUND · BEAR** 넷으로
화면이 넘기는 시장 상태 낱말과 **같은 체계**다. 그리고 같은 종목에서 표에 없는 낱말('BULL')을 넘기면 0.654,
화면이 실제로 넘긴 'PULLBACK' 이면 0.6632 — 값이 달라지므로 **그 층이 실제로 쓰였다.** 결함 아님.
⚠️ 그 프로브의 AST 추출은 시장 상태 함수에서 코드를 **0개** 찾았다 — 함수가 코드를 리터럴 dict 로 만들지 않아서다.
0 은 '없다'가 아니라 '못 읽었다'이고(R194), 판정은 앱 테스트의 실제 인자와 값의 차이로 했다.
