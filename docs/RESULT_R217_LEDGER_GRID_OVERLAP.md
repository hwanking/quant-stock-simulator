# R217 — 원장 기준일 격자가 날마다 밀렸다: 250,725건 중 25봉 간격을 지키는 것은 122,554건(48.9%) (2026-09-03)

**상태**: 관측 · 규칙 변경 없음 — **이미 채택된 규칙(25봉 간격)을 실제로
지키게 했다.** 원장 행은 지우지 않았다. 새 숫자는 없다.

## 발단

R216 을 끝내고 "못 다한 작업"을 찾다가 축적 루틴을 다시 봤다.
`docs/OPERATIONS_ROUTINE.md` §1 은 *"이후 매 거래일 자동 추가"* 와 *"중복
통제: 25봉 간격 기준일(지평 20봉과 비중복) · 미래 결과 기간 겹침 금지"* 를
적고 있고, 화면 원장 캡션은 *"독립 사례 250,725건 · 인접 기준일 중복은 25봉
간격 규칙으로 통제합니다"* 라고 말하고 있었다. 축적이 오늘 자랄 수 있는지
보려고 격자 함수를 읽었다.

## 기전 — 코드 두 줄

```python
# scripts/calibration_lab.py — make_asof_dates
usable = dates[260:len(dates) - horizon - 1]
picked = usable[::-spacing][:n_dates]     # 최근에서 과거로 spacing 간격

# load_done
done.add((r['ticker'], r['date']))         # (종목, 날짜) 정확 일치
```

격자는 **가장 최근 봉**에서 25봉씩 거슬러 뽑는다. 거래일이 하루 지나면
`usable` 이 한 칸 늘고 격자 전체가 **한 봉 밀린다.** 완료 집합은 정확
일치만 보므로, 다른 날 랩을 돌리면 밀린 격자의 108개 기준일이 전부 "아직
안 한 케이스"가 된다. R211~R213 이 같은 날(09-02) 돌아 그날 격자를 채웠고,
그것이 *"계획 소진"* 으로 보였다. 다음 날이면 같은 역사를 한 봉 옆에서
다시 표본화한다.

## 실측 — 원장 250,725행 · 1,547종목 (`_probe/r217_ledger_gaps.py` · 2026-09-03)

같은 종목의 이웃 기준일 간격(달력일 · 25봉 ≈ 35일):

| 간격 | 쌍 수 | 비율 |
|---|---:|---:|
| 3일 이하 | 45,791 | 18.4% |
| 4~14일 | 79,918 | 32.1% |
| 15~30일 | 53,928 | 21.6% |
| **31~40일 (격자 한 칸)** | 61,533 | **24.7%** |
| 40일 초과 | 8,008 | 3.2% |

**72%가 20봉 결과 창 안에서 겹친다.** 종목당 기준일 수는 108(한 격자 ·
427종목) · 296(184) · 484(92) · 376(73) 으로 뭉친다 — 밀린 격자 여러 벌의
합집합이다. 한 종목(296개)의 꼬리 간격을 나열하면 `5·23·8 | 5·22·15 |
5·22·8 | …` 로, 36일 주기 안에 세 격자가 끼어 있다.

채택된 규칙을 실제로 지키는 부분집합(종목별 이른 날짜부터 탐욕 · 35일 이상):

| 구간 | 전체 | 간격 준수 | 비율 |
|---|---:|---:|---:|
| train | 217,996 | 106,351 | 48.8% |
| valid | 17,560 | 8,616 | 49.1% |
| blind | 15,169 | 7,587 | 50.0% |
| **합계** | **250,725** | **122,554** | **48.9%** |

날짜 수는 2,749 → 2,563 으로 7%만 준다 — 겹침은 **같은 종목 안**에서
생기므로 날짜 군집 부트스트랩이 이 상관을 잡지 못한다.

### 표본 감사로 본 같은 사실 — 원장이 커지는 동안 독립 에피소드는 줄었다

라운드 72 표본 감사(`scripts/sample_audit.py` · ④ 같은 종목 35일 재신호 =
한 사건)를 현재 원장으로 다시 돌렸다:

| 산출 시점 | raw | 독립 에피소드 | 날짜 |
|---|---:|---:|---:|
| 2026-08-16 (종전 파일) | 184,759 | **57,496** | — |
| 2026-09-03 (이번) | 250,725 | **46,976** | 2,749 |

**+65,966건이 더해지는 동안 독립 에피소드는 −10,520.** 밀린 격자가 기존
기준일 사이의 빈틈을 메워, 따로 서 있던 사건들을 한 사슬로 이어 붙였다.
두 잣대는 다른 것을 잰다 — 간격 준수 부분집합(122,554)은 *겹치지 않게
남길 수 있는 케이스 수*, 에피소드(46,976)는 *원장이 담은 서로 다른 경험의
수*다. 헤더는 후자를, 원장 캡션은 둘 다 낸다 — 같은 파일에서.

## 이것이 뜻하는 것 · 뜻하지 않는 것

- **케이스 수를 표본 크기로 읽은 계산은 전부 실제보다 좁다.** 상관된
  표본은 신뢰구간을 좁혀 **거짓 양성을 늘리는** 쪽이다. 이 저장소가 낸
  결론은 거의 전부 "우위 없음"이라 방향으로는 살아남지만, 블라인드 단독
  신호가 배치마다 뒤집히던 것(R205·R208·R213)과 이 구조는 맞아떨어진다.
- "매 거래일 자동 추가"는 두 겹으로 틀렸다. 자동 스케줄이 없고(R196),
  있었더라도 새 날은 새 정보를 더하는 게 아니라 **옛 역사를 한 봉 옆에서
  다시 표본화**했을 것이다. 진짜 새 기준일은 25봉에 하나씩만 열린다.
- **원장은 지우지 않는다.** R197 이 파생물을 줄이는 실행을 금지했다.
  겹침 없는 부분집합은 `ledger_view.spaced_mask` 로 **연구 쪽이 고른다.**
  과거 라운드를 그 부분집합으로 다시 재는 것은 새 사전등록이다.
- R54b 는 이미 같은 규칙(같은 종목 35일 내 재신호를 한 사건으로)으로
  유효 표본을 세고 있었다(`data/effective_n.json`). 이번 35일은 그 규칙과
  25봉×7/5 의 달력 표기이지 새 문턱이 아니다 (§2).

## 고친 것

1. `ledger_view.py` — 규칙 한 곳: `MIN_GAP_DAYS = 25 × 7 // 5 = 35`,
   `too_close` · `dates_by_ticker` · `spaced_mask` · `spaced_count`.
2. `scripts/calibration_lab.py` — 계획을 세울 때 같은 종목 35일 안에 케이스가
   이미 있으면 그 기준일을 뺀다(`near_dup` 로 세어 찍는다). **전방 모드는
   제외** — R78 이 일부러 촘촘히 뽑고 에피소드로 병기한다.
3. `web_app.py` 원장 캡션 — "독립 사례" 를 지우고, 겹침 없는 부분집합 수를
   **그 자리에서 세어** 낸다(손으로 적은 수는 낡는다). "25봉 간격으로
   통제합니다" 도 지웠다. 모델 성적(국면×구간) 캡션도 표의 n 옆에 같은
   비율을 낸다 — 헬퍼는 모듈 수준 **한 곳**(캐시 · 키는 행수와 마지막
   기준일). 250,725행 셈은 pandas `.iat` 루프로 3.5초였고 리스트 루프로
   0.2초다 — 그래도 한 번만 센다.
4. `docs/OPERATIONS_ROUTINE.md` §1 · `CLAUDE.md` §2 — 거짓 문장을 고쳤다.
5. `test_pipeline_fixes.py` §234 — 규칙 심기(3일 쌍은 하나만 · 40일 쌍은 둘
   다) · 랩이 전방 모드 밖에서만 부르는지 · 캡션에 "독립 사례" 가 없는지 ·
   원장 실측으로 부분집합 < 전체(값은 안 잠근다).
6. **덤 — 헤더의 '유효 독립 표본 약 32,721건' 도 낡아 있었다.** R54b 의
   `data/effective_n.json` 은 **2026-08-09 · 원장 60,462행** 기준인데
   '누적 케이스 250,725건' 옆에 날짜 없이 서 있었다 — 4배 작은 원장의 수다.
   R197~R213 의 축적이 파생물 다섯을 갱신하면서 이 파일(과 R80 의
   `effective_n_icc.json`)은 목록에 없어 빠졌다. 더 나쁜 것은 그 파일에
   **생성 스크립트가 없다**는 점이다 — R54b 커밋은 JSON 만 넣었다. 같은
   정의(④ 같은 종목 35일 에피소드)를 라운드 72 표본 감사
   (`scripts/sample_audit.py` → `sample_audit.json`)가 세므로 헤더는 이제
   그것을 읽고 **기준 행수와 잰 날짜**를 같이 낸다. 두 산출물을 현재 원장으로
   다시 만들었고(ICC 전체 0.1406 → 유효 17,111 · 2026-09-03), 운영 루틴의
   갱신 목록(4b)에 넣었다. R54b 파일은 회귀(R122)가 구조를 보므로 지우지
   않았다 — 화면은 더 이상 읽지 않는다.
7. **덤 둘 — R198 의 결정이 네 자리 중 두 자리에만 닿아 있었다.** R198 은
   '누적 케이스'를 `total_cases`(캘리브레이션 대상) 대신 **원장 행수**로
   세기로 했고 사이드바·홈 카드를 고쳤는데, 헤더와 모델 성적 캡션은
   `total_cases` 그대로였다. 그래서 고친 헤더가 *'누적 케이스 249,748건 ·
   … 원장 250,725건 기준'* 을 **한 줄에** 띄웠다(서버에서 봐야 나온다 ·
   §6). 두 자리를 :753 과 같은 우선순위로 맞췄고 §234 가 `total_cases` 를
   그대로 띄우는 자리가 없는지 본다. 호출부를 하나씩 고치면 이렇게 남는다
   (§6 R120 의 그 모양).
8. **덤 셋 — 화면이 읽는 원장 파생물을 전수로 훑었다.** `data/*.json` 의
   `made` 를 마지막 축적일(동봉본 2026-09-02)과 대 보니 화면이 읽는 다섯
   중 셋이 낡아 있었다: 표본 감사(08-16) · ICC(08-16) · **업종 성적
   `sector_perf.json`(08-16 · R54b · 표시 전용)**. 나머지 낡은 파일은
   사전등록 판정 산출물이라 *판정한 날* 그대로 두는 것이 맞다(R107 의
   구분). 셋을 현재 원장으로 다시 만들었고, §234 가 셋의 `made` 가 동봉본
   `made` 이후인지 잠근다 — 값이 아니라 **신선도**를 잠근다(R212).
   그런데 업종 성적은 다시 만들어도 **거의 안 변했다**(반도체 n 5,750 →
   5,751). 처음엔 "새 행에 업종 백필이 안 돌았다"고 적었는데 **틀렸다** —
   표본 감사는 업종 미기록을 21,608/250,725(8.6%)로 센다(종전 10.0%). 새
   행에는 업종이 **있다.** 원인은 생성기다: `gen_sector_perf.py` 가 업종을
   **하위점수 패치에서만** 읽었고, 그 패치는 원래 60,462건용이다. 라운드 72
   이후 랩은 업종을 원장 행에 직접 쓰며, **R73 이 표본 감사에서 정확히 이
   결함을 고쳤다**(*"측정 도구가 한쪽만 보면 없는 구멍을 만들어 낸다"*) —
   이 생성기에는 그 고침이 닿지 않았다. 그래서 화면의 업종 성적(업황 카드 ·
   포트폴리오 업종 · 종목 상세)은 원장이 4배가 되는 동안 **옛 60k 행만**
   세고 있었다. 행의 업종을 먼저, 없으면 패치(R73 규칙)로 고치고 다시
   만들었다. §234 가 소스와 커버리지(파일 n 합 ≥ 원장에서 행에 업종이 적힌
   같은 필터 행수)를 본다.
   다시 만드니 **n 합 36,299 → 81,646** (업종 69 → 73 · 반도체 5,750 →
   9,743 · 적중 62.5%). 남은 것: 개발구간 매수권 행 98,600 중 **16,954(17%)**
   는 행에도 패치에도 업종이 없다 — 업종이 없는 자산(ETF·리츠)과 미백필이
   섞여 있고 가르는 것은 다음 일이다. 그리고 실행 중인 서버는 모듈 캐시
   (`sector_cycle._PERF` · 첫 호출에 한 번 읽음) 때문에 **재시작해야** 새 표를
   읽는다 — 새 프로세스로 확인했다(n 9,743).

## 남기는 물음

과거 라운드의 결론을 겹침 없는 부분집합(122,554)으로 다시 재면 무엇이
바뀌나 — "우위 없음"은 방향상 살아남을 것이나, **CI 폭**은 넓어진다.
R113(검정력 5%p)·R129(표본 천장)의 날짜 계산은 날짜 단위라 덜 영향을
받지만, 케이스 단위 조건(R124 §4 의 1,000건 등)은 다시 셈해야 한다.
새 사전등록으로 다룬다.
