# 업황 — 계획이 있는가, 그리고 언제 무엇을 잴 수 있는가

**작성** 2026-08-27 (라운드 181)
**요청** *"업황이 중요한데 업데이트 계획 없어?"*

**측정 전용 — 이 문서는 아무것도 판정하지 않는다.** 무엇이 이미 측정돼
기각됐는지, 남은 것이 무엇인지, 그것을 **언제** 잴 수 있는지만 적는다.
(`CLAUDE.md` §2-7 — *재기 전에 이득의 상한부터 셈한다.*)

---

## 1. 지금 상태 — 업황은 적정가를 **한 푼도** 안 움직인다

```
RULES_SECTOR.apply_to_fair_value = 0
cap_pct_normal / limited / reference = 0
```

업황은 **표시 전용**이다. 그렇게 정한 것이 라운드 44다.

## 2. 이미 측정하고 기각한 것 셋

### ⓐ 라운드 44 — `mom60` (업종 절대 모멘텀)

| | |
|---|---:|
| lift | **−14.8** |
| 게이트 | g1·g2·g3·g4 **전부 미달** |
| 판정 | **기각** |

**방향이 반대였다.** 사용자가 걱정한 바로 그것 — *"업황 좋으니 더 비싸도
된다"* 가 실측에서 **손해**였다(호황 구간 EV −2.467%). 이 길은 죽었다.

### ⓑ 라운드 44 — `rs60` (업종 상대강도)

| | |
|---|---:|
| lift | **+7.6** |
| 게이트 | **g1 통과** · g2·g3·g4 미달 |
| 판정 | **기각** |

mom60 과 달리 **완전히 죽지는 않았다.** 왜 걸렸는지가 중요하다 —
**블라인드 표본이 5분위에 78 · 18 · 28 · 21 · 99건**(합 **244**)이었다.
n=18 에 Wilson 구간이 **29.0 ~ 71.0** 이다. 라운드 27b 가 n=16 으로 물린
그 함정이라, 기각이 옳다.

### ⓒ 라운드 112 — 업종 내 백분위 상대화

**166,132건**으로 8종 전부 미달(문턱 z 2.9552). 그리고 결정적인 대조:
상대화의 **순수 기여가 도움 3/8 · 평균 −0.14** 로 동전 던지기였고,
**상대화 없이 업종 표본으로 줄이기만 해도 원값 z 가 −0.42 ~ +2.10 으로
흩어졌다.** 즉 그 범위의 z 는 증거가 아니다.

## 3. 오늘 새로 잰 것 — **이득의 상한**

라운드 163 이 KRX 표준산업분류로 **2,759종목**을 수집했다. CLAUDE.md 가
*"업종조정(업종 매핑 필요)"* 로 남겨 둔 조건이 채워졌으므로, 그 매핑으로
**잴 수 있는 표본만** 셌다 (`_probe/sector_ceiling_r181.py`).

| | |
|---|---:|
| 원장 | 184,759건 |
| 업종을 붙인 것 | **166,442건 (90.1%)** |
| 업종 수 | **131개** |
| 전체 날짜 | 2,695일 |

붙지 않은 것은 ETF(`069500` KODEX 200 등)라 정상이다.

### 그런데 **업종별로 나누면 날짜가 벽이다**

이 잣대가 쓰는 표본 단위는 **케이스가 아니라 날짜**다(라운드 113·129).

| 업종당 날짜 | 업종 수 |
|---|---:|
| 100일 이상 | 123개 |
| 300일 이상 | 47개 |
| **546일 이상** (8%p 를 보는 데 필요) | **20개** |
| 1,000일 이상 | 2개 |
| **2,051일 이상** (5%p) | **0개** |

최대가 1,342일(기타 금융업)이다. **업종 하나를 따로 보면 8%p 미만은
어느 업종에서도 못 본다.** 그리고 라운드 110 의 관측 점추정은 **0.0%p** 다.

## 4. 그러면 남은 길은 하나 — ⓑ 를 **사전등록 그대로** 다시 재는 것

라운드 110 이 R49 를 **한 글자도 안 고치고** 8배 표본에서 다시 돌린 것과
같은 수다. 될 만한지 표본만 셌다 (`_probe/rs60_feasible_r181.py`).

| | R44 (2026-08-05) | 지금 |
|---|---:|---:|
| 블라인드 5분위 합 | **244건** | — |
| 블라인드 전체 | — | **11,603건** |
| 그중 매수권(58+) | — | **5,458건 (22배)** |
| **블라인드 날짜** | — | **59일** |

**케이스 문제는 풀렸다(22배). 날짜 문제는 안 풀렸다 — 59일뿐이다.**
라운드 129 표로 보면 8%p 를 보는 데 546일이 필요하다. **59일로는
아무것도 못 본다.**

### 그리고 비용이 하나 더 있다

**`rs60` 이 원장에 안 실려 있다.** 재측정하려면 업종 상대강도를
**날짜별로 다시 만들어야** 한다 (2,695일 × 131업종). 그것이 이 재측정의
진짜 비용이고, 지금 치르면 **59일짜리 블라인드**에 쓰게 된다.

## 5. 그래서 계획은 이것이다

| 언제 | 무엇 | 왜 |
|---|---|---|
| **지금** | **아무것도 재지 않는다** | 블라인드 59일로는 8%p 도 못 본다. 지금 재면 기각이 아니라 **미측정**이 나온다 |
| 2026-11-16 이후 | 블라인드 날짜가 쌓인 뒤 **R44 rs60 사전등록을 한 글자도 안 고치고** 재실행 | 라운드 110 이 R49 에 쓴 수와 같다 |
| 그 전에 (선택) | `rs60` 을 원장에 **백필**해 두기 | 그때 한 번에 돌릴 수 있게. 다만 2,695일 × 131업종을 만드는 비용이 든다 — **먼저 물어보고 한다** |
| **영영 안 함** | `mom60` (절대 모멘텀) | 방향이 반대다. 되살릴 근거가 없다 |
| **영영 안 함** | 업종 내 백분위 상대화 | 166,132건에서 8종 전부 미달 · 순수 기여가 동전 던지기 |

## 6. 지키는 것

- **업황이 적정가를 올리는 일은 없다.** 그 방향이 실측에서 손해였다.
  게이트를 통과하기 전에는 `apply_to_fair_value = 0` 이다.
- **문턱을 미리 정하지 않는다.** R44 의 5분위 경계(`-4.43 · -1.34 ·
  1.65 · 5.93`)와 g1~g4 를 **그대로** 쓴다. 새 숫자를 만들지 않는다 (§2).
- **재기 전에 상한을 적는다.** 이 문서가 그것이고, 지금 상한은
  *"블라인드 59일 — 볼 수 있는 것이 없다"* 이다.
