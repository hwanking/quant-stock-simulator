## 1. 무엇이 잘못됐나

`bitemporal_engine.fetch_and_update_naver_realtime()` 이 시장 접미사를
**추정**한다. 입력에 접미사가 없고 `STOCK_NAME_MAP` 에도 등록이 없으면
무조건 `.KS`(KOSPI)로 떨어진다.

```python
else:
    _prev = str(STOCK_NAME_MAP.get(code) or "")
    ticker = f"{code}.KQ" if _prev.endswith(".KQ") else f"{code}.KS"
```

바로 위 주석이 에코프로 사고(시드값 78% 괴리)를 적어 두고 "기존 등록
시장을 따른다"고 했지만, **등록이 없을 때**의 폴백이 KOSPI 고정이다.
이 폴백은 §3('없는 값을 지어내지 않는다')을 어긴다 — 못 읽은 값을
`None` 으로 두는 대신 한쪽으로 찍는다.

### 규모 (2026-08-23 실측)

| 항목 | 값 |
|---|---:|
| `STOCK_NAME_MAP` 항목 수 | 79 |
| 그중 `.KQ` 로 등록된 **종목코드** | **3** |
| KRX 목록 수신 (네이버 시총 페이지) | 3,925 |
| KOSPI / KOSDAQ | 2,155 / 1,770 |
| **접미사 없이 조회하면 `.KS` 로 잘못 떨어지는 코스닥 종목** | **1,767 / 1,770 (99.8%)** |

예: 레인보우로보틱스(277810) · 주성엔지니어링(036930) · 원익IPS(240810) ·
HLB(028300) · 리노공업(058470) · 이오테크닉스(039030) · 에이비엘바이오(298380).
**경계 사례가 아니라 기본 동작이다.**

## 2. 파급 — 라벨 하나가 아니라 계산까지 번진다

접미사는 이 저장소에서 **시장의 유일한 표현**이라, 잘못된 접미사는
아래 전부를 오염시킨다.

| 자리 | 무엇을 유도하나 | 오염 결과 |

## 3. 무엇을 바꾸는가 (사전 기술)

### 3-1. 시장은 추정하지 않고 **읽는다**

`_detect_market(code, html)` 를 새로 만든다. 우선순위:

1. **네이버 종목 페이지 배지** — `<div class="wrap_company">` 뒤 창에서
   `class="kosdaq"` / `alt="코스닥"` / `btn_kosdaq.gif` (KOSPI 동형).
   ⚠️ **전역 검색을 쓰면 안 된다** — 페이지 머리말에 두 지수명이 다 있어
   코스피 종목에서도 `kosdaq` 이 4회 나온다 (실측). 반드시 창을 좁힌다.
2. **다음금융 API `market` 필드** — `finance.daum.net/api/quotes/A{code}`
   가 `"market": "KOSDAQ"` 을 그대로 준다.
3. 둘 다 못 읽으면 **`None`** 을 돌려주고 사유를 남긴다.

두 출처의 실측 대조 (2026-08-23, `_probe/p3_edge.py`):

| 코드 | 종목 | 네이버 | 다음 | |
|---|---|---|---|---|
| 069500 | KODEX 200 (ETF) | KOSPI | KOSPI | 일치 |
| 233740 | KODEX 코스닥150레버리지 | KOSPI | KOSPI | 일치 — **이름에 '코스닥'이 있어도 ETF 는 KOSPI 상장** |
| 005935 | 삼성전자우 | KOSPI | KOSPI | 일치 |
| 900140 | 엘브이엠씨홀딩스 | KOSPI | KOSPI | 일치 (코스닥→코스피 이전 상장) |
| 031510 | 오스템 | KOSDAQ | KOSDAQ | 일치 |
| 091990 | (상장폐지) | None | None | **못 읽음 → 지어내지 않는다** |

이름·재무로 추정하지 않는 이유가 233740 에 있다. 실측만이 맞는다.

### 3-2. 접미사 결정 순서

| 순위 | 조건 | 결과 |
|---|---|---|
| 1 | 실측 성공 | **실측을 따른다** |
| 2 | 실측 실패 · 입력에 접미사 있음 | 입력 접미사 보존 (에코프로 규칙) |
| 3 | 실측 실패 · `STOCK_NAME_MAP` 에 등록 있음 | 등록을 따른다 |
| 4 | 그 외 | **접미사를 붙이지 않는다** — `code` 그대로 + 사유 기록 |

**실측이 입력 접미사보다 앞선다.** 에코프로 회귀(§41 `"086520.KQ"` →
`.KQ` 보존)는 실측도 KOSDAQ 이라 그대로 통과한다. 입력과 실측이 어긋나는
경우란 **입력이 틀렸다**는 뜻이고, 그때 틀린 키에 저장하면 읽는 쪽이
낡은 값을 보는 에코프로 사고가 그대로 재발한다.

⚠️ 어긋날 때 **양쪽 키에 같이 저장하지 않는다.** 신선도 문제는 사라지지만
`_get_fallback_universe` 가 `STOCK_METRICS_DB` 키를 순회하므로 `.KS` 키가
존재하는 것만으로 코스닥 종목이 KOSPI 로 세어진다.

### 3-3. 시장을 값으로 들고 다닌다

`info["market"]` (`'KOSPI'|'KOSDAQ'|None`) 와 `info["market_source"]`
(어디서 읽었는지 / 왜 못 읽었는지)를 추가한다. 접미사에서 되유도하는
자리들이 **먼저 이 값을 보게** 한다. 접미사는 캐시 키로 남고, 시장의
근거는 실측값이 된다.

- `_get_fallback_universe` (:1539) — `meta['market']` 우선, 없으면 접미사
- `market_context.market_of_ticker` — 접미사가 없으면 **`None`**
  (종전 "없으면 KOSPI") → `fetch_domestic_context` 가 `available: False`
  와 사유를 돌려준다. **국면을 지어내느니 국면 없음이 정직하다.**
- `get_asset_currency_and_unit` — 접미사 없는 6자리 숫자를 **해외 주식(USD)**
  으로 보던 분기를 고친다. 6자리 숫자는 KRX 코드다.

### 3-4. 바꾸지 않는 것

- 점수 산식·게이트·가중치 — 손대지 않는다 (§2)
- `STOCK_NAME_MAP` 시드 79항목 — 늘리지 않는다 (손으로 적은 목록은 낡는다)
- 접미사가 이미 맞는 경로(스크리너 유니버스 `fetch_krx_universe`)는 그대로

고치고 있다면 공통 진입점을 찾고, 없으면 만든다."** 그래서 호출부를 하나씩
고치는 대신 `bitemporal_engine.market_of()` 하나를 만들고 열두 자리가 전부
그것을 타게 했다. 그리고 §198 이 **유도한 모듈 목록(35개)** 을 훑어 소유
모듈(`bitemporal_engine` · `portfolio`) 밖에서 접미사 유도가 다시 생기면
실패하게 했다. 목록은 `scripts/lineage_audit.reachable_modules()` 로 유도하고
**개수를 찍는다**(R120e).

**기본값을 어느 쪽으로 둘지도 같은 규칙으로 정했다.** `market_of` 는 모르면
`None` 을 돌려준다. 빠뜨렸을 때 나는 실패가 어느 쪽인지 보면 — '코스닥
종목을 코스피 국면으로 조용히 판정'은 눈에 안 띄고 오래 산다. '국면 미수신'
은 화면에 드러난다. 드러나는 쪽을 기본값으로 둔다.

### 못 읽었을 때 무슨 일이 벌어지는가

접미사를 안 붙이면 하류가 그 티커를 어떻게 다루는지 따라가 셋을 같이 고쳤다.

- `market_of_ticker` — 종전 *"접미사가 없으면 KOSPI 로 본다"* → **`None`**
- `fetch_domestic_context` — 시장이 KOSPI/KOSDAQ 이 아니면 지수를 고르지
  않고 `available: False` + 사유
- `get_asset_currency_and_unit` — 접미사 없는 6자리 숫자를 **해외 주식(USD)**
  으로 보던 분기. 6자리 숫자는 KRX 코드다. 이걸 안 고쳤으면 §3 을 지키려던
  변경이 원화 종목에 달러 단위를 붙이는 새 결함이 됐을 것이다.
- `portfolio.import_positions` — `resolve_market` 이 없으면 무조건 KOSPI 였다.
  이제 `None` 으로 두고 **행마다 경고를 남긴다.**

### 자기검사 — 0건이 '없다'인지 '못 봤다'인지

§110·R114 의 교훈대로 **일부러 심어서** 검사가 그걸 잡는지 확인했다.

- 배지 파서에 KOSPI/KOSDAQ 배지를 심어 각각 옳게 갈리는지
- 틀린 시장을 `_compose_ticker` 에 주면 **틀린 접미사가 나오는지**
  (안 나오면 검사가 아무것도 안 재는 것이다)
- 접미사 유도 스캐너에 세 가지 유도 표현을 심어 셋 다 잡는지,
  그리고 `be.market_of(ticker)` 는 **안 잡는지**

### 전역 검색이었다면 틀렸을 자리

네이버 종목 페이지는 머리말에 코스피·코스닥 지수를 **둘 다** 싣는다.
삼성전자 페이지에도 `kosdaq` 이 **4회** 나온다(2026-08-23 실측).
`'kosdaq' in html` 로 짰다면 코스피 종목 전부가 코스닥이 됐을 것이다.
`wrap_company` 블록 뒤 2,000자 창으로 좁혔고, 회귀가 *"코스피 종목
HTML 에도 kosdaq 이 들어 있다"* 를 **사실로 확인한 뒤** 파서가 그래도
KOSPI 로 읽는지를 잰다.

## 7. 남겨 둔 것

- **`STOCK_NAME_MAP` 시드 79항목을 늘리지 않았다.** 손으로 적은 목록은
  반드시 낡는다(R114). 실측이 시드를 대체하므로 늘릴 이유도 없다.
- **코넥스는 다루지 않는다.** 배지가 코스피·코스닥이 아니면 `None` 이고,
  그 종목은 '시장 미수신'으로 흐른다. 코넥스를 지원하려면 지수·국면까지
  따로 있어야 하므로 별도 작업이다.
- **`MARKET_BY_CODE` 는 실행 단위 캐시다.** 디스크에 남기지 않는다 —
  상장 시장은 바뀔 수 있고(코스닥→코스피 이전 상장, 예: 900140
  엘브이엠씨홀딩스), 낡은 파일보다 매 실행 실측이 옳다.

## 8. 회귀가 잡은 것 — 고치는 쪽이 만든 새 결함 다섯

전건 통과를 받기까지 다섯 칸이 걸렸다. **셋은 내 변경이 만든 것**이고
둘은 워크트리 데이터 공백이었다. 걸린 순서대로 적는다.

### ① `UnboundLocalError` — 분기 하나를 안 본 채 변수를 썼다

`rows_to_positions` 에서 `market` 을 `else` 가지 안에서만 만들어 두고
바깥에서 읽었다. `_ticker` 힌트가 맞는 행은 그 가지를 안 타므로 즉시 터졌다.
**첫 회귀 실행 20초 만에 잡혔다** — 문법 검사만으로는 안 나온다.

### ② `.KS` 를 기대하던 회귀 두 칸

- `NaN 대신 종목코드로 티커 재구성` — `.KS`/`.KQ` 로 끝나기를 요구
- `resolve_market 예외를 흡수` — 기대값이 `"005930.KS"`

둘 다 **옛 폴백을 요구하고 있었다.** 조회가 터졌는데도 KOSPI 로 찍던 값이
기대값에 박혀 있었던 셈이다. CLAUDE.md §6 이 허용하는 경우 —
*"검사가 옛 구현을 요구하고 있다면 검사를 현실에 맞춘다"* — 이므로
**왜 바뀌었는지 주석으로 남기고** 지켜야 할 것만 남겼다:
접미사가 아니라 **종목코드를 잃지 않는 것**, 그리고 **예외가 반영 전체를
죽이지 않는 것**. 그리고 칸을 지우지 않고 **늘렸다** — 새로 두 칸이
"시장을 지어내지 않고 사유를 남기는가"를 잰다.

곁들여 붙여넣기 경로가 시장 미상을 **조용히** 넘기고 있길래
(CSV 경로는 경고했는데 이쪽은 안 했다) 경고를 맞췄다.

### ③ 그리고 **진짜** 결함 — `.get(symbol)` 이 코드로 안 찾고 있었다

가장 값진 것은 §52 가 잡은 이것이다.

```
[FAIL] 레인보우: 사유에 근거(성장 기대 지배) 명시
       — 산출 불가 … 모델 적정가가 시장가격과 -84% 괴리. …
```

레인보우로보틱스(277810)는 **코스닥**인데 회귀가 `277810.KS` 로 넘긴다.
종전에는 그래도 됐다 — 엔진이 시장을 몰라도 `.KS` 를 붙였으니
**조회 접미사와 저장 접미사가 항상 같았다.** 이제 엔진이 실측한 `.KQ` 에
저장하자, `STOCK_METRICS_DB.get(symbol)` 만 하던 **세 자리**가 빈 dict 를
받기 시작했다 (`quant_indicators.py:2192 · 4812 · 4832` — per/pbr·`is_fund`,
종목명, OHLC·거래량).

결과는 조용했다. 예외도 안 나고 판정도 `OUT_OF_DOMAIN` 그대로였다.
사라진 것은 **사유의 근거 문구**뿐이다:

| | 사유 문구 |
|---|---|
| 결함 상태 | 산출 불가 — … **-84% 괴리**. 이 구간에서는 … |
| 고친 뒤 | 산출 불가 — … **-99% 괴리 (PER 7,094배, PBR 66.3배 — 이익·자산이 아니라 성장 기대가 가격을 지배)**. … |

값은 DB 에 **있었다**. 키만 안 맞았다. 사용자에게는 "왜 산출 불가인지"가
통째로 사라진 채 나갔을 것이다.

이건 내 변경이 **만든** 결함이 아니라 **드러낸** 결함이다 — 낡은
`positions.json` 이 코스닥 종목을 `.KS` 로 들고 있거나 리플레이가 예전
티커를 넘기면 전부터 같은 일이 났다. 우연히 두 접미사가 늘 같아서 안
보였을 뿐이다.

고친 방식도 같다 — **읽는 문을 하나로**(`bitemporal_engine.metrics_of`).
코드가 같으면 같은 종목이고, 접미사는 캐시 키일 뿐이다. 이걸로
`get_realtime_stock_price_triple_check` 이 손으로 적어 두던 폴백
(`get(symbol) or get(code)`)도 같은 문으로 합쳤다.

### ④ 워크트리 데이터 공백 (내 변경과 무관)

`실전 케이스 동결 저장` · `파이프라인 실행 로그 기록` 두 칸이
`.portfolio/improvement.db` 를 읽는데, 워크트리의 `.portfolio` 는
gitignored 라 비어 있었다(`prediction_cases=0` vs 본체 245).
**검사를 고치지 않고 환경을 채웠다** — 검사가 재려던 것은 그대로다.

→ 다섯 중 넷이 "잰다고 이름 붙은 것이 실제로 재고 있었다"의 사례다.
   특히 ③ 은 **회귀를 안 돌렸으면 절대 못 찾았다** — 화면도 안 죽고
   예외도 안 나고, 사유 한 문장만 조용히 짧아졌다.

### ⑤ 워크트리라서 걸린 것들 — 검사가 아니라 환경을 고쳤다

이 작업은 git worktree 에서 했고, `.portfolio/` 와 `_probe/` 는 gitignored 라
**따라오지 않는다.** 회귀가 그걸 정확히 짚었다. 검사를 느슨하게 하지 않고
환경을 본체와 맞췄다:

### 남은 하나 — 고치지 않고 보고한다

```
[FAIL] 훅이 실제로 연결돼 있다 (core.hooksPath)
       core.hooksPath="…\quant_backtest_claude\.githooks"
```

검사는 `core.hooksPath == '.githooks'`(상대경로)를 요구하는데
`git config --get` 이 절대경로를 돌려준다. **그런데 설정 파일에 적힌 값은
이미 상대경로다:**

```
$ grep hooksPath "$(git rev-parse --git-common-dir)/config"
	hooksPath = .githooks
```

즉 설정은 검사가 원하는 그대로이고, **linked worktree 에서 읽을 때 git 이
본체 작업트리 기준으로 펼쳐 주는 것**이다. 본체 저장소에서 같은 검사를
돌리면 통과한다. 훅도 정상 동작하고 있다 — 바로 위 칸
*"최근 커밋 중 이력이 함께 실린 것이 있다 — 12건"* 이 통과했다.

그래서 **고칠 것이 없다.** `scripts/setup_hooks.py` 를 여기서 돌려도
같은 값을 다시 쓸 뿐이고(worktree 는 `.git/config` 를 본체와 공유하므로
본체 설정을 건드리는 위험만 진다), 검사를 절대경로도 받게 넓히는 것은
검사를 느슨하게 하는 일이라 하지 않았다(§2 — 기준을 내리지 않는다).
worktree 에서 돌릴 때만 나오는 조건으로 기록해 둔다.
