# 라운드 454 — 내 한국투자 계좌 판 · '지금 진행 중인가'

2026-10-09 · 화면·장부 열 하나 · 판정·점수·문턱·주문 규칙 **불변** · 이 라운드의 변경에는 버전이 없다(계산부 파일을 열지 않았다).
다만 model **v2026.10.09.1**(`ui`)을 냈다 — 라운드 453 의 `verdict_core` 변경(entry_price 칸)이 10-08 에 v2026.10.08.2 로 나갔는데 커밋은
10-09 라 전체 회귀(6,428건)에서 버전 지연 검사 1건이 붉어졌다(라운드 351 과 같은 자리 · 같은 사유로 다시 냄 · 값·판정 불변).

## 왜

사용자: *"지금 진행중인지 아닌지도 표시해주면 좋겠어 · 내가 보내준 계좌정보처럼 우리거에 맞게 꾸며줘."* 붙인 것은 다른
워크스페이스(암호화폐 계좌)의 읽기 전용 계좌 화면이다 — 자동 갱신 · 총자산 타일 · '내 계좌 한눈에' 사실 문장 · 자산 구성 막대 ·
평가 범위와 점검 수 · 설정과 참고 비교 · 보유 표 · 최근 체결 · "현재 실행 중인 학습 없음" 같은 진행 줄.

**먼저 셌다**(라운드 288 의 규칙) — 우리 쪽에 이미 있는 것과 없는 것:

| 붙인 화면 | 우리 자료 | 한 일 |
|---|---|---|
| 총자산 · 매수금액 · 평가손익 · 수익률 · 현금 | 한국투자 잔고(`get_balance` · 종목 행 + 요약) | 타일 여섯(`uk.stat_tiles`) — 총자산은 **증권사 요약값**, 예수금과 **D+2 정산 예정 예수금**을 가른다 |
| 잠긴 현금 | 잔고에 없다 | 안 만든다 — '주문 가능 금액은 종목별로 따로 읽는다'고 적는다 |
| 자산 구성 막대(현금 포함) | 종목 평가 ÷ 총자산 | `uk.bar_list` |
| 평가 범위 · 점검 수 | 가격 있는 종목 수 · 손익 셈 가능 수 · 수익/손실/본전 · 상위 1·2종목 비중 · 현금 비중 | `uk.chip_row` + 한 줄 — **매매 승률이 아니라 열린 보유의 지금 상태**라고 적는다 |
| 설정과 참고 비교 | ⑥ 위험 한도 네 칸(종목 수 · 주식 비중 · 단일 비중 · 최소 현금) | 표 — '참고 한도 이내/밖/비교 불가' · **규칙 위반 판정도 매매 지시도 아니다** |
| 보유 표(비중 · 수량/잠금 · 평단 · 현재가 · 평가 · 손익 · 시세 시각) | 잔고 행(매도 가능 수량 포함) | 같은 열 · '매도 가능'은 걸려 있는 매도를 뺀 수량 |
| 최근 30일 체결 | `get_daily_orders` | 누를 때만 읽는 표 — **성과를 셈하지 않는다**(⑤ 영수증이 같은 채점기로 한다) |
| 자동 갱신 15초 | — | `st.fragment(run_every=…)` 로 **이 판만** 다시 돈다 · 기본 **꺼짐** · 15/30/60초 |
| 진행 줄 | 워커 잠금 파일 · 작업 스케줄러 · 저녁 작업 기록 | `swing_ops.progress` 한 곳 — 워커 · 예약 작업 둘 · 저녁 작업 · 자동 갱신 |

받지 않은 것: 건강 점수·등급 · 색으로 좋고 나쁨을 말하는 배지(§5·§9) · 암호화폐 쪽 낱말(잠긴 현금 · 티커).
