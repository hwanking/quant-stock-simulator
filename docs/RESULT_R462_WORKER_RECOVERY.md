# 라운드 462 — 워커가 장중에 죽어도 다시 뜬다

2026-10-09 · 판정·점수·문턱·주문 규칙 **불변** · 버전 없음 · 워커 표시 하나 · 등록 스크립트 반복 · 작업 상태 한 줄 · 레이더.

## 무엇이 비어 있었나

경쟁사 레이더(라운드 456)가 '상시 실행·복구' 축에 적어 둔 차이다 — *"가늠 워커는 이 PC 에 묶여 있고, 죽으면 다음 재시작은 작업
스케줄러의 다음 아침이다."* 워커는 한 바퀴가 예외로 죽어도 다음 바퀴를 돈다(라운드 446). 그런데 **프로세스 자체**가 장중에 죽으면
(전원 · 절전 복귀 실패 · 강제 종료) 작업 스케줄러는 다음 평일 08:50 까지 다시 부르지 않았다. 그사이 자동 관리 중 종목의 손절 매도를
낼 주인이 없다 — 라운드 453 이 '꺼짐이 보호를 끄지 않는다'고 고친 바로 그 보호다.

## 무엇을 바꿨나

1. **등록 스크립트가 장중에 다시 부른다.** 주간 트리거에 반복을 붙였다(기본 10분 · 8시간 — 08:50 → 16:50 · 수능일 마감 16:30 포함).
   워커가 돌고 있으면 작업 스케줄러가 새로 띄우지 않는다(`MultipleInstances IgnoreNew` · 종전 그대로). 죽었으면 다음 반복이 10분 안에
   다시 띄운다. `-EveryMinutes 0` 이면 종전처럼 반복이 없다.
2. **워커가 끝낸 날을 적는다.** 마감 뒤 바퀴(체결 내역 맞춤)가 **끝까지 돈 날만** `.portfolio/swing_worker_session.json` 에 그날을 적고,
   그 뒤 반복이 부르면 바로 끝난다. 마감 뒤 바퀴가 실패했거나 다른 워커가 잠금을 쥐고 있었으면 적지 않는다 — 다시 불리면 한 번 더
   맞춘다(한 바퀴 더 도는 쪽이 보호를 놓치는 쪽보다 낫다). 표시를 못 읽으면 '안 끝냄'으로 본다.
3. **다시 떠도 주문을 다시 보내지 않는다** — 라운드 446 의 규칙 그대로(UNKNOWN 은 체결 내역으로 맞춘다 · 잠금은 주인이 죽었으면 치운다).
4. **작업 상태 한 줄이 반복을 말한다.** 관제실이 읽는 작업 스케줄러 상태에 반복 간격을 더했다 — 있으면 *"장중 10분마다 다시 부름(돌고
   있으면 건너뜀 — 워커가 죽어도 10분 안에 다시 뜸)"*, 없으면 *"워커가 장중에 죽으면 다음 평일 아침까지 다시 안 뜸"*, 옛 응답이라 칸이
   없으면 아무 말도 안 한다(모르는 것을 '없음'이라 적지 않는다).
5. **레이더** — 가늠 칸과 그 축 항목의 차이를 *"장중에 죽으면 10분 안에 다시 부르지만 PC 가 꺼지거나 잠들면 못 돈다"* 로 좁혔다. 상태는
   '부분' 그대로다 — 워커는 여전히 이 PC 에 묶여 있다. 결정도 CONSIDER 그대로(다른 기기에 두는 구조는 비용·안전 설계가 먼저).

## 10분은 잰 값이 아니다

운영 선택이다 — 작으면 죽은 뒤 보호 공백이 짧고, 크면 반복마다 파이썬을 한 번 띄우는 일이 준다(워커가 돌고 있는 동안은 작업 스케줄러가
띄우지조차 않으므로 실제로 뜨는 것은 마감 뒤 표시를 읽고 끝나는 몇 번뿐이다). 판정·점수·문턱이 아니므로 §2 의 측정 대상이 아니지만,
근거가 없다는 사실은 등록 스크립트 머리에 적었다.

## 이 PC 에 적용

이 PC 의 `gaeum-swing-worker` 작업을 같은 스크립트로 다시 등록했다(종전 등록이 이미 있었다 · 지금 모드는 꺼짐이라 등록돼 있어도 새 매수는
없다). 결과는 아래에 적는다.

- 첫 재등록(18:11)은 반복 `PT10M` · 길이 `PT8H` · `IgnoreNew` 로 걸렸는데 작업 상태가 **놓친 실행 47회**를 적었다 — 시작점이
  오늘(휴장일) 08:50 이라 이미 지난 오늘의 반복 칸 47개를 '놓친 것'으로 셌다. 사실이지만 화면에 그대로 나가면 *장중에 47번
  못 돌았다* 로 읽힌다.
- 그래서 등록 스크립트가 **오늘 반복 창(08:50~16:50)이 이미 지났으면 시작점을 다음 날로** 잡는다(창 안에서 등록하면 오늘 남은
  반복은 그대로 돈다). 다시 등록한 뒤: 시작점 2026-10-10 08:50 · 반복 10분 / 8시간 · **놓친 실행 0** · 다음 실행 2026-10-12(월) 08:50.
- 앱이 읽는 작업 상태 한 줄(실측): *"… 장중 10분마다 다시 부름(돌고 있으면 건너뜀 — 워커가 죽어도 10분 안에 다시 뜸)"*.
- 모드는 꺼짐 그대로다 — 관리 중 종목이 없고 꺼짐이면 워커는 계획·모의만 남기고 증권사에 아무것도 보내지 않는다.
- 진짜 장중 재시작이 일어나는지는 **아직 못 봤다** — 월요일 장중에 워커가 죽는 일이 생기면 실행 기록에 두 번째 *'정규장 … 마감까지'*
  줄이 찍힌다. 그 줄이 없는 날은 *죽지 않았다* 이지 *복구가 됐다* 가 아니다.

되돌리려면 `scripts/register_swing_worker_task.ps1 -EveryMinutes 0` (반복 없이 다시 등록) 또는 `-Unregister`.

## 검사

갈래 · 등록 스크립트 · 레이더. §438 은 끝낸 날 표시도 `_probe` 로 돌린다(사용자 파일 쓰기 0).
