# 결과 R338 — '유 …' · '정리 검토'는 팔라는 말인가 · 매도 판정이 뜨면 '팔았음' (2026-09-18)

사용자: *"유 … 이게 뭐야? 그리고 정리 검토가 팔라는거지? 확실하게 이야기해줘 표현을. 매도가 나오면 팔 수 있게도 해주고."*

## ① `유 …` — 값이 아니라 결함이었다

관심종목 표의 사유 칸이 미보유 행 여섯에서 전부 `유 …` 였다(2026-09-18 화면 실측). 라운드 327 이 *"낱말
가운데서 끊긴 조각보다 한 문장이 낫다"* 며 첫 문장 끝(`다. `)에서 자르게 했는데, 그 판별이

```python
_s327 = _wy240.find('다. ')
if len(_wy240) > 34 and 0 < _s327 + 2 <= 34:
```

라서 **`find()` 의 −1(없음)** 을 못 걸렀다 — `0 < -1 + 2` 는 참이고, 그러면 `_wy240[:1]` 즉 **첫 글자 하나**만
남는다. 그 여섯 행의 사유는 전부 *"유사패턴 …"* 으로 시작해 `유 …` 가 됐다. 자르기를 `ui_kit.clip_reason`
**한 곳**으로 빼고 심어서 잰다(R120e) — '다. ' 없는 긴 사유는 폭에서 자르고 말줄임, 있으면 첫 문장에서,
짧으면 그대로.

## ② '정리 검토'는 팔라는 말이다 — 계획의 손절선 아래라는 뜻이다

kind `'정리 검토'` 는 `holder_kind` 가 **현재가 ≤ 버틸 수 없는 가격**일 때 내는 판정이고, 그 선은 **잰 날에
고정된 보유 계획의 손절선**이다(R224 — 방문마다 따라 내려가지 않는다). 사용자가 짚은 행의 실측:
현재가 392,000 · 손절선 **394,928**(0.7% 아래) · 진입가 412,464 · 1차 매도가 445,339. 엔진은 앞으로 어디로
갈지를 말하지 않는다 — **계획이 정한 선을 넘었다**는 사실을 말한다. 그러므로 답은 **"계획대로면 파는 자리"**
다. 그 말이 이름표에도 문장에도 없었다(R322 가 물타기 이름표에서 고친 그 모양 — 이름이 *어느 게이트*를
말하면 사용자는 *무엇을 하라*를 못 읽는다).

- kind 는 **안 바꿨다** — 순서표(`_WL_SELL_RANK`)·색 지도·저장 스냅샷·챗이 그 이름으로 잇는다(R292·R327).
- 사람에게 보이는 글자만 `ui_kit.HOLD_LABELS` **한 곳**에서 받는다: `정리 검토 → 매도 — 손절선 아래` ·
  `일부 정리 → 일부 매도 — 1차 매도가 넘음`. 소비자 넷(관심종목 행 · 칩 · 이름 캡션 · 금액 표)과 가늠 AI 가 같은
  표를 읽는다(§4).
- 이유 문장이 말을 끝낸다: *"현재가가 버틸 수 없는 가격(N원) 아래입니다 — **계획대로면 파는 자리입니다**"* ·
  *"1차 매도가(N원)를 넘었습니다 (+x%) — 계획대로면 일부 파는 자리입니다"*.

새 문턱 없음 · 판정 불변 — 바뀐 것은 **말**이다.

## ③ '팔았음' — 매도 판정이 뜬 행에서 판 뒤의 기록을 받는다

실제 매도는 증권사에서 한다. 이 화면이 할 수 있는 것은 **판 뒤**에 보유 기록을 정리하는 것이다. 매도 판정
(정리 검토 · 일부 정리)이 뜬 보유 행의 마지막 칸에만 `팔았음` 링크를 둔다 — 빼기·고치기와 같은 길(쿼리
파라미터 · 행 높이 불변 · R244·R320). 누르면 **매입가·수량만 비우고** 관심종목 행은 남긴다(그 행은 미보유
관점으로 넘어간다). 규칙은 `portfolio.mark_sold` **순수 함수 하나**(못 읽는 코드·없는 종목이면 아무것도 안 바꾼다 ·
§3)이고, 확인 대화상자 대신 **되돌리기**다(바뀌기 전 행을 통째로 되살린다 · R244·R321 의 원칙).

⚠️ 사용자 자료를 쓰는 기능이라 **창이 아니라 쓰기를 막은 앱 테스트**로 확인했다(R320 의 사고 — 공유 창에서
보유 두 행이 비었다). 결과는 `_probe/r338_sold_apptest.txt` 에 있고 아래 표가 옮긴다.

⚠️ 첫 판의 앱 테스트가 *"파일 수정시각 바뀜"* 을 냈다 — **누가 썼는지부터 가렸다**(R322). 그 시각 **앱 서버가 떠
있었고** 서버는 관심종목 행의 스냅샷을 새로 얹으며 같은 파일을 쓴다. 서버를 내리고 다시 돌리니 **수정시각 불변**
— 쓴 것은 테스트가 아니라 서버였다. 그리고 내 잣대 하나가 좁았다: *"다른 행 불변"* 을 세션 행과 파일 행의
**글자 전체**로 대 봤는데, 세션 행은 화면이 실시간 값(`snap_px` 등)을 새로 얹으므로 같을 수 없다 — '팔았음'이
손대는 칸(매입가·수량·코드·이름)만 대 보는 것으로 좁혔다.

## 바꾸지 않은 것

kind 이름 · 순서표 · 색 · 저장 칸 · 판정 규칙 · 문턱 · 가격선. 검사 §344(11건).
