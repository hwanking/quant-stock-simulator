# 라운드 178 — 아는 값을 두고 '판정 불가'라고 적고 있었다

**날짜** 2026-08-26 · **분류** 게이트 라벨 + 화면 정직성 (§2 · §3)
**요청** *"실행해주고 못 다한 작업해주고 틀린 부분 다시한번 전수 조사해서
고쳐줘"*

---

## 1. 먼저 라운드 177 이 과잉 차단을 만들지 않았는지 확인했다

R177 은 *"적정가 대비 +15% 초과면 차단"* 을 적정가만 있어도 걸리게 했다.
그때는 **막혀야 할 것이 막힌다**는 쪽만 쟀다. 반대편도 봐야 한다 —
**믿을 수 없는 적정가로 거르고 있지는 않은가?**

표본 240종목 (`_probe/gate_impact_r178.py`):

| | |
|---|---:|
| R177 이 새로 막는 종목 | **10개** |
| 적정가 신뢰도 최저 / 중앙 / 최고 | **68 / 74 / 74** |
| **신뢰도 60 미만인데 막히는 것** | **0개** |
| 적정가 상태 | CALIBRATED 9 · CAUTION 1 |

**막는 근거가 전부 신뢰도 68 이상이다.** 지어낸 값으로 거르고 있지 않다.

## 2. 그런데 라벨이 안 따라왔다

R177 은 **차단**을 고쳤지 **라벨**을 고치지 않았다. 화면을 렌더해 훑으니
(`_probe/noreason_screen_r178.py`) 현대건설 **한 종목에서**:

```
진입 위치 [판정 불가] → 상한 59점        ← 4곳 (점수 상한 설명)
진입 위치: 판정 불가                      ← 매도 탭
장기 가치 대비   판정 불가                ← 적정가 카드
```

**여섯 자리**다. 그리고 바로 옆에서 이렇게 적고 있었다:

```
적정가 대비 상승여력 -24.8% (신뢰도 73점) · 진입 위치: 판정 불가
```

**−24.8% 를 알면서 "모른다"고 적는다.** §3 위반이다.

## 3. 고침이 까다로운 이유 — 라벨을 고치면 점수가 움직인다

`entry_zone` 은 `price_location_score` 와 한 몸이다.

| 위치 | 종전(판정 불가) | 라벨대로면 |
|---|---:|---:|
| 적정가 이하 | 30 | **60** ← 올라감 |
| 소폭 초과 | 30 | **40** ← 올라감 |
| 경고 | 30 | 22 |
| 크게 초과 | 30 | 10 |

**점수를 올리는 것은 측정 없이 완화하는 것**이라 §2 위반이다.

→ **라벨은 정직하게, 점수는 보수적인 쪽으로만.** 권장 매수가가 없을 때는
종전 30 을 **상한**으로 두고 더 낮을 때만 내린다.

```python
_NO_RBP_SCORE_CAP = 30          # 종전 '판정 불가' 점수 — 상한으로 쓴다
entry_zone, _z = _zone_of(curr_price, fair_ref_any)
price_location_score = min(_NO_RBP_SCORE_CAP, _z)
```

**올라가는 칸이 하나도 없다.**

| 현재가/적정가 | 라벨 | 점수 | |
|---:|---|---:|---|
| 0.80 · 1.00 | 적정가 이하 | 30 | 그대로 |
| 1.03 | 소폭 초과 | 30 | 그대로 |
| 1.10 | 추격매수 경고 | **22** | 내림 |
| 1.16 · 1.33 · 1.50 | **크게 초과** | **10** | 내림 |

문턱(1.05 · 1.15)은 **한 글자도 안 바꿨다.**

### 실측 (수정 후)

```
현대건설
  entry_zone         적정가 크게 초과 (추격매수 위험)      ← 종전 '판정 불가'
  fair_overshoot_pct 33.0
  gate_reason        … 진입 위치 [적정가 크게 초과 (추격매수 위험)] → 상한 …
```

## 4. 곁들여 — '미수신'과 '기사 없음'을 섞고 있었다

화면에 이 문장이 나갔다.

```
뉴스 · 미수신 · 수신 기사 없음 — 판단에 미반영 · 영향 작음
```

앞은 **"우리가 못 받았다"**(우리 문제)이고 뒤는 **"받았는데 기사가 없다"**
(정상)다. §3 이 *"데이터 미수신 ≠ 추천 없음. 두 문장을 반드시 분리한다"*
고 못 박은 바로 그 자리다.

```python
if _news60 is None:      '미수신',   '뉴스 수집에 실패했습니다 — 판단에 미반영'
elif not _nt61:          '기사 없음', '수집은 됐고 관련 기사가 없습니다 — 판단에 미반영'
```

## 5. 전수 조사에서 **결함이 아니었던 것**

화면 census 12곳 중 아래는 정상이라 안 건드렸다.

| 문장 | 판정 |
|---|---|
| `미수신 입력 : 없음` | **정상** — 미수신 입력이 없다는 뜻 |
| `미수신 입력 지표 없음` | **정상** |
| `미산출 — 보유 포트폴리오 구성 미입력 — … 산출 불가` | **정상** (사유가 앞에 있다) |
| 고객센터 표의 `지수·시세 미수신 경고` 설명 | **정상** (설명문) |

**코드 스캔은 못 썼다** — 내부 상수·주석까지 잡아 100곳이 나온다.
`<b>` 때와 같은 교훈이다: **렌더한 화면이 진실이다.**

## 6. 회귀 — §212

- 권장 매수가가 없어도 적정가를 들고 있는다 (`fair_ref_any`)
- **적정가조차 없을 때만** '판정 불가'다
- **구역 함수를 AST 로 떼어 실제로 돌린다** — 문턱이 1.05 · 1.15 그대로인지
- **핵심**: 13개 위치를 다 넣어 **점수가 올라가는 칸이 0개**임을 확인
- 그리고 **실제로 내려가는 칸이 있다** (0칸이면 이 변경이 아무 일도 안 한 것)
- 뉴스 상태를 수집 실패와 기사 0건으로 가른다 · 옛 문장이 사라졌다

## 7. 회귀가 **두 건을 더 잡았다** — 둘 다 진짜였다

### ⓐ 새로 상장된 ETF 3개가 조용히 사유 없음이었다

```
[FAIL] 사유를 못 내는 ETF 가 하나도 없다 (전수) — 3건
       ['0233J0', '0233A0', '0231Z0']
```

라운드 171 이 *"전수 1,161종목 · 빈 사유 0건"* 을 확인했는데, 그건
**그날의 색인**에서 참이었다. 색인은 살아 있어 **1,164종목**으로 자랐고
분류표는 **2026-08-24 기준**에 멈춰 있다.

| | |
|---|---:|
| 색인 (실시간) | **1,164** |
| 분류표 (R170 · 2026-08-24) | 1,161 |
| 그 뒤 상장 | **3** |

§2 가 적어 둔 그대로다 — **날짜 없는 숫자는 반드시 낡는다.**
조용히 두지 않고 **왜 아직 모르는지**를 말하게 했다:

> `2026-08-24 전수 분류 이후에 생긴 종목이라 아직 분류하지 못했습니다`

### ⓑ 내 리팩터가 검사의 앵커를 옮겼다

```
[FAIL] 문턱을 새로 고르지 않았다 (구역 판정과 같은 15%)
```

§211 이 `'fair_ref * 1.15'` 라는 **글자**를 찾고 있었는데, 구역 판정을
`_zone_of()` 로 묶으면서 표기가 `_fair * 1.15` 가 됐다.
**문턱은 한 글자도 안 바뀌었다** — 검사가 옛 표기를 요구하고 있었을
뿐이다(§6).

→ 표기가 아니라 **값**으로 확인하게 고쳤다. 구역 함수를 AST 로 떼어
실제로 돌려 `114.9 → 경고` · `115.1 → 크게 초과` 인지 본다.
**이제 표기를 어떻게 바꿔도 문턱이 움직이면 걸린다.**
