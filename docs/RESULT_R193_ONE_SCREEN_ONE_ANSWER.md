# 라운드 193 — 한 화면이 반대되는 말을 하고 있었다

측정: 2026-08-31 · 근거: `_probe/r193_kind_vs_bucket.py` ·
`_probe/r193_verify.py` · 25종목 · 기준일 2026-08-28

라운드 192 를 병합하고 **서버를 띄워 눈으로 보다가** 잡았다(§6 —
화면 결함은 서버를 띄워야 나온다). 삼성전자 상세 한 장에 이렇게 있었다:

```
다음 조건   246,930원 이하에서 분할매수할 수 있습니다.
            현재가 260,000원은 권장 구간에 거의 닿았습니다 · [즉시·근접]
배너        지금은 사지 마세요 — 조건이 갖춰지면 후보
지시서      현재가 260,000원은 매수구간보다 +5.3% 위입니다. 쫓아가지 마세요.
```

**같은 종목 같은 화면이 "살 수 있다"와 "사지 마라"를 함께 말한다.**
이 세션을 시작한 사용자 지적(서진시스템 — *"매수 후보가 아닙니다"라고
말하면서 같은 칸에서 권장가를 내민다"*)과 정확히 같은 계열이다.

## 원인 — §4 가 금지한 그것, 경로가 둘

'다음 조건 — 언제 사면 되나' 칸이 `next_action` 의 `headline` 을
**그대로** 그리고 있었다:

```python
f"...>{_uk._esc(_NA['headline'])}</p>"
```

그런데 `next_action` 은 **가격 거리만** 본다. 진입가와 현재가의 괴리를
ATR 로 조정한 밴드에 넣고, '즉시·근접'이면 `kind='buy_now'` 를 낸다.
표본·거래대금·손익비·밸류 게이트를 **모른다** — 그건 중앙 판정의 일이다.

`verdict_core._bucket()` 의 kind 분기에도 `buy_now` 가 없다. 게이트가
하나라도 걸리면 buy_now 는 어느 분기에도 안 걸려 맨 아래로 떨어진다.
즉 **중앙 판정은 이미 "오늘은 아니다"라고 결론냈는데, 화면은 그 결론을
읽지 않고 next_action 을 직접 읽고 있었다.**

## 얼마나 자주인가 — 먼저 셌다 (§2-7)

25종목(사용자 관심종목 그대로) · 기준일 2026-08-28 · 실제 파이프라인:

| | 종목 수 |
|---|---:|
| `next_action.kind == 'buy_now'` 인데 중앙 판정은 '오늘 매수 가능'이 **아님** | **20 / 25 (80%)** |
| 그중 **`actionable=False`** — 엔진이 명시적으로 제외한 종목 | **11** |

무엇이 막고 있었나(중앙 판정의 bucket):

| bucket | 수 |
|---|---:|
| 신뢰도·표본 확보 대기 | 11 |
| 눌림목 매수 대기 | 6 |
| 거래량 회복 대기 | 3 |

**11종목은 거래대금이 기준(3억)에 못 미치거나 표본외 성적이 기준 미달**
인데, 화면은 그 종목들에 대고 *"…원 이하에서 분할매수할 수 있습니다"*
라고 적고 있었다. 예를 들어 풍강(093380)은 20일 평균 거래대금이
**0.8억**인데 칸은 `2,987원 이하에서 분할매수할 수 있습니다` 였다.

## 고침 — 결론은 중앙 판정이 정한다

`verdict_core.build()` 가 `next_headline` · `next_kind` 를 낸다.

- 중앙 판정이 **'오늘 매수 가능'** 이면 → `next_action` 의 말을 **그대로**
  쓴다 (덮어쓰지 않는다)
- `buy_now` 가 아닌 kind(pullback·breakout·observe)는 **손대지 않는다** —
  기다리라는 말은 이미 맞다
- 중앙 판정이 막았는데 `next_action` 만 `buy_now` 면 → **문장을 바꾼다**

문구는 새로 만들지 않고 **라운드 136 이 이미 채택한 말투를 재사용했다**
(§2-6) — *"여기까지 내려와도 아직은 못 삽니다."*

```
246,930원까지 내려와도 오늘은 아직 못 삽니다 — 미충족: 비용 차감 기대값 양수
2,987원까지 내려와도 오늘은 아직 못 삽니다 — 20일 평균 거래대금이 0.8억으로 기준(3억)에 못 미칩니다
```

조건 목록·가격선·괴리·대기일수는 **그대로 `next_action` 을 쓴다.**
바뀐 것은 **결론 한 줄**이다.

재측정: **20건 → 0건** (`_probe/r193_verify.py` · 같은 25종목).

## 곁들여 — 사유 자리에 체크 이름을 그대로 넣고 있었다

새 문장을 만들다 보니 이렇게 읽혔다:

```
오늘은 아직 못 삽니다 — 비용 차감 기대값 양수
```

**뜻이 뒤집혀 있다.** `비용 차감 기대값 양수` 는 **체크 이름**이고,
체크 이름은 *통과했을 때 참인 문장*이다. 그것을 사유 자리에 그대로
놓으면 "기대값이 양수여서 못 산다"로 읽힌다.

`_bucket()` 의 두 자리가 `' / '.join(failed[:3])` 으로 그렇게 하고
있었고, 그 값은 `exclude_reason` 이라 **카드·제외 목록·AI 답변까지**
같은 문장을 쓴다. 여기서도 새 말을 만들지 않고 **화면의 제외 목록이
이미 쓰는 '미충족:' 을 재사용했다**(§2-6):

```
오늘은 아직 못 삽니다 — 미충족: 비용 차감 기대값 양수
```

네 개 이상이면 `외 N건` 으로 줄이고, 목록이 비면 **빈 문장**이다
(없는 사유를 만들지 않는다 · §3).

## 검사 (§224)

- **값으로** — 거래대금을 기준 미달로 낮춘 스냅샷에서 `next_action` 은
  여전히 `buy_now` 인데(대조군) 중앙 판정의 결론 문장에는
  '분할매수할 수 있습니다'가 **없어야** 한다
- 그 자리에 **무엇이 막는지**가 적혀 있는가 · kind 가 `blocked` 인가
- **통과 스냅샷에서는 next_action 의 말을 그대로** 쓰는가 (덮어쓰지 않는가)
- `pullback` 문장은 **손대지 않는가**
- 화면이 `CORE['next_headline']` 을 읽는가, 그리고
  `_NA['headline']` 을 **직접 그리지 않는가** (경로가 다시 둘이 되지 않게)
- `_unmet()` 이 '미충족:' 을 달고 · 넷 이상이면 '외 N건' · 빈 목록이면
  빈 문장인가

## 남은 것

- `next_action.kind == 'buy_now'` 인데 게이트가 걸리는 일이 80% 라는
  것은 **밴드가 넓다**는 뜻일 수도 있다(ATR 조정 '즉시·근접'). 다만
  그건 **채택된 구간 규칙**(`BANDS = 5/10/15`)이라 결과를 본 뒤에
  손대지 않는다 — 별도 사전등록 감이다 (§2).
- 카드의 갭 경고 문턱 7% 를 채택 밴드로 바꾸는 것 (R192 ⓓ 에서 남긴 것)
