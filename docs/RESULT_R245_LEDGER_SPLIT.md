# 결과 R245 — 자동 축적은 돌고 있었다. 갈라진 원장을 키우고 있었을 뿐이다 (2026-09-08)

사용자: *"산식은 개선 안해? 스케줄된거 아냐? 뉴스랑 업황은? 계속 개선될 수 잇게 해줘."*

먼저 사실부터 확인했다. **스케줄은 있고 자동으로 돈다** — 그런데 그 톱니가 잘못된
원장을 물고 있었다.

## 1. 자동 축적은 멈춘 적이 없다 (문서가 틀렸다)

`CLAUDE.md` §2 는 *"그 루틴은 여전히 자동 스케줄이 없다 — 사람이 돌려야만 자란다"*
고 적고 있었다. **사실이 아니다.** `.github/workflows/daily_accumulate.yml` 이 평일
08:00 UTC(17:00 KST)에 돈다. 실행 이력(2026-09-08 확인):

| 기간 | 결과 |
|---|---|
| ~2026-08-18 | 성공 |
| **2026-08-19 ~ 09-01** | **연속 실패** |
| 2026-09-02 ~ 09-07 | 성공 (4회) |

## 2. 그런데 다시 시작한 자리가 옛 스냅샷이었다

워크플로는 릴리스에서 지난 원장을 복원해 이어 붙인다. 2주 실패로 릴리스 사슬이
`data-20260818` 에서 끊겼고, 09-02 에 되살아나며 **08-18 스냅샷**에서 다시 시작했다.
그 사이 손으로 키운 배치(라운드 197~213 · +65,956행)는 사슬에 올라간 적이 없다.

실측 (2026-09-08 · 열쇠 = (종목, 기준일)):

| | 행 |
|---|---:|
| 로컬 | 250,725 |
| 클라우드(자동이 키우던 것) | 185,962 |
| 공통 | 185,159 |
| **로컬에만** | **65,566** |
| **클라우드에만** | **803** |
| 합집합 | **251,528** |

**어느 쪽도 상위집합이 아니다.** 자동 파이프라인의 관측 연구(FN/FP·취약구간)와
전방 기록이 전부 3분의 1이 빠진 표본에서 돌고 있었다.

## 3. 가드는 그것을 **보고도** 통과시켰다

`scripts/study_freshness.py` 는 산출물이 원장 몇 줄일 때 만들어졌는지를 지금 원장과
견준다. 2026-09-07 실행 로그에 이 줄이 그대로 있다.

```
[OK  ] 취약구간 지도 (라운드 69) — 원장 250,725줄일 때 만듦 · 밀림 -64,763줄
```

`lag = now - rows` 이고 판정이 `lag <= MAX_LAG` 라 **음수는 항상 참**이다. 파일의
독스트링이 그 전제를 적어 두고 있었다 — *"원장은 늘기만 하므로, 차이가 곧 밀린
양이다."* 그 전제가 깨진 순간 가드는 눈을 감았다.

**음의 밀림은 신선함이 아니라 원장이 줄었거나 갈라졌다는 뜻이다.** 이제 실패한다.

## 4. 합쳤다 — 지운 행 0

합집합 **251,528**행. 규율은 라운드 197 사고 뒤의 것 그대로 — ① 세고 ② 백업하고
③ 이어 붙이고 ④ 항등식을 확인한다(`합친 행수 = 로컬 + 클라우드에만`).

**원본도 같이 합쳤다.** 랩은 `virtual_predictions*` 에서 원장을 **통째로 다시 쓴다**
(`open(..., 'w')` · 라운드 71c). 산출물만 합치면 다음 실행이 803행을 지운다. 합친 뒤
원본 합계와 원장이 둘 다 251,528 로 맞는다.

## 5. 클라우드 쪽은 오늘 안 올렸다 — 왜

스냅샷은 원장만이 아니라 `improvement.db` · 전방 기록부 · 유니버스 박제까지 통째로
바꾼다. 그건 합집합이 아니라 **교체**다. 자동 실행 직전에 240MB 짜리 교체를 밀어
넣는 것이 라운드 197(스모크 한 번으로 원장 972건이 사라진 사고)의 모양이다.
합칠 항목을 하나씩 정하고 나서 올린다 — 그때까지 클라우드는 185,962 에서 이어 가고,
**가드가 이제 그 사실을 매 실행 실패로 말한다.**

## 6. 산식·뉴스·업황은 왜 안 바뀌나 (답)

바뀔 근거가 없어서다. 일정은 `docs/SCHEDULE_R223_AXES.md` 에 있고 날짜는 전부 채택된
규칙의 투영이다.

| 축 | 언제 | 무엇이 막나 |
|---|---|---|
| 산식 `scoring` | **2026-11-16** | 전방 재평가 전까지 동결(R78). 근거를 세 번 못 찾았다(R111·R112·R159) |
| 룰북 `rulebook` | 09-15 · 11-16 | R205·R208 둘 다 기각 유지 (R213 진동 확인) |
| 뉴스 `news` | 11-16 이후 | 원장에 뉴스 재료가 **없다**. 전방 케이스에만 있고 확정 30건·날짜 30개가 필요하다 |
| 업황 `sector` | 11-16 이후 | R44 게이트 미통과. 블라인드 날짜 부족 → rs60 재실행 |

**이 라운드가 고친 것은 그 일정을 실제로 굴리는 톱니다.** 11-16 에 재평가할 표본이
3분의 1 빠진 채였다면 그날의 판정도 그만큼 좁았을 것이다.
