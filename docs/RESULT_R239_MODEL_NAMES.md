# 결과 R239 — 모델 이름이 받은 적 없는 자료를 약속하고 있었다 (2026-09-08)

R238 이 큐로 남긴 일곱 중 **가장 해로운 하나**. 사용자 지적: *"FCFF(DCF)·EV/EBITDA·SOTP·
EV/Sales 라는 이름이 나오는데 실제 계산은 EPS·BPS 와 고정 계수로 만든 간편 추정식이다."*

## 1. 무엇을 받고 있는가 — 여섯 개뿐이다

데이터 계층이 실제로 싣는 재무 항목(`bitemporal_engine.py` 의 재무 한 행):

```
'eps_ttm', 'bps', 'pbr', 'per', 'roe', 'debt_ratio'   ← 이게 전부다
'revenue_ttm': None, 'net_income_ttm': None, 'operating_cash_flow': None
EBITDA · 매출총이익 · 사업부/NAV · 배당성향 → 필드 자체가 없다
```

그런데 화면은 여덟 모형의 이름을 띄우고, 같은 표에 `할인율 가정 WACC 8.5% / 영구성장률
2.0%` 와 `미수신 입력 지표: 없음` 을 나란히 적었다. 세 줄이 함께 읽히면 "현금흐름·EBITDA·
매출을 각각 받아 여러 방법으로 교차검증했고 빠진 자료도 없다"가 된다. **셋 다 아니다.**

## 2. 이름과 실제 계산 (감사 결과 · 값은 그대로)

| 화면의 옛 이름 | 실제 계산 | 새 이름 |
|---|---|---|
| FCFF (DCF) | `정상화EPS × 0.85` 를 고정 WACC 0.085 · g 0.02 로 영구환원 후 × 0.65 → 실질 `정상화EPS × 8.76배` | EPS 기반 현금흐름 대용 모형 |
| EV/EBITDA | EBITDA 수신값 없음. `정상화EPS×1.45 + BPS×0.04` 추정치에 5.0/7.5배 | EPS·BPS 추정 EBITDA 배수 |
| SOTP / 조정 NAV | 사업부 자료 없음. 네 항이 전부 같은 BPS 에 곱한 상수 → `BPS × 1.275` 또는 `× 1.0625` | BPS 배수 (자산가치 대용) |
| EV/Sales & GP | 매출·매출총이익 수신값 없음. `BPS×1.8 + 추정EBITDA×10.0` | BPS·추정 EBITDA 혼합 배수 |

| PBR-ROE / RIM | 앞부분은 실제 BPS·ROE 를 쓴다. RIM(잔여이익)은 자기자본비용 계산이 없어 산출되지 않는다 — 이름의 절반만 참 | PBR-ROE 조정 배수 |
| 정상화 PER | 이름과 가장 가깝다. 다만 배수는 수신 PER 이 아니라 유형별 고정값(8.15/17.5/12.0) | 정상화 EPS × 고정 배수 |
| 파이프라인 rNPV | **이미 정직하다** — 자료가 없어 항상 무효이고 사유를 화면에 적는다 | 그대로 |

## 3. 고친 것 (표시 전용)

- 여덟 모형의 **표시 이름**만 바꿨다. `model_results` 의 계산 키(`PER`·`FCFF`·`EV_EBITDA`·
  `SOTP`·`EV_GP`·`DCF_SCENARIO`·`PBR_ROE`·`DDM`·`rNPV`)와 가중치 매트릭스, 배수·WACC·
  영구성장률은 **한 글자도 안 바꿨다.** 이름 문자열은 각자의 정의 줄 한 곳에만 있고 비교·
  분기·정렬·게이트 어디에도 쓰이지 않는다(정렬은 가중치 기준).
- 엔진이 **입력을 한 문장으로** 낸다(`model_inputs_note`) — *"이 모형들의 입력은 주당순이익·
  주당순자산·자기자본이익률이고, 일부는 PER·PBR 도 씁니다. 매출·영업현금흐름·EBITDA·
  사업부별 자료는 입력되지 않습니다."* 화면은 표의 한 행으로 읽기만 한다.
- `미수신 입력 지표` 행이 **무엇만 보는지** 그 자리에서 밝힌다 — 여섯 지표 기준이며
  "가치평가에 필요한 자료가 다 있다는 뜻이 아닙니다".
- `할인율 가정` 행이 **무엇에 적용되는지** 적는다 — "현금흐름표가 아니라 정상화 주당순이익에".

## 5. 이 라운드가 안 한 것

- **신뢰도 구성요소를 화면에 내는 일** — 검증에서 제안 결함 둘이 잡혀 보류했다. ⓐ 넣으려던
  자리가 하나의 HTML 블록 안이라 그 캡션이 표 아래로 밀린다. ⓑ 폴백 사유 문자열("표본외 검증
  미수행")이 **실제 사유가 아니다** — 표본외 검증은 나중에 실제로 수행되고, 적정가 계산이 그보다
  먼저라 그 시점에 값이 없을 뿐이다. 그대로 찍으면 화면이 틀린 원인을 단정한다(§3). 다음 라운드.
- 같은 77점이 한쪽에서 '제한적', 다른 쪽에서 '정상 표시'로 불리는 것 · 체결률 79.3% 고정 문자열 ·
  '핵심 합리적 범위' 이름 · 보정이 0일 때 두 축이 같은 수인 것 — 전부 실재 확인, 다음 라운드.
- **회귀의 결함 하나를 같이 찾았다**: "세 축이 서로 다른 값이다" 검사가 픽스처
  `market_adjustment_pct=-2.0` 으로 통과하는데, 규칙집이 업황 조정을 닫아 두어 **생산 경로는 그
  값을 만들 수 없다.** 즉 이 검사는 현실에 없는 입력으로 초록불이고, 화면에서 두 축이 같은 수가
  되는 상황을 영원히 못 잡는다. 픽스처를 현실값으로 바꾸면 그 검사가 실패하므로 별도 항목이다.
