# 결과 R331 — 배포 앱이 빈 DB 파일에서 통째로 죽었다 (2026-09-17)

사용자가 배포 화면을 붙였다: *"배포한 거 이렇게 나오는데."*

```
sqlite3.OperationalError (메시지는 가려짐)
web_app.py      _hist = _pm_view.grade_history()
premarket.py    t = _ct.tally(conn)
case_tracker.py "SELECT status, COUNT(*) FROM prediction_cases GROUP BY status"
```

## 원인 — '파일이 있다'와 '표가 있다'는 다르다

- `premarket.grade_history` 는 `.portfolio/improvement.db` **파일이 있는지만** 보고 조회했다.
- `improvement.database.get_connection` 은 `sqlite3.connect` 라 **연결만 열어도 빈 파일을 만든다.**
- 화면 **맨 위** 버전 칩(라운드 257)이 초기화 없이 연결을 열고(`ensure_schema` 의 PRAGMA 가 표 없음으로 실패 → `try` 가
  삼킴) 닫았다 → **파일은 있고 표는 없는** DB 가 남는다.
- 같은 페이지 **아래** 사후 검증이 그 파일을 보고 조회 → `no such table: prediction_cases` → 이 호출은 `try` 밖이라 **앱 전체가 죽었다.**
- 같은 DB 를 읽는 모델 성적의 추적 줄은 `initialize_database` 를 **먼저** 부르고 있었다 — 여는 자리마다 달랐다.

이 PC 에서는 DB 에 표가 이미 있어 한 번도 안 보였다. 배포 컨테이너는 `.portfolio/` 가 비어 새로 뜨므로 **새로 뜬 날**
처음 드러난다(R329·R330 배포로 컨테이너가 다시 떴다). 결함은 라운드 257(09-10)부터 있었다.

## 재현 (임시 경로 · 고치기 전 모듈)

| 순서 | HEAD | 새 코드 |
|---|---|---|
| 위: 연결만 열고 닫음 → 아래: `tally` | `OperationalError: no such table: prediction_cases` | 조회 성공 · 확정 0 |
| 표 없는 빈 파일에서 `grade_history` | 같은 예외 | `None`(기록 없음) |

이 PC 의 실제 DB 는 그대로 읽힌다(확정 176 · 대기 54).

## 고침

1. **여는 곳 한 곳**(`get_connection`)이 처음 여는 경로면 표부터 갖춘다 — `CREATE TABLE IF NOT EXISTS` 라 있는 행은 안
   건드리고 프로세스당 한 번. 호출부마다 초기화를 붙이지 않았다(R120e · 버전 칩 · 이슈 화면 · 사후 검증이 한 번에 닫힌다).
   못 갖추면(읽기 전용 등) 연결은 그대로 돌려주고 조회 실패는 호출부가 사유를 적는다.
2. `grade_history` 도 모델 성적 줄과 같은 순서(초기화 → 연결)를 따르고, 경로를 인자로 받는다(시험 가능).
3. 화면의 사후 검증 호출을 `try` 로 받는다 — 칸 하나 때문에 앱이 죽지 않고, 못 읽으면 *"기록이 없다는 뜻이 아닙니다"* 를
   적는다(§3 · '추천 없음'과 섞지 않는다).

값·판정·문턱 불변. 검사 §337(5건 · 새 순서 조회 · 심기(빈 파일에서 옛 조회는 정말 죽는다) · 빈 파일에서 None · 있는 행 불변 ·
화면 호출이 try 안).

## 곁들여 — 회귀가 하나 붉어졌다 (§288 · 판별식이 마크다운 표시를 사유 앞에 두고 읽었다)

이 고침의 전체 회귀에서 §288(R274 · 화면의 '산출 불가' 옆에 사유가 있나)이 1곳을 잡았다:
`- **예측 상승확률**: **\`산출 불가\`** — 20일 유효표본 2건 — 미산출 (유효표본 5건 미만)`. 사유는 **같은 줄에 붙어 있다**
(라운드 318 이 옮겨 둔 그 줄) — 그런데 판별식은 렌더 원문(마크다운)을 읽어 낱말 바로 뒤의 `` `** `` 때문에 구분자 `—` 를
못 봤다. 오늘 이 종목의 20일 유효표본이 **2건**(문턱 5건)으로 내려가 그 줄이 '산출 불가'가 된 날 처음 드러났다(R289 ·
*살아 있는 자료를 읽는 검사는 문턱을 넘는 날 처음 붉어진다*). 화면에는 안 보이는 인라인 표시(`**` · 백틱)를 걷고 읽게 했다 —
규칙(사유는 낱말 **바로 뒤** 구분자로 시작)은 그대로이고, 구분자 없이 붙은 글은 여전히 사유로 안 센다(심기 양방향 · 2곳 중 1곳).

## 남기는 것

**배포 앱은 이 PC 와 다른 초기 상태에서 뜬다** — `.portfolio/` 가 비어 있고, 먼저 도는 자리가 나중 자리의 전제를 바꾼다.
이 PC 의 회귀·브라우저 확인은 DB 가 이미 차 있는 상태만 봤다. 빈 상태는 임시 경로로 심어서 잰다.
