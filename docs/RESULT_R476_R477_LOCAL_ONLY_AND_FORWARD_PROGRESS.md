`.portfolio` **0**. 자격증명 파일은 저장소 밖(`~/.gaeum/kis.env`)이고, 키를 쓰는 코드는 한국투자 주소 둘(실전·모의)로만 보내며,
클라우드 워크플로에는 한국투자 관련 글자가 0 이다. 가늠 AI 의 외부 말풀이는 키가 어디에도 없어 꺼져 있다.

### 찾은 결함 — 같은 망의 기기가 헤더를 꾸미면 '이 PC'로 읽혔다

- 서버가 **모든 주소에서** 접속을 받고 있었다 — 실행 로그에 *Network URL*(내부망 주소)이 찍혔다. 실행 설정에 `--server.address` 가
  없어 Streamlit 기본(모든 주소)이었다.
- '이 PC 에서 연 화면인가'(`is_remote_exposed` — 비밀번호 잠금 · 보유·관심 자료 읽기 · 자동매매 칸 `allow_read` 가 전부 이 함수 하나를
  거친다)는 **Host 헤더 하나**로 정했다. 그 값은 접속하는 쪽이 적는다 — 같은 망의 기기가 `Host: localhost` 로 꾸며 웹소켓을 열면 비밀번호
  없이 보유·평단·자동매매 칸(설정·승인 버튼 포함)이 열리는 구조였다. 브라우저로 그냥 열면 헤더가 내부망 주소라 잠금 화면이 나오므로
  일부러 꾸며야 뚫린다 — 그래도 막는 쪽으로 틀려야 한다(이 함수의 독스트링이 이미 그렇게 적고 있었다).
- 비밀번호(`app_password`)가 설정돼 있지 않아 지금도 다른 기기에서는 잠금 화면뿐이었다 — 그래서 아래 고침으로 **잃는 기능이 없다**.

### 고침 — 두 겹

1. **서버를 127.0.0.1 에만 연다** — 앱 실행 설정(`.claude/launch.json` · 이 PC 에만 있음) · 사용자 실행 파일
   `run_quant_web_app.bat` · README · CLAUDE.md §6 의 명령 · 쓰기를 막은 시험 서버 둘(`_probe/`). 같은 망에서는 접속 자체가 안 된다.
   `config.toml` 에는 안 넣었다 — Streamlit Cloud 도 그 파일을 읽어 주소를 고정하면 클라우드가 안 뜬다(포트를 거기 안 두는 이유와 같다).
   Codespaces(`.devcontainer`)는 컨테이너 밖으로 포트를 넘겨야 해서 그대로 두었다 — 그 경로는 외부 판정이라 비밀번호 잠금이 걸린다.
2. **판정이 연결의 실제 상대 주소를 같이 본다** — `st.context.ip_address`(Streamlit 1.60 · 웹소켓 소켓의 상대 주소 · 이 PC 면 None).
   이것이 다른 기기면 헤더와 무관하게 바깥이다. Streamlit 이 쓰는 uvicorn 은 `X-Forwarded-For` 를 루프백에서 온 연결일 때만 믿으므로
   다른 기기는 이 값을 꾸밀 수 없다(설치된 소스에서 확인). 클립보드 판정(`is_local_session`)도 같은 둘째 겹.

⚠️ **첫 전체 회귀가 3건 실패했다** — 앱을 실제로 그리는 검사 셋(쓰기 금지 렌더의 평단 읽기 · '못 냈다' 표현 세기 둘)이 보유를 못
읽었다. AppTest 는 그 주소 자리에 문자열이 아니라 **가짜 객체(MagicMock)**를 넣고, 그 객체는 참으로 읽혀 첫 판이 시험 렌더를 '다른 기기'로
봤다(AppTest 안에서 찍어 확인). 실제 서버는 주소 문자열이나 None 을 주므로 **문자열 주소일 때만** 바깥으로 본다 — 아니면 종전 헤더 판정
그대로. 사전 점검은 렌더 검사를 안 돌아 못 봤다(§6 · 전체 회귀가 판정자다).

회귀 §458 이 판정 함수를 web_app 에서 떼어 돌려 일곱 경우를 본다(AppTest 의 가짜 객체 포함)(이 PC · AppTest · 헤더를 꾸민 다른 기기 · 내부망 · 클라우드) — 그리고
**심기 양방향**: 상대 주소 칸이 없으면(옛 판정) 꾸민 헤더가 통과한다는 것까지. 저장소의 앱 실행 명령은 전부 127.0.0.1 인지 줄 수를 밝혀
본다(3줄) · 이 PC 의 실행 설정도 있으면 같은 규칙. ⚠️ 시험 픽스처에 이 PC 의 실제 내부망 주소를 썼다가 지어낸 주소로 바꿨다 — 저장소가
공개다.
