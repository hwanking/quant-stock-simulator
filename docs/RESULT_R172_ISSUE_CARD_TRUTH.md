# 라운드 172 — 이슈 카드가 원장과 다른 말을 하고 있었다

**날짜** 2026-08-25 · **분류** 화면 결함
**요청** *"실행해주고 못다한 작업 있는지 해줘"*

---

## 1. 먼저 저장소에 물어봤다 — 톱니는 전부 날짜로 잠겨 있었다

손으로 목록을 적지 않고 `.portfolio/improvement.db` 를 읽었다
(`_probe/open_work_r172.py`). 열린 이슈는 셋이고 **오늘 할 것은 없다.**

| 이슈 | 중요도 | 다음 점검 |
|---|---|---|
| 점수 문턱이 결과를 가르지 못한다 | high | 2026-09-30 |
| 검증-블라인드 괴리 감시 | high | 2026-11-16 |
| 손절을 조이면 손실은 줄지만 도달률이 떨어진다 | low | 2026-09-15 |

그래서 §6 이 말하는 곳을 봤다 — **띄운 화면.**

## 2. 그 화면이 자기 원장과 어긋나 있었다

`_probe/screen_sweep_r172.py` 로 렌더한 글자를 훑다가 걸렸다.

```
[원장] status = resolved
[화면] 장기 개선 과제 · 20일 경과 · 즉시 수정 가능 · 다음 점검 2026-08-15
```

**그 날짜는 10일 지난 날이다.** 그리고 이 이슈는 **이미 해결된 것**이다.
해결된 이슈 **셋 전부**가 진행 중처럼 나오고 있었다.

| 이슈 | 원장 | 화면이 하던 말 |
|---|---|---|
| 원장 mfe/mae 는 청산 봉까지만 | `resolved` | 장기 개선 과제 · 20일 경과 · **즉시 수정 가능** · 다음 점검 **2026-08-15** |
| 매수 신호 발생률 과소 | `resolved` | 장기 개선 과제 · 22일 경과 · 다음 점검 2026-09-16 |
| 고신뢰 신호 표본 부족 | `resolved` | 즉시 수정 불가 · 22일 경과 · 다음 점검 2026-09-01 |

**회귀는 초록불이었다.** 코드는 옳고 화면만 틀린 부류다.

### 세 가지가 한꺼번에 틀렸다

1. **`status` 를 아무 데서도 안 보고 있었다.** 배지는 `work_status` 를
   찍는데, 그 값이 해결 시점에 안 바뀐 채 남아 있었다.
2. **`age_days` 가 해결 뒤에도 계속 자란다.** 끝난 일에 대해 *"20일
   경과"* 는 뜻이 없다 — 알고 싶은 것은 **얼마나 걸렸나**이다.
3. **지난 점검일을 예정일처럼 적는다.** 지났으면 지났다고 써야 한다 (§3).

## 3. 원인 — 닫는 길이 넷인데 하나만 `work_status` 를 고쳤다

```
improvement/issue_ops.resolve_with_verification   status + work_status  ✓
improvement/issue_tracker.resolve_issue           status 만            ✗
improvement/issue_tracker.resolve_by_key          status 만            ✗
scripts/close_issue_mfe.py                        status 만            ✗
```

**쓰는 쪽 넷을 고치지 않았다.** 넷을 고쳐도 다섯 번째가 생긴다 —
라운드 120e 가 같은 자리에서 배운 것이다(*"호출부 말고 기본값을 바꾼다"*).

→ **읽는 쪽이 `status` 를 먼저 보게 했다.** `issue_view` 가 앞으로 어느
길로 닫히든 옳은 문구를 만든다. 그리고 **문구까지 거기서 만든다** —
화면이 조립하면 조립 규칙이 또 두 곳에 생긴다 (§4).

`issue_ops._display_fields()` 가 돌려주는 넷:

| | 열린 이슈 | 해결분 |
|---|---|---|
| `state_label` | `work_status` 그대로 | **항상 `해결 완료`** |
| `age_label` | `20일 경과` | **`9일 만에 해결`** (생성→해결) |
| `fix_label` | `지금은 즉시 해결 불가` | **`None`** |
| `review_label` | `다음 점검 2026-09-30`<br>지났으면 `점검 예정일 … · N일 지남` | **`None`** |

### 고친 뒤 화면 (렌더 실측)

```
해결 완료      9일 만에 해결
              원장 mfe/mae 는 청산 봉까지만 — 연구용 창이 다르다

즉시 수정 불가  20일 경과 · 지금은 즉시 해결 불가 · 다음 점검 2026-09-30
              점수 문턱이 결과를 가르지 못한다
```

옛 문구 셋(`일 경과 · 즉시 수정 가능 · 다음 점검` · `다음 점검
2026-08-15` · `즉시 수정 가능 · 다음 점검`)은 화면에서 **전부 사라졌다.**

## 4. 회귀 — §206

- 이슈를 **실제로 읽었다** (0건이면 미측정)
- **화면이 원장과 같은 말을 한다** — 해결분에 진행 중 장식이 하나도 없다
- **해결분을 실제로 봤다** (0건이면 위 검사가 아무것도 안 잰 것이다)
- **심어서 확인한다** (§6):
  - 지난 점검일(`2020-01-01`)을 넣으면 `점검 예정일 … · 2427일 지남`
  - 해결분에 `장기 개선 과제`·`fixable_now=1`·지난 점검일을 다 넣어도
    `해결 완료 · 18일 만에 해결` 만 나오고 나머지는 `None`
- **화면이 문구를 스스로 조립하지 않는다** — `web_app.py` 에
  `"일 경과 · "` 와 `"다음 점검 {"` 가 없다
