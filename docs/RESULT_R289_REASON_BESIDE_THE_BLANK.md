# 결과 R289 — 검사가 스스로 붉어졌다. 사유 없는 자리 둘은 **서로 다른 결함**이었다 (2026-09-14)

## 1. 내가 찾은 게 아니라 검사가 찾았다

라운드 288 을 커밋하려고 전체 회귀를 돌렸더니 **§288(R274)이 처음으로 붉어졌다** —
*"핵심 세 낱말(판정 불가·미수신·산출 불가)에 사유 없는 자리가 0 이다"* 가 **10곳 · 사유 8 ·
없음 2** 를 냈다. 같은 날 아침 라운드 287 의 회귀는 5,054건 · 실패 0 이었다.

**내가 옮긴 것 때문이 아니다.** 회귀는 예시 하나만 찍으므로 둘을 다 읽었다
(`_probe/r288_unavail.py`):

| 낱말 | 곳 | 사유 있음 | 없음 |
|---|---:|---:|---:|
| 판정 불가 | 0 | — | 0 |
| 미수신 | 2 | **2** | 0 |
| 산출 불가 | 8 | 6 | **2** |

간밤 시황 판이 쓰는 `미수신` 2곳은 **둘 다 사유 있음**이다. 붉어진 것은 `산출 불가` 두 곳이고,
둘 다 이번에 손대지 않은 자리다. 이 검사는 **한 종목을 실제로 렌더해서** 세므로, 살아 있는
자료가 문턱을 넘으면 어제 안 보이던 문구가 오늘 화면에 나온다 — 그날 유사사례가 **9건**
(확률 환산 문턱 10건)이라 세 칸이 '산출 불가'로 바뀐 것이다. **검사가 제 일을 했다.**

## 2. 둘은 같은 낱말이지만 결함이 다르다

### ⓐ 엔진 요약 — 이름만 적고 사유를 버렸다

```
산출 불가 관점: 자기유사 예측, 대응 시나리오
```

이름은 **무엇이** 비었는지만 말하고 **왜** 는 말하지 않는다. 그런데 그 함수는 관점을 만들 때
사유를 **이미 내고 있었다**:

```python
add('pattern', '자기유사 예측', None,
    [f"유효표본 {mc}건 — 확률 산출 기준(10건) 미달, 관찰값만 참고"], available=False)
add('scenario', '대응 시나리오', None,
    ["표본 부족으로 목표·손절 선도달 확률 미산출"], available=False)
```

**결론과 함께 낸 사유가 요약 한 줄에서 버려지고 있었다** — 라운드 240 이 '추천 제외 사유'에서
고친 것과 같은 모양이다. 고침도 같다: 사유 문장을 **이 줄이 새로 짓지 않고** 그 관점이 낸
첫 줄을 그대로 옮긴다(§4 — 두 곳에 적으면 한쪽이 낡는다).

### ⓑ 타일 — 눈으로는 붙어 있는데 글자로는 떨어져 있었다

```
목표 방향이 먼저 나올 확률 (유사사례 실측)
산출 불가
유사사례 9건 — 확률로 환산하려면 10건이 필요합니다
```

**화면은 옳다.** 라운드 199 가 *"산출 불가 세 글자만 내밀면 고장인지 규칙인지 알 수 없다"* 며
넣은 사유가 값 바로 아래에 있다. 그런데 타일을 글자로 펴면

```
… (유사사례 실측) 산출 불가 유사사례 9건 — 확률로 환산하려면 10건이 필요합니다
```

가 되어 **값과 사유의 경계가 사라진다.** 붙여 준 것은 배치였고 글자에는 남지 않았다 —
화면을 글자로 읽는 쪽(검사 · 스크린리더)에서는 사유가 없는 것과 같다. 그래서 사유 문구가
**구분자로 시작**하게 했다(`— 유사사례 9건 · 확률로 환산하려면 10건이 필요합니다`).
**문턱 10건도, 그 까닭도 한 글자 안 바꿨다.**

## 3. 판별식은 **안 넓혔다** — 그게 제일 중요한 결정이다

ⓑ 만 보면 *"같은 줄 안에 구분자가 있으면 사유로 친다"* 로 넓히고 싶어진다. 그러면 ⓐ 의
`산출 불가 관점: 자기유사 예측` 도 `:` 때문에 통과한다 — **검사가 방금 잡은 결함에 눈이
먼다.** R274 가 적어 둔 그대로다: *좁으면 못 보고 넓으면 부풀린다.*

그래서 판별식(`scripts/unavailable_audit`)은 한 글자도 안 고치고 **화면·엔진 쪽을 고쳤다.**
§302 가 **옛 두 모양이 여전히 걸리는지**를 같이 심는다(양방향 · R194):

| 심은 글자 | 기대 | 실제 |
|---|---|---|
| 옛 ⓐ `산출 불가 관점: A, B` | 사유 없음 | 사유 없음 |
| 새 ⓐ `산출 불가 — A: 유효표본 9건 —…` | 사유 있음 | 사유 있음 |
| 옛 ⓑ `산출 불가 유사사례 9건 —…` | 사유 없음 | 사유 없음 |
| 새 ⓑ `산출 불가 — 유사사례 9건 ·…` | 사유 있음 | 사유 있음 |
| 새 ⓑ 표본 못 만듦 | 사유 있음 | 사유 있음 |

## 4. 계산부를 고쳤으므로 버전을 먼저 냈다

`quant_indicators.py` 는 §1 의 계산부이고 `model_freeze_guard` 의 **ⓐ(자동 실행이 바꾸면
안 되는 것)** 이다 — 다만 **ⓑ(11-16 까지 한 글자도 안 바뀌어야 하는 박제 대상)** 는 아니라서
사람이 사유와 버전을 달고 고칠 수 있다(박제였다면 문구라도 안 고친다 · R242).

`model` **v2026.09.11.1 → v2026.09.14.1** (`kind='ui'`) — 값·문턱·가중치·산식은 하나도
안 바뀌었고 바뀐 것은 표시 문구뿐이다. 안 냈으면 커밋 **뒤** 첫 회귀에서 §109 가
*"model 버전이 담당 파일 변경보다 뒤처진다"* 로 붉어졌을 자리다.

## 5. 규칙으로 남기는 것

- **검사가 붉어지면 먼저 "내 변경 때문인가"를 세어서 가른다.** 여기서는 아니었다 — 같은
  낱말 10곳 중 내 블록의 2곳은 둘 다 사유가 있었고, 붉어진 둘은 손대지 않은 자리였다.
  살아 있는 자료를 읽는 검사는 **문턱을 넘는 날 처음 붉어진다.**
- **배치로 붙여 준 것은 글자에는 안 남는다.** 값 아래 부제로 사유를 그리면 눈에는 붙어
  보이지만, 그 화면을 글자로 읽는 쪽에서는 떨어져 있다. 붙어 있음을 **글자에도** 남긴다.
- **판별식을 넓혀서 통과시키지 않는다.** 넓히면 그 검사가 방금 잡은 결함을 다시는 못 잡는다.
  고칠 것은 재는 쪽이 아니라 재이는 쪽이다.
