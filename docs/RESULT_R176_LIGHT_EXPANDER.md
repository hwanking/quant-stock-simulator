# 라운드 176 — 라이트 모드에서 펼친 패널의 글자가 안 보였다

**날짜** 2026-08-25 · **분류** 화면 결함 (§5 — 대비는 브라우저에서 실측)
**요청** *"실행해주고 못다한 작업해줘"*

---

## 1. 어디를 봤나 — 라운드 174 가 남긴 실마리

174 에서 드러났다: **손으로 박은 색은 테마를 안 따른다.** 방향색은 고쳤지만
**배경·글자색**은 그대로다. 코드로 먼저 세어 봤다.

| | 수 |
|---|---:|
| 손으로 박은 **배경색** | **355곳** · 6종 |
| 손으로 박은 **글자색** | **255곳** · 10종 |
| 그중 어두운 고정 배경(휘도<0.12) | 4종 · **353곳** |

숫자만 보면 큰일 같지만 — **그 다크 카드는 의도된 설계다.** 코드가 그렇게
적어 두었다(`web_app.py:199`):

> 기존 정보 카드는 자체 배경(다크)을 유지해 라이트 모드에서는
> **'흰 바탕 위 다크 카드' 대시보드 스타일**이 된다.

그래서 코드 세기로는 판정하지 않고, **브라우저에서 실제 대비를 쟀다** (§5).

## 2. 첫 측정이 틀렸다 — 그라디언트를 안 봤다

라이트 모드로 켜고 글자 마디 1,794개를 훑으니 **17개 실패**가 나왔고, 그중엔
**실제 매수 권고 문장**(`39,291원 이하로 내려올 때만 사세요`)도 있었다.

그런데 파 보니 그 카드는 이렇게 칠해져 있었다.

```html
<div style='background:linear-gradient(135deg,#161D2A 0%,#161D2A 100%); …'>
```

**`linear-gradient` 는 `backgroundColor` 가 아니다.** 내 측정기가 조상을
훑으며 `backgroundColor` 만 합성해 그 카드를 **투명으로 봤고**, 라이트
페이지 배경에 합성해 1.06 을 냈다. **카드는 실제로 어둡고 글자는 잘 보인다.**

§5 가 적어 둔 그대로다 — *"알파 합성과 배경 그라디언트를 **같이** 봐야
한다."* 측정기에 그라디언트를 넣고 다시 재니 **17 → 4개**.
**13개는 내 오탐이었다.**

## 3. 남은 4개가 진짜였다 — 그리고 하나의 결함이었다

| 글자 | 대비 |
|---|---:|
| `관심종목 18개` | **1.04** |
| `유사패턴 최적 관찰기간이 왜 미선정인가` | **1.04** |
| `keyboard_arrow_down` × 2 | **1.04** |

전부 **펼침 패널 머리**다. 글자는 `#111827`(라이트 `tx1`), 배경은
`#10141B`(다크). **다크 위에 다크다 — 사실상 투명이다.**

### 원인

`.streamlit/config.toml` 이 `base = "dark"` 로 잠겨 있어 Streamlit 이
**자기 위젯 크롬**을 다크로 칠한다. 그런데 실측해 보니 그 다크는
**펼친 것에만** 붙는다.

```
전체 summary 68개 — 투명 65개(접힘) · 다크 3개(펼침)
```

우리 라이트 오버라이드는 *"인라인 `color` 가 없는 요소만 어둡게"* 라는
규칙이라, 그 다크 배경(인라인이 아니라 CSS)이 가드에 안 걸린다. 그래서
**펼친 머리만** 다크 배경 + 다크 글자가 됐다.

## 4. 고침 — 그리고 **하마터면 더 나쁘게 만들 뻔했다**

첫 생각은 *"`summary` 와 그 자손을 글자색 예외로 두자"* 였다.
**그러면 접힌 65개가 흰 글자가 된다** — 흰 바탕 위 흰 글자다.
실측이 65 대 3 을 보여 주지 않았으면 그 함정에 빠졌다.

맞는 고침은 반대다. **펼친 머리의 배경을 지워** 나머지 65개와 같게 만든다.

```css
.stApp [data-testid="stExpander"] details[open] > summary {
    background: transparent !important;
}
```

### 같은 DOM 에서 규칙만 넣고 빼며 쟀다

| | 훑은 글자 마디 | 대비 미달 |
|---|---:|---:|
| 규칙 **없이** | 1,802 | **2** |
| 규칙 **있으면** | 1,802 | **0** |

(열린 익스팬더 4개가 화면에 있는 상태에서 잰 값이다.)

## 5. 회귀 — §210

- 펼친 익스팬더 머리의 배경을 라이트에서 지운다
- **그 규칙이 라이트 블록 안에** 있다 (다크에서 지우면 펼침 표시가 사라진다)
- **`summary` 전체를 글자색 예외로 두지 않았다** — 이 절이 그 함정을 막는다
- **실측값과 좁힌 이유**를 코드에 적었다
- **전제를 값으로 확인한다** — `config.toml` 이 여전히 `base = "dark"` 인가.
  전제가 바뀌면 이 규칙도 다시 재야 한다

## 6. 곁들여 — §110 이 **내가 방금 쓴 주석**을 잡았다

첫 회귀에서 한 건이 실패했다.

```
[FAIL] 화면 문자열에 이모지가 없다 — 4개: web_app.py:892(⚠) …
```

내가 새로 쓴 CSS 주석의 `⚠️` 다. 그 주석은 **f-string 안**이라 실제로
페이지 HTML 로 나간다 — 파이썬 주석이 아니다. **검사가 옳다.**
(§110 은 AST 로 산 코드만 보므로 진짜 파이썬 주석의 `⚠️` 는 안 잡는다.)
평문 표기로 바꿨다.

라운드 114 가 이 검사의 판별을 AST 로 바꾼 이유가 이것 — 화면 문자열과
주석을 가르지 못하면 49개를 놓치거나, 반대로 주석을 오탐한다.
