# 결과 R271 — 남은 옛 경로 셋(시총 1위 · 배당 · 관심도 순위)과, 세 결함의 뿌리였던 로그 한 줄 (2026-09-11)

라운드 270 이 다섯 경로를 새 사이트 JSON 으로 옮기고 회귀 4,954건을 통과시켰다. 그 코드를
**앱으로 띄우자** 화면이 셋을 더 보였다 — 회귀에는 없던 경로들이다(§6 · 화면 결함은 서버를
띄워야 나온다).

## 1. 무엇이 보였나 (8512 · R270 코드 · 2026-09-11 오전)

| 자리 | 화면 |
|---|---|
| 사이드바 | **'시총 1위 미수신 — 네이버 시세 응답 없음'** — 옛 시가총액 페이지를 직접 파싱하는 함수가 R270 의 유니버스 고침 밖에 있었다 |
| 그 다음 줄 | 그 `None` 이 `resolve_symbol(None)` → `.strip()` 에서 **`AttributeError` · 앱 전체 사망** |
| 시장 스캔 | `get_screener_universe` 가 '전 종목 수집 실패' 폴백으로 갔고, 그 폴백의 `print` 에서 **`UnicodeEncodeError: 'cp949' codec can't encode character '—'`** |
| 배당 · 관심도 순위 | 회귀 밖 경로 — 코드로 확인하니 옛 표·옛 순위 페이지를 읽고 있었다(배당은 "공시되지 않았습니다"를 냈다 · 순위는 코드 0개) |

## 2. 뿌리 — 로그 한 줄이 수집을 죽였다

서버 로그가 답을 줬다:

```
[Universe] KOSPI 수집 실패: 'cp949' codec can't encode character '—' in position 17
[Universe] KOSDAQ 수집 실패: 'cp949' codec can't encode character '—' in position 18
```

R270 이 넣은 **성공 로그** `[Universe] KOSPI — 새 네이버 증권 JSON 목록 …` 의 em-dash 가, streamlit
자식 프로세스의 표준출력(cp949)에서 예외를 냈다. 그 예외가 `fetch_krx_universe` 의 `except Exception`
에 잡혀 **'수집 실패'** 로 읽혔고, 폴백 print 도 같은 글자를 담고 있어 거기서 앱이 죽었다. 시총 1위
폴백도 같은 목록 함수를 부르므로 같은 자리에서 `None` 이 됐다. **셋이 한 줄이었다.**

왜 못 봤나 — 프로브도 회귀도 첫 줄에서 `sys.stdout.reconfigure(encoding='utf-8')` 를 한다. 차가운
프로세스로 돌린다고 적어 두고(R167) **인코딩은 데운 채** 돌리고 있었다.

실측(cp949 자식 프로세스 · `_probe/r271_cp949.py`):

| 자식 | rc | 출력 |
|---|---:|---|
| 엔진 import 뒤 `print('—')` | **0** | `[Universe] KOSPI ? 새 네이버 …` · `[probe] no1 삼성전자` · `? em-dash` · `R271_OK` |
| 엔진 없이 `print('—')` | **1** | `UnicodeEncodeError: 'cp949' codec can't encode character '—'` |

## 4. 미수신으로 남긴 것 — 외국인·기관 순매수 상위

옛 `sise/sise_deal_rank.naver` 는 새 사이트 **시장 홈**으로 302 된다. 새 끝점을 찾았다:

| 방법 | 결과 |
|---|---|
| 후보 주소 **71개**(`stocks/foreignerPureBuy` · `investor` · `trend` · `dealTrend` · 추세 API 필드 이름을 본뜬 50개 …) | **전부 404** |
| 새 사이트 4페이지의 JS 번들 218개에서 `api/…(deal|invest|foreign|organ|trend)` 문자열 | **1개** — `securityService/chart/foreign/INDEX/`(지수 차트용 · 종목 목록 아님) |

목록이 없으니 그 출처는 **미수신**이다. 영향은 균일하다 — `in_flow_list` 가 전원 `False` 라 `flow_score`
는 전원 0 이고 후보를 **거르지 않는다**(§3 · 못 잰 것으로 거르지 않는다). 종목별 투자자 추세
(`stock/{code}/trend` · R270)로 재는 '동시 순매수 · 순매수 전환'은 그대로 산다 — 관심점수의 '외국인·기관
수급' 항목(15%)은 그 추세에서 오므로 연동 현황 문구는 오늘도 참이다. 보고(`report`)의 그 줄에 `why` 를
실었고, 그 목록 진입만 보는 **'외국인·기관' 발굴 방식**은 후보 0 이 판정이 아니라 미수신이므로
`find_attention_candidates` 가 그 사유를 `unavailable` 로 옮긴다(화면은 경고로 낸다 · 이미 있는 길 ·
§3 데이터 미수신 ≠ 추천 없음). 출처 보고 자체는 화면 어디에도 안 나간다(`sources` 소비자 0) — 그래서
사유는 방식의 경고 한 줄로 닿는다.

## 7. 규칙으로 남기는 것

- **차가운 프로세스는 인코딩까지 차갑게.** 검사 도구의 첫 줄 `reconfigure(utf-8)` 이 앱의 실패를 가렸다.
  로그 한 줄이 수집을 죽일 수 있으면 그것은 로그가 아니라 게이트다 — 기본값을 관대하게(§120e · 한 곳).
- **고친 경로의 형제를 세고 나서 끝낸다**(R246). R270 은 회귀가 실패한 다섯 경로만 옮겼다. 회귀에 없던
  셋(시총 1위 · 배당 · 관심도 순위)은 화면이 알려 줬다 — 옛 주소 리터럴(`finance.naver.com/sise/` ·
  `item/`)을 훑는 것이 먼저였다.
- **'없다'는 찾아본 범위와 함께 적는다.** 순매수 상위 목록의 새 끝점은 71개 주소·218개 번들에서 못
  찾았다 — 그것이 "없다"의 근거이고, 그 밖은 모른다.
