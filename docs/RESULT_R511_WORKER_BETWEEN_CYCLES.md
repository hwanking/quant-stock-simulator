# 라운드 511 — 장중 세션 워커가 바퀴 사이에 '안 돎'으로 보였다

2026-10-13 장중(첫 실매수 날) · 화면 상태 판정 · 워커·실행부·주문 규칙 불변 · 버전 없음(담당 축 밖) · 회귀 §491(4건)

## 무엇을 봤나

첫 실매수 주문(09:00:12 접수)이 나간 뒤 관제실 시작 카드가 장중에 이렇게 적고 있었다:

> 시작 · 지금은 장중인데 워커가 돌고 있지 않습니다 — 직접 켜면 지금부터(python scripts/run_swing_worker.py --session --loop 60),
> 아니면 다음 장 …

워커는 08:50 부터 1분마다 돌고 있었다(실행 기록 · 심박 · 작업 스케줄러 상태 Running). 그 말대로 하나 더 켜면 워커가 둘이 된다
(잠금이 같은 바퀴를 막지만, 화면이 사용자에게 할 일을 잘못 시킨 것이다).

## 왜

`run_swing_worker.main` 은 잠금을 **바퀴가 도는 동안만**(1~2초) 잡고 바로 푼다. `swing_ops.worker_status`(라운드 454)는 잠금 파일의
주인이 살아 있나만 봐서, 장중 세션 60초 중 58초는 '지금 도는 워커 없음(잠금 파일 없음)'이었다. 라운드 454 의 *"심박은 '마지막
기록'이지 '지금'이 아니다"* 는 맞는 말이었지만, 그 대신 고른 잠금 파일은 세션 모드(라운드 452)에서 '지금'을 1/30 만 말했다.
같은 판정을 읽는 곳 넷(시작 카드 · 지휘 띠 '워커' · 시스템 갈래 진행 줄 · 작업 카드)이 다 같이 틀렸고, 작업 카드(라운드 472)는
워커 카드를 사실상 한 번도 못 띄웠다.

## 고친 것

- `swing_ops.session_status` — 잠금이 없으면 워커의 실행 기록(`.portfolio/swing_worker_run.txt`)에서 **오늘** 세션 시작 줄(`정규장 … 마감까지
  N초마다`)을 찾고, 그 뒤 마감 뒤 끝 줄이 있으면 '오늘 세션 끝', 마지막 바퀴 줄이 바퀴 간격 × 3 안이면 '실행 중(바퀴 사이 — 잠금은 바퀴가
  도는 동안만 잡는다)', 그보다 오래 멈췄으면 '끊긴 것으로 본다'. 오늘 시작 줄이 없거나 못 읽으면 None → 종전 판정 그대로.
  ×3 은 화면 표시 규칙이지 판정 문턱이 아니다(바퀴 하나가 늦어도 '안 돎'이라 하지 않을 여유).
- `worker_status` 는 잠금이 있으면 종전 그대로(바퀴 도는 중 · PID), 없을 때만 실행 기록을 본다. 실행 기록은 잠금 파일과 같은 폴더의 것을
  읽는다 — 시험이 임시 잠금 경로를 주면 임시 폴더를 본다(실제 기록을 섞지 않는다).
- 시작 카드가 '돌고 있지 않습니다'라 적을 때 그렇게 보는 사유(워커 상태 문장)를 같은 줄에 적는다.

실제 기록으로 잰 것(09:23): *"실행 중 · 장중 세션 08:50 부터 60초마다 · 마지막 바퀴 09:23:27 (바퀴 사이 …)"* · 10분 뒤로 가정하면 '끊긴
것' · 다음 날로 가정하면 None(어제 세션을 오늘로 읽지 않는다).

## 첫 전체 회귀가 잡은 하나

§454 ③' (작업 카드 목록)이 장중에만 붉어졌다 — 그 검사는 `running_jobs(…, worker=None)` 을 넘겼는데 None 은 *"실제 워커 상태를 읽어라"* 다.
종전엔 잠금이 바퀴 동안만 잡혀 실제로 읽어도 거의 늘 '없음'이라 통과했고, 이 라운드 뒤로는 장중 세션이 '실행 중'으로 잡혀 기대(빈 목록)와
달라졌다. 검사가 실제 환경에 기대고 있었다(R165) — '워커 없음'을 `worker=False` 로 넘긴다(코드 동작 불변).

## 안 한 것

- 워커(실행부 쪽 스크립트)에 '지금 도는 중' 표식을 따로 적게 하는 고침은 장중이라 안 했다 — 실주문을 내는 프로세스다. 실행 기록이 이미 그
  사실을 싣고 있어 화면 쪽에서 읽는 것으로 충분했다.
- 돌고 있던 앱 서버는 장중이라 안 내렸다 — 이 문장은 15:30 뒤 재시작에서 화면에 반영된다.
