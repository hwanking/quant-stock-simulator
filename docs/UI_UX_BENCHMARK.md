# UI/UX 벤치마크 — 10개 플랫폼 분석과 선별적 차용 전략

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 이 문서는 브리프가 지정한 10개 플랫폼에서 **무엇을 가져오고, 무엇을 버리며,
> 어떻게 우리 것으로 만드는지**를 화면 단위로 확정한다.
> 원칙: 모방이 아니라 번역이다. 각 플랫폼의 장점을 우리 앱의 4대 가치
> (데이터 정확성 / 근거 추적 / 행동 결론 / 과거 적중 검증)에 종속시켜 차용한다.

## 총괄 원칙

- 어떤 플랫폼도 통째로 복제하지 않는다. 각 항목은 "왜 우리 앱에 필요한가"가 먼저다.
- 벤치마크 대상은 모두 **실시간 트레이딩 도구**이지만, 우리는 **전일 확정 데이터
  기반 분석 도구**다. 실시간성을 전제로 한 UI 관행(틱 깜빡임, 호가창, 초단위
  갱신)은 처음부터 배제한다.
- Streamlit 위에서 구현 가능한 수준으로만 차용한다 (커스텀 도킹, 드래그 리사이즈
  같은 네이티브 데스크톱 패턴은 제외).

## 1. Bloomberg Terminal

**참고한 장점**
- 하나의 종목/주제를 중심으로 관련 정보(시세·뉴스·재무·비교)가 통합된 작업공간.
- 모든 데이터에 기준 시각과 출처가 붙는 문화 — 데이터의 "어디서 언제"가 항상 명시된다.
- 시장 전체 → 섹터 → 종목으로 내려가는 하향식(top-down) 정보 구조.
- 수십 년 검증된 기능 중심 설계가 주는 신뢰감.

**사용하지 않을 단점**
- 검은 배경 + 주황/녹색 고밀도 텍스트 격자 — 학습 곡선이 극단적으로 높다.
- 명령어(티커+펑션 코드) 기반 탐색 — 일반 사용자에게 부적합.
- 화면당 정보 밀도가 지나치게 높아 "무엇을 봐야 하는지"를 알려주지 않는다.

**적용할 화면**: 종목 분석(데이터 감사 탭), 홈, 모든 화면의 데이터 스탬프.

**적용 방식**
- 모든 카드·표에 "기준일 YYYY-MM-DD · 출처 네이버/다음/야후/DART" 스탬프 컴포넌트를
  일괄 적용 (COMPONENT_MAP의 '데이터 기준일 스탬프').
- 종목 분석의 '데이터 감사' 탭을 Bloomberg의 출처 투명성 수준으로: 원천 데이터
  매트릭스(SYSTEM_MAP §1)를 표로 노출, 교차검증 결과·미수신 항목을 숨기지 않는다.
- 홈을 시장(지수 카드) → 추천(종목) → 보유(내 위험) 순의 하향식으로 배열.

**차별화 요소**: Bloomberg는 데이터를 다 보여주고 판단은 사용자에게 맡긴다.
우리는 반대로 **행동 결론을 맨 위에** 두고 데이터는 그 근거로 내려보낸다.
밀도도 반대 — 카드당 정보 3단계 이하, 여백 우선.

## 2. TradingView

**참고한 장점**
- 차트가 화면의 주인공이며 기간(1D/1W/1M/1Y) 전환이 한 번의 클릭.
- 지표 추가/제거가 검색형 패널로 직관적.
- 종목 검색·심볼 전환이 어디서나 빠르다.
- 라이트/다크 테마 모두 완성도가 높다.

**사용하지 않을 단점**
- 소셜 기능(아이디어 공유, 팔로우) — 우리 목적과 무관.
- 그리기 도구 수십 종 — 유지비용 대비 가치 없음.
- 차트가 "결론"이 되어버리는 구조 — 사용자가 스스로 해석해야 한다.

**적용할 화면**: 종목 분석(가격 차트 탭), 홈의 미니 차트.

**적용 방식**
- chart_pro.py 종합 차트에 **지표 선택 패널**(브리프 추가 요청)을 붙인다:
  체크박스/멀티셀렉트로 이동평균(5·20·60·120)·볼린저·RSI·거래량·DeMARK 카운트·
  지지/저항선을 켜고 끈다. 선택 상태는 session_state로 유지.
- 기간 전환은 segmented control(3M/6M/1Y/전체)로 차트 상단에 배치.
- 차트 위에 우리 고유 오버레이: 권장 매수가·1/2차 목표·손절가 수평선을 기본 표시.

**차별화 요소**: TradingView는 차트로 시작해 차트로 끝난다. 우리는
**퀀트 결론이 먼저 나오고 차트는 그 결론을 눈으로 검증하는 수단**이다.
차트 탭에 들어가도 상단에 행동 결론 배너가 유지된다.

## 3. Koyfin

**참고한 장점**
- 시장 전체 대시보드(지수·환율·금리·섹터)가 한 화면에 정돈된 카드로 배열.
- 자산 유형별로 표현 방식을 달리한다(지수는 스파크라인, 환율은 값 중심).
- 절제된 색·타이포그래피 — 금융 데이터를 시끄럽지 않게 보여준다.

**사용하지 않을 단점**
- 워치리스트·대시보드 커스터마이즈의 깊이 — 초기 구현 범위 초과.
- 미국 시장 중심 데이터 구성 — 우리는 KOSPI/KOSDAQ 중심으로 재구성.

**적용할 화면**: 홈(시장 카드 그리드), 개장 전 브리핑(시장 요약 탭).

**적용 방식**
- 홈 상단에 시장 카드 4~6개: KOSPI·KOSDAQ·KOSPI200·USD/KRW·미국지수(S&P500/나스닥)·
  변동성(VIX). 각 카드는 값·전일비·기준일·미니 추세·정상 여부 배지 — 데이터는
  market_context.py의 기존 수집 결과만 사용.
- 개장 전 브리핑 첫 탭을 Koyfin식 시장 요약(전일 확정 종가 기준)으로 구성.

**차별화 요소**: Koyfin은 시장을 보여주고 끝난다. 우리 시장 카드는
**시장 국면이 점수에 어떻게 반영됐는지**(시장 국면 8% + 글로벌 감점표)로
연결되는 진입점이다 — 카드 클릭 시 "이 국면이 오늘 점수를 얼마나 움직였나"로 이동.

## 4. IBKR TWS (Trader Workstation)

**참고한 장점**
- 종목을 선택하면 연결된 패널들이 함께 갱신되는 종목 중심 연동.
- 워크스페이스를 사용자가 목적에 맞게 구성하는 유연성.

**사용하지 않을 단점**
- 자유 배치 도킹 UI — Streamlit에서 구현 불가하고, 초심자에게 혼란.
- 90년대풍 밀집 그리드와 팝업 창 남발.
- 주문 실행 중심 설계 — 우리는 주문 기능이 없다.

**적용할 화면**: 종목 분석, 설정.

**적용 방식** — 자유 배치 대신 **제한적 사용자 설정**으로 번역:
- 카드 순서 변경(설정에서 위/아래 이동), 자주 보는 탭 고정(기본 탭 지정),
  관심 지표 선택(차트 지표 패널과 공유), 간단 보기/전문가 보기 토글
  (3~4단계 상세를 숨기거나 펼침), 패널 접기 상태 기억.
- 저장은 session_state + 로컬 JSON(.portfolio/ui_prefs.json — 신규 인터페이스,
  계산 로직과 무관).

**차별화 요소**: TWS는 "모든 것을 어디에나"지만 우리는 **기본 배치가 이미
정답인 상태**(결론→가격→이유→상세)를 제공하고, 설정은 그 위계를 깨지 않는
범위에서만 허용한다.

## 5. thinkorswim

**참고한 장점**
- 하나의 종목을 다중 기간(일·주·월)으로 동시에 확인하는 분석 습관.
- 시나리오 분석(가격이 여기 가면 어떻게 되나)과 위험 지표의 동시 노출.
- 분석 도구의 깊이 — 표면 아래로 파고들 수 있는 구조.

**사용하지 않을 단점**
- 압도적 기능 수와 설정 항목 — 학습 장벽.
- 옵션 트레이딩 중심 화면 구성 — 무관.
- 어두운 전용 테마 하나에 최적화된 디자인.

**적용할 화면**: 종목 분석(매매 시나리오 탭, 핵심 요약).

**적용 방식**
- 다중기간 분석: 기존 엔진의 월봉 10선 게이트·이동평균 배열·DeMARK 일봉 카운트를
  "일/주/월 관점 합의" 카드로 재구성 (기존 build_tab_verdicts 결과 재배열, 계산 신설 없음).
- 시나리오 3분할 컴포넌트: 상승(2차 목표 도달)/중립(기간 만료)/하락(손절) 각각에
  기존 산출값(목표가·손절가·선도달확률·손익비)을 배치. 새 확률을 만들지 않고
  리플레이 실측(virtual_graded.jsonl 기반)만 인용.
- 신규 진입자 vs 보유자 시나리오를 나란히 비교(기존 build_easy_advice의 2모드).

**차별화 요소**: thinkorswim의 시나리오는 사용자가 조립한다. 우리는
**엔진이 이미 산출한 세 경로를 소비하기 쉽게 배열**할 뿐이며, 각 경로에
"과거 유사 사례에서 실제 비율"을 표본 수와 함께 붙인다.

## 6. Webull Desktop

**참고한 장점**
- 현대적 카드 레이아웃과 일관된 간격 체계.
- 반응형 그리드 — 창 크기에 따라 카드가 자연스럽게 재배열.
- 다크 테마의 완성도(순검정이 아닌 짙은 차콜, 카드 명도차).

**사용하지 않을 단점**
- 커뮤니티·페이퍼트레이딩 게임화 요소.
- 프로모션 배너가 화면을 침범하는 구조.

**적용할 화면**: 전 화면 공통 (DESIGN_SYSTEM.md의 카드·간격·다크 토큰).

**적용 방식**
- 카드 radius 10~14px, 약한 그림자, 카드 간 16~24px 간격을 CSS로 전역 적용.
- 다크 테마를 Webull 수준의 명도 위계(배경 < 카드 < hover 카드)로 설계 —
  구체 토큰은 DESIGN_SYSTEM.md 참조.
- st.columns + CSS media query로 그리드 재배열 (RESPONSIVE_RULES.md).

**차별화 요소**: Webull의 시각 언어에서 밀도만 가져오고, 색은 우리 팔레트
(네이비 주색·절제 녹색/민트)로 완전히 교체한다. 게임화 제로.

## 7. Finviz

**참고한 장점**
- 스크리너의 압도적 비교 속도 — 수백 종목을 한 표에서 정렬·필터.
- 색으로 상태를 즉시 전달하는 히트맵.
- 표 헤더 클릭 정렬 등 조작이 단순.

**사용하지 않을 단점**
- 깨알 글씨와 90년대풍 밀집 테이블 — 브리프가 명시적으로 금지.
- 광고 영역 혼재.
- 모바일 대응 부재.

**적용할 화면**: 시장 스캐너, 개장 전 브리핑(추천 후보 표).

**적용 방식**
- 스캐너에 **표 보기 + 카드 보기 토글** 제공: 표는 Finviz식 밀도(단, 최소 13px,
  tabular-nums)로 정렬·필터, 카드는 종목당 결론·점수·가격 3줄 요약.
- 히트맵 보기: 기존 스캔 결과(market_attention.py)의 점수·등락을 크기·색으로 —
  단, 색만으로 구분하지 않고 값 라벨 병기 (접근성 원칙).
- 필터는 기존 파이프라인이 이미 산출하는 축만: 시장·유형(STOCK/ETF/레버리지·인버스)·
  점수 구간·행동 판정·게이트 통과 여부·신뢰도.

**차별화 요소**: Finviz는 필터 결과가 끝이다. 우리 스캐너의 모든 행은
행동 판정(final_action_score 기반)과 게이트 상태를 달고 있으며, 클릭하면
"왜 이 판정인가"로 이어진다.

## 8. Robinhood Legend

**참고한 장점**
- 큰 숫자와 분명한 시각 위계 — 지금 중요한 값이 무엇인지 즉시 안다.
- 화면당 하나의 주요 행동이 명확.
- 여백과 타이포그래피 중심의 절제된 화면.

**사용하지 않을 단점**
- 게임화(색종이, 애니메이션 축하) — 브리프 명시 금지. 투자 판단을 오락화한다.
- 정보 깊이 부족 — 근거 없는 단순화.
- 주문 유도 중심 UX.

**적용할 화면**: 오늘의 추천(카드), 종목 분석(행동 판단 패널), 홈.

**적용 방식**
- 행동 결론 배너: 판정 문구(예: "분할매수 / 조건 확인·관망")를 24~30px로 가장 크게,
  종합점수·현재가를 26~36px tabular-nums로 그 다음 크게.
- 화면당 주요 행동 1개 원칙: 추천 카드의 첫 버튼은 항상 '상세 분석 보기'.
- 마이크로 인터랙션은 hover 미세 상승과 숫자 전환만 (축하 효과 금지).

**차별화 요소**: Legend는 큰 숫자 아래가 얕다. 우리는 큰 숫자 바로 아래에
**"이 점수는 이렇게 나왔습니다" 추적 경로**(가중합→신뢰도 수축→게이트 상한)를
항상 연결한다. 단순함이 근거 은폐가 되지 않게 한다.

## 9. eToro

**참고한 장점**
- 미보유/보유 상태를 명확히 분리한 화면 전환.
- 평단가·수량 입력 후 내 포지션 기준의 손익 추적.
- 가상 포트폴리오(실거래 없이 결과 추적).

**사용하지 않을 단점**
- 카피 트레이딩·소셜 피드 — 타인 추종은 우리 철학(근거 추적)과 정반대.
- 과도한 마케팅 톤과 CTA 남발.

**적용할 화면**: 내 보유종목, 종목 분석(행동 판단 패널), 케이스 스터디.

**적용 방식**
- 종목 분석의 행동 판단 패널에 미보유/보유 모드 토글 — 기존 build_easy_advice가
  이미 신규/보유 이원 판정을 산출하므로 UI 분리만 하면 된다.
- 보유 등록: 기존 스크린샷 OCR·CSV 가져오기·직접 입력(portfolio.py) 유지,
  평단가는 보유 판단에만 사용(예측·점수 미반영) 원칙 문구 유지.
- 가상 매매 추적: prediction_log.py의 기존 판정 기록을 "내가 따랐다면" 뷰로 노출.

**차별화 요소**: eToro의 소셜 증명("이 사람을 따라 해라") 대신 우리는
**모델의 과거 성적표**(케이스 스터디·리플레이 적중률)를 증명으로 쓴다.

## 10. TrendSpider

**참고한 장점**
- 자동 기술 분석 — 지지/저항·추세선을 시스템이 계산해 사람의 자의성을 줄인다.
- 다중 기간 합의(여러 시간축 신호의 일치 여부) 개념.
- 전략 백테스트 성능을 전략별로 노출.

**사용하지 않을 단점**
- 실시간 알림·자동매매 연동 — 범위 밖.
- 기능 나열형 마케팅 UI.

**적용할 화면**: 종목 분석(퀀트 점수·백테스트 탭), 모델 성과, 시장 스캐너.

**적용 방식**
- 자동 계산된 지지/저항(TDST·구조 저항)을 차트에 기본 오버레이 — 이미 엔진이
  손절가·목표가 산식에 사용 중인 값을 시각화만 추가.
- 게이트 체크리스트 컴포넌트: SYSTEM_MAP §5의 16개 게이트를 통과/발동/해당없음으로
  일람 — TrendSpider의 "조건 충족" 패턴을 우리 게이트 체계로 번역.
- 전략별 성능: market_attention.py의 전략 선택과 sq_cap(전략 품질 상한)의 근거인
  표본외 검증 등급을 모델 성과 화면에 전략 축으로 노출.

**차별화 요소**: TrendSpider는 신호 발견까지다. 우리는 발견(스캐너) 뒤에
**거부권(veto)과 상한 게이트가 결론을 깎는 과정**을 그대로 보여준다 —
"신호가 있어도 사면 안 되는 이유"가 우리 고유 화면이다.

벤치마크는 각 층의 표현 기법으로만 소비된다.
