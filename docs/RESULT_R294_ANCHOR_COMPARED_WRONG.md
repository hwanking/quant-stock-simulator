# 결과 R294 — 예산은 통했다. 그리고 판정일을 옳게 구해 놓고 **견주는 쪽**이 틀렸다 (2026-09-15)

## 1. 먼저 좋은 소식 — 네 번 죽던 자리를 지났다

2026-09-15 클라우드 실행(예약 · 크론 지연 **412분** · 생성 09-14T14:52Z)은 라운드
280·283·281 의 **첫 시험**이었다. 결과:

| 단계 | |
|---|---|
| 9 전방 판정 기록 (오늘 판정을 박제) | success — R253 의 '기록기를 맨 앞으로' |
| 11 케이스 축적 | success (종전엔 120분 시간초과) |
| 12 전방 구간 집중 축적 | success (종전엔 여기서 한도를 먹었다) |
| 13 경로·기준선 보강 | success — **R280 이 90분 예산을 준 그 단계** |
| 20 개인 자료 확인 (§9 · 올라가는 zip 을 연다) | success — R281 |
| **22 새 스냅샷 올리기** | **success** |

**업로드가 지나갔다.** 라운드 71c·247·253·280 에서 **네 번** *"쌓기는 쌓았는데 저장이 안
됐다"* 가 났던 자리다. R280 의 예산(90분 + job 350분)이 통했다.

## 2. 그런데 꼬리에서 둘이 나왔다

### ⓐ 실행 기록 검사가 **거짓으로** 실패했다

로그 두 줄을 나란히 놓으면 보인다:

```
판정일 2026-09-14 · 마지막으로 장이 끝난 거래일 (이 검사가 도는 지금은 2026-09-15 이다 — 넘겼다)
  DAILY-26016d07c516  시작 2026-09-14T20:20:13+00:00  끝 2026-09-14T20:24:48+00:00  success
>> 실패 — 판정일(2026-09-14) 에 시작한 실행 기록이 없다. 파이프라인이 시작조차 못 했다
```

**파이프라인은 돌았고 `success` 로 끝났다.** 시작 시각 `20:20 UTC` 는 한국 시간으로
**09-15 05:20** 이고, 검사는 *"기록의 지역 **날짜**가 판정일과 같은가"* 를 물었다.
날짜가 안 맞으니 *"시작조차 못 했다"* 가 나왔다.

**라운드 283 이 고친 것은 판정일을 구하는 쪽**이고(그건 옳게 돌았다 — 09-14 로 유도했다),
**견주는 쪽은 그대로 '날짜 같기'** 였다. 지연이 커져 작업이 자정을 넘기는 것이 이제
예외가 아니라 기본인데, 그러면 판정일 D 의 일이 **D+1 새벽**에 기록된다.

→ 판정일 D 의 일은 **D 의 장이 끝난 뒤** 벌어진다. 그러니 견줄 것은 날짜가 아니라
**창**이다 — `session_end(D)` **이후에 시작한 실행**. 마감 시각은 여기서도 다시 적지 않고
이미 채택된 상수를 부른다(§2-6). **두 시대가 둘 다 이 창에 든다**(자정 전에 끝나던 옛
실행도, 넘기는 지금도).

심어서 양방향으로 확인했다 — 클라우드가 실제로 낸 그 값을 그대로 되돌렸다:

| 심은 값 | 기대 | 실제 |
|---|---|---|
| **실측** `2026-09-14T20:20:13+00:00` (09-15 05:20 KST) | 잡는다 | 잡는다 |
| 옛 시대 — 같은 날 22:00 KST | 잡는다 | 잡는다 |
| 마감 직후 15:31 KST | 잡는다 | 잡는다 |
| 마감 **전** 09:00 KST | 안 잡는다 | 안 잡는다 |
| 전날 저녁 | 안 잡는다 | 안 잡는다 |
| 망가진 값 | 안 잡는다 | 안 잡는다 |

### ⓑ 그 거짓 실패가 **다음 가드를 통째로 숨겼다**

27단계 *"전방 기록부에 오늘 행이 있는지 검사 (거래일 0 = 실패)"* 가 **skipped** 로 남았다.
26이 실패했기 때문이다.

이 워크플로는 꼬리 검사를 업로드 **뒤**에 둔 이유를 스스로 적어 두었다 — *"축적이 인질로
잡지 않게 한다(R247)."* 그런데 **검사끼리 서로를 인질로 잡고 있었다.** 27번은 라운드 272 가
*"25단계 성공에 쌓인 것이 0 이었다"* 를 겪고 만든 가드다 — **가장 필요한 날에 안 도는**
구조였던 것이다.

→ 꼬리 검사 셋에 `if: always()` 를 달아 **따로 답하게** 했다. 실패하면 여전히 job 이
실패한다. **순서는 안 건드렸다** — R247 이 바로 여기서 2시간 16분을 잃었다.

## 3. 검사 — §307 (6건)

- 판정일의 장 마감 시각을 유도한다 · 못 구하면 None(§3)
- **심기 양방향** — 자정을 넘긴 시작을 잡고, 마감 전·전날은 여전히 안 잡는다
- 실행 기록 검사가 '날짜 같기'가 아니라 **'마감 뒤 창'** 으로 견준다
- 꼬리 검사 셋이 **따로 답한다**
- 순서는 그대로 — 꼬리 검사는 여전히 업로드 뒤다

## 4. 규칙으로 남기는 것

- **판정일을 옳게 구하는 것과 옳게 견주는 것은 다른 일이다.** 라운드 283 이 앞엣것을
  고쳤고 뒤엣것은 그대로 남아 있었다. 고친 쪽만 보고 "그 문제는 끝났다"고 적지 않는다.
- **검사끼리 서로를 인질로 잡지 않게 한다.** 축적을 인질로 안 잡게 꼬리로 보냈으면,
  그 꼬리 안에서도 같은 규칙이 필요하다 — 아니면 가장 필요한 날에 가드가 안 돈다.
- **거짓 실패는 실패보다 나쁠 수 있다.** 이번엔 거짓 실패 하나가 진짜 가드 하나를
  통째로 가렸다.
