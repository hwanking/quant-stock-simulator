# 축적보다 먼저 죽는다 — 라운드 87 (환경 점검 관문)

**신호를 찍는 것과 읽는 것은 다른 일이다.** 이틀 사이 조용한 실패를 두 번
잡았는데, 둘 다 증분 `+0` 이 로그에 찍히고 있었고 아무도 안 읽었다.

| | 라운드 81 | 라운드 86 |
|---|---|---|
| 증상 | 원장이 182,359 에서 정지 | 전방 기록이 171 에서 정지 |
| 원인 | 복원이 어제 스냅샷을 집음 | 러너 시계가 UTC (엔진은 KST 가정) |
| 전 단계 | `success` | `success` |
| 스냅샷 가드 | 통과 | 통과 |
| 찍힌 신호 | `+0` | `+0` |

그래서 사람이 안 읽어도 걸리게, **축적 앞에서 죽는 관문**을 만들었다.

```bash
C:/Python314/python.exe scripts/env_check.py
```

---

## 1. 왜 '앞'인가

환경이 틀렸으면 100분을 태우고 나서 0건을 쌓는다. 앞에서 멈추면 **아직
아무것도 안 쌓았으므로 잃는 것이 없고**, 로그 맨 위에 원인이 남는다.

`|| true` 를 붙이지 않는다 — 아무도 안 읽는 경고는 검사가 아니다.
(라운드 71 이 계보 감사에 쓴 것과 같은 원칙.)

## 2. 무엇을 보나 — 엔진이 **조용히 기대는** 것들

| 항목 | 왜 |
|---|---|
| 시계가 KST(UTC+9)인가 | `resolve_analysis_date` 는 `now()` 가 KST 라고 가정한다 (라운드 86) |
| 기준일이 최근 거래일과 맞는가 | 뒤처지면 어제 것을 다시 찍고 중복 방지에 걸린다 |
| 휴장일 표가 **필요한 해**를 덮는가 | 없는 해는 공휴일을 거래일로 센다 |
| 다가오는 해 (참고·막지 않음) | 미리 알리되 막지는 않는다 |
| 표준출력이 UTF-8 인가 | 한글 로그가 깨지면 사고를 못 읽는다 |

## 3. 첫 실행이 바로 두 개를 잡았다

### ① 검사 쪽이 틀렸다 — 자정 오탐

00:02 에 "기준일이 뒤처졌다"고 실패했다. 그런데 장 시작 전이면 직전
거래일이 **정상**이다(명세 §3). 처음에 장중(09:00~15:30)만 예외로 뒀다가
개장 전을 빠뜨렸다. **15:30 이전 전체**로 고쳤다.

> 검사가 규칙보다 세면 정상 상태에서 깨진다 — 라운드 81 에서 겪은 것과
> 같은 종류다. 그때는 "두 손절이 달라야 한다"였다.

### ② 2027년 휴장일 표가 없다 — 진짜다

```
등록 2025~2026 · 2027 미등록
```

`KrxCalendar.is_trading_day` 는 표에 없는 날을 **전부 거래일**로 본다.
2027-01-01 이 오면 신정을 거래일로 세고, 기준일·전방 기록·날짜 계산이
조용히 어긋난다.

**지어내서 채우지 않았다.** 2027 KRX 공고를 아직 확인할 수 없고,
`bitemporal_engine.py` 는 §1 보호 대상이다. 대신:

- 실패 조건은 **실제로 필요한 해**로 좁혔다 — 오늘 연도 + 전방 재평가일
  연도(2026). 지금은 둘 다 2026 이라 통과한다
- 다가오는 해 미등록은 **막지 않고 알린다**

> 아직 해롭지 않은 조건으로 파이프라인을 막으면 그건 신호가 아니라
> 소음이다. 매일 실패하는 검사는 곧 무시된다.

## 4. 남는 일 — 2027 휴장일 (기한 있음)

**2027-01-01 전에** KRX 공고로 `KRX_HOLIDAYS` 에 2027 을 채워야 한다.
그 전까지 이 점검이 매 실행 로그에 알린다. 전방 재평가(2026-11-16)는
2026 이라 영향이 없다.

## 5. 정직하게 남기는 것

- 이 라운드는 **아무 규칙도 바꾸지 않았다.** 관문과 문서, 회귀뿐이다
- 점검이 통과한다고 축적이 잘 된다는 뜻은 아니다. **환경 가정만** 본다
- 라운드 81 이 만든 증분 표시는 그대로 둔다 — 그것도 필요하다.
  이 관문은 그 신호를 **읽지 않아도** 걸리게 하는 층이다
