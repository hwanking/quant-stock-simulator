# 라운드 404 — 교정본 그림자 기록을 시작했다 (운영 불변)

> 2026-10-01 · 사용자 결정: *"교정본 그림자 기록으로 해줘."* · 사전등록 `docs/PREREG_R404_SHADOW_CORRECTIONS.md`
> (측정 전 커밋 `01f3eb6`) · model v2026.10.01.2(`ui` · 값·판정 불변) · 회귀 §393(10건)

## 무엇을 만들었나

외부 검토(라운드 401)의 산식 고침 다섯을 **운영에 안 넣고** 따로 만든 엔진 인스턴스에만 켜서, 매일 밤 전방 판정
기록기가 본 상위 60종목의 **운영 판과 교정 판**을 같은 기준일로 옆 파일에 적는다.

| 자리 | 무엇 |
|---|---|
| `QuantIndicatorsEngine.corrections` | 스위치(기본 **빈 집합**) — B1 윈저화 자르기 · B2 확률 점수 0~100 · B4 PBR 가지 · B5 검증 칸 |
| `verdict_core.build(corrections=())` | B3 — 같은 계획(눌림 진입가 · 20봉)의 실측 확률로 기대값 |
| `forward_shadow.py` | 규약 `sh-1` · 한 판의 칸(`side`) · 한 줄(`make_row` · `diff`) · 멱등 쓰기(`fin_pit` 의 함수 그대로) |
| `scripts/forward_recorder.py` | 운영 기록(판정 원장 · 전방 기록부 · 재무·호가 보관)을 **다 쓴 뒤** 교정 인스턴스로 같은 종목을 다시 판정 |
| 업로드 화이트리스트 · 축소 감시 | `forward_shadow.jsonl` — 그날 것만 만들 수 있다(잃으면 영영이다) |

## 오염을 막은 것

- 운영 엔진은 스위치가 꺼진 채다 — 클래스 기본이 빈 집합이고, 켜는 자리는 기록기의 교정 인스턴스 **하나**다(회귀가 AST 로 잠근다).
- 엔진은 스위치를 `'Bn' in self.corrections` 모양으로만 읽는다(다른 읽기가 생기면 회귀가 실패한다).
- 기록기에서 그림자는 운영 기록이 **끝난 뒤** 돈다 — 그림자가 무엇을 하든 그날의 운영 기록을 못 바꾼다. 실패해도 따로 세어 찍고 판정 기록과 무관하다.
- 전방 기록부 규약(`forward_registry.py`)·동결 파일(`forward_eval.py` 등)·화면·추천은 **그대로**다.
- 판정 기준은 첫 행 전에 커밋했다.

## 스위치마다 심어서 쟀다 (합성 입력 · 꺼짐/켜짐 양방향)

| 스위치 | 꺼짐 | 켜짐 |
|---|---|---|
| B4 (ROE 5%) | PBR 가지 모형 유효 | 무효 |
| B5 | 신뢰도 68.34 | 71.49 = (68.34 − 0.10×40) ÷ 0.90 |
| B1 (원 괴리율 +44 · +46% — 가격은 엔진 자신의 중앙값에서 유도) | +46% 가 +44% 보다 **낮게**(역전) | 순서를 지킨다 |
| B3 (진입 9,800 · 목표 10,300 · 손절 9,500 · 점수대 60%) | 1.43% | 0.90% = 0.783 × (0.542×5.10 + 0.393×(−3.06) − 0.41) |

B2 는 점수 산출 한가운데라 합성 입력을 만들지 않았다 — 읽는 자리가 `'B2' in self.corrections` 하나인지(구조)만 잠갔다.

## 연기 시험 (임시 파일 · `.portfolio` 안 건드림 · 사전등록 커밋 뒤)

시총 상위 5종목 · 기준일 2026-09-30: 교정 판 22초(종목당 약 4초 → 60종목 약 4~5분) · 다시 쓰기 0(멱등).
판정(`bucket`·`recommended`·`action`)은 **5종목 모두 같았고**, 값은 이렇게 갈렸다 — 기대값 5/5(B3 · 예 −0.30 → −0.39) ·
적정가 신뢰도 3/5(B5) · 한 종목은 B1 이 바로 걸렸다(괴리율 +45.46% → +48.0% · 적정가 약 1.7% 위로).
⚠️ 5종목은 표본이 아니다 — 판정 R0 은 사전등록대로 11-16 에 기록된 전체로 잰다.
