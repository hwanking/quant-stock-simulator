# 연구 후보 등록 — 이벤트 엔진 5종 (운영 반영 없음)

**등록일 2026-08-17.** 이 문서는 **후보 등록**이다. 사전등록이 아니다.
판정 기준은 각 후보를 실제로 재기 **전에** 별도 사전등록 문서로 쓴다 (§2).

출처: 사용자가 정리해 준 영상 아이디어 + 인용 문헌.
**영상의 숫자·전망은 근거로 쓰지 않는다.** 여기서 가져오는 것은
"어떤 이벤트를 변수로 만들 것인가"라는 **후보 목록**뿐이다.

## 0. 먼저 — 원장에 무엇이 있는지 (2026-08-17 실측)

원장 한 행의 필드 전부:

```
ticker · date · cohort · asset_type · market · regime · price · score
action_title · target · stop · horizon_days · m10_above · demark_state
entry_zone · net_expected · rsi · bb_pos · vol20 · range_pos
demark_bull · demark_bear · win_rate · eff_sample · outcome · touched_bar
return_pct · close_return_pct · mfe_pct · mae_pct · success · split
failure_class
```

**없는 것**: 공시(자사주·배당·계약) · 재무(ROE·FCF·PER·PBR·순현금) ·
수급(외국인 순매수·보유비율·공매도 잔고·대차) · 뉴스 이벤트 타입.

그래서 *"기존 원장에서 동일 train/valid/OOS 규율로 재현한다"* 는
**5개 중 1개에만 적용된다.** 나머지는 데이터가 애초에 수집된 적이 없다.
없는 것을 있는 것처럼 계획하면 그 계획은 실행되지 않는다 (§3).

원장 규모도 잰 날짜와 함께 적는다 — **2026-08-17 기준 184,759건**
(매수권 58점+ 는 82,259건). 제안서의 183,959 는 다른 날짜의 값이다.

**주의 — R55 와 같은 자리를 겨눈다.** R55(국면 라우팅)가 전방 재평가
중이므로, 이 후보가 채택되어도 **2026-11-16 이전에 게이트에 넣지

영원히 못 가른다.

## 3. 후보 1·2·3·5 — 먼저 '수집'만 시작한다

측정하지 않는다. **태깅과 결과 축적만** 한다.

### 3.1 뉴스 이벤트 타입 추가 (표시·연구 전용)

현재 뉴스 엔진은 키워드 위주다. 아래를 **이벤트 타입**으로 분리한다.
`news_memory` 가 이미 "점수·게이트·문턱에 쓰지 않는다 (11/16 동결)"로
표시 전용이므로, 타입을 늘려도 운영 판단은 바뀌지 않는다.

```
SPECIAL_DIVIDEND · DIVIDEND_INCREASE · BUYBACK · SHARE_CANCELLATION
FCF_RETURN_POLICY · LONG_TERM_CONTRACT · GUIDANCE_RAISE
MARGIN_EXPANSION · CAPEX_DISCIPLINE · INVESTOR_DAY
FOREIGN_FLOW_REVERSAL · INDUSTRY_DEMAND_SHIFT
```

**한계를 먼저 적는다.** 지금 뉴스는 제목·시각·링크만 저장하고 본문을
저장하지 않는다(§9 · 라운드 41). 제목만으로 태깅하면 재현율이 낮다.
그 낮음을 **측정해서 적는다** — 태깅 정확도를 모른 채 이벤트 통계를
내면 그 통계는 태깅 오류의 통계다.

### 3.2 이벤트마다 저장할 결과

발표일 기준 1/3/5/10/20일 초과수익 · MFE · MAE · 거래량 반응 ·
업종조정 수익 · 시장조정 수익 · 발표 전 20일 수익률 · 당일 갭 ·
그 시점 PER/PBR(수집되면) · **이미 반영됐는가**.

**⚠ mfe/mae 는 원장의 것을 쓰지 않는다.** 원장의 mfe/mae 는 **청산 봉
까지만** 잰 값이라 목표를 넓히는 연구가 원리적으로 불가능하다
(이 저장소가 이미 겪은 함정). 이벤트 창은 **별도로** 잰다.

### 3.3 수집 시작 조건

- DART: 공시 API 연동이 선행 조건. 연동 전에는 후보 1·2 를 열지 않는다.
- KRX 투자자별·공매도: 같은 이유로 후보 3 을 열지 않는다.
- 재무 시계열: 분기 재무를 **시점 보관**하기 시작해야 후보 5 가 열린다.
  현재 엔진은 '지금 값'만 읽으므로 과거 시점 복원이 불가능하다.

## 4. Event Confluence — 겹침 연구는 마지막이다

여러 이벤트가 동시에 날 때 반응이 더 큰가 — 좋은 질문이지만
**개별 이벤트가 각각 측정된 뒤에만** 의미가 있다.
개별이 전부 귀무인데 겹침만 유의하면 그것은 다중검정의 산물일
가능성이 높다. R111 이 같은 말을 했다 — *재료에 없는 정보를 합산이
만들지 못한다.*

겹침을 열 때는 조합 수만큼 다중검정 보정을 올린다. 3종 이벤트의
2·3중 조합은 4가지이고, 개별 12종까지 합치면 보정 문턱이 크게 오른다.
**그 비용을 미리 적어 두고 시작한다.**

## 5. 이 등록이 약속하지 않는 것

- 어떤 후보도 **운영 점수에 들어가지 않는다.**
- R55·R57·R66 전방 동결(2026-08-09~2026-11-16)을 건드리지 않는다.
- 블라인드·전방 표본을 모델 선택에 재사용하지 않는다.
- 후보가 채택되어도 화면에는 **표시 전용**으로만 나간다.
- 그리고 이 목록 중 **넷은 오늘 잴 수 없다.** 잴 수 없는 것을
  "연구 중"이라고 적지 않는다 — 수집 중이라고 적는다.
