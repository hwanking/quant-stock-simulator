# 계획 R326 — 포트폴리오 금액을 보고 보유·축소를 권하는 규칙 (초안 · 사람 승인 전 · 2026-09-16)

사용자: *"포트폴리오를 보고 또 보유할지 말지 줄일지도, 추후에 전체적인 금액을 보고도 판단해서 추천해 주는
시스템하면 좋을 듯해."*

> ⚠️ 이 문서는 **사전등록이 아니라 계획**이다. 문턱·판정 기준을 아직 적지 않았다 — 적는 순간 그것이 사전등록이고
> 그 전에 표본이 있는지부터 센다(R192 · §2-7).

## 1. 지금 한 것 (1단계 · 표시 전용)

관심종목 '내 포트폴리오 견해'에 **금액으로 본 보유** 표를 넣었다 — 종목마다 *지금 할 일*(표의 판단 그대로) ·
비중(평가금액) · 평가금액 · 평가손익 · 수익률 · 전체 손익 중 몫. 차례는 *손댈 수 있는 순 → 같은 자리 안에서는
금액 큰 순*. **추천은 하지 않는다** — 문장이 그렇게 말한다.

## 2. 왜 추천을 바로 못 만드나

| 막는 것 | 설명 |
|---|---|
| 문턱을 손으로 고르면 §2 | "한 종목이 20% 넘으면 줄인다"의 20 은 근거가 없다 |
| 원장이 **종목 단위** | 원장 251,528행은 종목 하나의 20봉 결과다 — *포트폴리오*(여러 종목 묶음)의 성적은 한 행도 없다 |
| 사용자의 실제 거래 이력이 없다 | 보유는 매입가·수량 한 점뿐이라 "줄였으면 어땠나"를 사용자 자료로 못 잰다(R292) |
| 엔진에 순위 정보가 없다 | 같은 날 종목을 점수로 세우는 데 정보가 없었다(R49·R110·R112·R113) — "무엇을 줄이나"의 순서를 점수로 못 정한다 |

## 3. 열 수 있는 길 (비용 순 · §2-7)

1. **R0 이득 상한 (싸다 · 분 단위)** — 원장에서 같은 날 매수권 케이스들로 가상 묶음을 만들고, *비중이 한 종목에
   쏠린 묶음*과 *고르게 나눈 묶음*의 20봉 결과 분산·최대 손실을 비교한다. 차이가 작으면 여기서 접는다.
2. **R1 규칙 후보 (재료 있음)** — 이미 채택된 것만 재사용한다: 보유자 kind('정리 검토'·'일부 정리') ·
   업종 HHI · 위험예산 블록의 종목 상관·분산효과(R278). 새 문턱은 **분위수**(자료가 정하는 값)로만.
3. **R2 세 구간** — train/valid/blind + 날짜 하한 30(R45·R84) · 기준 미달이면 기각하고 표시 전용 유지.

## 4. 하지 않는 것

- 외부 LLM·API 에 보유 금액·평단을 보내지 않는다(§9).
- 결과를 보고 문턱을 고르지 않는다.
- 11-16 전방 재평가 전에 판정 경로에 넣지 않는다.
