# 라운드 202 — 봉은 바뀌는데 화면은 2016년을 보고 있었다

측정: 2026-09-01~02 · 브라우저 실측 (`getVisibleRange` · `getVisibleLogicalRange`)

라운드 201 이 차트 스크립트를 되살렸다(TDZ). 그래서 버튼이 **눌리기
시작했다.** 눌러 보니 **두 가지가 더 틀려 있었다.** 둘 다 §229(스크립트가
끝까지 도는가)로는 안 잡힌다 — 스크립트는 멀쩡히 끝까지 돈다.

## ⓐ 숨긴 지표가 시간축을 지배했다

주봉으로 바꾸면 캔들은 638개로 줄어드는데, 화면은 **2016년 10월~2017년
1월**을 보여 줬다. 가격축도 30,000~39,000원 — 2016년 시세다.

칸별로 재 보니 갈렸다:

| 칸 | 보이는 기간 |
|---|---|
| 거래량 | 2025-09 → 2026-08 **✓** |
| 메인 · RSI · MACD · 스토캐스틱 · OBV | **2016-10 → 2017-01 ✗** |

**가시 범위는 논리 인덱스로 칸끼리 공유되는데, 각 칸의 시간축은 그 칸에
담긴 series 전체가 만든다.** 나는 지표를 **숨기기만** 했다:

```js
inp.checked = false; inp.dispatchEvent(new Event('change'));
// → setSeriesVisible(...)  = applyOptions({ visible: false })
```

숨은 series 도 **일봉 2,997개의 시각**을 그대로 쥐고 있다. 그러니 메인
칸의 시간축은 여전히 일봉 2,997칸이고, 논리 인덱스 586 은 2016년을
가리킨다. 거래량만 맞았던 이유는 **거기만 내가 집계 데이터로 갈아
줬기** 때문이다.

**고침**: 만들 때 원본을 적어 두고(`SNAP`), 일봉이 아니면 **데이터를
비운다**. 되돌아오면 채운다. 숨기는 것과 비우는 것은 다르다.

## ⓑ 리사이즈가 내가 넣은 범위를 다음 프레임에 덮어썼다

ⓐ 를 고치니 2016년은 사라졌는데, 이번엔 **주봉 '1년' 이 5년치**를
보여 줬다(월봉은 12년 전부). 논리 폭이 **255** — 일봉 환산(12×21)이다.

그런데 손으로 `setRange(12)` 를 부르면 **55** 가 나왔다(12×4.3, 맞는 값).
같은 함수인데 결과가 다르다는 것은 **호출 시점**의 문제다.

`setTf` 안에서 지표를 끄면 패널이 접히고 `relayout()` 이 resize 를 쏜다.
라이브러리는 그 리사이즈를 **다음 프레임에** 처리하면서 방금 넣은 가시
범위를 덮어쓴다. 내 `setRange` 는 그 전에 이미 끝나 있었다.

**고침**: 같은 값을 **지금과 다음 프레임에** 둘 다 넣는다.

```js
setRange(_m);
if (typeof requestAnimationFrame === 'function') {
  requestAnimationFrame(() => setRange(_m));
}
```

## 값으로 확인

| 봉 | 봉 수 | 보이는 기간 | 가시 봉 |
|---|---:|---|---:|
| 일봉 | 2,997 | 2025-08-19 → 2026-09-01 | 255 (≈12×21) |
| 주봉 | 638 | 2025-09-01 → 2026-08-31 | **55** (≈12×4.3) |
| 월봉 | 148 | 2025-09-01 → 2026-09-01 | **15** (≈12×1) |

세 봉이 **같은 1년**을 가리키고, 일봉으로 되돌리면 원래대로 온다.

## 이 라운드가 말해 주는 것

라운드 201 은 *"스크립트가 끝까지 도는가"* 를 검사로 만들었다. 그것은
필요하지만 **충분하지 않다** — 여기 둘은 스크립트가 멀쩡히 끝까지 도는
상태에서 일어났다.

| 무엇을 보는가 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| 소스에 글자가 있는가 (§227) | 오타·누락 | 실행 실패 · 잘못된 상태 |
| 스크립트가 끝까지 도는가 (§229) | TDZ · 문법 · ReferenceError | **틀린 결과** |
| **결과 상태를 값으로 재기** | 위 전부 | — |

그래서 이번 확인은 화면 글자가 아니라 **`getVisibleRange()` 의 값**으로
했다. 브라우저 없이 회귀에서 같은 것을 재려면 렌더 엔진이 필요한데,
node 스텁으로는 시간축 계산까지는 흉내 낼 수 없다 — **그 한계를 적어
둔다.** §229 는 *"끝까지 도는가"* 까지만 보장한다.

다만 ⓐ 는 **구조로** 막을 수 있다: 봉을 바꿀 때 `SNAP` 에 적힌 series 를
빠짐없이 다루는지 검사한다(숨기는 것으로 끝내지 않는지).
