# 결과 R303 — 캐시가 **성공만 기억했다** · 같은 종목을 243번 다시 물었다 (2026-09-15)

라운드 302 가 *"왜 원장이 안 자라나"* 를 다음 라운드로 남겼다. 클라우드 단계 로그를
열었다(R272 가 같은 방식으로 답한 길).

## 1. 답은 두 줄에 있었다

```
가상 판정 계획: 완료 251,528건 · 남음 0건 (계획 251,528건)
  같은 종목 35일(25봉) 안에 이미 케이스가 있어 계획에서 뺀 기준일 52,022건 (R217)
채점 대상 가상 판정: 251,528건 (파일 7개 합산)
```

그리고 축적 요약:

```
virtual_graded.jsonl        251,528 →   251,528 (+0)
virtual_predictions*.jsonl  251,528 →   251,928 (+400)
```

읽으면 이렇다. **새로 만들 케이스는 없다**(계획 남음 0 — R217 의 겹침 차단이 52,022
기준일을 빼고 나머지는 이미 완료). **원시 예측은 +400 늘었지만** 결과 창 20봉이 안
닫혀 아직 채점 대상이 아니다. 그런데 **채점은 251,528건 전부를 다시 돌린다** — 그리고
그 단계가 **120분 예산을 다 쓰고 시간초과**했다(같은 실행에서 집중 축적 100분·경로
보강 90분도 시간초과).

## 2. 왜 그렇게 오래 걸리나 — **세어 봤다**

로그에서 실패 요청을 종목별로 세니(로그가 잘려 있어 **하한**):

| 종목 | 실패 요청 | *"영구 실패"* 로 찍힌 횟수 |
|---|---:|---:|
| (상장폐지 A) | **243회** | 1 |
| (상장폐지 B) | 93 | 1 |
| … 합계 **8종목** | **627회** | 각 1 |

**그 종목들은 이미 한 번 영구 실패라고 찍혀 있었다** — *"[건너뜀] … 네이버에 종목
페이지가 없습니다 — 상장폐지·합병이면 이 코드로는 다시 받을 수 없습니다."*
라운드 165·270 이 사유를 갈라 둔 덕에 로그가 그렇게 말하고 있었다. **기억만 안 했다.**

원인은 한 줄이다:

```python
pdf = price_cache.get(r['ticker'])      # ← 성공만 들어 있다
if pdf is None:
    try: ...                            # 실패하면 drop_tickers 에만 넣고 continue
    except Exception:
        drop_tickers.add(r['ticker']); continue
```

`price_cache` 는 **성공만** 기억한다. 실패한 종목의 **다음 행**에서 `cache.get` 은
여전히 `None` 이므로 **또 받아온다.** 원장에 81행 있는 종목이면 81번 × 엔드포인트
3개 ≈ 243 — 로그의 수와 맞는다.

## 3. 고침 — **실패도 기억한다**

가져오는 자리를 함수 하나로 빼고(`price_for_grading`) 그 안에서 **실패한 종목은 다시
묻지 않는다.** 동작은 그대로다 — 실패 종목은 어차피 채점에서 빠지고 종전 채점을
`carried_over` 로 이어받는다(R197). **값·판정·원장 내용 불변, 요청만 안 한다.**

회귀 §315 가 **심어서** 잰다(글자만 보지 않는다 · R195): 늘 실패하는 엔진을 주고
같은 종목을 50행 돌려 **호출이 1회**인지, 그때 전부 `None`(지어낸 일봉 없음)인지,
그리고 **성공 경로가 안 깨졌는지**(20행에 호출 1회)를 값으로 본다.

## 4. 이것이 원장을 다시 자라게 하나 — **모른다고 적는다**

627회를 없애면 그만큼 시간이 돌아온다. 그러나 **그것이 120분 안에 채점을 끝내기에
충분한지는 이 라운드가 모른다** — 잘린 로그로는 전체 소요를 못 나눈다. 그리고
**계획은 여전히 남음 0** 이므로, 시간이 남아도 새 케이스는 **20봉이 닫히기 전까지**
안 생긴다(원장의 마지막 기준일이 오늘보다 6주 뒤처지는 구조 · R302).

→ **다음 실행이 증명한다.** 증분 요약이 그날 `+0` 이 아닌지, 시간초과가 사라지는지를
보고 적는다(R259 가 *"클라우드에서 실제로 만들어지는지는 다음 실행이 증명한다"* 라
적은 그 자리).

## 5. 규칙으로 남기는 것

- **캐시는 실패도 기억해야 캐시다.** 성공만 넣으면 실패한 입력이 가장 비싼 입력이 된다.
- **로그가 이미 사유를 말하고 있어도, 읽고 기억하지 않으면 없는 것과 같다**(R165 가
  사유를 갈라 둔 덕에 이번엔 한 번에 보였다).
- **"왜 안 자라나"는 로그를 열면 두 줄이다.** 추측하기 전에 그날 단계 로그를 연다
  (R272·R263 이 같은 자리에서 배운 것).
