# 라운드 463 — 자동매매 사건을 이 PC 의 Windows 알림으로 (밖으로 보내지 않는다)

2026-10-09 · 판정·점수·문턱·주문 규칙 **불변** · 버전 없음 · 새 모듈 하나(`swing_notify`) · 워커 두 자리 · 화면 한 줄과 설정 칸.

## 무엇이 비어 있었나

경쟁사 레이더의 '알림·외부 전달' 축에 *"체결·오류 사건을 밖으로 보내는 길이 없다"* 가 '검토'로 서 있었다. 실전 자동매매에서
체결·거절·응답 없음·손절 매도를 사람이 모르는 것은 실제 빈칸이다. 그런데 메일·메신저·웹훅으로 보내면 계좌 자료(종목·수량·가격)가
밖으로 나간다 — §9 가 막는 자리다. 그래서 **이 PC 안**에서 끝내는 길만 만들었다.

## 무엇을 알리나 — 장부 한 곳을 읽는다

알림은 실행부가 아니라 **장부의 새 사건**을 읽는다(§4 · 화면과 같은 한 곳). 체결은 실행부 출력에 없고 주문 내역 맞추기가 장부에 남기기
때문이다.

| 사건 | 알림 |
|---|---|
| 체결 · 일부 체결 | 종목·사유·수량·평균 체결가 |
| 거절 | 사유(80자에서 '…') |
| 응답 없음(UNKNOWN) | *다시 보내지 않고 체결 내역으로 맞춥니다* |
| 매수 주문 접수 · 보호 매도(손절·기간 만료) 접수 | 수량 · 지정가/시장가 |
| 매수 주문 만료 | 그날 체결 없음 |
| 관리 끝 | 사유 |
| 1차 목표 지정가 매도의 **접수·만료** | **안 알린다** — 날마다 다시 걸리고 이튿날 만료되므로 소음이다(체결·거절은 알린다) |
| 취소 · 관리 시작 | 안 알린다(체결 알림과 겹친다) |
| 실행부의 경고 · 워커 바퀴 실패 | *경고 — …* |

같은 날 같은 문장은 한 번만 뜬다. 한 바퀴의 사건이 여럿이면 알림 하나로 묶고 앞의 세 줄 + *"외 N건"* 을 적는다(말없이 자르지 않는다).

## 안전장치

- **기본 꺼짐** — 장부 설정 `notify`. 시스템 갈래 → 설정 → '이 PC 알림 켜기'. 이 PC 에서는 켜지 않았다(사용자가 정한다).
- 꺼져 있는 동안에도 읽은 자리(커서)는 앞으로 간다 — 켠 순간 옛 사건이 쏟아지지 않는다. 상태 파일이 없을 때 켜져 있어도 같다.
- 알림이 실패해도 바퀴는 그대로다(워커가 예외를 삼키고 사유를 노트에 적는다) · 실패한 문장은 바퀴마다 다시 띄우지 않고 사유를 남긴다.
- 쓰기 금지(`GAEUM_NO_LOCAL_WRITE=1`)면 띄우지도 적지도 않는다.
- 알림 모듈은 **네트워크를 쓰지 않는다** — 가져오는 모듈에 urllib·requests·http·socket·smtplib·broker_kis 가 없다(회귀가 본다).
  알림은 PowerShell 의 WinRT 알림 API 로 이 PC 의 알림 센터에만 뜬다.
- 상태 파일 `.portfolio/swing_notify_state.json` 은 종목 이름이 든 개인 자료라 백업 거부 목록(`swing*`)에 걸린다.
- 회귀의 심은 실패(§445 ④ · §446 ⑦)는 실패 알림을 **바꿔 끼워** 사용자 화면에 뜨지 않는다.

## 확인

- 띄우지 않는 시험(알림 객체까지 · 특수문자 `< & "` 이스케이프 포함): 0.4초 · 통과.
- 이 PC 에 **실제 알림 한 번**('가늠 알림 시험')을 띄웠다 — 반환 정상. 화면에 뜬 모양은 내가 보지 못했다.
- 회귀 §446(11건): 사건 문장 · 묶기 · 꺼짐/켜짐/커서 · 같은 날 한 번/다음 날 다시 · 실패 사유 · 쓰기 금지 · 바퀴 실패 알림 · 화면 한 줄 ·
  네트워크 없음 · 워커 배선 · 백업 거부 · 알림 경로 · 시스템 갈래 자식 렌더(상태 줄 · 토글 · 시험 버튼).

## 남은 것

- 밖으로 보내는 알림(메일·메신저·웹훅)은 여전히 없다 — 보내려면 *종목·수량 없이 사건 종류만* 보내는 설계와 사용자의 결정이 먼저다.
- 레이더 상태는 '부분' 그대로다.
