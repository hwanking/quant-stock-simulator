# 라운드 410 — "다음 실행부터"는 실행만으로 화면에 닿지 않았다 · 0행으로 오는 원천

2026-10-01 · 코드: 연구 스크립트 하나 · 산출물: 되받기 + 동봉본 · 값·문턱·판정 불변 · 버전 없음

못 다한 일을 찾다가 둘이 나왔다.

## ① 라운드 395 의 약속이 화면에 안 닿아 있었다

라운드 395 는 추천 절의 *"점수 띠별 블라인드 적중"* 줄에 58~59점 띠를 넣으면서 *"랩에 `splits.ext_zone` 을 더했다 —
다음 클라우드 실행부터 파일에 있다"* 고 적었다. 클라우드는 실제로 그 칸을 만들었다(2026-09-30 실행). 그런데 화면이
읽는 `calibration.json` 은 **이 PC(`.portfolio/`)와 배포 동봉본(`data/`) 둘 다 그 전 판**이라 칸이 없었고, 화면은 규칙대로
*"못 읽는 띠는 그 조각만 뺀다"* 를 해 **조용히 60점+ 띠 하나만** 보여 주고 있었다(§3 을 지켰기 때문에 안 보였다).

**클라우드가 만든 것은 되받고 다시 눌러 담아야 배포 화면에 닿는다**(라운드 261 *만든 것은 실린 것이 아니다* · 라운드 360 의
되받기 묶음). 했다:
- 되받기(`pull_research_data --apply`) — 원장 255,930 → **256,330** · 전방 기록부 1,020 → 1,080 · 시점 재무·잔여 호가
  각 +60 · 예측 원장은 열쇠로 합쳐 이 PC 에만 있던 10행을 지켰다(라운드 392) · 줄어든 파일 0.
- 동봉본(`refresh_bundle --apply`) — 원장 **전량** 256,330행(gzip 32,784,878바이트) · 집계표 · `calibration.json`.
- 관측 산출물 일곱은 클라우드가 같은 원장(256,330)에서 만든 판을 받았다(신선도 규약 그대로).

실측(2026-10-01 · 블라인드): 58~59점 띠 적중 **58.0%** (n 5,828 · Wilson 하한 56.8 · 비용 차감 평균 −0.74%). 값은
라운드 395 가 오늘 원장에서 잰 것과 같은 방향이다(띠가 전체보다 더 잘 맞는다는 근거가 없다). §399 는 값을 잠그지 않고
**배포 동봉본에 화면이 읽는 칸이 있는가**와 동봉본이 전량인가만 본다.

## ② 상폐 목록이 예외 없이 0행으로 온다

라운드 409 가 업종표 원천(FDR `KRX-DESC`)이 404 라는 것을 찾았으니, 같은 라이브러리의 다른 원천을 전부 쟀다(2026-10-01):

| 원천 | 상태 |
|---|---|
| 미국 프록시 ETF 22개 · 원달러 · WTI · 구리 · 금 · VIX · 미10년 · S&P500 | **살아 있다**(마지막 09-30 · 10-01) |
| KS11 · KQ11 | 09-17 에서 멈춤 — 라운드 405 가 네이버로 이어 붙인다 |
| 한국 종목 일봉 | 살아 있다 |
| `KRX` 상장 목록 · `ETF/KR` | 살아 있다(2,873 · 1,171행) |
| `KRX-DESC`(업종) | **404** — 라운드 409 가 마지막 판으로 |
| `KRX-DELISTING`(상폐·사명 변경 이력) | **예외 없이 0행** |

마지막 줄이 가장 위험한 모양이다 — 404 는 예외를 내지만 0행은 **성공처럼** 온다. 이것을 쓰는
`scripts/disclosure_name_match.py`(라운드 146 · 공시 회사명 → 종목코드 이름 마스터)는 **예외만** 잡았다. 마스터 스냅샷이
없어 다시 만드는 날이면 상폐·사명 변경 이력이 조용히 빠진 마스터가 굳고, 옛 구간 매칭률이 소리 없이 내려간다.
지금은 08-21 스냅샷이 있어 닿지 않는다(이득 상한 0 · 그래서 지금 다시 만들지 않았다). 고침: 0행도 실패로 적고
(`delisting_note`) 스냅샷에 남기며, 마스터를 읽는 쪽이 그 사실을 찍는다. §399 가 가짜 원천(상폐 0행)을 심어 잰다.

**404 보다 0행이 위험하다 — 실패가 예외로 오지 않으면 세어서 실패로 만든다**(라운드 37 · 197 · 334 의 계열).
