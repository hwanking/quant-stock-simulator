# 라운드 524 — 첫 실주문 날 밤의 관제실: 두 날을 섞은 깔때기 · 장이 끝난 주문의 '지금' · 맨 뒤로 간 저녁 작업 (2026-10-13)

> 화면 전용(`swing_dash` · `swing_view`) · 실행부·판정·문턱·주문 규칙 불변 · 버전 없음(두 파일은 어느 축의 담당 파일도 아니다 · 라운드 510).

## 무엇을 봤나

2026-10-13 은 첫 실주문 날이다(관심종목 추천 한 종목 · 13,620원 지정가 · 그날 저가 14,000원이라 체결 0). 그날 밤 22:34 실제 장부로 관제실을
그렸더니 한 화면에 셋이 어긋나 있었다. 셋 다 회귀는 초록불이었다 — 실주문이 있는 장부로 저녁에 그린 적이 없었다.

1. **깔때기가 '실주문 자격 0 → 승인 0 → 주문 냄 1'.** 계획 칸은 판정일 10-13 의 계획(내일 10-14 에 살 것)이고, 주문 칸은 달력 '오늘'(10-13)
   낸 주문 — 즉 **앞 판정일 10-12 계획의 주문**이었다. 라운드 491 이 장중의 어긋남(판정일 = 전 거래일인데 주문을 판정일로 셌다)을 고치며
   주문을 거래일로 세게 했는데, 그날 봉이 확정돼 판정일이 오늘로 넘어간 저녁엔 반대 방향으로 어긋났다.
2. **시작 카드가 그날 체결 0 으로 끝난 주문을 '지금 증권사 접수'라 적었다.** 실행부는 마감 직후 늦게 알려지는 체결을 버리지 않으려고 그날
   주문을 그날엔 만료로 적지 않는다(`swing_executor.reconcile` · 지난 거래일 것만 만료) — 장부 상태는 맞고 **'지금'이 틀렸다.**
3. **최근 사건의 '저녁 작업 끝' 줄이 늘 맨 뒤.** 기록 줄은 `MM-DD HH:MM:SS`(연도 없음)인데 정렬 열쇠에 `2000-` 을 붙였다 — 21:05 끝 줄이
   01:04 계좌 동기화 아래에 섰다.

## 고친 것

- `swing_dash.exec_day_of(판정일)` 한 곳 — 그 판정의 계획이 처음 사는 거래일(판정일 **다음 거래일** · 실행부 `_entries` 의 waited ≥ 1 · 거래일은
  장부의 달력 한 곳). `next_judgement` 의 매수일도 이것을 부른다(같은 셈이 두 벌이던 자리).
- `swing_dash.funnel_intents` — 깔때기의 주문·체결 칸은 **판정일 계획의 매수일** 주문을 센다. 장중엔 매수일 = 오늘이라 라운드 491 과 같은
  날이고, 저녁엔 내일이라 0 이다. 오늘 낸 앞 판정의 매수 주문은 지우지 않고 따로 돌려줘 관제실이 한 줄로 가리킨다(*"오늘 낸 매수 주문 1건은
  앞 판정일 계획의 주문이라 위 깔때기에 넣지 않았습니다 … 시작 카드와 '주문·체결' 갈래에"*). 제목에 매수일 · '주문 냄' 칸 부제도 그 날.
  위험 한도 막대의 '오늘 신규 주문'은 그대로 거래일로 센다(실행부의 하루 한도가 거래일이다).
- `swing_dash.session_ended_for(날짜, 지금)` — 그 거래일의 정규장이 끝났나(마감 시각은 엔진의 표 한 곳 · 수능일 포함). 시작 카드는 열린 주문의
  그날 장이 끝났으면 *'장부 상태 증권사 접수'* 와 *"그날 주문이라 다음 거래일로 넘어가지 않습니다 · 다음 거래일 워커의 첫 바퀴가 그날 내역으로
  맞춰 체결이 있었으면 체결로, 없으면 만료로 적습니다"*(실행부가 하는 일 그대로) — 장중엔 종전대로 '지금'. '주문·체결' 갈래의 생애 머리도
  같은 규칙(같은 함수)이다 — 같은 주문을 두 자리가 다르게 말하지 않게.
- 최근 사건 — 기록 줄에 지금의 연도를 붙이고(앞날이 되면 한 해 전 · 12월 기록을 1월에 읽는 자리) 시각 구분을 다른 줄과 같은 `T` 로.

## 확인

- 실제 장부(읽기 전용) — 22:40 판정일 10-13 → 매수일 10-14 · 깔때기 주문 0 · 앞 판정 주문 1 / 10:00 판정일 10-12 → 매수일 10-13 · 깔때기 주문 1
  (종전과 같음) / 다음 날 07:00 → 깔때기 0 · 앞 판정 주문 0(그날 주문은 '오늘'이 아니다).
- 앱을 다시 띄워 관제실을 그렸다 — 세 문장이 그대로 나오고 최근 사건이 21:05 → 15:30 → 01:04 차례 · 서버 오류 0.
- §504(7건) — 매수일 셈(휴장일 건너뜀) · 저녁/장중 주문 칸 · 장 끝 판정 · 시작 카드 세 갈래 · 최근 사건 차례(연말 경계 포함) · 관제실 호출(AST) ·
  주문·체결 갈래 머리(AST).

## 안 한 것

- 실행부가 그날 주문을 그날 밤 만료로 적게 하지 않았다 — 늦게 알려지는 체결을 버리지 않으려는 설계이고 실주문 경로다.
- 정규장 지정가 주문이 시간외 거래에서 체결되는지는 재지 않았다 — 그래서 *"더 체결되지 않는다"* 고 적지 않고 *"다음 거래일로 넘어가지 않는다"*
  와 실행부가 하는 일만 적었다(§3).
