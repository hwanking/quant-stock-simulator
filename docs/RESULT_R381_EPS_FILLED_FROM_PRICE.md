# 라운드 381 — EPS 를 못 받으면 가격으로 만든 이익이 모형에 들어갔다 (2026-09-29)

계산부 한 곳(`quant_indicators.evaluate_valuation_metric`) · model **v2026.09.27.2 → v2026.09.29.0**(`kind='gate'`) ·
식·배수·가중치·문턱 불변 · 검사 §373(앞 5건) · §360 한 줄(입력 이름).

## 1. 무엇이었나

외부 검토(사용자가 붙인 분석문 · 한 종목 화면과 저장소 `main 522129c`)가 짚었다: EPS 가 없으면

```python
eps = in_eps if in_eps is not None else (curr_price / 15.0 ...)     # :2426 — 주석: "분류 산식용"
norm_eps = max(1.0, eps * 1.05 if roe > 10 else (eps if eps > 0 else ...))
_eps_synth = bool(eps is not None and float(eps) <= 0)              # 라운드 358 깃발
```

분류용 대체값이 **정상화 EPS** 가 되어 EV/EBITDA · FCFF · EV_GP · DCF_SCENARIO 가 **현재가의 배수**로 섰고,
라운드 358 의 깃발도 **채운 값**(늘 양수)을 봐서 막지 못했다. 바로 위 주석은 *"norm_eps 는 eps 가 없으면 bps·roe
로 유도된다"* 고 약속했는데 코드는 그렇게 하지 않았다 — 라운드 167·188 이 걷어낸 "가격에서 만든 값이 게이트를
켠다"의 네 번째 자리다. 곁들여 경기민감형 FCFF 는 `bps × 0.15` 를 더하는데 이 모형만 `_have_bps` 를 안 봐,
BPS 를 못 받으면 그 bps 가 `현재가 × 0.8` 이었다.

⚠️ **외부 검토가 본 그 종목은 이 경로가 아니었다** — 그 종목은 EPS 를 **받았다**(적자 · 음수). 화면 타일이

종목에 닿는다** — 둘을 섞어 적지 않는다.

## 3. 고친 것

모형에는 **받은 값만** 쓴다: 받은 EPS → 없으면 받은 BPS·ROE 의 **항등식**(EPS = BPS × ROE · 가격에서 만든 값이
아니다 · 주석이 약속한 그 유도) → 그것도 없으면 None(그때는 `_have_norm_eps` 가 이미 거짓이라 이익 모형은 안
선다). 깃발은 그 값으로 판정하고, EPS 미수신·ROE≤0 이면 사유가 *"EPS 미수신 · 받은 BPS×ROE 로 보면 이익 0 이하"*
라고 적는다(받은 적자는 종전 문장 그대로 — 받은 것과 유도한 것을 가른다). 경기민감형 FCFF 는 받은 BPS 가 있을
때만. 분류 산식의 대체값은 **안 건드렸다**(주석대로 분류용이고 유형 확률을 바꾸면 가중치가 움직인다 · 별도 물음).

## 5. 남긴 것 — 모형이 하나면 수축이 되돌려진다

같은 검토의 두 번째 주장도 코드로 **확인했다**: 괴리를 줄이는 윈저화 뒤 결과를 유효 모형 10~90분위 안으로

손으로 고르는 수이고(라운드 358 이 '합의도'에서 같은 이유로 멈췄다 · §2), 지금 그런 종목은 가치 기준선이 안 서
