10-13 은 실전 모드(완전 자동 · 사용자가 02:42 에 켰다)로 맞는 첫 장이다. 읽기 전용으로 장부를 보니:

| 판정일 | 계획 | 실주문 자격 |
|---|---:|---:|
| 2026-10-12 (리포트 = 시장 스캔 상위 5) | 5 | **0** — 전부 '추천 아님'(비용 차감 기대값 −0.25~−0.41%) |
| 2026-10-08 | 5 | 0 |

엔진이 낸 **추천**(조건 11개 전부 통과)은 관심종목 한 종목이었는데 자동매매 계획은 리포트 상위 5 에서만 만들어져 거기 없었다 —
그대로면 09:00 에 주문 0 이다. 두 길을 물었고 사용자가 *"관심종목 추천도 계획에 넣기"* 를 골랐다.

## 새 판단을 만들지 않는다 (§4)

- **같은 정밀 분석** — 관심종목의 숫자 코드 종목을 리포트와 같은 `run_screener_scan`(시세 교차검증·유동성 하한까지)으로 같은 분석 기준일에 잰다.
- **같은 조립** — `premarket.pick_from_scan_row` 로 후보를 만들고 중앙 판정이 추천(`core['recommended'] is True`)인 것만 남긴다.
- **같은 계획 함수** — 문서의 모양이 리포트와 같아(`date`·`day_basis`·`generated_at`·`engine_version`·`picks`) 계획은 `plans_from_report` 가 만든다. 계약·실주문 자격·plan_id 규칙이 하나다.
- **같은 관문** — 만들지는 리포트의 `decide` 그대로(정규장 중·봉 확정 전·쓰기 금지면 안 만든다 · `--force` 는 '이미 있음'만 넘는다) · 시세 관문은 `feed_gate` 그대로 · **저장 직전에 같은 판단을 한 번 더**.
- 리포트에 이미 있는 종목은 문서에서 뺀다(리포트가 이긴다) · 실행부도 같은 종목은 한 번만 산다(이중 안전).
- 계획의 판정 기록에 `source='watchlist'` — 화면 '오늘 계획' 표가 *'관심종목 추천 · '* 으로 적는다(plan_id 에는 안 든다).

문서: `swing_watch.py`(만들기·읽기 · 이 PC 의 `.portfolio/swing_watch_picks_YYYYMMDD.json` · 백업 거부 `swing*` · 업로드 밖 · git 밖 — 관심종목 코드가 들어 있다 · §9) ·
`scripts/build_watch_picks.py`(저녁 작업의 새 단계 — 리포트 뒤 · 워커 앞).

## 독립 검토가 잡은 것 (적대적 · 읽기 전용 · 적용 전)

| | 무엇 | 고침 |
|---|---|---|
| 심각 | 문서 길에 **정규장 중 막기가 없었다** — 리포트는 `report_fix_blocker`(15:30~20:00)에 더해 '장중'을 따로 막는데 첫 판은 앞엣것만 베꼈다. 장중에 손으로 돌리면 장중 가격으로 '전 거래일' 계획이 서고 1분 안에 실주문 | 리포트의 `decide` 를 **그대로 부른다** · 저장 직전 다시 |
| 심각 | 리포트의 **시세 관문**(`feed_gate`)을 안 지났다 — 다음 시세가 죽은 밤에 리포트는 멈추는데 문서는 검증 안 된 가격으로 계획을 만든다 | `feed_gate` 를 분석 앞에 |
| 심각 | **최신 판정을 안 본다**(종전부터의 빈틈) — 실행부는 한 번 추천된 계획을 대기 기간 20거래일 내내 오늘 판정과 무관하게 산다. 관심종목은 매일 다시 재므로 흔해진다 | **최신 판정이 이긴다**(아래) |
| 작음 | 문서를 읽다 실패하면 바퀴 전체(보호 매도)가 멈출 수 있었다 | 읽기를 try 로 · 실패하면 그 문서만 빠진다 |
| 작음 | R506(시장 실측)이 커밋 전이었다 | R506 을 먼저 커밋했다 |
| 작음 | 리포트 스캔의 경량 유동성 거르기(그날 거래대금 5억)는 안 지난다 — 정밀 분석의 20일 평균 20억 하한은 지난다 | 안 고쳤다(정밀 분석의 하한이 실제 관문 · 적었다) |

**검토가 없었으면 첫 둘을 안은 채 실전에 나갔다** — 내 첫 판은 리포트 길의 관문을 '봉 확정' 하나로 알고 베꼈다.

## 최신 판정이 이긴다 (막기만 하는 규칙)

`swing_executor._entries` — 실주문 자격 계획은 ① 같은 종목의 **가장 새 판정일** 계획만 보고 ② 그 뒤에 잰 판정(그날 리포트 후보의
`core.recommended` · 관심종목 문서의 `verdicts` = 잰 종목 전부의 추천 여부)이 추천이 아니면 옛 계획으로는 사지 않는다(막힘에 사유).
같은 종목이 둘 다에 있으면 '추천 아님' 쪽이 이긴다. 사람이 고른 계획(R494)에는 안 건다. **사는 쪽으로는 아무것도 안 연다.**
⚠️ 리포트 계획에도 걸린다 — 종전 계약('대기 기간 내내 산다')보다 엄해졌다. 오늘 판정이 그 종목을 **안 잰** 경우(상위 5 에서 빠짐)는
종전대로 산다(모르는 것을 '추천 아님'으로 읽지 않는다 · §3).
