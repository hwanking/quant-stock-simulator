# 접근성·신뢰성 체크리스트

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 이 앱에서 접근성과 신뢰성은 같은 문제다: 정보를 일부 사용자에게만 보이게
> 하거나(색맹·저시력), 일부 정보를 아예 숨기는 것(오류 은폐·추정치 위장)은
> 둘 다 "화면이 거짓말을 하는 것"이다. 릴리스 전 전 항목 점검한다.

## 1. 색상 — 색 단독 구분 금지

- [ ] 상승/하락이 색+부호(+/−)+방향 아이콘(▲/▼) 3중으로 표기된다 (색만으로
      구분되는 곳 0건)
- [ ] 게이트 상태(통과/발동/거부/비적용)가 아이콘+텍스트로 표기된다 (✓/▼/⛔/−)
- [ ] 상태 배지(정상/지연/오류)에 텍스트 라벨이 항상 붙는다
- [ ] 히트맵의 모든 셀에 값 라벨이 있다 (색 농도만으로 값 전달 금지)
- [ ] 신뢰도·점수 막대에 숫자 값이 병기된다
- [ ] 차트에서 계열 구분이 색 + 선 스타일(실선/점선) 또는 마커 모양으로
      이중 부호화된다
- [ ] positive/danger 팔레트가 적록색맹 시뮬레이션(protanopia/deuteranopia)에서
      구분 가능함을 확인했다

## 2. 대비 — 양 테마 공통 목표

- [ ] 본문 텍스트(`--text-1`,`--text-2`) 대 배경 대비 **4.5:1 이상** (WCAG AA)
- [ ] 큰 텍스트(18px 이상 또는 14px bold — 페이지 제목·행동 결론·핵심 숫자)
      대비 **3:1 이상**
- [ ] 보조 텍스트(`--text-3`, 12–13px) 대비 **4.5:1 이상** (작을수록 기준 강화,
      완화 금지)
- [ ] 의미 색 텍스트(positive/warning/danger)가 카드 배경 위에서 4.5:1 이상
- [ ] 아이콘·막대·경계 등 비텍스트 UI 요소 대비 **3:1 이상**
- [ ] 라이트/다크 **양 테마 모두** 위 기준을 통과한다 (한 테마만 검증 금지)
- [ ] 의미 색 틴트 배경(배너) 위의 텍스트도 별도로 측정했다
- [ ] 대비 검증 결과(측정값)를 DESIGN_SYSTEM.md 토큰 표에 기록했다

## 3. 키보드·포커스

- [ ] 모든 인터랙티브 요소(탭·토글·버튼·카드 링크)에 Tab 키로 도달 가능하다
- [ ] 포커스 링(`--accent-strong` 2px)이 양 테마에서 보인다 — `outline: none`
      으로 제거한 곳 0건
- [ ] 커스텀 HTML 카드가 클릭 가능하면 `role`/`tabindex`/Enter 동작을 갖춘다
      (가능하면 실제 `<a>`/`<button>` 사용)
- [ ] 포커스 순서가 시각 순서(결론→가격→이유)와 일치한다
- [ ] 하단 고정 메뉴(모바일)가 본문 마지막 요소를 가리지 않는다
- [ ] 장식 아이콘은 `aria-hidden`, 의미 아이콘은 대체 텍스트를 갖는다

## 4. 타이포·크기

- [ ] 12px 미만 텍스트 0건 (Finviz식 깨알 글씨 금지)
- [ ] 본문 14px 이상, 모바일에서도 축소하지 않는다
- [ ] 터치 타깃 44×44px 이상 (모바일 버튼·탭·하단 메뉴)
- [ ] 숫자는 전부 tabular-nums — 표에서 자릿수 정렬이 유지된다
- [ ] 브라우저 확대 200%에서 가로 스크롤 없이 본문을 읽을 수 있다

## 5. 데이터 정직성 — 오류 은폐 금지

- [ ] 수집 실패·미수신 값이 "0"이나 빈칸으로 위장되지 않는다 — "수집 실패/
      미수신"으로 명시 (수급 NaN을 0 채움 금지 원칙과 동일)
- [ ] 미산출 값은 "미산출"+사유(신뢰도 미달·표본 부족)로 표기된다 (fmt_num
      na 관례 전 화면 일관)
- [ ] 부분 실패 시 실패 영역만 오류 카드로 표시하고 정상 영역은 렌더된다 —
      전체 화면 백지화 금지
- [ ] 오류 배너에 원인(출처·항목)과 마지막 성공 시점이 표기된다
- [ ] 제외·차단된 종목/후보는 개수와 사유를 항상 열람할 수 있다 (조용한 필터링
      금지)
- [ ] "후보 0건"이 오류가 아니라 게이트의 정상 결과임을 문구로 설명한다
- [ ] 미연동 데이터(컨센서스·공시 원문 등)는 "미연동"으로 표기하고 흉내 내지
      않는다

## 6. 예상/확정 구분

- [ ] 확정 데이터(전일 종가·게시 재무)와 추정치(배당락일 관례 추정·적정가·
      기대수익)가 시각적으로 구분된다 — 추정치에 "추정" 배지
- [ ] 개장 전 브리핑에 "전일 확정 데이터 기준"과 생성 시각·기준일·모델 버전이
      박제된다
- [ ] 모든 카드에 데이터 기준일 스탬프가 있다 — 기준일 없는 숫자 0건
- [ ] 장중 실시간 값과 전일 확정 값이 같은 카드에서 섞이지 않는다 (섞이면
      각각 라벨)

## 7. 불확실성 표시

- [ ] 모든 적중률·승률에 표본 수(n)가 병기된다 — n 없는 % 0건
- [ ] 모델 성과의 적중률에 신뢰구간(Wilson)이 병기된다
- [ ] 표본 부족 구간은 값 대신 "표본 부족 (n={n})"으로 표기한다
- [ ] 적중률이 "보장"이 아니라 "과거 실측"임이 문구로 구분된다 (calibration.json
      실측만 인용, 목표치를 실적처럼 쓰지 않는다)
- [ ] 리플레이 표본의 국면 편중(2025~2026)이 모델 성과 화면에 명시된다
- [ ] 예측 범위·기대수익에는 비용 차감 여부가 표기된다

## 8. 모션·인지

- [ ] `prefers-reduced-motion` 존중 — 설정 시 전환 애니메이션 제거
- [ ] 무한 반복 애니메이션·자동 갱신 깜빡임 0건
- [ ] 데이터 로딩 중 레이아웃 점프가 없다 (스켈레톤 자리 고정)
- [ ] 색·아이콘·문구의 의미가 전 화면에서 일관된다 (같은 판정 = 같은 표현)

## 9. 릴리스 게이트

- [ ] 위 전 항목을 라이트/다크 × 데스크톱/태블릿/모바일 6조합에서 점검했다
- [ ] 키보드만으로 홈→추천→종목 분석→보유 등록 흐름을 완주할 수 있다
- [ ] 색맹 시뮬레이터로 8개 화면 스크린샷을 검토했다
- [ ] 신규 화면·컴포넌트 추가 시 이 체크리스트를 다시 통과해야 한다
