# 클라우드가 매일 어제 날짜를 찍고 있었다 — 라운드 86

**전방 기록이 8/12 이후 하나도 안 쌓이고 있었다.** 전 단계 `success` 였고
스냅샷 가드도 통과했다. 축소가 아니라 **정체**라 아무도 못 봤다 —
라운드 81 과 같은 모양이다.

---

## 1. 증상

일일 워크플로 로그:

```
전방 판정 기록 — 기준일 2026-08-12 · 상위 60종목
  오늘 이미 기록됨 60종목 — 건너뛴다
기록 0건 · 실패 0건 / 대상 0종목
```

`predictions.jsonl` 이 **171 에서 멈춰** 있다. 8/13 20:05 KST 에 돌았는데
기준일이 **2026-08-12** 다.

## 2. 원인 — 러너 시계는 UTC 인데 엔진은 KST 를 가정한다

`bitemporal_engine.resolve_analysis_date` 는 명세 §3 그대로다:

```
정상 거래일 장 종료 후 → 오늘 확정 종가
장중 / 장 시작 전      → 직전 거래일 확정 종가
```

판단 기준은 `datetime.datetime.now()` 다. **그 값이 KST 라고 가정한다.**
GitHub 러너의 시계는 UTC 이고 KST − 9 다.

같은 순간을 두 시계로 본 실측:

| 실제 시각 | 러너가 보는 시각 | 판정 | 기준일 |
|---|---|---|---|
| 17:00 KST (스케줄) | 08:00 | 장 시작 전 | **2026-08-12** |
| 〃 (KST 시계였다면) | 17:00 | 장 종료 후 | 2026-08-13 |

스케줄이 `0 8 * * 1-5`(UTC) = 17:00 KST 이므로, **매 실행이 반드시**
'장 시작 전'으로 읽힌다. 기준일은 항상 직전 거래일이 된다.

그다음 중복 방지가 작동한다 — 어제 것은 이미 기록됐으므로 **건너뛴다.**
결과: 첫날 이후 **영원히 0건.**

## 3. 누출은 아니다 — 그러나 축적이 멎는다

`run_full_pipeline(sym, t_ref)` 는 바이템포럴이라 `t_ref` 이전 데이터만
쓴다. 그래서 어제 날짜로 찍혀도 **미래 참조는 없다.** 문제는 값이
틀린 것이 아니라 **아무것도 안 쌓이는 것**이다.

전방 재평가(2026-11-16)는 전방 데이터로만 판정한다. 그 데이터가 안
쌓이면 그날 할 수 있는 것이 없다.

## 4. 고침 — 엔진을 고치지 않고 시계를 진실로 만든다

```yaml
jobs:
  accumulate:
    env:
      TZ: Asia/Seoul
```

계산 파일(`bitemporal_engine.py`)은 §1 보호 대상이고, 명세 §3 자체는
틀리지 않았다 — **가정이 성립하지 않는 환경에서 돌았을 뿐**이다.
시계를 KST 로 맞추면 그 가정이 실제로 참이 된다.

> `date -u +%Y%m%d`(릴리스 태그)는 그대로 UTC 를 쓴다. 명시적으로
> `-u` 를 준 자리라 TZ 변경에 영향받지 않는다.

## 5. 다음에 또 조용히 멈추지 않게

`forward_recorder` 가 **스스로 뒤처짐을 알린다**:

```
시계 2026-08-13 20:14 · 달력상 최근 거래일 2026-08-13
⚠ 기준일이 최근 거래일(2026-08-13)보다 뒤처졌다. 시계가 KST 가 아닐 수
  있다 (러너는 UTC). 이대로면 어제 것을 다시 찍고 중복 방지에 걸려
  아무것도 안 쌓인다 — TZ 를 확인한다.
```

라운드 81 이 만든 증분 표시(`snapshot_guard --delta`)는 이미
`predictions.jsonl 171 → 171 (+0)` 을 찍고 있었다. **신호는 있었고 내가
안 읽었다.** 그래서 이번에는 원인을 그 자리에 적는다.

## 6. 이 사고가 말해 주는 것

라운드 81 과 같다 — **가드는 자기가 보도록 만들어진 실패만 잡는다.**
그리고 새로 하나 더:

> **환경 가정을 코드가 아니라 환경에서 만족시켜라.** "now() 는 KST"는
> 개발 PC 에서 참이고 클라우드에서 거짓이었다. 같은 코드가 두 곳에서
> 다르게 동작하는 자리는 시계·로케일·인코딩·경로 구분자다.
