# 라운드 500 — 저녁 작업의 되받기가 GitHub 504 한 번에 멈췄다: 일시 오류면 쉬었다 다시

2026-10-12(월) 21:10 · 이 PC 저녁 작업 · 판정·점수·문턱·주문 규칙 불변 · 버전 없음

## 무엇을 보고

2026-10-12 21:00 저녁 작업이 *"가장 나쁜 종료 코드 1"* 로 끝났다. 여섯 단계 중 첫 단계(클라우드 되받기)만 실패했다:

    gh 로 못 받았다 (종료 1): could not find any host configurations
    공개 주소로도 못 받았다 — 멈춘다: HTTPError: HTTP Error 504: Gateway Time-out

라운드 428 이 붙인 '인증 없는 공개 주소' 물러섬 길이 **GitHub 의 서버 쪽 일시 오류(504) 한 번**에 바로 멈췄다. 같은 날 나머지 다섯
단계(개장 전 리포트 — 리포트 가격 = 확정 종가 5/5 · 추적 동결 · 관심종목 재측정 · PROOF · 스윙 계획 +5)는 다 돌았다. 되받기가 하루
빠져도 다음 날 저녁 작업이 더 새 스냅샷을 받으므로 잃은 것은 없다 — 다만 504 같은 일시 오류에 하루를 통째로 거르는 것은 고칠 자리다.

## 고친 것 (`scripts/pull_research_data.py`)

- `_retrying` — 일시 오류(HTTP 5xx · 연결 실패 · 시간 초과)면 `RETRY_WAITS`(5초 · 20초) 쉬고 다시, 최대 세 번. 4xx(없는 자산 · 권한)는
  다시 해도 같으므로 바로 멈춘다. 쉬는 간격은 판정 문턱이 아니라 재시도 간격이다(라운드 445 의 업로드 재시도와 같은 모양).
- 공개 목록 읽기(`_http_json`)와 공개 내려받기(`http_download`)가 같은 것을 쓴다. 내려받기는 매번 반쪽 파일(.part)을 지우고, 앞서 실패가
  있었으면 받은 뒤 *"N번 일시 오류 뒤 받음 — …"* 을 사유 칸에 남긴다(몇 번 해 봤는지가 기록에 남는다). 끝내 실패하면 사유 셋을 다 적는다.

## 확인

회귀 §479(네트워크 0 · 여는 함수와 쉬기를 바꿔 끼운다) — 504 두 번 뒤 성공(쉰 간격 5·20 · 사유 칸) · 404 는 다시 안 함 · 끝까지 504 면
세 번 뒤 None · 사유 셋 · 반쪽 파일 없음 · 목록 읽기도 같은 재시도. 라운드 383·415 의 되받기 절도 그대로 통과.
