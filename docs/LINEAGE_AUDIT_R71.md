### ③ 실행 추적 — 실제 종목을 흘린다

종목 N개를 파이프라인에 통과시켜 `verdict_core.build()` 결과를 만들고,
화면에 나갈 값들의 **출처 키**를 기록한 뒤 정합을 재계산한다.

- 손절 < 진입 < 목표 가 실제로 성립하는가

  남아 있으면 여기서 어긋난다 (라운드 30 사고의 자동 탐지)
- 진입가가 축(`price_axes.entry`)에서 왔는가, 폴백에서 왔는가
- 신규 값과 보유자 값이 같은 숫자로 겹치는가

산출물: `data/lineage_audit.json`

## 훑다가 나온 것 — 적중률을 읽는 기준선

정합을 세다 보니 **손익비가 사실상 상수**였다. 60,462건 중 99.4%가 `0.70`
이다 (목표 폭 중앙 +3.29% · 손절 폭 중앙 −4.70%). 폭은 종목 변동성에 따라
움직이지만 **비율은 고정**이다.

그러면 적중률은 혼자서는 아무것도 말하지 못한다. 손익분기 적중률과 견줘야
한다 — 이건 새 문턱이 아니라 기록된 폭에서 나오는 값이다:

```
p* = (손절폭 + 비용) / (목표폭 + 손절폭)
   = (4.70 + 0.36) / (3.29 + 4.70) = 63.3%
```

| 구간 | n | 매수권 적중률 | 비용 후 손익분기(63.3%) 대비 |
|---|---:|---:|---:|
| train | 13,796 | 59.11% | **−4.21%p 아래** |
| valid | 1,536 | 66.15% | +2.82%p 위 |
| blind | 1,207 | 51.86% | **−11.46%p 아래** |

**손익분기선 위인 구간은 valid 하나뿐이다** — 모델이 맞춰진 바로 그 구간이다.
train 과 blind 는 둘 다 아래다. 이것은 CLAUDE.md 의 서 있는 결론(*"매수권
신호에 재현되는 비용 차감 우위가 없다"*)을 뒤집지 않는다. **왜 그런지를
구조로 설명한다** — 적중률이 55~59%인데 지는 게 아니라, 이 목표·손절 폭에서는
55~59%가 애초에 지는 자리다.

감사 전용 관측이므로 여기서 목표·손절 폭을 손대지 않는다. 8/23 동결 준수.

## 라운드 71c — 클라우드가 원장을 깎고 있었다

권한을 고치고 나서 워크플로가 처음으로 끝까지 성공했다. 그런데 요약 줄이
이상했다:

```
원장 행수: 400        ← 로컬은 60,462
경로 행수: 60,862
```

**원인.** `calibration_lab.py` 는 매 실행마다 원본(`virtual_predictions.jsonl`)
을 전부 다시 채점해 산출물(`virtual_graded.jsonl`)을 `open(..., 'w')` 로
덮어쓴다. 그런데 백업 화이트리스트에 **산출물만 있고 원본이 없었다.**
그래서 클라우드는 매번 그 회차 400건만 가진 원장을 새로 만들고, 그것을
`--clobber` 로 좋은 스냅샷 위에 올렸다. 스냅샷이 28MB → 22.7MB 로 줄었다.

로컬 원장은 무사했으므로 영구 손실은 없었다. 클라우드 사본을 온전한
로컬 데이터로 다시 올렸다 (22.7MB → 35.1MB).

**두 가지를 고쳤다.**

1. `virtual_predictions.jsonl` 을 백업에 넣었다 — 산출물만 지키면 안 되고
   **재생성의 입력을 지켜야** 한다.
2. `scripts/snapshot_guard.py` — 복원 직후 줄 수를 박제하고, 업로드 직전에
   다시 세서 **줄었으면 업로드를 막는다.** 화이트리스트를 고친 것만으로는
   부족하다. 같은 종류의 사고(무언가가 파일을 재생성하며 줄이는)는 또 날
   수 있고, 그때도 조용히 덮어쓰기가 성공할 것이다.

가드가 실제로 막는지도 검사한다 — 기준선을 조작해 축소를 심으면 `verify()`
가 1을 돌려줘야 하고, `--allow-shrink` 로만 통과해야 한다. **한 번도 울리지
않는 경보는 증명이 아니다.**

### 곁다리 — 같은 stdout 함정을 하루에 세 번 밟았다

`sys.stdout = TextIOWrapper(sys.stdout.buffer, ...)` 를 모듈 수준에서 하면
임포트하는 쪽의 stdout 까지 갈아끼우고, 옛 래퍼가 수거될 때 버퍼를 닫아
그 뒤 출력이 통째로 죽는다. `lineage_audit` · `snapshot_guard` ·
`backup_research_data` 세 곳에서 같은 실수를 했다. 셋 다 `__main__` 에서만
`reconfigure` 하도록 고쳤다.
