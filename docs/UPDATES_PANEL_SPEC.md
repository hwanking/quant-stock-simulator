# 업데이트 패널 명세 (v4 — 구현됨: web_app.py '최근 업데이트 · 업데이트 히스토리')

## 원칙
원천은 **git 커밋 로그 원문** — 손으로 쓰지 않는다(누락·과장 불가).
카테고리는 제목 낱말 규칙으로만 분류하고 내용은 재작성하지 않는다.

## 파이프라인
1. `scripts/gen_update_history.py` — git log → `data/update_history.json`
   (날짜별 그룹, 해시·제목). **푸시 전에 실행**해야 배포 화면이 최신이 된다.
2. `product_ops.enrich_update_history()` — 카테고리·버전 표기(v{YY.MM.DD}) 부여.
3. 화면: 요약(누적 N건·운영 모델 버전) → 최근 5건 리스트(날짜·카테고리 뱃지·제목)
   → expander "전체 업데이트 보기 (N건·카테고리 필터)" + selectbox 필터 + 표.

## 카테고리 8종과 분류 규칙 (product_ops.UPDATE_CATEGORIES — 우선순위 순)
| 카테고리 | 대표 낱말 |
|---|---|
| 버그 수정 | 수정, 버그, 오류, 폭탄, 깨지 |
| 케이스 스터디 | 케이스, 리플레이, 원장, 캘리브레이션, 표본 |
| 뉴스 분석 | 뉴스, 공시, 후행, 컨텍스트 |
| 추천 로직 | 추천, 개장 전, 게이트, 스캔, 관심종목 |
| 모델 | 모델, 점수, 판정, 적정가, DeMARK, 블라인드, 검증, 손절, 기하 |
| 데이터 | 데이터, 시세, 출처, 수집, 평단가, OCR, 인식, 배당 |
| UI/UX | UI, 디자인, 테마, 차트, 탭, 카드, 화면, 위계, 토큰 |
| 성능 개선 | 성능, 캐시, 속도 |
미매칭 → '기타'.

## 이슈와의 연결
업데이트 = 그동안 바뀐 것 / 이슈 = 지금 중요한 것.
모델 변경 → 커밋(자동으로 업데이트에 반영) + 성과 악화 시 이슈 자동 생성.
데이터 장애 → 이슈 먼저(지수 미수신 자동), 해결 커밋이 업데이트에 남음.
