# 반응형 규칙 — 데스크톱·태블릿·모바일

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 3개 브레이크포인트에서 "결론→가격→이유→상세" 위계가 유지되는 것이 유일한
> 불변 조건이다. 좁아질수록 상세가 먼저 접히고, 결론은 마지막까지 남는다.

## 1. 브레이크포인트

| 구간 | 폭 | 기기 가정 |
|---|---|---|
| 데스크톱 | ≥ 1024px | 모니터, 좌측 내비 |
| 태블릿 | 640–1023px | 태블릿·좁은 창 |
| 모바일 | < 640px | 폰 세로 |

CSS: `@media (max-width: 1023px)` / `@media (max-width: 639px)` 2개만 사용
(구간 남발 금지).

## 2. 데스크톱 (≥1024px)

- 콘텐츠 최대 폭 `--content-max: 1280px`, 중앙 정렬 — 초광폭에서 카드가
  무한히 늘어나지 않게 한다.
- 좌측 탐색: 사이드바에 글로벌 메뉴 9개(아이콘+라벨) 고정. 접기 지원.
- 그리드: 시장 카드 4~6열, 추천 카드 2~3열, 지표 카드 3~4열.
- 우측 보조 패널(선택): 종목 분석에서 관심종목·최근 조회를 우측 260px에 —
  1280px 미만이면 자동 숨김.
- 표 보기는 데스크톱의 특권 — 스캐너·브리핑 후보 표는 이 구간에서만 기본값.

## 3. 태블릿 (640–1023px)

- 카드 그리드 일괄 2열. 시장 카드 3열 허용.
- 탭이 6개 이상이면 가로 스크롤(스크롤 가능함을 우측 페이드로 암시).
- 사이드바 내비는 아이콘 전용으로 축소 또는 햄버거.
- 표는 가로 스크롤 컨테이너로 유지하되, 열 우선순위 하위(거래량 배수·뉴스 등)
  숨김 토글 제공.
- 히트맵 보기는 이 구간까지만 (모바일 제외).

## 4. 모바일 (<640px)

- **결론·가격 우선**: 각 화면의 첫 뷰포트에 행동 결론 배너 + 핵심 숫자
  (현재가/점수)가 반드시 들어간다. 그 외는 스크롤 아래로.
- **표→카드 전환**: 모든 표는 카드 리스트로 대체 (가로 스크롤 표를 모바일
  기본값으로 두지 않는다).
- 하단 고정 메뉴 5개: 홈·추천·분석·보유·더보기 (더보기 시트: 브리핑·스캐너·
  케이스·성과·설정). 터치 타깃 최소 44×44px.
- 가격 사다리는 세로형 유지(원래 세로), 시나리오 3분할은 세로 스택.
- 차트는 높이 우선 축소 + "가로 모드에서 더 크게" 안내. 지표 패널은 시트로.
- 폰트 하한 준수: 본문 14px, 보조 12px 미만 금지 — 모바일에서 축소 스케일 없음.

## 5. Streamlit 제약과 보완 방법

### 5-1. st.columns의 한계

- st.columns는 뷰포트 폭과 무관하게 **항상 지정 열수를 유지**한다 — 좁은 화면에서
  열이 뭉개질 뿐 재배열되지 않는다. 진짜 반응형이 필요한 그리드는 st.columns
  대신 **st.markdown HTML + CSS grid**로 만든다:
  `display:grid; grid-template-columns:repeat(auto-fill,minmax(240px,1fr));`
  — 이 한 줄이 데스크톱 다열→모바일 1열을 자동 처리한다.
- st.columns를 쓰는 곳(위젯이 필요한 레이아웃)은 media query로 컬럼 블록에
  `flex-wrap`/`min-width`를 강제해 줄바꿈시킨다. Streamlit 버전에 따라 내부
  클래스명이 바뀌므로 `[data-testid="column"]` 계열 셀렉터를 쓰고, 오버라이드
  목록을 DESIGN_SYSTEM.md §8과 함께 관리한다.

### 5-2. media query 주입

- 토큰 `<style>` 블록(DESIGN_SYSTEM §8)에 media query를 함께 선언한다.
  Streamlit은 뷰포트 폭을 파이썬에 알려주지 않으므로 **분기는 전적으로 CSS**로
  한다 — 파이썬에서 "모바일이면 다른 위젯" 분기는 불가능함을 전제로 설계.
- 따라서 표→카드 전환은 "둘 다 렌더 + CSS로 표시 전환"이 아니라(성능 낭비·
  데이터 이중화), **카드형을 기본으로 렌더하고 표는 데스크톱 전용 토글**로
  제공하는 방식을 원칙으로 한다 (사용자가 명시적으로 전환).

### 5-3. 기타 제약

- 사이드바: Streamlit 사이드바는 모바일에서 자동 드로어가 되지만 하단 메뉴는
  제공하지 않는다 — 하단 고정 메뉴는 CSS `position:fixed` HTML 바 + 쿼리 파라미터
  (st.query_params) 링크로 구현하고, 본문 하단에 메뉴 높이만큼 패딩을 준다.
- st.dataframe은 자체 가상 스크롤이 있어 모바일 터치와 충돌 — 모바일 카드 전환
  원칙의 근거.
- st.tabs는 넘치면 자동 가로 스크롤되므로 그대로 사용 가능 (탭 라벨은 짧게).
- 차트(plotly/lightweight-charts)는 `use_container_width=True` 필수, 고정 px 폭 금지.

## 6. 화면별 요약표

| 화면 | 데스크톱 | 태블릿 | 모바일 |
|---|---|---|---|
| 홈 | 시장 4~6열·추천 3열 | 시장 3열·추천 2열 | 시장 2열·추천 1열 |
| 브리핑 | 탭 5개 + 표 | 탭 스크롤·표 열 축소 | 탭 스크롤·카드 고정 |
| 추천 | 카드 2~3열 | 2열 | 1열·액션 축약 |
| 종목 분석 | 3단 + 탭 9 + 보조 패널 | 보조 패널 숨김·탭 스크롤 | 결론→사다리→탭 시트 |
| 보유종목 | 요약 스트립 + 그룹 | 2열 카드 | 아코디언·1열 |
| 스캐너 | 표 기본·히트맵 | 표 스크롤·히트맵 | 카드 고정·필터 시트 |
| 케이스 | 표/카드 + 상세 분할 | 카드 | 상세 전체 화면 전환 |
| 모델 성과 | 지표 3~4열 | 2열 | 2×2 스트립·표는 카드 |
