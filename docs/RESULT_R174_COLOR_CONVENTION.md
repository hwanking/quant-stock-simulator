# 라운드 174 — 같은 색이 화면마다 반대 뜻이었다

**날짜** 2026-08-25 · **분류** 화면 결함 (§5 관행 위반)
**요청** *"못다한 작업 계속 찾아서 해줘"*

---

## 1. 어떻게 찾았나 — 이번 세션에서 잡은 **결함 유형**을 다른 자리에 대 봤다

라운드 171(칸을 더하면 값이 잘려 보인다)과 172(같은 사실이 두 칸에 있으면
어긋난다)는 둘 다 **유형**이다. 한 번 잡았으면 같은 모양이 다른 데도 있는지
훑어야 한다 (`_probe/pattern_sweep_r174.py`).

- **ⓐ 칸 수** — 7칸 이상인 표는 넷뿐이고 전부 **10칸 이하**였다. 닫혀 있다.
- **ⓑ 상태 조립** — 화면이 `status`·`state` 를 직접 읽는 자리를 훑다가
  **색 지정 줄**이 눈에 들어왔다.

## 2. 토큰은 맞았는데 화면이 손으로 반대 색을 박고 있었다

`CLAUDE.md` §5 — *"색은 **상승 빨강 / 하락 파랑** (한국 관행)."*
토큰도 그대로다.

| | dark | light |
|---|---|---|
| `up` | `#F1574C` (빨강) | `#D02E24` |
| `down` | `#488AF7` (파랑) | `#186AD5` |

그런데 화면 아홉 자리가 **손으로** 이렇게 박고 있었다.

```python
upside_color = "#35C98B" if upside_val > 0 else "#ff453a"   # 초록=양수
```

**초록=상승 · 빨강=하락** — 서양 관행이고 §5 와 반대다.

### 가장 분명한 증거: 같은 색의 두 뜻

```
chart_pro.py:26    _UP = '#ff453a'       ← 차트에서 빨강은 **상승**
web_app.py:3393    음수일 때 '#ff453a'    ← 표에서 빨강은 **하락**
```

**한 앱에서 같은 색이 반대 뜻이었다.** 차트를 보고 표를 보면 방향이
뒤집힌다.

### 그리고 손 색은 테마를 안 따른다

`#35C98B`·`#ff453a` 는 고정값이라 **라이트 모드에서도 다크 색이 그대로**
나온다. 토큰을 쓰면 테마마다 대비가 맞춰진 값이 온다.

## 3. 무엇을 바꿨나 — '가격 방향'과 '좋다/나쁘다'를 갈랐다

§5 의 관행은 **가격 방향**에 대한 것이다. 모델이 좋은지 나쁜지는 다른
축이라 초록/빨강이 맞다. 그래서 열두 자리를 둘로 갈랐다.

### 가격에서 나온 수 → `up` / `down` (관행이 뒤집혀 있던 것)

| 자리 | 무엇 |
|---|---|
| `web_app.py:2256` | 총 평가손익 (내 보유종목) |
| `:2283` | 종목별 수익률 |
| `:3393` | 스크리너 **상승여력%** |
| `:3397` | 월봉 10선 **위/아래** |
| `:4107` | 스캔 보유 손익 |
| `:5652` | **등락률** (▲/▼ 옆) |
| `:8406` | 평가손익 (20px) |
| `:8918` | **평단 대비 띠** (차트 음영) |
| `:9101` | 종목 상세 상승여력% |

### 성과 판정 → `pos` / `neg` (뜻은 그대로, 토큰으로만)

| 자리 | 무엇 |
|---|---|
| `:9667` | 비용 차감 후 모델 성과 |
| `:9729` | 알파(잔차) |
| `:9837` | 순 우위 |

색 뜻은 안 바꿨다. **테마를 따르게** 했을 뿐이다.

### 내가 하루 전에 만든 어긋남도 같이 고쳤다

라운드 171 이 넣은 **포트폴리오 평가손익 타일**만 `pos`(초록)였다.
바로 위 표의 같은 값은 `up`(빨강)이다 — **한 화면에 두 색 언어**였다.
타일도 `up`/`down` 으로 맞췄다.

## 4. 남긴 것 — 그리고 왜 남겼나

같은 두 색이 **111곳** 더 있다. 훑어서 갈라 보니:

| | 수 | 판정 |
|---|---:|---|
| 방향색 · 가격 | **0** | 이번에 다 고쳤다 |
| 방향색 · 판정 (통과/실패) | 2 | 초록=좋음이 맞다 |
| 방향색 · 뜻 불명 (PER · 뉴스 비율 · 현금 비중) | 3 | 좋다/나쁘다다 |
| 한 색 · 배지·테두리·차트 | 106 | 방향과 무관 |

**106개를 이번에 안 건드렸다.** 차트(`chart_pro.py`)는 이미 관행대로
빨강=상승을 쓰고 있고, 배지·테두리를 토큰화하는 것은 별개의 큰 정리다.
**범위를 넓히면 이 라운드가 재는 것이 흐려진다.**

## 5. 회귀 — §208

- 가격에서 나온 수에 **손 색을 안 쓴다** — 유도 모듈 전체(37개)를 훑는다
- **훑은 줄이 있다** (0줄이면 미측정 · §6)
- **토큰이 관행을 지키는가를 값으로 본다** — `up` 은 R>B, `down` 은 B>R.
  이름이 아니라 **RGB 로** 잰다 (다크·라이트 둘 다)
- **심어서 확인한다** — 위반을 만들면 잡히고, 판정용(초록=좋음)은
  위반으로 안 본다
- **타일도 같은 언어를 쓴다** — 가격에서 나온 값에 `tone='pos'` 를 쓰면 실패

## 6. 회귀가 **다른 결함**을 하나 더 잡았다 — 공시 제목이 HTML 원문이었다

전체 회귀에서 *"공시 유형 분류 — ['IR·안내', '기타']"* 가 실패했다.
색과 무관해 보였지만 **이름이 엉뚱했을 뿐 진짜 결함이었다.**

파 보니 제목이 이렇게 들어와 있었다.

```
[기타] <a href="/dsaf001/main.do?rcpNo=20260825000100"  onclick="openRe…
```

원인은 `market_attention._clean` 의 **순서**다.

```python
re.sub(r'<.*?>', '', cell).replace('\n', '').replace('\t', '')
```

`.` 는 개행을 안 먹는다. 그런데 DART 는 `<a>` 를 **여러 줄에 걸쳐** 준다:

```
'\r\n\t\t<a href="/dsaf001/main.do?rcpNo=…"  onclick="…"\r\n
 \t\ttitle="특수관계인으로부터자금차입 공시뷰어 새창" >특수관계인으로부터자금차입…'
```

→ **태그가 통째로 살아남았다.** 곁들여 `\r` 은 아예 안 지우고 있었다
(DART 는 CRLF 로 온다). 그래서 제목에 낱말을 대는 분류가 무너져
**50건 중 44건(88%)이 '기타'** 였고, **화면에도 그 HTML 이 나갔다.**

고침은 순서를 뒤집는 것이다 — 공백을 먼저 한 칸으로 만들고, 그 다음
`<[^>]*>` 로 태그를 지운다(닫히지 않은 태그에서 뒤를 통째로 먹지 않는다).

```
고치기 전 : '<a href="/x?a=1"  onclick="f(\'1\'); return false;"\rtitle="특수관계인…'
고친 뒤   : '특수관계인으로부터자금차입'
실제 공시 : 53건 · HTML 잔존 0건
```

### 검사도 고쳤다 — 기준을 내린 것이 아니다

제목이 깨끗해졌는데 **유형은 여전히 2종**이다. 그 시각 공시가 실제로
행정 공시(대규모기업집단현황 · 특수관계인 자금거래 · 감사보고서)뿐이라
그렇다 — **자료지 결함이 아니다.**

그래서 다양성은 **표본 150건 이상일 때만** 묻고, 대신 **우리가 지킬 수
있는 불변식**을 새로 걸었다:

> **공시 제목에 HTML 이 남지 않았다**

**그 검사가 있었으면 이번 결함을 첫날에 잡았다.** 기준을 내린 것이 아니라,
재던 것(다양성이라는 대리 지표)을 **직접 잴 수 있는 것**으로 바꾼 것이다.
심어서 잡히는지도 확인했다.
