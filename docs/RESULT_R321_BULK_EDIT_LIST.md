# 결과 R321 — 매입가·수량을 **목록에서 여러 개 한꺼번에** 고치고, 계산은 곧바로 (2026-09-16)

사용자: *"매입가 수량 리스트에서 수정할 수 있도록 해줘 매입가 넣고 수량 넣으면 계산 바로 쉽게 될 수
있도록 한번에 여러개 고칠수도 있게."*

## 1. 무엇이 반대였나

| 종전 | 요청 |
|---|---|
| 토글을 켜면 행마다 입력칸 둘(위젯 격자) — 표 전체가 바뀐다 | **목록에서** |
| 한 칸만 바꿔도 **앱 전체를 다시 돌리고**(수십 초) 곧바로 파일에 썼다 | **계산 바로** · **쉽게** |
| 한 칸 = 한 번 저장 · 되돌리기 없음 | **여러 개 한꺼번에** |
| R320 이 오전에 넣은 한 종목 칸 — 한 번에 하나 | 〃 |

## 2. 고침 — 편집 길을 하나로

| 무엇 | 어떻게 |
|---|---|
| **목록 편집기** | `st.data_editor` — 보유 중 표 하나 + 접힌 미보유 표 하나 · 칸은 종목(잠김)·매입가·수량뿐 (아래 2-1) |
| **곧바로 계산** | `st.fragment` — 셀을 고치면 편집기 함수만 다시 돌아 매입금액·평가금액·평가손익·수익률 표와 **합계**가 곧바로 바뀐다(저장 전 값으로) |
| **한 번에 저장** | 버튼 이름이 *"변경 N개 저장"* · 바뀐 것이 없으면 잠김 · **실제로 바뀐 행만** 적는다 |
| **되돌리기** | 저장 **전** 값을 쥐었다가 같은 규칙으로 되적는다(빼기 R244 · R320 사고에서 나온 원칙) |
| 켜는 길 | 토글 *"매입가·수량 한꺼번에 고치기"* · 행마다 **'고치기'** 링크(`?edit=`)도 같은 편집기를 켠다 |
| 보기 표 | **늘** 그린다 — 편집기는 그 위에 열린다(표 높이 그대로) |
| 걷어낸 것 | 옛 행별 입력칸 격자(약 170줄) · R320 의 한 종목 칸 · 읽는 곳이 사라진 열 너비 상수 |

### 2-1. 같은 날 다시 고침 — 고칠 수 없는 칸을 고칠 칸 옆에 두지 않는다

사용자(첫 판을 본 뒤): *"현재가는 내가 고치는 게 아니잖아. 조금 더 편하게 · 헷갈리고 보유종목이랑
나눠줘야."* 첫 판은 한 표에 **코드·종목·현재가(잠김)·매입가·수량**을 보유·미보유 섞어 놓았다.
잠긴 칸이 고칠 칸과 같은 모양이라 어디를 고치는지 헷갈렸고, 새로 산 종목이 아니면 볼 일 없는
미보유 행이 보유 행과 한 목록이었다.

| 무엇 | 첫 판 | 고친 판 |
|---|---|---|
| 편집 표의 칸 | 코드 · 종목 · 현재가 · 매입가 · 수량 | **종목 · 매입가 · 수량** (코드는 숨긴 행 열쇠) |
| 보유 / 미보유 | 한 표에 섞음(보유 먼저) | **보유 중** 표 · **미보유**는 접힌 칸 *"새로 샀으면 여기서"* |
| 현재가 | 편집 표 안(잠김) | 아래 **계산 결과**(읽기 전용)에만 · *"자동으로 받아 온 값"* |

저장·되돌리기·계산 규칙(순수 함수 넷)은 **그대로**다 — 두 표의 값을 한 사전으로 모아 같은 함수에 넘긴다.

⚠️ **표를 가르자 미보유 표에 입력이 안 됐다** — 사용자가 바로 잡았다(*"미보유는 매입가 및 수량 수정
못하잖아"*). 미보유 행은 매입가가 **전부 빈 칸**이라 pandas 가 그 열을 object 로 두고, streamlit 은 그
열을 `EMPTY` 종류로 본다(실측: 전부 빈 칸 → EMPTY · 숫자 섞임 → FLOAT · float64 로 못 박음 → FLOAT).
첫 판은 보유 행과 한 표라 열이 FLOAT 였고, 그래서 **가르기 전에는 드러날 수 없었다.** 두 칸을 숫자 열로
못 박았고 §329 가 그 규칙과 EMPTY → FLOAT 를 양방향으로 심는다. ⚠️ 쓰기를 막은 앱 테스트는 이것을
**못 잡았다** — 시험 도구는 편집 상태를 세션에 직접 넣으므로 브라우저의 "이 열은 입력 불가"를 거치지
않는다. **시험이 사용자 동작을 재현했는지**(§4 의 그 문장)가 여기서 한 번 더 맞았다. 그래서 이번엔
**브라우저에서 직접** 확인했다 — 사용자 탭이 아닌 **새 탭(따로 된 세션)** 에서 미보유 매입가 칸에 입력하니
버튼이 *"변경 1개 저장"* 으로 바뀌었다(저장은 안 누르고 탭을 닫았다).

그리고 사용자: *"미보유 종목에 고치기 누르면 바로 고칠 수 있게 해줘야 하는 거 아냐?"* — 행의 '고치기'는
편집기를 **켜기만** 했고, 미보유 칸은 **접힌 채** 그 종목이 23행 어딘가에 있었다. 누른 종목을 기억해
(`wl_edit_focus`) **그 표 맨 위**로 올리고 미보유면 칸을 **펼치며**, 위에 *"고른 종목 … 맨 위에
두었습니다"* 를 적는다. 보기 순서만 바뀐다(저장 순서·행 수 불변 · 행 열쇠는 숨긴 코드). 맨 위 행이
바뀌면 편집 표의 열쇠도 바뀐다 — 옛 편집 상태의 **행 번호**가 다른 종목에 붙지 않게. 저장하면 안내가
끝난다.

그리고 사용자: *"수정한 뒤에 저장 버튼이 인식이 안 되거나 없어."* — **둘 다 실제였다.** ① 버튼이 계산 결과
표(보유 행 수만큼)와 합계 **아래 맨 끝**이라 표를 고친 자리에서 안 보였다. ② 버튼이 `disabled=(바뀐 행 0)`
이었는데, 표 칸은 **입력을 마쳐야(Enter · 다른 칸)** 값이 서버로 넘어간다 — 칸에 쓰는 중에 곧바로 저장을
누르면 그 순간 버튼은 **아직 잠겨** 있어 아무 일도 안 났다. 고침: 버튼을 **표 바로 아래**로 올리고 **잠그지
않는다** · 바뀐 것이 없으면 *"바뀐 칸이 없습니다 — … Enter 를 누른 뒤 다시 저장하세요"* 를 **말한다**(조용히
무시하지 않는다 · §3) · 캡션이 *"칸에 넣은 뒤 Enter"* 를 적는다. ⚠️ **잠근 버튼은 '누르지 마라'가 아니라
'눌러도 아무 일 없음'으로 읽힌다** — 입력이 비동기로 넘어가는 표 옆에서는 더 그렇다.

규칙은 순수 함수 넷(`_wl_pos_num` · `_wl_with_position` · `_wl_apply_edits` · `_wl_position_calc`)이
정하고 편집기·되돌리기가 **같은 것을 부른다**(§4).

- 합계는 매입금액·평가금액을 **둘 다** 구한 행만 더하고, 그런 행이 없으면 합계를 **안 만든다**(§3).
- 매입가를 비우거나 0 으로 두면 **미보유**로 옮겨진다 — 보유 여부는 매입가 하나로 갈린다(`_wl_owned`).
  편집기 캡션이 그 규칙을 그대로 적고, *"보유 판단에만 쓰이고 점수·적정가·추천에는 안 들어간다"* 를
  적는다(§9).

## 3. 곁들여 잡은 결함 — 빈 칸이 **값**이 될 뻔했다

표 편집기는 빈 칸을 **NaN** 으로 넘긴다. `float('nan')` 은 참이라 종전 규칙(`paid if paid else None`)이면
**매입가 칸에 NaN 이 저장**됐을 것이다 — 못 읽은 것을 값으로 만드는 자리(§3). `_wl_pos_num` 이
NaN · 0 이하 · 숫자 아님을 전부 None 으로 둔다. §329 가 심어서 잰다.

## 4. 확인 — 사용자 파일을 안 바꾸고 (앱 통째로)

`GAEUM_NO_LOCAL_WRITE=1`(세션만 바뀐다)로 앱 전체를 돌렸다. 값·이름은 안 찍고 참/거짓만:

```
① 토글 켠 렌더 예외 0 · 편집기와 저장 버튼이 뜬다 · 처음엔 잠겨 있다          참
② 보유 두 행을 고침(수량 +1 · 매입가 +10) → 버튼 '변경 2개 저장' · 풀림 · 합계 줄   참
③ 저장 → 두 행만 바뀜 · 다른 행 전부 그대로 · 행 수 그대로 · 예외 0             참
④ 되돌리기 버튼 → 두 행 원래 값 · 되돌리기 바 닫힘 · 예외 0                     참
⑤ 관심종목 파일 수정시각 그대로                                                 참
```

⚠️ **첫 판은 ③에서 '거짓'이 나왔다** — 버튼은 '변경 2개 저장'으로 풀렸는데 눌러도 안 바뀌었다.
앱 결함이 아니라 **내 시험의 틀**이었다: 브라우저는 저장을 누를 때 편집기 상태를 **같이** 보내는데,
시험 도구는 심어 둔 편집 상태를 그 다음 실행에 다시 안 보내 버튼이 빈 편집으로 눌렸다. 같은 수정을
누르는 실행에도 다시 심자 전 단계 참. **"안 됐다"를 앱 결함이라 적기 전에 시험이 사용자 동작을 재현했는지
본다**(R304 의 *안 나온 것이 아니라 안 재진 것*).

## 5. 사고 후속 (R320 §5)

오전 확인 중 보유 두 행의 매입가·수량이 비워진 일은 **아직 사용자 답을 받지 못했다.** 복구 도구
(`_probe/r320_restore_two_rows.py` · 백업 후 두 행만 · 그 사이 다시 적었으면 안 덮음)는 **돌리지 않았다.**
이제 편집기로 사용자가 직접 두 칸을 다시 적을 수도 있고, 적은 뒤 되돌리기도 된다.

## 6. 바꾸지 않은 것

값·문턱·산식·판정·점수·추천 불변. 계산부 파일 안 열었음. 관심종목 파일 형식 불변(같은 `paid`·`qty` 칸).
