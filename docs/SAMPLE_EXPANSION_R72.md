# 표본 확장 — 라운드 72

**"60,462건이 적은가?"** 에 답하려면 먼저 그 60,462건이 무엇인지 세야 한다.

```bash

C:/Python314/python.exe scripts/calibration_lab.py --universe 1500 --shard 1/6 --limit 25000
C:/Python314/python.exe scripts/calibration_lab.py                       # 전 샤드 합산 채점
```

## 1. 먼저 잰 것 — raw 가 아니라 정보량

| 지표 | 값 |
|---|---:|
| ① raw cases | 60,462 |
| ② 고유 종목 | 583 |
| ③ 고유 거래일 | 1,728 |
| ④ **독립 에피소드** (35일 묶음) | **17,428** (raw의 29%) |
| ⑤ 섹터군집 보정 유효표본 | 3,476 (섹터 미기록 54,718건 = 90.5%) |
| ⑥ 시장국면 보정 유효표본 | 1,831 |
| ⑦ 전방 전용 평가 n | **0** |
| ⑧ **고신뢰 전방 신호 n** | **0** |

기간은 **2013-11-12 ~ 2026-07-06** 이지만 실질은 2018년 이후다.
2013~2017 을 다 합쳐 **172건**뿐이고 2018년부터 연 4,000~8,200건이다.

**왜 앞이 비었나.** 생성기가 종목당 `n_dates=80` 개를 `spacing=25` 거래일
간격으로 뽑는다. 80 × 25 = 2,000봉이라 최근에서 과거로 8년만 닿는다.

국면은 **40.8%가 미기록**(`None`)이고, 섹터는 **90.5%가 미기록**이다.
섹터별 표본을 논하려면 이것부터 채워야 한다.

---

## 2. 천장을 먼저 쟀다

넓히기 전에 **얼마나 넓힐 수 있는지**부터 실측했다. 목표 숫자를 정해 놓고
거기에 맞추면 중복을 만들어서라도 채우게 된다.

### 날짜 축 — 천장 108개/종목

`start_date` 를 2010 으로 당겨도 **소용없다.** 시세 제공처가 종목당 약
3,000봉만 준다(2014-05-20 부터). 앞 260봉(지표 워밍업)과 뒤 21봉(채점용)을
빼면 usable 2,716봉이고, 간격 25로 뽑으면 `2,716 // 25 = 108` 개가 전부다.

현재 80 은 그 천장의 **74%** 만 쓰고 있었다. → `N_DATES = 108` 로 올렸다.

**간격(25)은 건드리지 않았다.** 보유기간이 20영업일이므로 그보다 좁히면
같은 종목의 인접 케이스가 겹쳐 독립성이 깨진다. 표본을 늘리려고 중복을
만드는 것은 raw 만 부풀리고 정보량은 그대로다.

### 종목 축 — 천장 3,014개

| | 종목 | 계획 최대 | 신규 |
|---|---:|---:|---:|
| 현재 (고정 목록) | 600 | 64,800 | — |
| `--universe 600` | 835 | 90,180 | 29,718 |
| `--universe 1000` | 1,141 | 123,228 | 62,766 |
| **`--universe 1500`** | **1,582** | **170,856** | **110,394** |
| `--universe 3014` | 3,066 | 331,128 | 270,666 |

전 종목은 3,014개(KOSPI 1,421 · KOSDAQ 1,593)다. `--universe 1500` 을
택했다 — 시총 1,159억 이상이고, 계획 170,856건이다.

## 3. 붙인 것

- **`N_DATES = 108`** — 데이터 천장까지. 2015~2017 커버가 열린다
- **`--universe N`** — 시총 상위 N 까지 유니버스 확장
- **`--shard i/n`** — 종목을 n 갈래로 나눠 병렬 축적. 워커는 자기 샤드
  파일에만 append 하고 **채점하지 않는다** (채점은 원장을 통째로 다시
  쓰므로 동시에 하면 서로를 덮는다 — 라운드 71c 와 같은 사고)
- **유니버스 캐시** — 목록을 파일에 박제한다. 샤드 6개가 각자 3,014종목을
  받아 오면 느릴 뿐 아니라 **분할이 깨진다**: 시총 순위는 장중에 바뀌므로
  워커마다 목록 순서가 다르면 `k % n` 이 같은 종목을 두 번 돌리거나
  빠뜨린다
- **`scripts/sample_audit.py`** — 위 8개 지표를 항상 같이 낸다

## 4. 정직하게 남겨 둘 한계

**생존편향은 넓혀도 안 없어진다.** 유니버스는 *현재 상장된* 종목만 준다.
상장폐지·거래정지 종목이 없다. 이건 데이터 출처의 한계이고, 종목을
3,014개로 늘려도 그대로다. 성과가 실제보다 좋게 보일 수 있다.

**2014-05 이전은 못 본다.** 3,000봉 상한 때문이다. 2008 금융위기,
2011 유럽 재정위기 같은 큰 하락 국면이 표본에 없다.

**표본을 늘려도 우위가 생기지는 않는다.** 라운드 71c 에서 잰 것 —
이 원장의 비용 후 손익분기 적중률은 63.3% 인데 blind 실적중은 51.86%
(−11.46%p 아래)다. raw 를 3배로 늘리면 **추정이 정밀해질 뿐** 그 격차는
줄지 않는다. 넓히기의 진짜 이득은 다른 데 있다:

- **유사사례 0건 문제 완화** — 횡단면 짝을 찾을 종목이 늘어난다
  (BGF리테일에서 실제로 0건이 나왔다)
- **섹터·국면 빈칸 채우기** — 지금은 섹터가 90.5% 미기록이다
- **중소형주 커버** — 현재 600종목은 대형주 편중이다

**⑧ 고신뢰 전방 신호가 0 이라는 사실은 넓혀도 안 바뀐다.** 그건 시간이
쌓아야 하는 숫자다. 과거 케이스가 30만 건이어도 미래에서 처음 본 고신뢰
추천이 몇십 건뿐이면 그 적중률은 여전히 불안하다.
