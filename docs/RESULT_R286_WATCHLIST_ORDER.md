# 결과 R286 — 미보유 표를 '살 자리가 가까운 순'으로 · 그 차례가 우열이 아님을 적는다 (2026-09-14)

## 1. 계기

사용자: *"미보유는 좋은거 위로 정렬해줘야지."*

라운드 214 는 같은 사람의 앞선 요청(*"안 산 것은 이름순으로 정리하고 매수할 거 우선순위로"*)을
**표는 이름순 · 우선순위는 머리에 한 줄**로 읽었다. 이번 말은 그 읽기를 정정한다 —
**표 자체**를 순서대로 놓아 달라는 것이다.

## 2. 무엇을 기준으로 놓았나 — 새 순서를 만들지 않았다

우선순위 줄이 **이미 쓰던 순서표**를 그대로 표에 적용했다(§2-6 — 새 문턱·새 순위 금지):

```
지금 매수 가능 → 매수 가능 → 눌림목 매수 대기 → 돌파 후 매수 대기 → 과열 해소 대기
→ 거래량 회복 대기 → 시장 국면 회복 대기 → 신뢰도·표본 확보 대기 → 데이터 부족
→ 권장가 괴리 과다 → 추천 제외
```

- 값은 `watch_action` 의 **kind** 다 — 화면이 이미 각 행에 그리고 있는 그 판단이다.
- **같은 자리 안에서는 이름순**(찾기 쉽게 · R214 가 지키던 것).
- 순서표에 없는 kind 와 **판단을 못 낸 행도 버리지 않는다** — 맨 뒤로 보낸다(§3).
- **점수순이 아니다.** 같은 날 종목을 점수로 세우는 데 정보가 없다는 것은 이미 쟀다.
- **보유 중은 이름순 그대로** 뒀다 — 가진 것은 이름으로 찾는다. 사용자가 말한 것도 미보유다.

정렬 열쇠와 우선순위 줄은 **같은 함수**(`_wl_kind_of`)로 kind 를 정한다 — 두 곳에 두면
언젠가 갈라진다(§4 · R214 가 라벨 승격을 두 번 적고 있던 자리를 하나로 합쳤다).

## 3. '위에 있는 것이 좋은 종목'으로 읽히면 안 된다

이 저장소가 업종 적중에서 한 번 고친 자리다 — **숫자만(차례만) 보여 주면 그게 판단이 된다.**
바로 어제도 차트의 `13 매수` 표식이 그렇게 읽혔다(R285). 그래서 표 위에 한 줄을 적는다:

> 위에 있을수록 **지금 손댈 수 있는 자리**라는 뜻입니다 — 종목의 좋고 나쁨을 매긴 순위가
> 아닙니다. 같은 날 종목을 점수로 세우는 것에는 정보가 없었습니다(개발 구간 166,132건 ·
> 기준일 2,609일 · 2026-08-16 실측).

근거는 **날짜와 표본 수**로 적는다(라운드 번호는 화면에 안 쓴다 · R227).

## 4. 화면 확인 (2026-09-14 · 서버에서 실측 · 미보유 18종목)

종목 이름은 사용자의 관심종목이라 **적지 않는다**(§9). 차례의 **모양**만 적는다:

```
미보유 18종목 · 매입가가 없는 종목 — 신규 매수 기준 · 살 자리가 가까운 순(같은 자리는 이름순)
살 자리가 가까운 순: 눌림목 매수 대기 2 · 과열 해소 대기 5 · 거래량 회복 대기 3 ·
                    신뢰도·표본 확보 대기 1 · 추천 제외 7

표 차례:  눌림목 대기 2행 → 과열 대기 5행 → 거래량 대기 3행 → 신뢰도·표본 1행 → 추천 제외 7행
          (각 묶음 안은 이름 오름차순)
```

무리 머리의 줄과 표의 차례가 **같다.** 오늘은 '지금 매수 가능'이 0종목이라 눌림목 대기가 맨
위다 — 위에 있다고 살 수 있다는 뜻이 아니라는 것이 그대로 보인다.

⚠️ **이름 감사가 나를 잡았다.** 처음에 이 자리에 실제 종목 이름 여덟을 적었다가
`_probe/r214_name_audit.py` 가 *"이번에 추가 1"* 로 찍어 걷어냈다 — 커밋 메시지에도 같이
들어가 있었다. 화면을 옮겨 적을 때 **사용자 자료가 문서로 새는** 자리가 여기다(§9).

## 5. 검사 — §299 (7건)

- 정렬 열쇠와 우선순위 줄이 **같은 함수**로 kind 를 정한다 · 모르는 kind 는 맨 뒤
- 무리 머리 문구가 실제 차례와 같다(종전 '이름순'이 남아 있으면 실패) · 보유 중은 이름순
- 차례가 우열이 아님을 적고 근거를 날짜·표본 수로 단다
- **심기**: '지금 매수 가능'이 맨 위 · 같은 자리는 이름순 · 모르는 kind 맨 뒤 · 판단 None 도
  안 버림 — 규칙을 **값으로** 돌려 확인한다(존재는 실행이 아니다 · R195)

**곁들여 옛 검사 둘이 조립을 잠그고 있었다.** §231 과 §243 이 `.sort(...)` **줄을 두 번
세는** 방식이라(R98b) 정렬을 바꾸는 순간 깨졌다. 잠글 것은 성질이다 — 보유 중은 이름순,
미보유는 순서표순, 그리고 §243 이 재려던 것은 애초에 **이름표**('안 산 것' → '미보유')였다.

## 6. 규칙으로 남기는 것

- **차례를 바꿔 달라는 말에 새 순위를 만들지 않는다.** 화면이 이미 각 행에 그리고 있는
  판단을 그대로 세우면 새 문턱이 안 생긴다.
- **차례에는 그것이 무엇의 차례인지 적는다.** 안 적으면 '위 = 좋은 것'으로 읽힌다.
