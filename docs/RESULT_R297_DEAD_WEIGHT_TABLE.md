# 결과 R297 — 산식을 재려다 **산식이 아닌 표**를 재고 있었다 (2026-09-15)

사용자: *"남은 것 계속 해줘"* — 남은 것 중 하나가 라운드 296 사전등록(DeMARK 가중치
0.13 이 값어치를 하는가)의 실제 측정이었다. **재려고 그 표를 따라가다 전제가 무너졌다.**

## 1. 내가 사용자에게 틀린 수를 말했다

어제·오늘 두 번, 나는 이렇게 적었다:

> *"DeMark은 그래프 장식이 아닙니다 — **종합 점수의 13%**입니다."*

**사실이 아니다.** 근거로 삼은 것은 이 표였다:

```python
TAB_WEIGHTS = {
    'pattern': 0.25, 'valuation': 0.22, 'scenario': 0.15,
    'demark': 0.13, 'technical': 0.13, 'integrity': 0.12,
}
```

이름은 *"탭 → 종합 점수 가중치 (합 1.0)"* 이고, 규칙집(`RULES_TAB_WEIGHTS`)에 들어 있고,
회귀가 **합 = 1.0** 과 **규칙집 일치**를 검사한다. 모든 신호가 *"이것이 점수를 만든다"*
라고 말한다.

**그런데 곱하는 코드가 없다.** AST 로 web_app 에서 닿는 모듈을 전수로 훑었다:

| | |
|---|---|
| 훑은 모듈 | **39개** |
| `TAB_WEIGHTS` 정의 | **1곳** (`quant_indicators.py:1523`) |
| **읽는 곳** | **0곳** |

## 2. 왜 표만 남았나 — 코드가 이미 적어 두었다

같은 파일 `:1721` 에 이유가 있다:

> ⚠️ 종합 점수는 **하나만** 존재해야 한다. 한때 이 함수가 탭 가중평균으로 별도 점수를
> 만들어, 화면에 49점과 65점이 동시에 떴다(16점 차이). … 규칙집 기반
> `final_action_score` 가 스캐너·TOP3·게이트를 모두 구동하는 시스템의 정본이므로
> 그것을 유일한 종합 점수로 삼는다. **탭 점수는 관점별 독립 판정으로만 쓰고 합산하지
> 않는다.**

**그 결정이 내려질 때 합산 코드는 지워졌고 표는 남았다.** 라운드 164 의 *"쓰기만 하고
아무도 안 읽는 세션 키는 죽은 버튼이다"* 와 라운드 195 의 *"존재는 실행이 아니다"* 가
만나는 자리다 — 다만 이번엔 **화면 키가 아니라 산식 표**였고, 그래서 더 그럴듯했다.

## 3. DeMARK 의 **진짜** 경로와 크기

끝까지 추적했다:

```
demark_bullish_signal / demark_bearish_signal        ← 0 또는 1
  bullish_consensus = demark + tdst + bollinger + williams + rsi + volume_flow + trend   (7개)
  signal_consensus_score = clip(50 + (강세 − 약세) × 10, 0, 100)
  final_action_raw_score += signal_consensus_score × 0.10
```

- DeMARK 는 **7개 신호 중 하나**다(TDST 도 DeMARK 계열이라 세면 2개).
- 신호 하나가 합의도를 **10점** 움직이고, 합의도의 최종 가중치가 **0.10** 이다.
- ⇒ **신호 하나의 종합 점수 기여 상한 = 1.0점** / 100점 (DeMARK 계열 둘이면 2.0점).

**13% 가 아니라 약 1%다.**

## 4. 그래서 사전등록 R296 은 R0 에서 접는다

사전등록이 **비용 순으로** 적어 둔 첫 관문이 *"R0 — 이득 상한: DeMARK 가 실제로 종합
점수를 움직인 폭이 작으면 접는다"* 였다. 그 관문이 그대로 답했다:

> **이득 상한 = 1~2점.** §2-7 — *"이득의 상한을 재기 전에 먼저 셈해 본다. 상한이 작으면
> 그것만으로 접는다 — 기각도 비용이다."*

**판정: (다) 현행 유지 · R0 미달로 접음. 재측정은 안 했다.** 사전등록 문서는 지우지
않고 정정 블록을 머리에 붙였다 — 틀린 전제로 무엇을 물으려 했는지가 기록이다(R260).

**R0 을 맨 앞에 둔 것이 실제로 돈을 아꼈다.** 그 관문이 없었으면 부트스트랩까지 돌려
놓고 *"13% 를 뺐더니"* 라는 존재하지 않는 비교를 발표했을 것이다.

## 5. 고침 — 지우지 않고 **말을 사실에 맞췄다**

- `TAB_WEIGHTS` 주석이 *"**이 표는 종합 점수에 곱해지지 않는다**"* 를 먼저 말하고,
  진짜 경로(신호 합의도 → 0.10 → ≤1점)를 적는다. 이름도 *"탭별 표시용 가중치
  (합 1.0 · **종합 점수 산식이 아니다**)"* 로.
- **표를 지우지 않았다** — 규칙집에도 있는 값이라 지우는 것은 규칙집을 건드리는 별도
  결정이다. 지금 필요한 것은 **읽는 사람이 속지 않는 것**이다.
- 회귀에 셋을 더했다: **읽는 운영 코드가 0곳**인가(AST 전수) · 그 사실이 표 옆에 적혀
  있는가 · **DeMARK 의 진짜 경로**가 그대로인가.
  종전 검사(*합 = 1.0*)는 그대로 두되, 그 옆에 *"이 표는 산식이 아니다"* 가 붙는다 —
  **합만 검사하면 없는 권위를 준다.**

## 6. 규칙으로 남기는 것

- **가중치 표가 있다고 그것이 산식인 것은 아니다.** 곱하는 자리를 눈으로 보기 전에는
  "이 지표가 점수의 N%"라고 말하지 않는다. 이름·규칙집·회귀 검사 셋이 다 있어도
  **읽는 코드가 없을 수 있다.**
- **내가 사용자에게 말한 수는 내가 검증한 수여야 한다.** 이번엔 표를 보고 말했고
  틀렸다. 정정은 빨리, 그리고 **왜 틀렸는지까지** 적는다.
- **비용 순 관문(§2-7)은 장식이 아니다.** R0 하나가 이 라운드를 몇 시간짜리 측정에서
  몇 분짜리 확인으로 바꿨고, 없는 비교를 발표하는 것을 막았다.
