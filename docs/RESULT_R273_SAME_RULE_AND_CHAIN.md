# 결과 R273 — 같은 식인 두 게이트 줄은 설명이 그것을 말한다 · 실패 분류는 우선순위 사슬임을 화면이 말한다 (2026-09-11)

전수조사 상태표(`docs/CENSUS_R252_STATUS.md`)의 남은 화면 항목 둘(#9 · #78). 둘 다 **값·문턱·자리·
조건 수 불변**이고 바뀐 것은 화면이 말하는 문장이다(R221·R234·R236·R237 계열 — 이름이 계산보다
넓으면 사용자는 없는 근거를 있다고 읽는다).

## 1. #9 — 11조건 중 두 조건의 판정식이 글자까지 같다

`verdict_core` 의 게이트 표에서 `'진입 깊이 현실적'` 과 `'보유기간 안 도달 가능'` 의 판정 불리언은
같은 식(`depth_sigma <= MAX_ENTRY_SIGMA` · σ 상한 하나)이다. 라운드 246 이 실재를 확인하고 **안
합쳤다** — 회귀가 `checks[7]` 을 자리로 읽어 조건을 합치면 자리가 밀린다. 그런데 안 합치는 것과 화면이
서로 다른 것을 재는 것처럼 보이는 것은 다른 문제다. 두 줄은 늘 같이 통과하고 같이 미달한다.

고침은 설명 문자열 한 조각: `'보유기간 안 도달 가능'` 의 설명 끝에 *"판정은 위 '진입 깊이 현실적' 과
같은 규칙(σ 상한 하나)"* 을 붙였다. §262 가 잠근 앞부분(`{HORIZON}봉 실측 체결률 기준 ` · 통과/미달
가르기)은 그대로다. 이름을 바꾸지 않은 이유: 조건 이름은 `verdict_core.exclude_reason`(두 이름을 한
사유 '권장가 괴리 과다'로 묶는다)과 회귀가 리터럴로 읽는다.

**왜 두 줄인가**는 이 라운드가 답하지 않는다 — 두 번째 줄이 원래 재려던 것(체결률 모형 `fill_p`)은
설명에 이미 숫자로 있고, 그것을 판정에 넣는 것은 새 문턱이다(§2). 지금은 "같은 규칙"이라고 말하는
것이 사실이다.

## 2. #78 — 실패 사유가 우선순위 사슬인데 화면은 나란한 원인으로 냈다

`calibration_lab.classify_failure` 는 **return 사슬**이다: 기간 내 미도달 → 인버스 방향 해석 → 레버리지
변동성 → 자기유사 표본 부족 → 과열 추격 → 시장 국면 역풍 → 노이즈 손절(목표 절반까지 갔다 반락) →
추세 역행(월10선 아래) → 방향 오판. 한 건은 처음 맞는 유형 하나에만 세어지고 **앞 가지가 뒤 가지를
먹는다.** 실측(2026-09-09 · 매수권 58+ 실패 · `_probe/r251_upper_bound.py`): '시장 국면 역풍' 이 '노이즈
손절' 조건까지 만족하는 건을 train 3,420건(9.31%) · blind 187건(7.38%) 가져가고, valid 는 BEAR 가 4건
(0.14%)뿐이라 그 건들이 뒤 가지로 흘러 '방향 오판' 44.71% 가 된다 — 원인의 크기가 아니라 사슬을 지난
뒤의 몫이다.

화면(모델 성적 ④ 실패 원인 분류)은 건수·누적손실 표만 냈다. 고침:

| 자리 | 무엇 |
|---|---|
| `scripts/calibration_lab.py` | 사슬 순서를 상수 `FAILURE_CHAIN` 으로 적고 산출물 `calibration.json` 에 `failure_chain` 으로 싣는다 — 문턱(70·85·0.5·5)·순서·이름 불변 |
| `web_app.py` | 표 아래 한 줄: *한 건은 처음 맞는 하나에만 세어진다 · 앞 유형이 드문 구간에서는 그 건들이 뒤 유형으로 흘러간다* · 판정 순서는 **산출물에서 읽어** 붙인다(§4 · 화면은 읽기만) · 산출물에 아직 없으면 "다음 채점 실행부터 표시" |

지금 배포된 `calibration.json` 에는 `failure_chain` 이 없다(랩이 다시 돌아야 생긴다 · 클라우드 축적이
매일 돌린다) — 그때까지 화면은 순서 없이 사슬이라는 사실만 말한다. 순서를 화면에 손으로 적지 않은
이유: 채점기와 화면이 두 곳에서 같은 목록을 들면 한쪽이 낡는다(R191·R120e).
