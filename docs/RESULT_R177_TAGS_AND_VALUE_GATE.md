## 1. 네 번째 물음이 결함이었다

짐작으로 답하지 않고 그 종목을 실제로 돌렸다.

| | |
|---|---:|
| 현재가 | **121,300원** |
| 펀더멘털 적정가 | **91,822원** (신뢰도 73 · CALIBRATED) |
| 현재가 / 적정가 | **+32.1%** |

문턱은 이미 정해져 있다 — 적정가의 **1.15배**를 넘으면
`적정가 크게 초과 (추격매수 위험)` 이고, `next_action` 이 그것을 **차단**한다.
**+32.1% 는 차단됐어야 한다.**

### 왜 안 막혔나

```python
fair_value_usable = (displayed_fair_value is not None
                     and recommended_buy_price is not None)   # ← 둘 다 필요
...
fair_ref = float(displayed_fair_value) if fair_value_usable else None
```

현대건설은 **'모델 간 편차 허용범위' 미달**로 `recommended_buy_price` 가
`None` 이었다. 그래서 `fair_ref` 까지 `None` 이 되고
`entry_zone = '판정 불가'` → 밸류 가드가 **통째로 안 걸렸다.**

**못 잰 값(권장 매수가) 때문에 아는 값(적정가)까지 버렸고, 그 기본값이
하필 '통과'였다.**

그리고 화면은 **같은 카드에서** 이미 이렇게 적고 있었다:

```
적정가 대비 상승여력 -24.3% (신뢰도 73점) · 진입 위치: 판정 불가
```

## 3. 고침 — **차단 쪽으로만**, 점수는 안 건드린다

적정가만 있으면 낼 수 있는 값을 따로 낸다.

```python
'fair_overshoot_pct': round((curr_price / displayed_fair_value - 1) * 100, 1)
```

`fair_value_usable` 에 **묶지 않는다.** 그리고 밸류 가드가 그것을 본다:

```python
_OVER_BLOCK_PCT = 15.0       # = entry_zone 의 fair_ref * 1.15 와 같은 값
over_value = over_value or (overshoot is not None and overshoot > 15.0)
```

**지킨 것 셋**

1. **문턱을 새로 고르지 않았다** (§2) — 구역 판정이 이미 쓰는 1.15 다.
2. **점수를 안 바꿨다** — `price_location_score` 도 `entry_zone` 도 그대로다.
   이 갈래는 **차단만** 하고 통과를 만들지 않으므로 완화가 아니다.
3. **못 잰 것으로 거르지 않는다** (§3) — 적정가가 없으면 이 가드는 안 건다.

## 4. 날 `<b>` 태그 — 전수

사용자 화면에 `<b>분석 보기</b>` 가 **글자 그대로** 나왔다.
`ui_kit._esc()` 는 이스케이프를 먼저 하고 `**굵게**` 표기만 되살린다
(라운드 120d — *"산문은 마크다운으로 쓴다, 받는 쪽에서 해석한다"*).

**코드 정적 스캔은 못 쓴다** — f-string 조각이 HTML 조립문과 안 갈려
109곳이 잡히는데 대부분 오탐이다. **렌더한 화면의 `innerText` 가 진실**이라
거기서 셌다: **4곳 · 2쌍**, 둘 다 추천 카드였다.

| 자리 | 고침 |
|---|---|
| `say = f"<b>{headline}</b>"` | `**{headline}**` |
| `<b>{gap:.1f}%</b>` | `**{gap:.1f}%**` |
| `<b>지금은 기다리는 편</b>` | `**지금은 기다리는 편**` |
| `<b>분석 보기</b>` | `**분석 보기**` |
| `<b>진입 기준이 없어…</b>` | `**진입 기준이 없어…**` |

회귀가 그 함수 안의 날 태그를 **0개로** 잠근다.

## 5. 관심종목 — 보유 / 안 산 것

두 무리는 **읽는 법이 다르다.** 보유분은 *들고 갈까·더 살까·정리할까*,
안 산 것은 *지금 살 자리인가*다. 라운드 169 가 판단 문구를 이미 그렇게
갈라 놓았는데(`watch_action` 의 `held`) 표는 섞여 있었다.

**순서만 나눈다.** 줄을 지우거나 합치지 않고 저장 색인(`_wl_body` 의
인덱스)은 그대로 써서 저장 로직이 그대로 맞는다.

## 7. 회귀 — §211

- 적정가만 있어도 넘침을 낸다 · 그 값이 `fair_value_usable` 에 안 묶였다
- 문턱을 새로 고르지 않았다 (구역 판정과 같은 15%)
- **`next_action` 을 실제로 호출해** 경계를 잰다:
  `+8% → buy_now` · `+15.0% → buy_now` · **`+15.1% → observe`** ·
  `+32.1% → observe` · **넘침 없음 → buy_now**
- **기준선이 매수 후보인지 먼저 확인한다** — 처음엔 진입가를 안 넣어
  '넘침 없음'과 '+32%'가 **둘 다 observe** 였다. 검사가 아무것도 못 재고
  있었고, 그 검사가 스스로 걸려서 알았다
- 추천 카드 산문에 날 `<b>` 가 0개 · **그 검사가 카드를 실제로 봤다**
