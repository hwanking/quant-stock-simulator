# 라운드 370 — 추가매수하면 위험이 얼마나 느나 (계산이지 판정이 아니다)

2026-09-27 · 순수 함수 하나 · 보유 포지션 카드에 접힌 계산기 하나 · 검사 1절(14건)
· 게이트·문턱·판정·산식 **불변** · 버전 없음(바뀐 파일이 어느 축의 담당도 아니다)

## 1. 왜

라운드 369 의 검토문이 가장 날카롭게 짚은 것이 이것이었다:

> 평단이 낮아져도 위험 금액은 커집니다 … 가늠이 판단해야 할 질문은 "첫 양봉이 나왔으니
> 평단을 낮출까?"가 아니라 "기존 물량에 더해도 손실예산과 계좌 한도 안인가?" 입니다.

라운드 357 도 같은 자리를 적어 두었다 — *"지금 화면에는 거래 단위 손실예산이라는 개념 자체가
없다 · 계산기가 먼저다."* 그리고 이 셈에는 **문턱이 하나도 없다** — 사용자가 정한 추가 수량의
결과를 보일 뿐이라 §2 에 안 걸린다.

## 2. 무엇을 했나

- **`portfolio.add_on_risk(paid, qty, px, stop, add_qty, add_px)`** — 순수 함수 한 곳(§4).
  추가 전/후 각각 보유 수량 · 평단 · 매입 금액 · 평가손익 · 손절선에 다 팔면 총손익 ·
  현재가에서 손절선까지 더 잃을 금액을 낸다.
- **보유 포지션 카드 아래 접힌 계산기** — 추가할 수량(기본 0)과 추가 가격(기본 현재가).
  수량이 0 이면 아무 표도 안 그리고 *"추가매수를 해도 되는지는 위의 '물타기 판정'이
  정합니다"* 만 적는다. 손절선은 **보유 계획의 손절선**(잰 날에 고정된 값 · R224)을 쓴다.
  `st.fragment` 로 감싸 입력마다 앱 전체가 다시 돌지 않는다(R329). **파일에 안 쓴다.**

검토문의 예시가 그대로 나온다(회귀가 값으로 심는다):

| | 추가 전 | 8,500원에 100주 추가 후 |
|---|---:|---:|
| 평단 | 10,000 | 9,250 |
| 현재 평가손익 | −150,000 | −150,000 |
| 손절선 8,000 에 다 팔면 | −200,000 | **−250,000** |
| 현재가에서 손절선까지 더 잃을 금액 | −50,000 | **−100,000** |

**평단은 내려가도 이미 난 손실은 그대로이고, 앞으로 걸리는 금액은 추가한 만큼 커진다.**

## 3. 지어내지 않는다 · 가정을 숨기지 않는다

- 입력을 못 읽으면(None · NaN · 0 · 음수 · 소수 주식 수) **None** — 표를 안 그리고 사유를 적는다(§3).
  NaN 은 편집기의 빈 칸이 넘겨주는 값이다(R321).
- 손절선이 없으면 손절 두 줄은 **계산하지 않는다**.
- 현재가가 이미 손절선 **아래**면 *"앞으로 더 잃을 금액"* 은 정의가 안 된다 — 음수를 만들지 않고
  *"계획대로면 파는 자리입니다"* 를 적는다(R338 의 낱말).
- **가정 둘을 결과와 같이 적는다** — ① 손절선 가격에 그대로 팔린다고 가정했다(갭·체결 불가면
  더 잃는다) ② 거래비용은 빼지 않았다. ①은 라운드 367 이 **바로 그 가정에 속을 뻔한** 자리다
  (손절선 체결을 가정하자 세 구간이 다 통과하는 허구가 나왔다). 문장은
  `portfolio.ADD_ON_ASSUMES` 한 곳에 있고 화면은 읽기만 한다.

## 4. 판정이 아니다 — 그리고 옛 블록과 다르다

카드 바로 위 주석(라운드 224)이 걷어낸 옛 블록 넷째 줄은 *"평단을 1차 목표가로 낮추는 데
필요한 **주수**"* 를 셈했다 — 그것은 **물타기를 돕는** 셈이었고 `:2113` 이 이미 *"평단 낮추기
목적의 추가 매수는 하지 마세요"* 로 폐기한 산식이다. 이것은 반대 방향이다 — 사용자가 이미 정한
수량이 **위험을 얼마나 키우는지** 보인다. 추가매수를 해도 되는지는 여전히 중앙 판정 한 곳
(`ui_kit.holder_kind` · `avg_down_ok` · 물타기 6조건)이 정하고, 계산기의 제목과 문장이 그렇게
말한다(§4).

## 5. 확인

- 회귀 §365(14건): 예시 값 넷 · 추가 0 이면 전후 같음 · 손절선 넘으면 None · 못 읽는 입력 여섯 →
  None · 손절선 없으면 None · 가정 둘 · 화면이 계산을 한 곳에서 받음 · 파일에 안 씀 · 가정 문장을
  다시 적지 않음 · '판정이 아닙니다' 와 판정 자리를 가리킴 · 조각으로 감쌈. 문자열은 AST 로 읽는다.
- **쓰기를 막은 앱 테스트**(`GAEUM_NO_LOCAL_WRITE=1` · 창으로 안 한다 · R320): 보유 행 하나를
  열어 카드·계산기 펼침이 그려지고 · 수량 100 을 넣자 전후 표가 나오며 · 화면의 추가 후 평단이
  함수와 같고 · 가정 문장이 화면에 있고 · 예외 0(두 번) · **파일 수정시각 불변**.
- ⚠️ 처음엔 창(브라우저 칸)으로 보려 했다 — 그 종목이 검색 단계에 멈춰 있어 클릭해야 했고,
  그 창은 사용자와 같이 쓴다(R320 에서 보유 두 행이 비워진 자리). 계산기는 안 쓰지만 같은 화면에
  쓰는 버튼이 있어 앱 테스트로 바꿨다.
- ⚠️ 돌고 있던 서버는 `add_on_risk` 가 없던 `portfolio` 를 들고 있었다 — 재시작한 뒤 봤다(R293·R328).

## 6. 안 한 것

- **비중 한도·손실예산 %** 는 안 넣었다 — *"계좌의 2%"* 같은 기본값을 넣는 순간 손으로 고른 수다(§2).
  사용자가 정한 예산과 견주는 칸은 사용자 설정이 먼저다.
- 1:2:6 분할·피라미딩은 안 넣었다(R357) — 수량 정책은 매매정책 변경이고 잰 적이 없다.
- 계좌 전체 합산(다른 종목·ETF 겹침)은 안 했다 — 이 카드는 한 종목의 계산이다.
