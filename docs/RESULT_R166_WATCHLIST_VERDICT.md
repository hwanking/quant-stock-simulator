## 1. 파다가 먼저 나온 것 — 문구가 게이트와 다른 값을 댔다

다날 화면이 이렇게 적고 있었다.

> 적정가 5,184원보다 **−6.2% 비싸서** 규칙이 막고 있습니다.

**−6.2% 는 싸다는 뜻이다.** 문장이 자기모순이었고, 더 나쁜 것은
**게이트가 쓰지 않는 숫자**를 근거로 댔다는 점이다. 실측:

| 값 | 다날 |
|---|---:|
| 적정가 | 5,184원 |
| **안전마진선** (게이트가 보는 값) | **4,147원** |
| 진입가 | 4,863원 |
| 게이트 비율 (진입 ÷ 안전마진선) | **1.173** → 1.15 초과 → 차단 |

고쳤다. 이제 이렇게 나간다 (화면 실측):

> 여기까지 내려와도 아직은 못 삽니다. **규칙이 보는 선은 안전마진선
> 4,147원인데 이 값이 그보다 +17.2% 위입니다.**

그리고 접힌 설명에 **세 값의 관계**(적정가 → 안전마진선 → 이 값)를
적어 어느 것과 견주는지 보이게 했다.

## 2. 미산출을 '0점'으로 적고 있었다

관심종목 표에서 ETF 의 적정가 신뢰도가 **`0 낮음`** 으로 나왔다.

```
fair_value_status      = UNCALCULATED     ← 산출하지 않았다
fair_value_confidence  = 0.0             ← '못 쟀다'는 뜻
화면                     = "0 낮음"        ← 0점짜리 낮은 신뢰도로 읽었다
```

**미산출을 값으로 만든 것**이라 §3 위반이다. 적정가가 없으면 신뢰도도
없다 — 이제 `—` 로 나간다 (화면 실측 확인).

## 3. 관심종목에 **엔진 판단** 칸을 붙였다

사용자 요청 1번. `verdict_core` 가 낸 `bucket` 을 그대로 담는다 —
**화면이 새 판정을 만들지 않는다** (§4).

| 엔진이 낸 말 | 표에 적는 말 |
|---|---|
| 오늘 매수 가능 | 매수 가능 |
| 눌림목 매수 대기 / 돌파 후 매수 대기 | 눌림목 대기 / 돌파 대기 |
| 과열 해소 대기 / 거래량 회복 대기 / 시장 국면 회복 대기 | 과열·거래량·국면 대기 |
| 권장가 괴리 과다 | 괴리 과다 |
| 추천 제외 | 제외 |
| (아직 안 잰 종목) | **아직 안 잼** |

**'내 계획'(사용자)과 '엔진 판단'(엔진)은 다른 칸이다.** 섞지 않는다 —
전자는 §9 에 따라 점수·적정가·판정에 들어가지 않는다.

## 4. 빈 칸을 채우는 버튼

사용자 요청 2번. 종전에는 **그 종목을 열어야만** 채워졌다(라운드 141).
개장 전 리포트에 오르지 않는 종목은 영원히 비어 있었다 — 화신·남화토건·
BGF리테일이 그랬다.

자동으로 돌리지 않는다. 한 종목 정밀분석이 **1~3분**이라 화면을 열
때마다 돌면 앱이 멈춘다(라운드 141 이 그래서 안 했다). 대신

- **버튼**으로 사용자가 시작하고
- **얼마나 걸리는지 미리 적고** (한 번에 5종목씩)
- 실패한 종목은 **사유를 그대로** 적는다 (통과로 넘기지 않는다 · §3)

**실제로 눌러서 확인했다.** 로직을 베껴 검사하면 아무것도 증명하지
못하므로(`tests-that-copy-the-logic-prove-nothing`) AppTest 로 **그
버튼**을 눌렀다 (`_probe/wl_fill_click.py`).

```
버튼 찾음: 1개 (label='3종목 지금 계산해서 채우기')
누른 뒤 — 예외 0건
값 없는 것 3 → 0 · 채워진 종목: ['BGF리테일', '남화토건', '화신']
```

그리고 채워진 값이 **정직하다**:

| 종목 | 목표 매수가 | 적정가 | 엔진 판단 |
|---|---|---:|---|
| 다날 | 4,863원 | 5,184원 | 눌림목 매수 대기 |
| 화신 | **—** | 16,412원 | **데이터 부족** |
| 남화토건 | **—** | 8,486원 | **데이터 부족** |
| BGF리테일 | **—** | 136,440원 | **데이터 부족** |

세 종목은 적정가는 나오지만 실행 가격을 못 낸다. 종전에는 그냥 `—` 라
**왜 비었는지 알 수 없었는데**, 이제 엔진 판단 칸이 *'데이터 부족'* 이라
답한다. 사용자가 물은 것이 정확히 그것이었다.

## 5. 보유 여부를 관심종목과 연동

사용자 요청 3번. 관심종목 표에 매입가·수량을 적어 두고도 *"이 종목을
갖고 계신가요?"* 칸은 0 이라 같은 사실을 두 번 적어야 했다.

**순서를 못 박았다** — 보유종목이 먼저, 없으면 관심종목.
그리고 **어디서 온 값인지 화면이 밝힌다**:

> **다날** — **관심종목**에 적어 두신 값으로 채웠습니다 (105주 · 평단
> 4,760원). 포트폴리오 판단에도 넣으려면 '내 보유종목'에 등록하세요 —
> 관심종목의 값은 개인 메모입니다.
