## 3. 설계

### 3.1 업종 → 글로벌 프록시 매핑

KRX `Industry`(KSIC) 79종을 프록시 그룹으로 묶는다. 이 매핑은 **의미
대응**이지 수치가 아니다(§2가 금지하는 것은 문턱·가중치·상한이다).
매핑되지 않는 업종은 **미연동**으로 두고 조정하지 않는다.

### 3.2 업황 신호 정의 — 측정 전 고정

기준일 `date` 시점에 **그 전날까지의 데이터만** 써서 계산한다.

```
mom60  = 프록시 60거래일 수익률
mom20  = 프록시 20거래일 수익률
rs     = mom60(프록시) − mom60(US500)      # 시장 대비 상대강도
```

### 3.3 업황 구간 — 새 문턱을 만들지 않는다

§2.6: *"가능하면 새 숫자 대신 이미 채택된 구간 규칙을 재사용한다."*

`regime_policy.BANDS` 가 이미 사전등록된 구간 규칙이다. 프록시 모멘텀을
그 구간 체계에 넣는다. 새 경계(+15%/−10% 같은)를 손으로 만들지 않는다.
구간 경계는 **train 구간 분위수**(20/40/60/80분위)로 잡는다 — 이것은
데이터가 정하는 값이지 내가 고르는 값이 아니다.

### 3.4 조정 폭 — 측정값에서만 나온다

사양은 신뢰도 80+ → ±15%, 60~79 → ±8%, 40~59 → ±3%를 예시로 들었다.
**이 숫자를 그대로 쓰지 않는다.** 신뢰도 등급 경계(80/60/40)는
`price_axes.TIERS` 에 **이미 사전등록돼 있으므로 재사용**하되, 각 등급의
조정 **폭**은 train 구간에서 실측한 lift 로 정한다.

측정되지 않으면 폭은 **0%다.** 라운드 42 뉴스 가점을 0으로 둔 것과 같은
원칙 — 검증 못 한 것으로 위험을 늘리지 않는다.

## 4. 채택 조건 (측정 전 고정)

### 4.1 신호 자체가 존재하는가 — 게이트 0

이걸 못 넘으면 나머지는 볼 필요가 없다.

| # | 조건 | 기준 |
|---|---|---|
| G1 | 최상위 업황 구간과 최하위 구간의 **블라인드 적중률 차이** | **≥ 5.0%p** |
| G2 | 두 구간 Wilson 95% 구간이 **겹치지 않음** | 겹치면 기각 |
| G3 | 방향이 train·valid·blind **세 구간 모두 동일** | 하나라도 뒤집히면 기각 |
| G4 | 각 구간 표본 | **≥ 100건** |

G1의 5.0%p 는 라운드 28b에서 **이미 사전등록해 쓴 lift 기준**이다.
새로 만든 숫자가 아니다.

### 4.2 운영 반영 조건 — 전부 충족

| # | 조건 | 기준 |
|---|---|---|
| ① | 업황 상위 구간 블라인드 비용후 EV | **> 0** |
| ② | 상위 구간 블라인드 표본 | **≥ 100건** |
| ③ | 상위 구간 Wilson 하한 | **≥ 기준선(56.1%) 하한(50.2%)** |
| ④ | 손익비 | 기준선 대비 **비악화** |
| ⑤ | 신호율 | 매수권의 **≥ 30%** 유지 |
| ⑥ | 국면 편중 | 한 국면이 통과 신호의 **≤ 60%** |
| ⑦ | 업종 편중 | 한 업종이 통과 신호의 **≤ 40%** |

⑧을 '통과'로 세지 않는다. **측정 못 한 것을 통과로 세면 그때부터
숫자를 지어내는 것이다.**

### 4.3 조건별 처분

- **G1~G4 미달** → 오버레이 **전면 기각**. 데이터층과 화면 표시만 남기고
  조정 폭 0%로 출시. 화면에 "검증 미통과 — 적정가 미반영"이라고 적는다
- **G 통과 · ①~⑦ 일부 미달** → 조정 폭을 **표시 전용**으로 두고 판정 미반영
- **전부 통과** → 실측 lift 를 조정 폭으로 삼아 운영 반영

## 5. 과도 반영 방지 (사양 §4 수용)

조정 계수는 다음을 **전부** 만족할 때만 활성화한다.

1. 독립 데이터 **3개 이상** 같은 방향 (글로벌 프록시 · 국내 업종 상대강도 · 매크로)
2. 프록시 데이터 신선도 — 최종 수신일이 기준일 대비 **5거래일 이내**
3. 종목의 업황 민감도 β 가 유의 (미산출이면 조정 없음)
4. 가격 선반영 — `range_pos` 상위 구간이면 조정 폭 축소
5. 출처·수집시각·기준일을 결과에 **같이 저장**

독립 데이터가 3개 미만이면 조정하지 않고 "근거 부족"으로 적는다.

## 6.5 뉴스 엔진과 적정가 엔진의 역할 분리 (사양 §5 수용)

사양: *"뉴스 엔진이 직접 적정가를 올리고 내리게 하지 마세요."*

동의한다. 라운드 42에서 뉴스에 이미 같은 구조를 썼다 — 재는 쪽
(`news_feed`)과 쓰는 쪽(룰북 `[RULES_NEWS]`)을 갈랐다. 섹터도 같다.

```
① news_feed        산업 변화 후보 탐지 (제목·시각·링크만)
② news_feed        중복·후행·저품질 제거 (24시간 신선도 · 낱말 경계)
③ sector_cycle     프록시·매크로로 사실 확인 ← 라운드 44 신설
④ sector_cycle     업종 선행지표 변화 확인   ← 대부분 미연동
⑤ (미구현)         기업 실적 연결 가능성      ← 컨센서스 미연동
⑥ (미구현)         가격 선반영 확인           ← range_pos 로 가능하나 미적용
⑦ 룰북             ①~⑥ 통과분만 계수에 반영  ← **현재 계수 0**
```

**③~⑥ 중 실제로 도는 것은 ③뿐이고, ⑦의 계수는 0이다.** 그러므로 지금
파이프라인은 **뉴스도 섹터도 적정가를 움직이지 않는다.** 구조만 세워
두고 계수를 0으로 둔 것이며, 이 사실을 화면에 적는다.

기사 수나 긍정 낱말 수가 적정가를 움직이는 경로는 **코드에 없다.**
