# R220 — 업종 칸에 `동일업종 PER` 이 들어가 있었다: 비교표 라벨을 업종으로 집었다 (2026-09-04)

**상태**: 데이터 정직성 수정 (§3) · 판정·문턱 변화 없음 · 업종 성적은 여전히
**표시 전용**(R44). 새 숫자 없음.

## 발단 — R218 이 넓힌 표를 눈으로 훑다가

R218 이 업종 커버리지를 82.8% → 97.1% 로 올린 뒤, 표시 문턱(n≥30) 근처의
업종을 감사하다가 목록에서 이것을 봤다:

```
동일업종 PER      n 35 · 적중 45.7 · W하한 30.5 · EV -0.980
```

**그건 업종이 아니다.** 네이버 종목 페이지의 '동일업종 비교' 표에 붙은 라벨이다.

## 기전 — 첫 매치를 그대로 썼다

```python
sec_m = re.search(r'sise_group_detail\.naver\?type=upjong&no=\d+"[^>]*>(.*?)</a>', html_m)
if sec_m:
    sector = re.sub(r'<.*?>', '', sec_m.group(1)).strip()
```

그 링크는 페이지에 **여러 개**다. 실물로 확인했다(2026-09-04):

| 종목 | 매치 수 | 매치 내용 |
|---|---:|---|
| 005930 | 4 | **반도체와반도체장비** · 더보기 · 동일업종 PER · 동일업종 등락률 |
| 071840 | **2** | 동일업종 PER · 동일업종 등락률 — **진짜 업종 링크가 없다** |

정상 종목은 첫 매치가 진짜 업종이라 아무 문제가 없었다. 그런데 회사 정보에
업종 링크가 **없는** 종목에서는 비교표 라벨이 첫 매치가 되고, 그것이 그대로
업종이 됐다. 원장 실측: `동일업종 PER` 이 업종인 행 **108건 · 종목 1개**.

**라운드 164 가 적어 둔 그대로다** — *"못 읽은 것을 '다른 값'으로 만들지
않는다. 판별에 실패하면 None 이다."* 그때는 종목코드였고 이번엔 업종이다.

## 고침 — 판별을 모듈 함수로 빼고, 못 읽으면 None

`bitemporal_engine.sector_from_html(html)` 하나가 규칙을 갖는다. 페이지
가구(`동일업종…` 로 시작하는 라벨 · `더보기`)를 건너뛰고, 남는 것이 없으면
**None** 을 돌려준다. 자리를 채우지 않는다.

**영향은 재고 나서 고쳤다** — 25종목으로 현행 규칙과 새 규칙을 대조:

| | 결과 |
|---|---|
| 달라진 종목 | **1개**(071840 → `None`) |
| 그대로인 종목 | **24개** (글자까지 동일) |
| 고친 함수 재대조 | **25/25 일치** |

근거: `_probe/r220_sector_impact.txt` · `_probe/r220_verify_fix.txt`

## 원장에 이미 남은 108행은 어떻게 했나

**지우지 않았다**(R197 — 파생물을 줄이지 않는다). 대신 소비자인
`scripts/gen_sector_perf.py` 가 **엔진과 같은 판별**을 불러(라벨 목록을
베끼지 않는다 · §4) 그 행을 빼고, 그 수를 **사유로 세어 적는다**:

```
커버리지 95,681/98,600 (97.0%) — 행 45,309 · 패치 36,302 · 종목 14,070
빠짐: ETF 2,697 · 업종 중복기록 32 · 미상 155 · 업종 아닌 라벨 35
```

업종 수 **74 → 73** (가짜 하나가 빠졌다). 커버리지 97.1% → 97.0% 로 0.1%p
내려간 것은 **정직해진 것**이지 나빠진 것이 아니다 — 35행이 '아는 업종'에서
'못 읽은 업종'으로 옮겨 갔다.

§235 의 항등식(출처+사유=대상 행수)에도 새 항을 넣었다. 항등식은 **모든**
사유를 담아야 한다.

| ② 비교표 라벨만 있는 HTML | **None** |
| ③ '더보기'만 있는 HTML | **None** |
| ④ 빈 HTML · None | **None** |

그리고 구조를 본다 — 호출부가 그 함수를 쓰는가(파싱 규칙이 두 벌이 되지
않게) · 생성기가 엔진의 판별을 **불러 쓰는가**(베끼지 않는가) · 뺀 행을
사유로 세는가 · 표에 그 가짜 업종이 **없는가**(값으로) · 그럼에도 원장 행은
남아 있는가.

## 남는 것

- 그 종목의 진짜 업종은 **여전히 모른다**. 네이버 페이지에 링크가 없으니
  이 경로로는 못 받는다 — `None` 이 맞는 답이다. 다른 출처(KRX·FDR)를 붙일지는
  별도 판단이다(§2 — 이득 상한이 1종목이라 지금은 접는다).
- 같은 모양이 또 있는지: 업종 라벨 전수를 훑어 '업종 같지 않은 문자열'을
  찾았고, `동일업종 PER` 하나뿐이었다(`양방향미디어와서비스` 는 정상 업종명).
