# 디자인 시스템 — 토큰·타이포·카드·인터랙션

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 톤의 기준은 핫셀블라드(hasselblad.com)식 절제: 여백이 구조를 만들고,
> 색은 의미가 있을 때만 쓰며, 장식은 없다. 금융 데이터 앱이므로 여기에
> "숫자의 정확한 정렬(tabular-nums)"과 "상태의 정직한 표기"를 더한다.
> 모든 토큰은 CSS 변수로 선언하고, 라이트/다크는 변수 값 교체만으로 전환한다.

## 1. 디자인 토큰

### 1-1. 표면 (Surface)

| CSS 변수 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--bg-app` | `#f4f6fa` | `#12161f` | 앱 배경 (다크는 순검정 금지 — 짙은 차콜/네이비) |
| `--bg-card` | `#ffffff` | `#1a202c` | 카드 배경 |
| `--bg-card-hover` | `#fafbfd` | `#202736` | 카드 hover (미세 명도차) |
| `--bg-inset` | `#eef1f6` | `#151a24` | 카드 안 하위 영역(코드·표 헤더) |
| `--border` | `#e2e7ef` | `#2a3242` | 기본 경계선 (다크는 낮은 대비) |
| `--border-strong` | `#c9d2df` | `#3a4458` | 강조 경계선 (중요 카드만) |

### 1-2. 텍스트 3단계

| CSS 변수 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--text-1` | `#1a2233` | `#e8ecf4` | 제목·핵심 숫자·행동 결론 |
| `--text-2` | `#46536b` | `#a8b2c4` | 본문·카드 설명 |
| `--text-3` | `#7a879e` | `#727e93` | 보조·캡션·기준일 스탬프 |

### 1-3. 의미 색 (Semantic)

| CSS 변수 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--accent` | `#1f3a6e` (네이비) | `#5b8def` (블루) | 주색 — 링크·선택 탭·주 버튼 |
| `--accent-strong` | `#2b52a3` (딥블루) | `#7ea8f5` (시안 기운 블루) | 강조·포커스 링 |
| `--positive` | `#1e7a5a` (절제 녹색) | `#4fd1a5` (민트) | 상승·매수 계열·게이트 통과 |
| `--warning` | `#b07a1e` (앰버) | `#e0b34e` (골드) | 관망·지연·주의 게이트 |
| `--danger` | `#b3403f` (절제 빨강) | `#f08a80` (코랄) | 하락·손절·차단 게이트·오류 |
| `--neutral` | `#6b7787` | `#8b95a8` | 중립·산출 불가·해당 없음 |

의미 색 배경 틴트(배지·배너용)는 각 색의 8~12% 투명도 오버레이로 파생한다
(`color-mix(in srgb, var(--positive) 10%, var(--bg-card))`). 형광·채도 과잉 금지.

주의: 한국 시장 관례(상승=빨강)와 국제 관례(상승=녹색)가 충돌한다.
**등락 색은 의미 색과 분리해 `--up`/`--down` 별도 변수로 두고, 기본값은
상승=`--positive` 계열로 하되 설정에서 한국식 반전을 허용**한다. 어느 쪽이든
색 단독 표기는 금지 — 부호(+/−)와 방향 아이콘을 항상 병기한다
(ACCESSIBILITY_CHECKLIST 참조).

### 1-4. 기타 토큰

| CSS 변수 | 값 | 용도 |
|---|---|---|
| `--radius-card` | `12px` (허용 10~14px) | 카드 모서리 |
| `--radius-badge` | `6px` | 배지·칩 |
| `--shadow-card` | 라이트 `0 1px 3px rgba(20,30,50,.06)` / 다크 `0 1px 3px rgba(0,0,0,.25)` | 매우 약한 그림자 |
| `--space-1..6` | `4/8/12/16/24/32px` | 간격 스케일 (카드 안 16, 카드 사이 24 기본) |
| `--content-max` | `1280px` | 데스크톱 최대 콘텐츠 폭 |

## 2. 타이포그래피

- 글꼴: **Pretendard** (한글) + 시스템 폴백(`"Pretendard", -apple-system,
  "Malgun Gothic", sans-serif`). 숫자는 전 구간 `font-variant-numeric:
  tabular-nums` — 표·카드에서 자릿수가 흔들리면 안 된다.
- 웹폰트는 로컬 서빙(외부 CDN 의존 금지 — 오프라인 실행 고려).

| 위계 | 크기 | 굵기 | 용도 |
|---|---|---|---|
| 페이지 제목 | 28–32px | 700 | 화면당 1개 |
| 행동 결론 | 24–30px | 700 | 결론 배너 문구 |
| 핵심 숫자 | 26–36px | 600 | 종합점수·현재가 (tabular-nums) |
| 섹션 제목 | 18–22px | 600 | 카드 그룹 제목 |
| 카드 제목 | 14–16px | 600 | 카드 헤더 |
| 본문 | 14–16px | 400 | 설명·근거 |
| 보조 | 12–13px | 400 | 기준일·출처·단위. **12px 미만 금지** |

행간: 본문 1.6, 숫자 블록 1.2. 한 카드 안에서 크기 위계는 3단 이하.

## 3. 카드 규칙

- radius `--radius-card`, 그림자 `--shadow-card`, 내부 여백 16~20px.
- **정보 3단계 이하**: 카드 제목 → 핵심 값 → 보조 1줄. 그 이상은 펼쳐보기나 탭으로.
- 강조 테두리(`--border-strong` 또는 의미 색 1px)는 화면당 1~2개의 중요 카드만.
  전 카드 채색 금지 — 카드 배경은 항상 `--bg-card`, 의미 색은 배지·막대·아이콘에만.
- 모든 데이터 카드는 우하단 또는 헤더에 기준일 스탬프(`--text-3`, 12–13px)를 단다.
- 클릭 가능한 카드는 hover 시 `--bg-card-hover` + 1px 상승(translateY(-1px))만.

## 4. 아이콘·그래프 규칙

- 아이콘: 단일 선형(line) 세트 하나로 통일(예: Lucide 계열을 로컬 포함).
  픽토그램 혼용 금지. 크기 16/20/24px 3종.
- 이모지는 **행동 결론 배너에만** 허용(현재 코드의 사이드바·캡션 이모지는
  이행 시 선형 아이콘으로 교체). 전문 화면(감사·모델 성과)은 이모지 0.
- 그래프:
  - 양 테마에서 **같은 의미는 같은 색 변수** — 테마 전환 시 의미가 바뀌면 안 된다.
  - 색맹 친화: 상승/하락을 색+마커 모양(▲/▼)으로 이중 부호화.
  - 그라데이션 채움·3D·파이 차트 금지. 점수는 수평 막대가 기본.
  - 원형 게이지는 종합점수 한 곳만 선택적 허용 (점수 카드 위계 원칙).
  - 축·격자선은 `--border`, 라벨은 `--text-3`.

## 5. 점수 카드 위계 (브리프 §점수 카드 위계 구현 규격)

| 단계 | 내용 | 표현 |
|---|---|---|
| 1 | 최종 행동 (7단계 판정) | 결론 배너 — 24–30px, 의미 색 틴트 배경 |
| 2 | 종합점수·신뢰도·표본·적중률 | 큰 숫자 26–36px + 신뢰도 수평 막대 + "n=표본" 병기 |
| 3 | 핵심 세부점수 (추세·모멘텀·거래량·뉴스·위험·전략 품질) | 수평 막대 6개, 값 라벨 |
| 4 | 기타 상세 (산식·기여도) | 펼쳐보기(expander) 내부 |

## 6. 마이크로 인터랙션 — 허용 목록 (이외 전부 금지)

| 허용 | 규격 |
|---|---|
| 카드 hover 미세 상승 | translateY(-1px) + 배경 전환, 120ms ease |
| 숫자 값 전환 | 150ms 부드러운 교체 (카운트업 애니메이션 금지) |
| 탭 전환 | 120ms 짧은 fade |
| 갱신 상태 표시 | 스피너/스켈레톤 (고정 위치, 레이아웃 점프 금지) |
| 오류 배너 등장 | 1회 slide-in, 이후 정적 |
| 포커스 링 | `--accent-strong` 2px outline (제거 금지) |

**금지**: 반짝임, 펄스, 색종이·축하 효과, 게임화 요소, 자동 스크롤,
무한 애니메이션, 호버 시 내용이 바뀌는 카드.

## 7. 절제·여백 원칙 (핫셀블라드식)

- 화면의 첫인상은 "빈 곳"이 만든다 — 채우지 못해 남은 여백이 아니라
  설계된 여백. 섹션 사이 32px 이상.
- 한 화면에 의미 색이 동시에 4종 이상 보이면 과다 — 상태가 없는 요소는 무채색.
- 장식 목적의 선·박스·배경 금지. 경계는 여백으로 먼저 만들고, 부족할 때만 `--border`.
- 문구는 짧고 단정하게. 느낌표·과장 수식어("완벽", "폭등") 금지 —
  불확실성은 불확실하다고 쓴다 (신뢰성 원칙).

## 8. Streamlit 적용 방법

- 토큰은 `st.markdown`으로 주입하는 단일 `<style>` 블록에 `:root { ... }` 와
  `[data-theme="dark"]` (또는 라이트 토글 session_state 기반 클래스)로 선언.
  현재 코드의 산재한 인라인 스타일을 이 블록 하나로 수렴한다.
- st.metric·st.dataframe 등 기본 위젯은 CSS 변수 참조로 오버라이드하되,
  Streamlit 버전 업그레이드 시 셀렉터가 깨질 수 있으므로 오버라이드 목록을
  이 문서 하단에 유지·관리한다 (초기 목록: metric 값 크기, 탭 밑줄 색,
  expander 헤더, dataframe 헤더 배경).
- 커스텀 카드류(결론 배너·가격 사다리·게이트 체크리스트)는 st.markdown HTML
  컴포넌트 함수로 작성하고 토큰만 참조한다 — 컴포넌트 안에 하드코딩 색 금지.
