# 라운드 383 — 스캔이 실패해도 '최신화 완료'였다 (2026-09-29)

화면 상태·흐름만 · 값·문턱·판정·스캔 계산 불변 · 버전 없음(축 담당 파일 불변) · 검사 §374(6건) · §245 한 줄.

## 1. 무엇이었나

라운드 376 이 사이드바를 정리하며 **동작을 바꾸는 제안**은 미뤘다 — 그중 하나가 사용자가 붙인 *"성공·부분 성공·실패
구분 · 마지막 시도와 성공 시각 분리"* 였다. 열어 보니 제안이 아니라 결함이었다:

```python
try:
    run_market_scan()
finally:
    st.session_state['scan_done_at'] = now      # ← 무조건
```

스캔이 **예외로 죽어도**, 후보를 **하나도 못 받아도** 사이드바는 *"최신화 완료 · HH:MM:SS"* 였고 상단 띠는 *"마지막
갱신 HH:MM:SS"* 였다. 그 아래 스캔 결과는 **옛 성공**의 것이었다(§3 — 못 한 것을 한 것으로 적었다).

## 2. 고친 것

- 스캔이 결과를 **돌려준다**: 후보 0 → `empty`(사유는 후보 발굴이 낸 문장 그대로) · 끝까지 감 → `ok`(빠진 후보를 사유
  갈래로 센다 — 채택된 유동성 하한은 **실패가 아니다**(라운드 216) · 두 출처 시세 불일치 · 그 밖 예외와 코드 미매핑은
  분석 실패). 예외는 호출부가 잡아 `fail`(사유 · 서버 로그에 역추적).
- 시도 시각(`scan_tried_at`)은 늘, 성공 시각(`scan_done_at` · 띠가 '마지막 갱신'으로 읽는 키)은 **`ok` 일 때만**.
- 사이드바 한 칸은 킷 한 곳(`ui_kit.scan_status_line`)이 만든다: **최신화 실패**(사유 · 마지막 성공 시각 또는 *"이 세션에서
  끝까지 간 최신화는 아직 없습니다"*) · **후보 0개**(사유) · **최신화 부분 완료**(분석 실패 N개 · 불일치 M개) · 최신화 완료.
  사유가 길면 자르되 잘랐다고 적는다(…). 사유 갈래를 가르는 문장 머리는 엔진 문장과 같은지 회귀가 잠근다.
- 띠도 마지막 시도가 실패면 그것을 먼저 적는다(*"최신화 실패 09:04:55"* · *"마지막 갱신"* 은 끝까지 간 시각).

## 3. 고치다 나온 것 — 두 번째 호출이 같은 예외로 페이지를 멈췄다

예외를 잡자 새 결함이 드러났다: 추천 절이 `scan_results` 가 없으면 **스캔을 한 번 더 부른다**(첫 진입용). 실패한 뒤의
다시 그리기에서 그 자리가 곧바로 다시 돌아 **같은 예외로 페이지가 멈췄다**(앱 테스트로 심어 확인). 그렇다고 빈 목록을
넣으면 추천 절이 *"통과한 종목 없음"* 을 적는다 — **못 잰 것을 추천 없음으로** 적는 것이다(§3). 실패 상태면 다시 부르지
않고 *"시장 스캔이 실패해 이 목록을 채우지 못했습니다 — {사유}. 추천이 없다는 뜻이 아닙니다(재지 못했습니다)"* 를 적고
목록은 안 그린다(라운드 228 이 '미룬 상태'에서 같은 이유로 한 그대로). 그리고 예외로 멈추면 스캔 안의 '처리 중' 끄는
자리를 못 지나므로 그 세 키를 예외 갈래에서 내린다(켜진 채 남으면 '처리 중'이 영원하다).

## 4. 확인 (앱 테스트 · 쓰기 막음 · 세 판 · 예외 0)

| 판 | 사이드바 | 성공 시각 | 처리 중 |
|---|---|---|---|
| 실제 스캔 | *"최신화 완료 · 09:02:23 / 관심종목 5개 · 정밀분석 5개"* | 찍힘 | 꺼짐 |
| 후보 발굴이 예외를 던지게 심음 | *"**최신화 실패** · 09:04:55 — RuntimeError: … / 이 세션에서 끝까지 간 최신화는 아직 없습니다"* | 없음 | 꺼짐 |
| 후보 0 을 돌려주게 심음 | *"최신화 · 09:06:40 — **후보 0개**: 순위 페이지에서 후보를 받지 못했습니다."* | 없음 | 꺼짐 |

⚠️ 첫 심기는 **안 먹었다** — 앱이 시작할 때 그 모듈을 `importlib.reload` 해서 심은 함수를 지웠고, 실제 스캔이 돌아
*"완료"* 가 나왔다. 앱 결함이라 적기 전에 시험이 사용자 동작을 재현했는지 본다(라운드 320 의 규칙) — 시험에서만
reload 를 그대로 돌려주게 하고 다시 쟀다. (그 첫 판이 결과적으로 '실제 스캔' 줄이 됐다.)
