# 결과 R322 — 보유 행의 추가매수 문구: *어느 게이트*가 아니라 *무엇을 하라는 말* · 안 잰 종목 먼저 (2026-09-16)

사용자: *"보유 유지 물타기 불가 · 신규 매수 판정만 이게 뭐고, 보유 유지 물타기 가능 이게 뭐야 — 쉽게.
(다른 종목)처럼 추가매수 가능 맞는지. 그리고 전체적으로 각각 유기적으로 잘 연동되고 있는지 확인 및
점검 전수조사해서 개선해줘. (한 종목)은 아직 안 잼인데 개선해주고."*

## 1. 먼저 셌다 — 판단은 맞물려 있었다 (보유 16행 · 읽기만 · 2026-09-16)

킷의 규칙을 **불러서** 불변식을 쟀다(`_probe/r322_holder_census.py` · 새 문턱 없음):

| 불변식 | 어긋난 행 |
|---|---:|
| '추가 매수 가능' ⇒ 물타기 6조건 통과 **그리고** 현재가 ≤ 진입가 | **0** |
| 물타기 통과 **그리고** '보유 유지' ⇒ 현재가 > 진입가 | **0** |
| 가늠 AI(`holder_kind`)와 관심종목(`watch_action`)의 판단이 같다 (R304) | **0** |
| 옛 기준 물타기 스탬프 | **0** |

그날 kind 분포는 16행 전부 '보유 유지'(스냅샷 현재가 기준 · 화면은 실시간이라 다를 수 있다) · 물타기 등급은
포지션 미달 5 · 판단 보류 5 · 조건 통과 2 · 신규 매수 판정에 막힘 2 · 안 잼 2.

→ **계산은 서로 맞다.** 사용자가 헷갈린 것은 낱말이었다.

## 2. 무엇이 헷갈렸나 — 낱말이 *어느 게이트*를 말하고 *무엇을 하라*를 말하지 않았다

| 옛 표기 | 실제 뜻 | 왜 헷갈렸나 |
|---|---|---|
| 보유 유지 · **물타기 가능** | 물타기 6조건은 통과 · 그러나 **현재가가 진입가 위** → 지금은 보유 유지 | '가능'만 보면 *지금 사라*. 진입가 이하로 내려와야 '추가 매수 가능'이 된다 |
| 보유 유지 · **물타기 불가 · 신규 매수 판정만** | 포지션 조건 5개 통과 · 중앙 판정이 지금 **새로 살 후보가 아니다** | '신규 매수 판정만'은 **내부 게이트 이름**이다 — 무엇을 하라는지 안 말한다 |
| 추가 매수 가능 | 조건 통과 **그리고** 진입가 이하 | (이것은 맞게 읽혔다) |

## 3. 고침 — 등급·규칙·이유 문장은 그대로, 이름표와 표의 한 줄만

| 등급(불변) | 이름표 (옛 → 새) | 표의 짧은 줄 (새 · `avg_down_short`) |
|---|---|---|
| 가능 · kind '추가 매수 가능' | 물타기 가능 → **추가매수 조건 통과** | *진입가 N원 이하 — 지금 추가매수 가능* |
| 가능 · kind '보유 유지' | 〃 | *추가매수는 **N원 이하로 내려오면*** |
| 시장게이트 | 물타기 불가 · 신규 매수 판정만 → **추가매수 안 함 · 지금은 새로 살 때 아님** | 같은 말 |
| 포지션미달 | 물타기 불가 → **추가매수 안 함** | *추가매수 안 함 · 조건 N개 미충족* |
| 보류 | 물타기 판정 보류 → **추가매수 판단 보류** | *… · 표본 부족* |
| 안 잼(보유 · 수량 있음) | (없음 — 칸이 비었다) | *추가매수 아직 안 잼 · 아래 '지금 계산해서 채우기'* |

- 가격 갈래는 `holder_kind` 의 **같은 갈래**를 말로 옮긴 것이다(새 문턱 없음 · §2).
- 출처(신규 매수 판정)는 사라지지 않았다 — 마우스를 올리면 나오는 **이유 문장**이 그대로 말한다.
- 포트폴리오 견해의 칩('추가매수 조건 통과 · 진입가 이하로 내려오면')과 채울 것 목록도 같은 낱말로 맞췄다(§4).

## 4. '아직 안 잼' — 채우는 차례가 파일 순서였다

그 종목은 관심종목 **37행 중 37번째**(새로 담은 것)이고 스냅샷 칸이 **하나도 없었다.** 채우기 버튼은
한 번에 5개씩 **파일 순서**로 채워, 대상 15개 중 15번째라 **3번 눌러야** 닿았다. 그리고 표의 칸은 *'아직 안
잼'* 만 적어 어떻게 재는지 말하지 않았다.

- 채우기 순서를 **급한 순**으로: ① 보유 행 ② 한 번도 안 잰 행 ③ 나머지 (같은 자리 안에서는 파일 순서 ·
  안정 정렬). → 그 종목은 **첫 번째 누름**에 채워진다.
- 칸에 길을 적었다: *"아래 '지금 계산해서 채우기' · 또는 이름을 눌러 열기"*.
- **자동으로 돌리지는 않았다** — 한 종목 정밀분석이 1~3분이라 화면을 열 때마다 돌면 앱이 멈춘다(R166 이
  같은 이유로 버튼을 뒀다). 그리고 사용자 파일을 쓰는 일이라 사용자가 누른다.

## 5. 곁들여 — 쓰기를 막은 앱 테스트 중에 관심종목 파일이 바뀌었다

R321 앱 테스트의 마지막 줄이 *"파일 수정시각 그대로: False"* 였다. **테스트가 쓴 것인지부터 가렸다** — 테스트가
심은 값(매입가·수량 쌍 둘)과 같은 행이 파일에 **0**이고, 테스트 시작 때 보유 14행이 지금 16행이다. 그 시각에
사용자가 앱에서 새로 산 종목을 저장했다 — **사용자의 쓰기**였다. (거짓 경보를 그대로 적었으면 사용자의 저장을
테스트 탓으로 되돌릴 뻔했다.)

## 6. 바꾸지 않은 것

등급(cls) · 6조건 · kind 갈래 · 문턱 · 산식 · 판정 불변. 계산부 파일 안 열었음. 검사: §330(4건) · §231·§238·§241·§243
의 옛 낱말 락을 새 낱말로(등급 락은 그대로).
