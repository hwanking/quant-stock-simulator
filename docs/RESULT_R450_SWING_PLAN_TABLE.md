## 받은 것 — 전부 이미 있는 값으로, 새 문턱 없이

1. **② '오늘의 스윙 계획'** — 행마다
   - 오늘 상태: 판정일 / 진입 대기 N/20거래일째 / 대기 기간 지남 / 보유 중(자동 관리) / 실주문 없음. 대기 창은 계약의 진입 대기 거래일
     (라운드 32 산출물 `max_bars`)이고 거래일 수는 워커와 같은 `trading_days_between` 이다(`swing_view.plan_status`).
   - 중앙 판정 조건: `N/11 통과 · 미충족: …(전부)`. 계획이 만들어질 때 중앙 판정의 `checks` 에서만 센다(라운드 312·316 과 같은 규칙 ·
     `plan_from_pick` 이 `verdict` 에 `checks_n`·`failed`·`expected_return`·`wait_curable`·`current_price` 로 든다 · 없으면 None 이고 표는
     '조건 기록이 없습니다' — 0 이나 빈 목록으로 채우지 않는다 · §3). 이미 남은 옛 계획에는 기록이 없으므로 그렇게 보인다(R327).
   - 수량 미리보기: 워커와 **같은 함수**(`swing_risk.size`)로 마지막으로 읽은 계좌와 지금 위험 한도에서 센 수량 · 주문 금액 · 정한 제한 ·
     손절 시 손실(손절가 체결 가정) · 매수 뒤 주식 비중. 계좌를 읽은 적이 없거나 한도가 비면 '—' 와 사유(§3). 워커는 주문 때 잔고·주문 가능
     금액·대기 주문을 다시 읽어 센다 — 표는 미리보기라고 적는다. '남은 위험 예산'은 넣지 않았다 — 그런 한도가 없고 새 한도를 두면 새 문턱이다.
   - '기록만 모의' → '연구 모의(일봉)' — 증권사 결과(③·⑤)와 다른 층이라는 것이 이름에 보이게.
2. **실주문 자격 0 인 날** — *"오늘 후보 N개 중 실주문 자격 0 — 가장 많이 막은 조건은 X 입니다 (k/N개 · 조건 기록이 있는 계획 기준). 조건별로
   세어 본 것이고, 어느 조건을 풀어야 한다는 뜻이 아닙니다."* 세는 규칙은 `ui_kit.top_blocker` **한 곳** — 추천 절(라운드 316)의 인라인 셈을
   그리로 옮겨 두 자리가 같은 것을 부른다(§4 · 수가 같으면 이름 순 · 조건 기록 없는 후보는 분모에서 뺀다).
3. **① 계좌 ↔ 앱 보유종목 대조표** — 종목코드로 맞춰 같음 · 수량 다름 · 평단 다름 · 계좌에만 · 앱에만. 평단은 원 단위 소수 둘째 자리까지 같으면
   같다고 본다(표시 정밀도이지 판정 문턱이 아니다). 덮어쓰지 않는다 — 옮기는 것은 라운드 449 의 버튼이 그대로.
4. **보호 매도의 주인** — 손절·1차 목표 매도는 증권사에 미리 걸어 두는 주문이 아니라 워커가 장중에 가격을 보고 그때 낸다. '먼저 알아 두실 것'에
   그 문장을 넣고, **장이 열려 있는데 오늘 장 시작 뒤 워커 기록이 없으면** 맨 위에 경고(`protection_line` · 기준은 그날 장 시작 시각 한 곳
   `bitemporal_engine.session_times` · 문턱 없음). 장 밖이거나 기록이 장 시작 뒤면 없고, 모드가 '꺼짐'이고 관리 중인 종목도 없으면 워커가 안
   도는 것이 설계라 없다 — 관리 중인 종목이 있으면 모드와 무관하게 적는다(꺼 두면 보호 매도도 멈춘다는 사실).
