# R185 — R183 이 뺀 종목이 '실제로 손댈 수 있는 후보'로 되살아났다

**날짜**: 2026-08-30 · **트리거**: 사용자 스크린샷 — *"또 나왔는데
서진시스템 왜 나오는거야"*

## 무엇이 화면에 있었나

서진시스템(178320) 카드 하나가 **세 가지 다른 말**을 하고 있었다:

| 자리 | 말 | 출처 |
|---|---|---|
| 칸 제목 | **다음 거래일에 실제로 손댈 수 있는 후보** | `verdict_core.actionable` |
| 배지 | 장기 관찰 | `web_app` 의 kind→라벨 사본 |
| 본문 | 펀더멘털 적정가를 내지 못해 오늘의 매수 후보에서 **뺐습니다** | R183 (`next_action`) |

R183 은 정확히 이 종목을 빼기로 했고 실제로 뺐다 — **next_action 안에서만.**

## 왜 — 판정자가 둘이었다 (§4 위반)

- **상세 경로**: next_action 이 `kind='observe'` + 제외 사유를 내도,
  `verdict_core._bucket()` 끝자락이 EV 실패를 근거로 observe 를
  **'눌림목 매수 대기'로 승격**시켰다. 그 버킷은 `ACTIONABLE_BUCKETS`
  소속이라 `actionable=True` → '실제로 손댈 수 있는 후보' 칸.
- **관심 카드 경로**: `premarket._core_of` 가 `_na.build(fs, None, …)` 로
  **tech_df=None** 을 넘겨 na 가 늘 `no_data` 조기 반환 — R183 가드가
  그 경로에서 **아예 안 돌았다.** 못 받은 값이 게이트를 조용히 끈,
  라운드 177 과 같은 모양이다.
- 더 나쁜 것: 중앙 판정의 추천 조건에 **밸류 검증 자체가 없어서**,
  적정가를 초과한 종목이 10조건을 다 통과하면 `'오늘 매수 가능'` 까지
  갔다 (프로브 실측 — 종전 코드에서 recommended=True).
- 배지 '장기 관찰'은 라운드 47 이 *"언제 다시 봐야 하는지 알 수 없는
  이름"* 이라며 BUCKETS 에서 지운 이름이다. §105 가 BUCKETS 는 잠갔지만
  web_app 의 kind→라벨 **사본**이 살아남아 배지로 되살아났다. 심지어
  §99 검사가 그 사본의 '장기 관찰'을 **요구**하고 있었다(라운드 24 의
  검사를 라운드 47 이 안 고친 것).

## 고침 — 판정을 한 곳으로 (새 숫자 0개)

1. **`next_action.value_block(fs)`** — R177+R183 밸류 게이트의 단일 구현.
   `(None|'no_fair'|'over_fair', 사유)` 를 돌려준다. 문턱은 R183 그대로
   (`_OVER_BLOCK_PCT = 0.0` = 구역 판정의 적정가 ×1.00). `build()` 는
   이 함수를 부르고 `out['value_block']` 표지를 싣는다.
2. **`verdict_core.build()`** 가 같은 함수를 **fs 에서 직접** 부른다 —
   na 인자에 기대지 않는다(못 받은 na 가 게이트를 끄는 구멍 봉쇄).
   추천 조건 11번째로 `펀더멘털 밸류 검증` 을 **끝에** 더했고
   (checks[7] 자리 불변 — §6231 보호), `_bucket` 이 그 실패를
   kind 승격보다 **먼저** `'추천 제외'` + R183 사유로 잡는다.
3. **`premarket._core_of`** 가 스냅샷의 tech_df 를 실제로 넘긴다.
4. **배지**: 중앙 판정이 있으면 bucket 을 그대로 배지로 쓴다. 사본
   (`_NA_LABEL`)은 옛 리포트 폴백 전용이고 observe 는 '오늘 후보 아님'.
   '장기 관찰' 매핑 삭제, §5537 검사를 현실에 맞춤(사유 주석).

## §3 — 과차단이 아님을 함께 실측

프로브(`_probe/r185_gate.py`) 16개 기대값 전부 일치:

- OUT_OF_DOMAIN → `추천 제외` (na=None 이어도 · 두 경로 동일 사유)
- 적정가 초과 +11.1% + 10조건 전부 통과 → `추천 제외` (종전 '오늘 매수 가능')
- **UNCALCULATED(못 잰 것) → 종전 그대로** '눌림목 매수 대기' (§3)
- 적정가 이하(−8.1%) + EV 실패 → 종전 승격 그대로 (게이트는 차단만 한다)

## 실측 — 그 종목 그대로 (차가운 프로세스)

`_probe/r185_sj.py` 가 실제 파이프라인으로 178320 을 다시 돌렸다
(2026-08-30 · t_ref 2026-08-28):

```
fair_value_status: CAUTION            ← 스크린샷 시점엔 OUT_OF_DOMAIN
displayed_fair   : 27,989원 · 현재가 38,950원 (+39% 초과)
value_block      : ('over_fair', '적정가 크게 초과 — 추격매수 위험')
core.bucket      : 추천 제외 · actionable False · recommended False
checks[10]       : 펀더멘털 밸류 검증 — 미충족
```

그 사이 재무가 수신돼 모델이 값을 냈고(OUT_OF_DOMAIN → CAUTION), 이제는
**적정가 초과** 쪽 가지로 걸린다 — 어느 가지든 이번에 연결한 게이트가
막는다. 스크린샷 당시의 OUT_OF_DOMAIN 꼴은 §215 픽스처가 잠근다.

같은 서버 렌더에서 관심 후보 칸도 확인했다: 실행 가능 0 · 조건 대기 1
(세방전지 — 배지가 bucket 그대로 '과열 해소 대기') · 뺌 4, 요약 타일과
목록이 같은 분류를 읽고, '장기 관찰'은 화면 어디에도 없다.

곁들여 그 카드에서 **R184 ① 의 생존자**를 찾았다 — `why_pick` 이
같은 리플레이 표본(n=89,520)을 **'검증된 적중률'** 이라 부르고 있었고,
같은 카드 아래 칸은 R184 가 고친 '리플레이 적중'이라 **한 카드가 두
말**을 했다. R165 의 '같은 결함의 다른 표기' 그대로다. 문구를 통일하고
§215 ⑥ 이 두 표기('안 본 사례'·'검증된 적중률')를 **유도된 전 모듈**에서
잡는다 — §214 는 두 파일만 봤다.

## 검사

- **§215** (신규): 단일 구현 존재·중앙 판정이 fs 로 직접 호출·na=None
  구멍 심기·두 경로 버킷 일치·사유 문장 동일성·10/10 통과+초과 차단·
  UNCALCULATED 미차단·checks[7] 자리·premarket tech_df·11조건.
- §99 ⑤ 갱신: '장기 관찰' 요구 → '오늘 후보 아님' + bucket 우선 배지 +
  매핑에 '장기 관찰' 부활 금지.

## 영향 범위

- 이 게이트는 R183 이 이미 채택한 규칙의 **적용 범위 수정**이다 — 문턱·
  방향 불변, 차단만 하고 통과를 만들지 않는다. 측정 근거는
  `docs/RESULT_R183_VALUE_GATE.md` 의 블라인드 구역 실측
  (적정가 이하만 양수 +0.238% · OUT_OF_DOMAIN 최악 −1.237%).
- forward_registry 가 기록하는 bucket/recommended 도 같은 규칙을 따르게
  된다(경로가 하나이므로) — 전방 표본의 정의 변경이 아니라 **R183 규칙이
  이제 실제로 작동**하는 것.
