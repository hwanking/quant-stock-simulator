# 라운드 199 — 사용자가 짚은 셋, 그리고 죽어 있던 경고 하나

측정: 2026-09-01 · 사용자 지적 셋 + 그 과정에서 나온 결함 둘

## ⓐ "가지고 있는데 '이 종목을 갖고 계신가요'도 연동되게 해줘야지"

**원인은 코드가 아니라 그 코드가 있던 자리다.**

라운드 166 이 이미 관심종목의 매입가를 끌어오게 만들어 두었다. 그런데
그 조회가 **사이드바 아코디언 안**에 있었다:

```python
if _uk.acc_row(_SB_STEPS[1], _sb_open, _sb_busy):   # '내 보유종목'
    _reg = next((p for p in st.session_state['positions'] ...), None)
    ...
    user_entry_price = st.sidebar.number_input(..., value=_wl_paid)
```

CLAUDE.md §5 가 *"사이드바는 아코디언. '종목 찾기'만 항상 펼침,
나머지는 접힘"* 이라고 정해 두었다. 그래서 그 칸은 **기본이 접힘**이고,
접혀 있으면 저 블록이 **통째로 안 돈다.** `user_entry_price` 는 폴백
**0.0** 으로 떨어지고, 본문의 라디오가

```python
_pos_default = 1 if user_entry_price > 0 else 0
```

이라 **'아직 없음'** 을 고른다. 매입가를 적어 둔 종목인데도.

**화면 전체가 쓰는 값을 접히는 위젯이 만들고 있었다.** 위젯은 값을
*고치는* 자리이지 *만드는* 자리가 아니다 — §4 의 사촌이다.

고침: 조회를 `_held_of()` 로 빼서 **아코디언 밖에서** 부른다. 아코디언은
열렸을 때 그 값을 보여 주고 덮어쓸 뿐이다. 폴백 기본값도 0.0 이 아니라
조회값이다. 그리고 **어디서 끌어왔는지 화면이 밝힌다**(§3) —
*"관심종목에 적어 두신 값으로 채웠습니다 — 평단 N원 · M주"*.
출처 순서는 라운드 166 이 정한 그대로다 — **보유종목이 먼저**(정식 등록),
관심종목이 다음(개인 메모).

## ⓑ "종합차트에 분봉, 일봉, 주봉도 되게 해줘야지"

차트는 **일봉 데이터**만 그리고 있었고, 상단에는 기간 버튼
(3개월·6개월·1년·전체)만 있었다 — **봉 단위 전환이 없었다.**

| 봉 | 어떻게 | 근거 |
|---|---|---|
| **일봉** | 그대로 | 수집하는 원자료 |
| **주봉·월봉** | **일봉을 묶어서** | 시가=첫 봉 · 고가=최고 · 저가=최저 · 종가=마지막 · 거래량=합 |
| **분봉** | **없다** | 이 저장소는 분봉을 수집하지 않는다 |

**분봉을 지어내지 않았다.** 버튼을 숨기지도 않았다 — 숨기면 *"왜 없지"*
를 알 수 없다. **비활성 버튼 "분봉 없음"** 으로 두고 이유를 툴팁에
적었다: *"분봉 자료를 받지 않습니다. 그래서 같은 날 목표·손절이 함께
닿은 케이스를 성공으로 세지 않습니다(선도달 순서를 알 수 없으므로)."*
이건 새로 만든 말이 아니라 `improvement/performance.py` 가 이미 적어 둔
이 저장소의 알려진 한계다.

**두 가지를 함께 고쳤다.**

- **기간 환산**을 봉 단위마다 다르게 했다 — 일 21 · 주 4.3 · 월 1.
  안 나누면 주봉에서 '1년' 이 **5년치**를 보여 준다. 같은 수를 다른
  단위로 읽는 것이라 라운드 190(σ 단위 혼동)과 같은 모양이다.
- **지표는 일봉으로 계산한 값**이다. 주봉·월봉 캔들 위에 그대로 얹으면
  다른 잣대를 겹쳐 읽게 되므로 **함께 끄고 그 사실을 적는다.**

## ⓒ "산출 불가는 어떻게 해야 해. 자꾸 현명하게 해줘"

확률 세 칸이 전부 `산출 불가` 였다. **규칙 자체는 옳다** — §11 이
유효표본 10건 미만에서 확률 환산을 막는다(`probabilities_allowed`).
작은 표본을 확률처럼 내밀면 없는 근거를 만드는 것이다.

문제는 화면이 **세 글자만** 내밀었다는 것이다. 그러면 사용자는

- **고장인지 규칙인지** 알 수 없고
- 우리가 **대신 무엇을 아는지**도 못 보고
- **언제 채워지는지**도 모른다

고침은 숫자를 만드는 것이 아니라 **말을 더하는 것**이다(§3):

| 무엇 | 화면에 |
|---|---|
| 왜 못 내나 | *유사사례 N건 — 확률로 환산하려면 10건이 필요합니다* |
| 고장인가 | *비어 있는 것은 고장이 아니라 규칙입니다* |
| 그래도 아는 것 | *관찰값 — 과거 N건 중 M건 상승* |
| 대신 볼 값 | *계층 보정 확률(아래 줄)* — 같은 점수대·국면·자리·업종 실측 혼합 |
| 언제 채워지나 | *거래일이 쌓여 10건을 넘으면 자동으로* |

**§11 규칙은 한 글자도 안 바꿨다.** 검사가 그것을 값으로 확인한다.

## ⓓ 덤 — 죽어 있던 경고를 찾았다

§226(정의 전 사용 검사)을 `web_app.py` 까지 넓혔더니 하나가 나왔다:

```python
_sp_raw = str((m_indices.get('sp500') or {}).get('pct') or '')   # 5,502줄
...
except Exception:
    _sp_pct = None
...
m_indices = engine_init.get_market_indices()                      # 5,844줄
```

`m_indices` 를 **342줄 먼저** 쓰고 있었다. `except Exception` 이
`NameError` 를 삼켜 `_sp_pct` 가 **항상 None** 이었고, 그래서 라운드 16
의 실측 경고 — *"전날 미국장이 보합인 날의 추천 성적이 가장 나빴다"* —
가 **한 번도 화면에 안 나왔다.**

**경고는 안 나와도 티가 안 난다.** 그래서 아무도 몰랐다.

고침은 지수 조회를 그 블록 앞으로 올린 것이다(네트워크를 타므로 **한
번만** 부른다 — 뒤의 중복 호출은 지웠다).

## ⓔ 그리고 내가 판별식을 두 벌 만들었다

§226 을 넓히자 **74건**이 나왔다. 전부 오탐이었다 — 최상위 문장이
**그 자체로 `def`** 일 때 몸통까지 훑는 버그다.

그 버그를 **프로브에서는 이미 고쳤다.** 회귀 §226 에는 안 고쳤다.

> 판별식이 **두 벌**이었고, **한쪽만 고쳤다.**

이 세션이 라운드 191~198 내내 다룬 그 결함(§4 — 경로가 둘이면 한쪽만
고치는 일이 생긴다)을 **판별식에서 그대로 저질렀다.**

고침도 같다 — 구현을 `scripts/usebefore_audit.py` **한 곳**에 두고
프로브도 §226 도 그것을 부른다. **심기 목록(`PLANTS`)도 모듈이 갖는다** —
검사가 자기 심기를 따로 적어 두면 그것도 두 벌이 된다.

실측: **38개 모듈 · 최상위 6,445문장 · 위반 0** · 심기 5/5.

- §226 — 유도 37개 + 회귀 자신을 훑는다. 손으로 파일을 적지 않는다.
  심기 다섯(정의 전 사용 · 정상 순서 · for 변수 · `dir()` 방어 ·

## Ⓖ 그리고 그 수정을 **값으로** 확인하려다 더 큰 것이 나왔다 (라운드 200)

ⓐ 를 고치고 나서 화면 글자가 아니라 **세션 값**으로 확인하려고 AppTest
프로브를 돌렸다. 그런데 보유 종목인데도 `pos_mode` 가 **'아직 없음'**
이었다.

원인은 내 수정이 아니라 **라운드 165 의 주석이 거짓**이었던 것이다:

> 프로브가 `GAEUM_NO_LOCAL_WRITE` 를 켜고 화면이 그때 **쓰기만** 멈춘다
> — **읽기는 그대로 둔다**(읽기까지 끄면 검사가 빈 화면을 본다).

```python
ALLOW_LOCAL_STORE = not is_remote_exposed() and not NO_LOCAL_WRITE
if 'watchlist' not in st.session_state:
    if ALLOW_LOCAL_STORE:                 # ← 읽기를 여기서 막고 있었다
        st.session_state['watchlist'] = portfolio.load_watchlist()[0]
    else:
        st.session_state['watchlist'] = []
```

**이름이 하나뿐이라 읽기와 쓰기가 안 갈렸다.** 그래서
`GAEUM_NO_LOCAL_WRITE=1` 로 도는 회귀의 AppTest 렌더는 보유종목·관심종목이
**늘 빈 목록**을 봤다 — **보유자 경로가 한 번도 검사된 적이 없다.**

고침은 이름을 가르는 것이다: `ALLOW_LOCAL_READ`(원격만 막음) ·
`ALLOW_LOCAL_STORE`(원격 + 쓰기 금지). 저장 패널은 여전히 STORE 로
막힌다 — 쓰기가 금지된 곳에 저장 버튼을 보일 이유가 없다.

값으로 확인:

| 종목 | 관심종목 평단 | `pos_mode` |
|---|---|---|
| 004370 농심 | 429,333원 · 3주 | **보유 중** |
| 005930 삼성전자 | 없음 | 아직 없음 |

그리고 `watchlist.json` 수정시각은 그대로다 — **읽되 쓰지 않는다.**

**§228 의 판별식은 이번엔 두 번 넓었다.** 이 세션은 좁아서 못 본 경우가
많았는데 여기는 반대다 — ① `ast.walk` 로 모든 `If` 를 훑으니 바깥 `if`
가 안쪽 로딩을 품어 함께 잡히고 버튼 핸들러까지 걸렸다 ② `test` 가
`ALLOW_LOCAL_*` 인 `If` 로 좁혔더니 **저장 패널**이 걸렸는데, 거기
`load_positions()` 는 *"저장본 불러오기"* 버튼 핸들러이고 STORE 로
막히는 것이 **옳다.** 재려는 것은 **세션 초기 로딩**이므로 그 모양만
본다. 심기 셋으로 양방향 확인한다.
