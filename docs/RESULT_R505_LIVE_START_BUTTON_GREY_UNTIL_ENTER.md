# 라운드 505 — '실전 시작'이 안 눌렸다: 문장이 앱에 닿기(Enter) 전엔 버튼이 회색이었다

2026-10-13 01:00 · 화면(swing_view)만 · 조건·관문·잠금 문장·주문 규칙 불변 · 버전 없음

## 사용자

*"실전 시작 안 눌리는데?"*

## 원인

라운드 501 의 '실전 시작 — 한 번에' 칸은 버튼을 `disabled=not ready` 로 그렸다(`ready` = 입력 칸의 문장이 잠금 문장과 같은가). 그런데
Streamlit 의 입력 칸은 **Enter 를 누르거나 칸 밖을 눌러야** 글자를 앱에 보낸다. 그래서 문장을 치고 바로 버튼을 누르면 그 순간의 버튼은
**아직 회색**이고 클릭이 사라진다. 문장이 한 글자(마침표·빈칸) 달라도 버튼은 이유 없이 회색이었다. 아래 '실전 잠금'의 '잠금 풀기'는 더해서,
문장이 앱에 닿기 전엔 버튼이 아예 없었다. 회귀 §480 ② 는 바로 그 `disabled=not ready` 를 글자로 못 박고 있었다(R98b 계열 — 지키던 성질은
'문장이 같을 때만 켠다'였다).

⚠️ 같은 때(01:04) 내가 변경을 반영하려고 앱 서버를 다시 띄웠다 — 그때 열린 화면은 연결이 끊겨 무엇을 눌러도 안 됐을 수 있다. 둘 중 무엇이
그 순간의 원인이었는지는 가르지 못했다. 버튼 결함은 실재한다(아래 실측).

## 고침

- 두 칸을 **폼**으로 — 누르는 순간 입력한 글자가 같이 가고, 버튼은 늘 눌리며, 안 켜면 이유를 적는다(`phrase_why`: 비었는지 · 입력한 것과
  필요한 것). **Enter 로는 켜지지 않는다**(`enter_to_submit=False`) — 실계좌 주문을 켜는 것은 버튼으로만.
- 문장 판정은 `swing_view.phrase_ok` 한 곳 — 같은 낱말·같은 차례면 빈칸 개수·앞뒤 빈칸만 너그럽게(확인의 뜻은 같다), 글자가 하나라도 다르면 아니다.
- 누르는 순간 장부 설정을 다시 읽어 조건(자격증명 · 한도 여섯 · 긴급정지 · 증권사 관문)을 다시 보는 것은 그대로.

## 실측 (쓰기를 막은 것이 아니라 **임시 장부**에 · 증권사 차단 · 자격증명 모양만 심음 · 실제 장부 수정시각 불변)

| 입력 | 누를 때 버튼 | 결과 |
|---|---|---|
| 잠금 문장 그대로 · Enter 없이 바로 누름 | 눌림 | 잠금 풀림 · 모드 '실전' |
| 빈칸이 더 많은 같은 문장 | 눌림 | 켜짐 |
| 끝에 마침표 | 눌림 | 안 켬 — *"입력한 문장이 다릅니다 — 입력: … · 필요: …"* |
| 빈 칸 | 눌림 | 안 켬 — *"문장을 입력하지 않았습니다"* |
| '잠금 풀기'에 잠금 문장 | 눌림 | 잠금만 풀림(모드 그대로) |

회귀 §485 가 이 가운데 셋을 매번 사용자처럼 누른다(누르는 순간 버튼이 회색이 아닌지까지).
