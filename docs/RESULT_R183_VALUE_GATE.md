# 라운드 183 — 사용자가 옳았고 내 §3 방어가 틀렸다

**날짜** 2026-08-28 · **분류** 게이트 강화 (측정 근거 있음)
**요청** *"적정가가 없는데 이걸 추천한 게 못 미더워. 개선해주던가
추천 안 하던가. 또한 추천한 게 펀더멘털 적정가보다 현재가가 높은데
추천한 것도 이상해."*

---

## 1. 라운드 182 에서 내가 한 방어

사용자가 서진시스템(적정가 미산출)이 추천된 것을 지적했을 때, 나는 §3
(*"못 잰 것으로 거르지 않는다"*)을 들어 **거르지 않고 고지만** 붙였다.

**그 방어가 틀렸다.** 두 가지를 혼동했다.

| | |
|---|---|
| **데이터 미수신** | 우리가 값을 못 받았다 — §3 이 지키려는 것(라운드 37: 2,997종목 전멸) |
| **모델이 거부** | 값을 받았고 계산도 했는데 **모델이 이 구간에서 못 쓴다고 판단** |

서진시스템은 **후자**다(`OUT_OF_DOMAIN` · 모델 적정가가 시장가와 −72% 괴리).
§3 은 이 경우를 지켜 주지 않는다.

## 2. 원장이 사용자 편이었다

`entry_zone` 이 원장 **184,759건 전부**에 실려 있어 구역별 성적을 직접 셌다
(매수권 58+ · 판정완료 · 손익분기 62.9% 는 라운드 168 값 재사용).

### 개발 구간에서는 반대로 보인다

| 구역 | n | 적중% | 원시수익% |
|---|---:|---:|---:|
| 판정 불가 | 13,983 | **61.1** | +0.191 |
| 안전마진 확보 | 59,024 | 59.6 | +0.184 |

*"적정가를 못 낸 종목이 오히려 낫다"* 로 읽힌다. **여기서 멈췄으면 사용자
지적을 기각했을 것이다.**

### 블라인드에서 뒤집힌다

| 구역 | n | 적중% | 손익분기와 | 원시수익% |
|---|---:|---:|---:|---:|
| **적정가 이하** | 335 | 59.4 | **−3.5** | **+0.238** |
| 안전마진 확보 | 3,074 | 53.6 | −9.3 | −0.956 |
| 적정가 소폭 초과 | 71 | 53.5 | −9.4 | −0.890 |
| 적정가 초과(경고) | 97 | 54.6 | −8.3 | −0.652 |
| **판정 불가** | **1,536** | **52.9** | **−10.0** | **−1.237** |

**적정가를 못 낸 종목이 블라인드에서 가장 나쁘다.** n 1,536 · 968일 —
표본 부족 탓이 아니다. 그리고 **적정가 이하만 유일하게 양수**다.

이것이 이 저장소가 계속 추적하는 **검증-블라인드 괴리**의 또 다른 사례다.

## 3. 무엇을 바꿨나

### ⓐ 모델이 거부한 종목은 매수 후보에서 뺀다

```python
if _no_fair and _fv_status == 'OUT_OF_DOMAIN':
    out['kind'] = 'observe'
    out['exclude_reason'] = '적정가 산출 불가 — 밸류 검증 없이 추천하지 않음'
```

**§3 은 지킨다** — 못 잰 경우(`UNCALCULATED` 등)는 **그대로 둔다.**
막는 것은 **모델이 값을 거부한 경우**뿐이다.

| 상태 | 판정 |
|---|---|
| `OUT_OF_DOMAIN` (모델 거부) | **observe** — 후보에서 뺌 |
| `UNCALCULATED` (못 잼) | pullback — **그대로** |

### ⓑ 적정가를 넘으면 막는다 (+15% → **0%**)

```python
_OVER_BLOCK_PCT = 0.0      # = entry_zone 의 fair_ref * 1.00 과 같다
```

**새 숫자를 만들지 않았다** — 구역 판정이 이미 쓰는 경계(적정가 × 1.00)를
그대로 재사용한다 (§2-6).

| 넘침 | 판정 |
|---:|---|
| −0.1% | 통과 |
| **0.0%** | 통과 (넘어야 막는다) |
| **+0.1%** | **observe** |
| +32% | observe |

## 4. 얼마나 못 사게 되나 — 밝힌다

게이트를 조이면 반드시 물어야 한다. 원장 매수권 **82,259건** 기준:

| | 전체 | blind |
|---|---:|---:|
| 그대로 통과 | 78.7% | **64.7%** |
| 새로 차단 (적정가 초과) | 2.2% | **3.1%** |
| 판정 불가 (일부 새로 차단) | 19.0% | **32.2%** |

*"판정 불가" 19.0% 중 실제로 빠지는 것은 **모델이 거부한 경우만**이다 —
원장에 그 사유가 안 실려 있어 여기서는 **상한**으로만 보인다.*

## 5. 정직하게 남기는 한계

- **'소폭 초과'·'경고' 구간의 블라인드 표본이 71 · 97 건으로 작다.**
  방향은 개발 구간과 같고(둘 다 손익분기 아래) 이 변경은 **차단만** 하므로
  완화가 아니지만, 표본이 작다는 사실을 숨기지 않는다. 라운드 27b 가 n=16
  으로 물린 자리를 기억한다.
- **모든 구역이 손익분기 아래다.** 이 변경은 "좋은 것을 고른다"가 아니라
  **"가장 나쁜 것을 뺀다"** 이다. 이 엔진에 비용 차감 우위가 있다는 뜻이
  아니다 — 그 결론은 그대로다(§9).
- 이 측정은 **결과를 본 뒤의 분석**이다. 사전등록이 아니다. 그래서 문턱을
  **새로 만들지 않고** 이미 있는 경계를 골랐고, 방향도 **차단 쪽으로만**
  잡았다.

## 6. 회귀

- `OUT_OF_DOMAIN` 은 빼고 `UNCALCULATED` 는 안 뺀다 — **둘이 실제로 다르게
  나오는지** 값으로 확인 (같으면 안 가른 것이다)
- +0.1% 막힘 · 0.0% 통과 · −0.1% 통과
- 문턱이 구역 판정의 경계(×1.00)와 **같은 자리**를 가리키는지
- **표본이 작다는 사실을 코드 주석에 적었는지** (원문을 읽는다 —
  `code_lines` 는 주석을 걷어내므로 처음에 헛짚었다)
