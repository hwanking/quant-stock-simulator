# 라운드 165 — 같은 결함의 **다른 표기**가 네 자리 더 있었다

측정일 **2026-08-24** · `_probe/etf_bars_probe.py` · `_probe/etf_pipeline_probe.py`

---

## 1. 무슨 일이 있었나

라운드 164 에서 문자 포함 KRX 코드를 읽게 고쳤고, 검색·해석·NAV 까지
화면으로 확인했다. 그런데 사용자가 `0040Y0` 을 열자 앱이 죽었다.

```
bitemporal_engine.DataUnavailableError:
  0040Y0.KS: 네이버 일봉 시계열 수신 실패 — 합성 가격으로 대체하지 않고
             분석에서 제외합니다.
```

**이 메시지가 거짓말이었다.** 네이버는 멀쩡히 주고 있었다.

---

## 2. 재 보니 우리가 코드를 망가뜨려 물어봤다

```
symbol='005930'     →  3,000봉
symbol='480020'     →    566봉
symbol='0040Y0'     →    325봉   ← 정상 제공
symbol='00400'      →      0봉   ← 우리가 물어본 것
symbol='0040Y0.KS'  →      0봉
```

원인:

```python
clean_symbol = ''.join(filter(str.isdigit, symbol))   # '0040Y0.KS' → '00400'
```

**라운드 164 가 고친 것과 같은 결함이다.** 다만 표기가 달랐다 —
정규식(`\d{6}`)이 아니라 `filter(str.isdigit)`.

전수로 훑으니 **네 자리**였다.

| 자리 | 표기 | `0040Y0` → | 증상 |
|---|---|---|---|
| `bitemporal_engine` 일봉 | `''.join(filter(str.isdigit, …))` | `00400` | **앱이 죽음** |
| `bitemporal_engine` 배당 | `''.join(filter(str.isdigit, …))[:6]` | `00400` | "종목코드를 해석하지 못했습니다" |
| `market_context` 뉴스 | `re.sub(r'\D', '', …)[:6]` | `00400` | "종목코드를 알 수 없습니다" |
| `market_context` 공시 | `re.sub(r'\D', '', …)[:6]` | `00400` | 같음 |

고친 뒤 실측:

- 일봉 **325봉** (2025-04-22 ~ 2026-08-21 · 마지막 종가 8,180)
- 뉴스 **3건** (전에는 "종목코드를 알 수 없습니다")
- 배당 → *"주당배당금이 공시되지 않았습니다"* — **진짜 답**에 도달

## 3. §201 이 왜 못 잡았나 — 여기가 이 라운드의 알맹이

라운드 164 에서 검사를 붙였는데 하루 만에 뚫렸다. 이유가 둘이고, 둘 다
이 저장소가 이미 배운 것이다.

**① 표기 하나만 찾았다.** `\d{6}` 만 봤고 `filter(str.isdigit)` ·
`re.sub(r'\D')` 는 안 봤다. 같은 뜻의 다른 표기다.

**② 검사 대상을 손으로 적었다.** 함수 **두 개**(`search_naver_stocks_realtime`
· `fetch_and_update_naver_realtime`)만 봤다. 터진 곳은 넷 다 그 밖이었다.

라운드 114 가 *"검사 대상 목록을 손으로 적지 않는다"* 를, 라운드 120e 가
*"유도에도 범위가 있다"* 를 배웠는데 — **내가 하루 전에 그 둘을 다시
어겼다.**

### 그래서 §202 는 이렇게 만들었다

- **표기가 아니라 idiom 을 막는다** — 코드에서 *숫자만 뽑는* 표기 자체.
  판별(`code.isdigit()` 로 물어보기)은 오탐하지 않는다
- **모든 모듈을 훑는다** (37개 · 손 목록이 아니라 유도)
- **심어서 확인한다** — 두 표기를 심으면 잡고, 판별은 안 잡는지
- 오늘 자리 넷은 *"실제로 `stock_code` 를 부르는가"* 로 따로 못 박되,
  그 목록이 낡을 것을 주석에 적어 뒀다 (일반 그물은 idiom 검사 쪽)

## 4. 곁들여 — 화면이 스스로 모순되고 있었다

ETF 적정가 미산출 문구가 이렇게 적고 있었다.

> 순자산가치(NAV)·괴리율은 **연동되어 있지 않으므로** 적정가를 산출하지
> 않습니다.

**라운드 164 에서 연동했다.** 화면은 바로 옆 칸에 `NAV 10,240원 ·
괴리 +0.49%` 를 띄우면서 이 줄로는 "연동 안 됨"이라 말하고 있었다 —
§4 가 금지한 그 모양이다. 문구만 고쳤고(표시 전용), 검사가 못 박는다.

---

## 5. 사유를 섞지 않는다 (§3)

`DataUnavailableError` 하나가 **두 가지 다른 실패**를 같은 문장으로
말하고 있었다.

- 코드를 **못 읽었다** (우리 문제 — 조회를 아예 안 했다)
- 시세를 **못 받았다** (상대 문제)

앞의 경우를 *"네이버 일봉 시계열 수신 실패"* 라고 적으면 원인을 밖으로
떠넘기게 된다. 실제로 그 문장 때문에 처음에 네이버를 의심했다.
이제 판별 실패는 *"종목코드를 읽지 못했습니다 — 조회를 시도하지
않았습니다 (수신 실패와 다릅니다)"* 로 나간다.

## 5b. 곁들여 둘 — **검사가 사용자 자료를 바꾸고 있었다**

라운드 164 가 '최근 본 종목'을 파일에 남기게 했다. 그런데 회귀가 한 번
돌고 나서 목록을 보니 이랬다.

```
000660  SK하이닉스     02:25      ← 회귀가 넣은 것
005930  삼성전자       02:01      ←
064260  다날          02:01      ←
035760  CJ ENM       00:40      ←
0040Y0  SOL 팔란티어…  01:46      ← 내가 실제로 본 것
```

회귀의 AppTest 렌더가 돌 때마다 **테스트 종목이 사용자 목록에 쌓였다.**
지워진 건 없지만 검사가 사용자의 것을 건드리면 안 된다 (§9).

`scripts/render_probe.py` 가 `GAEUM_NO_LOCAL_WRITE` 를 켜고, 화면은 그때
**로컬 파일을 쓰지 않는다.** **읽기는 그대로 둔다** — 읽기까지 끄면
검사가 빈 화면을 보게 되고, 그건 검사가 아니다.

그리고 이 검사는 **값으로** 잰다. 회귀 시작 시점에 `.portfolio/` 세 파일의
수정시각을 찍어 두고, 끝에서 안 바뀌었는지 본다 — *"소스에 스위치가
적혀 있나"* 가 아니라 *"실제로 안 바뀌었나"* 다.

> 이미 쌓인 항목은 **지우지 않았다.** 어느 것이 사용자가 본 것이고 어느
> 것이 검사가 넣은 것인지 확실히 가를 수 없기 때문이다. 화면의
> '최근 목록 비우기' 로 사용자가 직접 비울 수 있다.
