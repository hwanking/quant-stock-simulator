# 화면 명세 — 8개 화면 상세 사양

기준: docs/REDESIGN_BRIEF_ko.md (2026-08-01)

> 각 화면은 정보 5단계(무엇을→왜→계산→과거 적중→원천 데이터)를 따른다.
> **데이터 규칙**: UI에 필요한 필드가 현재 파이프라인(quant_indicators.py의
> four_scores/final_action_score/build_final_verdict/build_easy_advice,
> premarket.py의 build_report/grade_history, .portfolio/calibration.json,
> .portfolio/virtual_graded.jsonl, market_context.py, portfolio.py)에 이미
> 있으면 그대로 쓰고, **없으면 각 화면의 '필요 데이터 인터페이스' 절에 정의만
> 남긴다. UI 계층에서 임의 값·추정치·자리 채움 숫자를 만드는 것을 금지한다.**
> 미산출 값은 "미산출/표본 부족/미연동"으로 정직하게 표기한다.
>
> 공통 오류 원칙: 데이터 오류는 은폐하지 않는다 — 화면을 비우는 대신
> 무엇이 왜 실패했는지 배너로 밝히고, 정상인 나머지 영역은 계속 렌더한다.

---

## 1. 홈 (지휘센터)

**화면 목적**: 앱을 연 순간 5초 안에 "오늘 시장 상태 / 오늘 후보 / 내 보유 위험 /
모델 신뢰 상태"를 한 화면으로 파악하게 한다.

**주요 사용자 질문**
- 오늘 시장은 정상 국면인가?
- 오늘 볼 만한 후보가 있는가?
- 내 보유 중 지금 확인해야 할 것이 있는가?
- 이 모델은 지금 믿을 만한 상태인가?

**우선 노출 정보 (위→아래)**
1. 시장 카드 4~6개: KOSPI·KOSDAQ·KOSPI200·USD/KRW·미국지수·변동성 —
   각 값·전일비·기준일·미니 추세·정상 여부 배지
2. 개장 전 한 줄 결론 (premarket 보고서의 easy_line) + 브리핑 바로가기
3. 오늘의 추천 1~5위 미니 카드 (순위·종목·점수·행동 문구)
4. 보유종목 위험 알림 (즉시 확인 그룹만 발췌, 없으면 "위험 알림 없음")
5. 모델 상태 스트립: 버전·케이스 수·표본외 적중률·고신뢰 적중률·최근 30건·
   손익비·MDD·데이터 정상률

**탭 구조**: 없음 (단일 대시보드 — 탭은 하위 화면의 몫).

**카드 구조**: 시장 카드(3단: 지수명/값+전일비/기준일+배지), 추천 미니 카드
(순위·종목명·점수 막대·행동 배지), 모델 상태는 카드가 아닌 수평 스트립(st.metric 행).

**사용자 행동**: 시장 카드 → 브리핑 시장 요약 / 추천 카드 → 종목 분석 딥링크 /
위험 알림 → 내 보유종목 / 모델 스트립 → 모델 성과.

**오류 상태**: 지수 미수신 카드는 값 대신 "수집 실패 (출처: 네이버 fchart)" +
`--danger` 배지, 나머지 카드는 정상 렌더. 브리핑 미생성이면 한 줄 결론 자리에
"오늘 브리핑이 아직 생성되지 않았습니다" + 생성 버튼.

**빈 상태**: 추천 0건이면 "오늘 게이트를 통과한 후보가 없습니다 — 후보 N건 중
전부 제외 (사유 보기)"로 제외 사유 링크. 보유 미등록이면 위험 알림 영역에
등록 유도 1줄. **0건은 실패가 아니라 게이트가 일한 결과임을 문구로 명시.**

**모바일 구조**: 시장 카드 2열 → 한 줄 결론 → 추천 세로 카드 → 위험 알림 →
모델 스트립은 2×4 그리드.

**필요 데이터 인터페이스 (현재 없음 — 정의만)**
- `model_status`: {model_version, case_count, oos_hit_rate, high_conf_hit_rate,
  recent30_hit, profit_factor, mdd, data_health_pct} — calibration.json에 일부
  존재하나 "데이터 정상률(data_health_pct)"은 집계 로직이 없다. 집계가 구현되기
  전에는 해당 칸을 "미집계"로 표기한다.
- 시장 카드의 "정상 여부" 배지: market_context 수집 성공/실패 플래그의
  카드별 노출 규격 필요 (수집 결과에 이미 있으면 매핑, 없으면 "미표기").

## 2. 개장 전 브리핑

**화면 목적**: 장 시작 전, **전일 확정 데이터만으로** 오늘의 전략과 후보를
보고서 형태로 고정 제공한다. 생성 후 불변(박제)이 신뢰의 핵심.

**주요 사용자 질문**
- 이 보고서는 언제·무엇을 기준으로 만들어졌나?
- 시장은 어떤 국면이고 주요 뉴스는 무엇인가?
- 오늘 후보는 누구이고, 누가 왜 제외됐나?

**우선 노출 정보**: 헤더에 생성 시각·기준일(전일)·모델 버전을 박제 스탬프로.
그 아래 한 줄 결론(easy_line).

**탭 구조 (5개)**
1. 시장 요약 — 지수·글로벌·환율 전일 확정 + 국면 판정
2. 주요 뉴스 — 뉴스 카드(방향·강도·신뢰도·기반영 여부 표시)
3. 오늘의 전략 — 국면에 따른 전략 문구 + 근거
4. 추천 후보 — 표 보기 + 카드 보기 토글
5. 제외 종목 — 사유별 그룹(과열·유동성·뉴스 위험·손익비 부족·데이터 오류·
   표본 부족·출처 불일치)

**카드 구조**: 추천 후보 카드는 '오늘의 추천' 카드(§3)의 축약형(순위·종목·점수·
행동·권장매수가). 제외 종목은 사유 배지 + 종목명 리스트.

**사용자 행동**: 후보 → 종목 분석 / 하단 "지난 추천의 실제 성과" 링크(grade_history)
→ 모델 성과. 브리핑 재생성은 명시적 버튼 + "기존 보고서를 대체합니다" 확인.

**오류 상태**: 일부 데이터 미수신 상태로 생성된 보고서는 헤더에 "일부 데이터
누락 상태로 생성됨 (누락: ○○)" 경고를 박제. 생성 자체가 실패하면 실패 사유와
마지막 성공 보고서(날짜 명시)를 대신 표시.

**빈 상태**: 후보 0건 → "게이트 통과 후보 없음"을 정상 결과로 명시하고 제외
탭으로 유도. 뉴스 0건 → "수집된 위험 낱말 해당 뉴스 없음".

**모바일 구조**: 탭 가로 스크롤, 후보는 카드 보기 고정(표는 데스크톱만),
헤더 스탬프는 2줄 축약.

**필요 데이터 인터페이스 (현재 없음 — 정의만)**
- 뉴스 카드의 `direction`(호재/악재/중립)·`strength`·`priced_in`(기반영 여부):
  현재 뉴스 파이프라인은 **제목 위험 낱말 감점만** 수행한다(SYSTEM_MAP §1).
  방향·강도·기반영 판정 로직은 존재하지 않으므로, 구현 전까지 뉴스 카드는
  "위험 낱말 감지: −N점"만 표시하고 방향·강도 칸은 "미분석"으로 둔다.
  임의 감성 라벨 생성 금지.
- `strategy_of_day`(오늘의 전략 문구): premarket.build_report에 국면 기반
  문구 필드가 없으면 시장 요약의 국면 판정 값을 그대로 쓰고, 별도 전략 문구는
  인터페이스 정의만: {regime, stance, rationale[]}.
- 제외 사유 코드 체계: 스캔 제외 사유가 자유 문자열이면 7개 사유 그룹에
  매핑하는 코드 enum이 필요 — {OVERHEAT, LIQUIDITY, NEWS_RISK, RR_SHORT,
  DATA_ERROR, SAMPLE_SHORT, SOURCE_MISMATCH, OTHER}.

## 3. 오늘의 추천

**화면 목적**: 게이트를 통과한 고신뢰 후보를 순위 카드로 제시하고, 각 카드에서
"행동·가격·근거"를 완결적으로 전달한다.

**주요 사용자 질문**
- 지금 검토할 후보는 몇 개이고 순위는?
- 각 후보를 얼마에 사서 어디서 익절/손절하나?
- 이 점수대는 과거에 실제로 얼마나 맞았나?

**우선 노출 정보**: 히어로 영역 — "전일 확정 데이터 기준 고신뢰 후보" 제목 +
기준일·모델 버전·후보 N건 중 통과 M건.

**탭 구조**: 없음 (카드 리스트 단일 뷰. 정렬: 점수순 고정).

**카드 구조 (후보 1건 = 카드 1장, 4개 구역)**
1. 헤더: 순위 · 종목명(코드) · 종합점수(큰 숫자) · 신뢰도 등급 배지
2. 행동: 판정 문구(7단계) — 카드 안에서 가장 크게
3. 가격: 가격 사다리 축약형 — 전일 종가·권장매수·추격금지·1/2차 목표·손절·
   예상 기간·손익비 (미산출 항목은 "미산출" 그대로)
4. 근거: 긍정 요인 3 · 위험 요인 2 · 뉴스 감점 여부 · 유사 사례 n건 성과 ·
   게이트 충족 k/전체
   액션 행: [상세 분석] [관심 등록] [가상 매매 기록] [보유 등록]

점수 표현 규칙: 큰 숫자 + 수평 막대. 원형 게이지 금지(종합점수 1곳 선택 허용).
게이트는 체크/경고 아이콘+텍스트. **적중률은 반드시 표본 수와 함께**
("이 점수대 리플레이 적중 62% · n=34" — calibration.json 실측만 인용).

**사용자 행동**: 상세 → 종목 분석 딥링크 / 가상 매매 → prediction_log 기록 /
보유 등록 → portfolio 추가 (평단가 입력 유도).

**오류 상태**: 특정 후보의 스냅샷 재계산 실패 시 그 카드만 "분석 실패 (사유)"로
표시하고 목록 유지. 전체 실패 시 마지막 성공 목록 + 실패 배너.

**빈 상태**: "오늘 통과 후보 0건 — 후보 N건 전원 게이트 차단. 이는 모델이
확신 없는 날 매수를 권하지 않는다는 뜻입니다." + 제외 사유 보기 링크.
(현재 TOP3가 0개인 것은 Blind Test 미구현에 따른 의도된 게이트임 — 이 상태를
결함처럼 보이게 하지 말 것.)

**모바일 구조**: 카드 전폭 세로 나열, 가격 구역은 2열 그리드, 액션 버튼은
[상세] 1개 + 나머지 오버플로 메뉴.

**필요 데이터 인터페이스**
- `positives[3]`·`risks[2]` 요약 문구: build_final_verdict의 reasons 배열에서
  상·하위 기여를 추출 가능하면 매핑. 기여 방향 구분이 없으면 인터페이스 정의만:
  {factor, direction(+/−), delta_points, source_tab}.
- 신뢰도 "등급"(예: 상/중/하): 연속 신뢰도 값은 있으나 등급 절단 규칙이 UI용으로
  정의돼야 함 — 계산 로직 추가가 아니라 표시 구간 정의: 예 ≥75 상 / 50~74 중 /
  <50 하 (하는 veto로 애초 미노출). 확정 전까지 원값 그대로 표기.

## 4. 종목 분석

**화면 목적**: 단일 종목에 대한 완결 분석 — 결론(행동 판단)에서 시작해 원하는
깊이까지 파고들 수 있는 3단 구조.

**주요 사용자 질문**
- 이 종목, 지금 사도 되나 / 기다려야 하나? (미보유)
- 나는 이 평단가로 들고 있는데 어떻게 해야 하나? (보유)
- 이 점수는 어떻게 나왔고, 어떤 게이트에 걸렸나?
- 과거 유사 상황에서 실제로 어땠나?

**3단 구조**
1. **헤더**: 종목명·코드·자산 유형 배지(STOCK/ETF/레버리지·인버스) · 현재가(큰 숫자) ·
   전일비 · 기준일 스탬프 · 데이터 정상 여부 배지(교차검증 결과)
2. **행동 판단 패널**: [미보유 | 보유] 모드 토글 즉시 전환
   - 미보유: 행동 결론 배너 + 가격 사다리(현재가·신규 검토가·1/2차 분할매수가·
     추격금지가·1/2차 목표가·손절가) + 근거 요약(올린 3·내린 3·차단 게이트) +
     신뢰도 수평 막대 + 유사 사례 적중률(n 병기) + 최대 위험 1줄
   - 보유: 평단가·수량 입력 → 보유자 행동 결론(build_easy_advice 보유 모드) +
     보유자 대응가(추가매수 가능가·일부/전량 매도 기준·손절가) + 내 손익
3. **분석 탭 9개** (INFORMATION_ARCHITECTURE §3 매핑)
   ① 핵심 요약 ② 가격 차트 ③ 퀀트 점수 ④ 뉴스 이벤트 ⑤ 매매 시나리오
   ⑥ 자기유사 예측 ⑦ 백테스트 ⑧ 케이스 스터디 ⑨ 데이터 감사

**탭별 핵심 카드**
- ② 차트: chart_pro.py 종합 차트 + **지표 선택 패널**(이동평균 5/20/60/120·볼린저·
  RSI·거래량·DeMARK·지지/저항 토글) + 가격 레벨 수평선 오버레이 + 기간 전환
- ③ 퀀트 점수: 점수 위계 카드(1~4단계) + "가중합→신뢰도 수축→게이트 상한" 추적
  경로 + 게이트 체크리스트(16개) + 적정가 산출 근거(펼쳐보기)
- ⑤ 시나리오: 시나리오 3분할(상승/중립/하락) + 신규 vs 보유 비교 + 다중기간
  합의 카드 + 예상 보유기간 근거
- ⑨ 감사: 원천 데이터 매트릭스·교차검증 로그·미연동 항목 명시·10대 레포트
  원문(전문가 보기)

**사용자 행동**: 모드 토글 / 지표 선택 / 관심·보유 등록 / 가상 매매 기록 /
탭 고정(설정 연동).

**오류 상태**: 교차검증 실패(네이버·다음 1% 이상 괴리) 시 행동 판단 패널을
"판정 보류 (데이터 정합성)"로 대체하고 사유 명시 — 기존 엔진 판정 그대로 표기.
탭 단위 실패는 해당 탭 안에서만 오류 카드.

**빈 상태**: 표본 부족 종목은 결론 배너에 "산출 불가 — 유효표본 n<기준" +
가능한 탭(차트·감사)만 활성. ETF는 적정가 계열 카드에 "ETF — 해당 없음
(기술·추세 기준 평가)" 명시.

**모바일 구조**: 헤더 축약(종목+현재가+배지 1줄) → 결론 배너 → 가격 사다리
세로형 → 근거 → 탭 가로 스크롤. 차트는 가로 모드 안내.

**필요 데이터 인터페이스**
- "올린 요인 3·내린 요인 3": §3과 동일한 {factor, direction, delta_points} —
  four_scores 기여 내역에서 파생 가능해야 하며, 파생 불가 항목은 목록에서 제외
  (허구 요인 생성 금지).
- "최대 위험 1줄": 발동 게이트 중 상한이 가장 낮은 것의 설명문 — 게이트 결과에
  상한값·설명이 이미 있으므로 min 선택 로직만 UI에서 수행(계산 아님, 선택임).
- 탭 고정·카드 순서: `.portfolio/ui_prefs.json` {pinned_tab, card_order[],
  expert_mode} — 신규 파일, 계산 파이프라인과 완전 분리.

## 5. 내 보유종목

**화면 목적**: "지금 뭘 확인해야 하나"를 행동 우선순위로 정렬해 보여주는
포지션 관리 화면.

**주요 사용자 질문**
- 지금 즉시 봐야 할 종목은?
- 전체 평가액·손익·위험 노출은?
- 어떤 종목이 손절/목표에 근접했나?

**우선 노출 정보**: 상단 요약 스트립 — 평가액·총 손익(액/률)·위험 노출
(손절 근접 종목 수)·목표 근접 카운트.

**탭 구조 (기존 3탭 유지 + 정렬 개편)**
1. 보기 — 행동별 그룹 (아래)
2. 가져오기 — 스크린샷 OCR / CSV·Excel / 직접 입력 (기존 파이프라인 유지)
3. 관리 — 수정·삭제·평단가 갱신

**보기 탭의 행동별 그룹 (위험 우선 순서)**
① 즉시 확인 ② 손절 근접 ③ 일부 매도 검토 ④ 보유 유지 ⑤ 추가매수 가능
⑥ 추가매수 금지 ⑦ 데이터 부족 — 각 그룹은 접이식, 종목 카드에는
보유자 행동 결론·평단 대비 손익·대응가·점수.

**카드 구조**: 종목명 · 보유자 판정 배지 · 손익(tabular-nums, 부호+색+아이콘) ·
평단가/현재가 · 대응가 1줄 · [상세] 버튼.

**사용자 행동**: 카드 → 종목 분석(보유 모드로 열림) / OCR·CSV 가져오기 /
평단가 수정. **매매 실행 기능은 없다** — 판단 보조까지만.

**오류 상태**: OCR 인식 실패 행은 기존처럼 "확인 필요 N행" 경고로 노출(은폐 금지).
개별 종목 시세 실패 시 해당 카드에 "시세 수집 실패" + 마지막 성공값(날짜 병기).

**빈 상태**: "등록된 보유종목이 없습니다" + 가져오기 3경로 안내 카드.
평단가 없는 종목은 "평단 미입력 — 손익 계산 불가" (0원 취급 금지).

**모바일 구조**: 요약 스트립 2×2 → 그룹 아코디언 → 카드 전폭.
표 형태는 제공하지 않는다(카드 고정).

**필요 데이터 인터페이스**
- 그룹 분류 기준: build_easy_advice 보유 모드 판정을 7그룹 enum으로 매핑하는
  규칙 필요 — {IMMEDIATE_CHECK, NEAR_STOP, PARTIAL_SELL, HOLD, ADD_OK,
  ADD_FORBIDDEN, DATA_SHORT}. 판정 문구→enum 매핑표를 UI 계층 상수로 정의
  (판정 로직 자체는 불변).
- "손절 근접" 임계(예: 손절가까지 −3% 이내): 표시용 임계이므로 UI 상수로 정의
  하고 화면에 임계값을 명시한다 (숨은 규칙 금지).

## 6. 시장 스캐너

**화면 목적**: 전 시장에서 조건에 맞는 종목을 빠르게 발굴·비교한다.
발굴은 시작점일 뿐, 모든 행이 "왜"로 이어진다.

**주요 사용자 질문**
- 지금 시장에서 조건(전략·점수·추세)에 맞는 종목은?
- 후보들을 표로 한눈에 비교하면?
- 스캔에서 왜 제외된 종목이 있나?

**우선 노출 정보**: 필터 바(상단 고정) + 마지막 스캔 시각·대상 종목 수·
통과/제외 수.

**보기 3종 토글**: 카드 / 표 / 히트맵
- 표: 정렬 가능 열 — 종목·가격·등락·점수·행동·추세·거래량 배수·뉴스·신뢰도·
  권장매수·목표·손절·손익비 (최소 13px, tabular-nums)
- 카드: 종목당 결론·점수·가격 3줄
- 히트맵: 점수(색+값 라벨)·거래대금(크기) — 색 단독 금지

**필터 (기존 파이프라인이 산출하는 축만)**: 시장(KOSPI/KOSDAQ)·자산 유형·
시총 구간·거래대금·점수 구간·추세·모멘텀·변동성·뉴스 감점 유무·신뢰도·
전략(market_attention 전략 선택)·국면 적합·추천 가능(게이트 통과) 여부.

**사용자 행동**: 스캔 실행(진행 바) / 필터 조합 저장(ui_prefs) / 행 클릭 →
종목 분석 / 제외 목록 펼쳐보기.

**오류 상태**: 스캔 중 개별 종목 실패는 기존처럼 "분석 제외 N개 사유 보기"로
집계 노출. 전략 사용 불가(STRATEGY_UNAVAILABLE)면 해당 전략 선택지에 사유 표시.

**빈 상태**: 필터 결과 0건 — "조건에 맞는 종목 없음" + 가장 제한적인 필터
표시(어떤 필터를 풀면 되는지). 스캔 미실행 — 실행 안내 + 마지막 스캔 결과
(날짜 명시) 제공.

**모바일 구조**: 필터는 시트(bottom sheet)로, 보기는 카드 고정, 히트맵은
태블릿 이상만.

**필요 데이터 인터페이스**
- 표의 일부 열(모멘텀·변동성·국면 적합)은 스캔 결과 행에 개별 필드로 존재해야
  정렬·필터 가능 — 현재 스캔 행 스키마에 없는 열은 "미제공"으로 비활성화하고
  스키마 확장 인터페이스만 정의: scan_row {ticker, name, price, change_pct,
  score, action, trend, vol_mult, news_flag, confidence, entry, target, stop, rr}.

## 7. 케이스 스터디

**화면 목적**: 모델의 과거 판정 원장(virtual_graded.jsonl)을 열람·분석하는
화면. "이 모델이 실제로 어땠나"에 대한 유일한 정직한 답.

**주요 사용자 질문**
- 전체/조건별 성과는 어땠나?
- 실패는 어떤 유형이 많고, 개선됐나?
- 그때 그 판정 화면을 그대로 다시 볼 수 있나?

**우선 노출 정보**: 성과 요약 스트립 — 사례 수·성공률(Wilson 구간 병기)·
평균 손익·손익비 (전부 calibration.json/원장 실측).

**구조 (탭 3개)**
1. 사례 목록 — 필터(기간·종목·유형·판정·성공/실패·실패 분류) + 표/카드
2. 실패 분석 — 빈번 실패 원인 순위 · 최대 손실 원인 · 최근 증가 유형 ·
   개선 전후 비교(모델 버전 축) · 미해결 항목
3. 사례 상세 — 선택 사례의 당시 재현(기준일 시점 점수·게이트·가격 레벨) /
   실제 경로(MFE/MAE·선도달 결과·수익률) / 개선 반영 여부

**카드 구조**: 사례 카드 — 종목·기준일·당시 판정·결과 배지(성공/실패+분류)·
수익률. 실패 분류는 기존 원장 필드(노이즈 손절/방향 오판/미도달) 그대로.

**사용자 행동**: 필터 / 사례 → 상세 / 상세 → 해당 종목 현재 분석으로 이동.

**오류 상태**: 원장 파일 없음/파싱 실패 — "케이스 원장을 읽을 수 없습니다
(.portfolio/virtual_graded.jsonl)" + 리플레이 실행 안내.

**빈 상태**: 필터 결과 0건 정상 표기. 원장 자체가 비어 있으면 "아직 채점된
사례가 없습니다 — 리플레이를 실행하면 여기에 쌓입니다".

**모바일 구조**: 요약 2×2 → 목록 카드형 → 상세는 전체 화면 전환.

**필요 데이터 인터페이스**
- "당시 재현": 원장에 기록된 스냅샷 필드(점수·판정·진입/목표/손절가·국면)만으로
  재현 카드를 구성한다. 원장에 없는 세부(당시 4대 점수 분해 등)는 재현하지 않고
  "원장 미기록 항목"으로 표시 — 현재 엔진으로 재계산해 "당시"처럼 보이게 하는 것
  금지 (룩어헤드 위장 방지).
- "개선 반영 여부": 실패 사례와 이후 모델 변경의 연결 필드 {case_id,
  addressed_by_version, note} — 현재 없음. 구현 전까지 "미추적" 표기.

## 8. 모델 성과

**화면 목적**: 모델을 감사(audit)하는 화면. 잘한 것과 못한 것, 그리고
지금 경고등이 켜진 곳을 동일한 비중으로 보여준다.

**주요 사용자 질문**
- 적중률은 얼마이고 신뢰구간은?
- 표본외/블라인드 검증은 어떤 상태인가?
- 지금 이 모델을 신뢰하면 안 되는 이유가 있나?

**우선 노출 정보**
1. 적중률 패널: 전체 / 표본외(Walk-Forward) / 블라인드 / 고신뢰 구간 —
   각각 값 + 신뢰구간 + 표본 수. **블라인드 미수행 상태면 "미수행"을 크게
   표기** (이것이 현재 TOP3 게이트의 원인임을 설명).
2. 신호율·손익비·비용 차감 기대값
3. 경고 패널: 표본 부족 · 장세 편중(2025~2026 국면 편중 명시) · 성능 저하 ·
   신뢰구간 확대 · 과최적화 위험 — 해당/비해당을 전 항목 표시
4. 점수대별 리플레이 적중률 표 (게이트 상한과의 연결 설명)
5. 모델 버전 이력 (MODEL_VERSIONS.md 연동)

**탭 구조**: 없음 — 감사 화면은 단일 스크롤로 전부 노출 (숨김이 없는 화면).

**카드 구조**: 지표 카드에는 반드시 {값, 신뢰구간, n, 기준일}. 경고 카드는
해당 시 `--warning`/`--danger` 좌측 보더 + 판정 근거 수치.

**사용자 행동**: 점수대 행 → 케이스 스터디 필터 이동 / 버전 → 변경 내역.

**오류 상태**: calibration.json 부재/스키마 불일치 — "성적 데이터를 읽을 수
없습니다" + 파일 경로 명시. 오래된 데이터(예: 기준일 7일 초과)면 상단에
"성적이 N일 전 기준입니다" 경고.

**빈 상태**: 검증 미수행 항목은 빈칸이 아니라 "미수행 — 이 항목이 미수행인
동안 관련 게이트가 점수 상한을 낮춥니다"로 상태와 결과를 함께 설명.

**모바일 구조**: 적중률 패널 2×2 → 경고 세로 나열 → 점수대 표는 카드 전환.

**필요 데이터 인터페이스**
- 경고 판정 임계(표본 부족 n<?, 성능 저하 최근 30건 대비 −?%p 등): 판정
  규칙이 파이프라인에 없으면 UI가 판정하지 않는다 — 근거 수치만 나열하고
  경고 자동 점등은 {rule_id, threshold, current, triggered} 인터페이스 정의 후
  파이프라인 구현을 기다린다.
- 블라인드 테스트 결과 스키마: {run_date, n, hit_rate, ci} — 현재 미구현
  (미구현 상태 자체를 화면에 명시).
