# 라운드 376 — 휴장일은 규칙으로 다시 유도해 대 본다 · 사이드바는 전역 메뉴와 종목 목차를 가른다 (2026-09-28)

> 사용자: *"항상 무슨 날짜가 휴일로 지정이 되면 맞는지 항상 확인할 수 있는 시스템으로 해주고"* ·
> *"왼쪽에 사이드바도 효율적으로 — 앱 전체 메뉴와 현재 종목 목차가 한곳에 뒤섞여 있고, '모델 성적'·'고객센터'가
> 상단과 하단에 중복."*

값·문턱·판정·점수·추천·산식은 **하나도 안 바꿨다.** 버전 없음(계산부 파일 불변 · 화면 배치와 검사만).

## 1. 휴장일 — 규칙으로 다시 유도해 날짜마다 대 본다

라운드 375 가 고친 두 결함(2026-09-28 을 휴장으로 · 2027-05-03 을 거래일로)은 둘 다 **사람이 대체공휴일 규칙을 머리로
적용해 날짜를 옮겨 적는** 자리의 실수였다. 지나간 날은 일봉 대조가 잡지만 **미래는 봉이 없어 못 잡는다.** 그래서 규칙을
코드로 적었다 — `krx_holiday_rules.py`:

| 공휴일 | 대체 규칙 |
|---|---|
| 신정 · 현충일 | 없음 |
| 3·1절 · 광복절 · 개천절 · 한글날 · 제헌절(2026~) | 토·일 겹침 → 다음 첫 비공휴일 평일 |
| 어린이날 · 부처님오신날 · 기독탄신일 · 노동절(2026~) | 토·일(·다른 공휴일) 겹침 → 같음 |
| 설날·추석 연휴 (당일 ±1) | **일요일**·다른 공휴일 겹침만 (토요일은 아니다) |
| 선거일 · 임시공휴일 | 규칙으로 못 낸다 → `AD_HOC` 에 출처와 함께 |
| KRX 연말 휴장 12/31 | 거래소 규정 |

음력 명절의 양력 날짜만 작은 표(`LUNAR` · 연 3개)로 둔다 — 음력 환산 라이브러리가 설치돼 있지 않고, 이 표는 엔진 표와
**독립**이며 오늘의 두 결함은 둘 다 규칙 쪽이었다. 2025·2026 은 그날의 실제 휴장(일봉 없음)으로도 확인됐다.

실측: 현재 표 · 평일 **52일 전부 일치** · 대 본 해 2025~2027. 옛 표(09-28 휴장 · 5/3·1/27 없음)를 넣으면 **세 결함을
정확히 잡는다** — 그중 2027-05-03 은 일봉 대조로는 2027년 5월까지 못 잡았을 날이다.

**"항상 확인할 수 있게"를 세 자리에 걸었다:**
1. **화면** — 본문에 '휴장일 확인' 절(검증과 이력 묶음 · `#nav-holidays`): 다가오는 평일 휴장 12개를 사유·규칙 판정과
   함께 · 어긋나면 붉게 · '지난 날짜를 실제 거래일과 대 보기' 버튼(일봉 · 이 절만 다시 돈다 · 저장 없음 · 실측 약 6초
   "거래일 86일 · 규칙 52일 전부 맞다"). 사이드바 푸터에 한 줄("휴장일 표 · 규칙과 평일 52일 일치 · 다음 휴장 10-05(월)
   개천절 대체공휴일") — 누르면 그 절로 간다.
2. **매일 밤** — `scripts/calendar_truth.py`(라운드 375 · 워크플로 꼬리)가 이제 규칙 대조도 한다. 일봉을 못 받아도
   규칙 어긋남은 실패로 낸다.
3. **회귀 §369** — 표의 **모든 해가 규칙으로 대 봐져야** 한다. 표에 2028 을 넣으면서 `LUNAR` 2028 을 안 넣으면 여기서
   '못 댄 해' 로 실패한다 — 규칙 없이 날짜를 넣지 못하게 하는 것이 이 시스템의 요점이다.

표는 **고치지 않는다** — 판정만 한다. 고치는 것은 사람이 사유와 함께 한다.

## 2. 사이드바 — 전역 메뉴와 종목 목차를 가르고, 부가 정보는 맨 아래로

바꾸기 전 실측(1920 아닌 창 · 사이드바 스크롤 높이): **2,788px**. 위에서부터 로고 → 검색 → 상단 목록 5개(홈·종목 분석·
모델 성적·업데이트·고객센터) → 번호 묶음 5개(1 오늘의 시장 … 5 도움 · 전부 펼침 · 23줄) → 처음으로·라이트 모드 → 설정
아코디언. 상단 목록 다섯 중 **넷이 아래 묶음과 같은 앵커**(종목 분석 = 이 종목 한 줄 결론 · 모델 성적 · 업데이트 ·
고객센터)였고, '3. 이 종목'(지금 보는 종목의 목차)이 앱 전체 메뉴 사이에 끼어 있었다.

| 자리 | 바꾼 뒤 |
|---|---|
| 맨 위 | 로고 → 종목 검색 (그대로) |
| 검색 바로 아래 | **이 종목 · {종목명}** 목차 — 한 줄 결론 · 차트 · 가늠 AI · 판정 근거 · 시장·뉴스 · 점수 요인. 알약 모양(두 줄 · 102px). 스크롤해도 붙어 있다(sticky) |
| 전역 메뉴 | 접는 묶음 셋 — **오늘의 시장**(맨 위·오늘의 판단 · 오늘의 추천 · 개장 전 결론 · 간밤·전일 시황 · 펼침) · **내 자산**(보유 · 관심) · **검증과 이력**(모델 성적 · 사례 모음 · 업데이트 내역 · 휴장일 확인 · 시세 교차검증 · 고객센터 — 교차검증은 라운드 287 의 결정대로 고객센터 바로 앞에 둔다) |
| 설정 아코디언 | 그대로 — 분석할 종목 · 내 보유종목 · 종목 찾기(항상 펼침) · 분석 기준 |
| 맨 아래 푸터 | 데이터 점검 상태 · 엔진 7축 버전(누르면 업데이트 이력) · 휴장일 한 줄 · 앱 업데이트 날짜 · 처음으로 · 라이트 모드 |

- 중복 상단 목록을 걷어냈다. '홈'은 '오늘의 시장' 첫 항목 **'맨 위 · 오늘의 판단'** 으로 — 로고(검색어·스캔 결과를
  **비우며** 첫 화면)와 달리 **비우지 않고** 맨 위로만 간다(둘은 다른 동작이라 둘 다 둔다).
- '점수 요인'은 이 종목의 세부 점수라 목차로 옮겼다. '사례 모음'은 원장 전체라 전역에 남았다.
- 번호(1.~5.)를 뗐다 — 접는 묶음 셋에서 번호가 순서 외에 말하는 것이 없고, 목차와 같은 체계로 읽히지 않게.
- 엔진 버전 칩과 데이터 점검 상태를 본문 상단 바에서 **사이드바 푸터로** 옮겼다. 종전 요구("업데이트가 가장 중요하다 —
  맨 위")는 끊지 않는다 — 상단 바에 **"업데이트 2026-09-28"** 한 줄을 남기고 누르면 이력으로 간다.
- '종목 찾기' 설명(5줄 · 121px)을 두 문장으로 — 출발점(순위 상위) · 최종 조건 통과만 · 전 종목 정밀분석 아님은 그대로
  (§96 이 잠근다). 뺀 두 문장(한산한 종목은 빠진다 · 관심도≠매수)은 스캔 결과 칸이 더 자세히 말한다(확인함).
- Streamlit 구분선(위아래 여백 65px)을 얇은 선으로. 스캔 진행 막대는 '최신화' 아래 미리 잡은 자리로(푸터 아래로 안 떨어지게).

실측(브라우저 · 같은 창): 사이드바 높이 **2,788 → 2,315px**(−17%). 메뉴 링크 18개 전부 본문 앵커에 닿는다(빠진 것 0) ·
예외 0 · 목차 sticky(사이드바 900px 스크롤 뒤에도 머리 바로 아래 60px) · 375px 폭에서 사이드바 기본 접힘 · 가로 스크롤 없음.
⚠️ 첫 판의 sticky 는 **안 걸렸다** — 목차 div 가 감싼 칸과 높이가 같아서였다(스크롤하면 −318px 로 밀려 올라감). 감싼 칸에
`div:has(> …)` 로 걸었다. 그리고 첫 측정에서 본문 앵커가 대부분 "없다" 로 나왔는데 **덜 그려진 화면**이었다 — 이 앱은 첫
분석에 1~2분 걸린다. 글자 수가 멈춘 뒤 다시 세니 전부 있었다.

## 3. 안 한 것

사용자가 붙인 제안 중 **배치가 아니라 동작을 바꾸는 것**은 이번에 안 했다 — 따로 재고 따로 결정할 일이다:
- 검색어 입력 중 자동 분석 안 하기 · 종목 전환 중 이전 수치 가리기 · 늦게 온 결과 혼입 막기 (검색 체인 수술)
- '시장 후보 최신화'와 '이 종목 최신화' 가르기 · 성공/부분 성공/실패 구분 · 마지막 시도와 성공 시각 분리
- 분석 설정을 폼으로 묶어 '설정 적용' 한 번에 (지금은 바꿀 때마다 다시 돈다)
- 로고(처음으로)가 검색어·스캔 결과를 비우는 동작 — 라운드 42 부터의 동작이라 그대로 두고, 비우지 않는 '맨 위' 링크를 더했다
- 라이트 모드 화면은 대비를 **계산으로만** 확인했다(두 테마 모두 AA · §369) — 인앱 브라우저의 클릭이 테마 토글에 안 닿는다(라운드 126)
- 제안의 이모지 묶음 이름(📁📊⚙️)은 쓰지 않았다(§5 이모지 금지).
